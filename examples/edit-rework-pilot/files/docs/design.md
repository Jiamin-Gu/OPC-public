# 设计说明：健身房团课预约微信小程序（MVP）

- 版本：v1.1（按产品经理第 1 轮审查意见修订 5 处：① B2 补「候补中」状态；② 可配置阈值一律改为读门店/场次生效值；③ B2 已约态按钮改为可点的取消/请假入口（全文统一）；④ 新增「预约已截止（未开课）」状态；⑤ 标签对比度改为实测值并修正「已约」标签文字色）
- 作者：设计师
- 日期：MVP 阶段（仅文档、不写代码）
- 唯一需求依据：`docs/PRD.md`（v1.1）。**本文档不引入 PRD 之外的新功能**；凡属"设计补充"的地方都显式标注 `[设计补充]`，并在 §9 列出需要产品经理/CEO 确认的条目。
- 本文档中的假设一律标注 `假设：……（验证方式：……）`，不编造用户调研结论。本机无联网能力，未引用任何外部规范原文或竞品截图作为依据。

**一句话目标（与 PRD §0 对齐）**：让会员在微信里 30 秒内完成「看课表 → 约课 → 去不了就快速让出名额」，满员时用候补把释放的名额自动补给最想上课的人，教练上课前 30 秒点完名。

## 1. 用户与核心任务

| # | 任务 | 对应的用户故事 | 成功标准（可验收） |
|---|---|---|---|
| T1 | 登录并绑定门店会员 | S1 [P0] | 首次授权后 3 秒内首页可交互；未绑定时可浏览课表但预约按钮置灰并给出前台联系方式；已绑定后静默登录不再要求授权 |
| T2 | 按日期看课表并判断"还有没有位置" | S2 [P0] | 默认展示今天起 7 天；每张卡片能看到「课程名 / 时间 / 时长 / 教练 / 门店 / 教室 / 剩余名额-容量 / 状态标签」；剩余名额公式与 S3、详情页完全一致 |
| T3 | 一键预约有名额的课 | S3 [P0] | 一次点击完成（无二次确认页）；返回后「我的预约」立即可见；并发满员时给出"名额刚被约满，要加入候补吗？"并一键转候补 |
| T4 | 集中查看自己的预约（含候补） | S4 [P0] | 「进行中 / 历史」两组；进行中显示距开课还剩多久；候补项显示实时位次；待确认递补项显示倒计时与两个按钮 |
| T5 | 截止前免费取消；来不及则请假让出名额 | S5 [P0] | 两种操作的入口文案与后果提示不同，且弹窗强制写清"记录 1 次晚取消，不计爽约；名额立即释放" |
| T6 | 满员后排队候补 | S6 [P0] | 入队后立刻看到"第 N 位"（实时 rank，不是 position）；候补满时给出兜底文案；可随时退出且无处罚 |
| T7 | 收到递补通知后限时确认 | S7 [P0] | 首页红点 / 订阅消息 → 候补页显示倒计时 + 「确认参加」「放弃」；名额锁定期间其他会员看不到该名额 |
| T8 | 教练上课前点名 | S8 [P0] | 开课前 30 分钟可进入点名页；30 秒内可完成一场 20 人点名（含"全部到场"批量）；窗口关闭后只读 |
| T9 | 知道自己的到场结果与信用状态 | S9 [P0] | 历史里能区分"已到课 / 未到 / 已结束·到场状态待门店确认"；黑名单时按钮置灰并显示解除时间 |
| T10 | 运营配置规则 / 处理异常（P1 范围） | S10、S13 [P0/P1] | 规则页可改 6 个参数并留审计；名单页高亮"临期空位""未点名异常" |

> 教练是**次要用户**，但 T8 是全部指标的**唯一数据源**，因此点名页按"单手持机、站着操作、30 秒完成"来设计，不做任何需要输入文字的操作。

### 2.2 导航结构

微信小程序原生 tabBar 最多 5 项、**不支持按角色动态改文案**，因此：

```
启动 ──► A1 授权启动页
          │  读取 user_role（PRD §10.2 user_role 表）
          ├─ role = 会员  ──► tabBar：B1 课表 ｜ B3 我的预约 ｜ B5 我的
          ├─ role = 教练  ──► tabBar：C1 我今天的课 ｜ B5 我的
          └─ role = 运营  ──► 同会员 tabBar，B5「我的」内多出「门店管理」分组（D1/D2）
```

- **实现说明（给工程师）**：因原生 tabBar 无法按角色切换，需使用 `custom-tab-bar`（自定义 tabBar），按 `user_role` 渲染 2～3 个 tab；tab 数量变化时首页要重新计算安全区高度。这是 D1 依赖项，请在技术方案中确认。
- **教练同时也是会员**时（同一 openid 绑定了教练身份），在 C1 顶部提供一次「以会员身份约课」入口，切回会员 tabBar；该入口只是角色切换，不是新业务（S8 未禁止教练约课）。
- 非 tab 页面一律用 `navigateTo` 压栈（B2、B4、B6、C2、D1、D2），保留左上角返回；**所有页面必须处理"从微信通知直接进入"的场景**：递补通知 → B4 候补页；黑名单通知 → B5；课程取消通知 → B3。此时返回键要能退回到 B1（用 `redirectTo` + 兜底 `switchTab`）。

## 3. 用户流程

> 约定：流程中"服务端时间"= PRD 的口径；括号内是 PRD 条目号；**出错路径**用 `!` 标出。
> **参数化文案约定（全文有效）**：门店级参数（S10）在界面上**一律读生效值**（场次级覆盖优先），文档中用占位符表示，**禁止写死默认数字**：
> `{确认时限}` = 接口返回的 `rule.waitlistConfirmMinutes`（默认 15 分钟）；**不递补阈值 = `{确认时限}` + 5 分钟**（默认 20 分钟，即 R3 的 `min(start_at) − now < confirmMinutes + 5`）；
> `{取消截止}` = `rule.cancelDeadlineMinutes`（默认 120 分钟）；`{预约截止}` = `rule.bookingDeadlineMinutes`（默认 0 分钟）。
> 字段出处：tech-design §5.3 接口 ③/④ 的 `rule` 对象与接口 ④ 的 `myBooking` / `myWaitlistEntry`。**文档里出现的 15 / 20 / 120 都是默认值示例，不是固定值。**

### 流程 1：查看课表 → 预约（T2 → T3）

```
进入小程序
  └─ A1 静默登录（S1）
      ├─ ! 未绑定会员 → B1 可浏览，预约/候补按钮置灰，顶部黄条"请先绑定门店会员手机号 [去绑定]"
      └─ 绑定成功 → B1 课表
          ├─ 默认选中"今天"，加载今天起 7 天（S2）
          ├─ 切换日期 / 类型 chip / 门店 → 2 秒内刷新（S2）
          ├─ ! 空数据 → "这天还没有团课"（S2）
          ├─ ! 网络失败 → 错误态 + [重试]，**不清空已加载内容**（S2）
          └─ 点击卡片 → B2 课程详情
                ├─ 剩余名额 ≥ 1 → 底部按钮【立即预约】（主色，全宽 44px 高）
                │     └─ 点击 → 请求 → 成功轻提示"预约成功" + 按钮变【已预约 ✓】（禁用态）+ 名额 -1
                │           └─ ! 并发满员 → 弹窗"名额刚被约满，要加入候补吗？" [去候补]/[知道了]（S3）
                │           └─ ! 时间冲突 → "与已约课程《X》时间冲突（HH:MM–HH:MM）"（S3）
                │           └─ ! 已在黑名单 → "你在该门店的预约权限已暂停至 YYYY-MM-DD HH:MM" + [联系门店]（S3）
                │           └─ ! 已开课/门店停用/重复提交（幂等）→ 见 §6 文案表
                ├─ 剩余名额 = 0（含锁定给递补者的名额） → 按钮变【排队候补】（强调橙）
                ├─ 我已在该场次候补中（接口 ④ myWaitlistEntry.status = waiting）→ 按钮变〔候补中 · 第 N 位〕+【查看候补】→ B4（N = 实时 rank，与 B1 同源）；status = notified → 〔待确认递补〕+【去确认】→ B4。
                │     **绝不显示【排队候补】**，否则点击必被服务端 WAITLIST_DUPLICATE 拒绝（S6/R2）
                ├─ 已过预约截止但未开课（now ≥ start_at − {预约截止}）→ 按钮置灰，文案「已过预约截止时间（开课前 {预约截止} 分钟）」。
                │     **不得**写「已开课」——课还没开始（S3/R4，tech-design §5.2 SESSION_STARTED）
                └─ 已开课 / 已取消 → 按钮置灰，文案"已开课"/"已取消"
```

**设计决策（记录）**：B2 详情页**不设**独立的"预约确认"二次页。理由：S3 明确要求"一键约上，按钮变为已约"；多一次点击会直接拉低 S2→S3 转化。为降低误操作感，改为在底部操作栏上方常驻一行摘要（时间 / 地点 / 规则一句话），把"确认信息"和"操作"放在同一屏内。**需要二次确认的只有"有后果且不可逆"的操作：取消、请假、放弃递补。**

### 流程 2：取消 / 请假（T5）

```
入口（两处等价，弹窗与判定完全相同）：B3 我的预约卡片按钮 ｜ B2 课程详情底部按钮
  （B2 的已约态按钮**可点**，文案按服务端 myBooking.cancelMode 显示【取消预约】(ontime) 或【我要请假】(late)；cancelMode = none 时置灰显示"已开课，等待教练点名结果"。
   不做右滑等隐藏手势，见 §7.3）
  └─ 点击 → 服务端时间判定（R4）
      ├─ now ≤ start_at − cancel_deadline_minutes（默认 120 分钟）
      │     → 弹窗【取消预约】：标题"取消这次预约？"
      │        正文"名额会立即释放给候补的人，不记录任何处罚。"
      │        [再想想] [确认取消]
      │        → 成功轻提示"已取消，名额已释放"；卡片移入历史（S5）
      │        └─ 若该场次有候补队列 → 系统按 S7 触发递补（会员无感）
      │        └─ ! start_at − now < waitlist_confirm_minutes + 5min → 不递补，名额标"临期空位"（S5/R3）
      ├─ start_at − 120min < now < start_at
      │     → 弹窗【我要请假】：标题"已过取消截止时间，改为请假？"
      │        正文（**文案强制口径，R4**）"此操作将记录 1 次晚取消，不计爽约；名额立即释放。"
      │        [再想想] [确认请假]
      │        → 成功轻提示"已请假，名额已释放（记录 1 次晚取消）"
      ├─ now ≥ start_at → 已经没有取消/请假按钮，卡片显示"已开课，等待教练点名结果"
      └─ ! 操作竞态（名额已被系统递补给他人）→ 轻提示"操作未生效，名额状态已变化，请刷新"（S5）
```

**文案红线**：请假相关弹窗与后置提示**只能**出现"记录 1 次晚取消 / 不计爽约 / 名额立即释放"。禁止出现"记爽约""累计 N 次暂停预约权限"（R4、PRD §6.2 第 6 条）。

### 流程 3：满员 → 排队候补（T6）

```
B2 详情页（剩余名额 0）→ 点【排队候补】
  └─ 校验（S6）：未绑定 / 黑名单 / 已预约 / 已在候补 / 时间冲突 / 候补已满 / 已开课
      ├─ 全部通过 → 弹一次微信订阅消息授权引导（S6）
      │     ├─ 允许 → 请求成功
      │     └─ 跳过 → 页面标注"不授权将无法及时获知递补"，仍入队成功（S6）
      │   → 进入 B4 候补页；按钮/卡片状态变【候补中 · 第 N 位】
      └─ ! 候补已满 → "候补已满，可在开课前再来看看"（S6）
         ! 已在候补 → "你已在候补队列第 N 位"（N 为实时 rank，R2）
         ! 已是预约 → "你已预约该课程"
  └─ B4 内点【退出候补】→ 二次确认"退出后位次不再保留" → 成功 → 状态变 canceled，退到 B3（S5/R2）
```

**位次展示口径（R2，S2 / S4 / S6 三处必须一致）**：界面上的"第 N 位"永远是**实时 rank** = 队列中 `status ∈ {waiting, notified}` 且 `position ≤ 自己 position` 的记录条数（含自己）；绝不显示存储的 `position`。他人退出/超时后位次自动前移。

### 流程 4：递补通知 → 限时确认（T7）

```
名额释放（有人取消/请假、运营加容量）
  └─ 系统 5 秒内：锁定名额（reserved_count +1，课表剩余名额同步 −1）→ 队首置 notified → 发订阅消息（S7/R3）
      ├─ 通知送达 → 会员点通知直接进入 B4（从 B3 角标/首页红点也可进）
      │     └─ B4 显示：课程名 / 门店 / 开课时间 / 确认截止时间 / 倒计时 / [确认参加] [放弃]
      │         ├─ 点【确认参加】→ 成功页内提示"已确认，请在 XX:XX 前到店" → B3 变"待上课"（S7）
      │         │     └─ ! 释放事件已关闭或名额已被占用 → "名额已被占用，本次候补未成功"，记录置 expired（S7）
      │         ├─ 点【放弃】→ 名额立即转下一顺位；提示"已放弃，本次候补结束"，不计任何处罚（S7/D7）
      │         └─ 超时未操作 → 定时任务把记录置 expired，顺延下一位（`try_count` +1，名额仍锁定在同一释放事件上）
      │               └─ 同一释放事件连续 3 次无人确认 → 释放事件 abandoned，名额标"临期空位"（S7/R3）
      ├─ ! 通知未授权/发送失败 → 首页红点 + B3 角标降级；**确认时限延长为 min(30min, start_at − now)**（S7；此处的 30 分钟是 PRD 固定上限，不是门店参数，不随 S10 变化）
      ├─ ! 释放时 start_at − now < {确认时限} + 5 分钟（默认 < 20 分钟） → 不发起递补：不创建释放事件、不锁定名额，名额保持空闲可约并标"临期空位"（S7/R3）
      └─ ! now ≥ start_at → 所有 waiting/notified 置 expired，释放事件 expired，reserved_count 归零，候补关闭（S7）
```

会员在倒计时期间看到的关键说明（必须出现，避免"为什么我看不到名额"的困惑）：**"名额已为你锁定至 XX:XX，课表上的剩余名额已同步扣除。"**

### 流程 5：教练上课前点名（T8）

```
教练打开小程序 → A1（手机号 + 门店绑定教练身份）→ C1 我今天的课
  └─ 场次卡片：课程名 / 时间 / 门店 / 预约 n/容量 / 候补 m / 点名状态
      ├─ 未进入窗口（now < start_at − 30min）→ 点名按钮置灰 + "开课前 30 分钟开放点名"（S8）
      ├─ 在窗口内 [start_at − 30min, start_at + 15min] → 点进 C2 点名页
      │     默认全部"未标记"，逐行点【已到】/【未到】
      │       ├─ 可反复修改（打错撤回），以最后一次为准（S8）
      │       ├─ 【全部到场】/【全部未到】批量按钮（顶部）
      │       ├─ ! 名单变化（有人取消 / 递补进来）→ 自动刷新，新入会者标"补位加入"，已标记不丢（S8）
      │       ├─ ! 无网络 → 行内标"待提交"，恢复网络后自动提交；提交失败显示明确失败提示（S8 P1）
      │       └─ ! 无预约会员 → 显示"暂无预约"，不阻塞（S8）
      └─ now > start_at + 15min → 点名页只读 + 顶部条"点名窗口已关闭，如需修改请联系门店运营"（S8）
  └─ 场次结束后的判定（离线任务，S8/S9/R5）：
      - 教练明确标 absent → no_show（计爽约）
      - 整场无任何 check_in 记录，或某条预约未被标记 → pending_review「未点名异常」，**不自动计数**
      - 运营在 D2 处理异常；撤销爽约只改 booking.status，计数由实时重算自动回退（R5）
```

> **关于任务中"签到码校验失败"**：PRD 的 D4 与 S8 明确 MVP **不做二维码/签到码签到**，改为"教练为会员点名"，因此**不存在"签到码校验失败"这一环节**。我按等价异常做了映射（camera 不可用/扫码 → 点名提交失败、窗口已关闭、名单已变化、离线），见 §6.6。若 CEO 要求保留扫码签到，需要产品经理先改 PRD 的 D4 与 S8（涉及数据模型与防代签方案），再回来补这一屏设计。

## 4. 设计规范（含视觉风格指南）

### 4.1 设计基准

- 设计稿基准：**375 pt 宽**（iPhone 6/7/8/SE 逻辑宽度），1 px（设计稿）= **2 rpx**。所有尺寸同时给出 px 与 rpx。
- 内容最大宽：≥ 768 pt（平板 / PC 微信小程序）时，内容区最大 **600 pt** 水平居中，**不做多列**（信息结构是"按时间的一条线"，多列会破坏时间可读性）。
- 主题：只做浅色主题。`假设：MVP 不做深色模式（验证方式：上线后看微信深浅色用户比例与投诉量）；若后期开启，必须重跑 §7 的对比度检查`。

### 4.2 色彩（含对比度）

| 用途 | 色值 | 对比度（对白 #FFFFFF） | 用法 |
|---|---|---|---|
| 品牌主色 | `#1F7A55` | **5.28:1** ✅ AA | 主按钮底、选中日期胶囊、tab 选中态、链接强调 |
| 主色-按下/深 | `#165B3F` | **8.06:1** ✅ AAA | 主按钮按下、白字深底 |
| 主色-浅底 | `#E8F4EF` | — | 主色系标签底、选中 chip 底（配 `#165B3F` 文字，>7:1） |

| 语义-成功 | `#14804A` | **4.98:1** ✅ AA | "已到课""预约成功""候补成功" |
| 语义-错误 | `#C62828` | **5.62:1** ✅ AA | 错误提示、校验失败、危险操作按钮（确认取消/请假） |
| 语义-信息 | `#1A5FB4` | **6.28:1** ✅ AA | 说明性链接、"了解规则" |
| 语义-警告文字色 | `#8A5A00` | **5.93:1** ✅ AA | 黄底提示条上的文字（底 `#FFF7E6`） |

| 文本-次要 | `#5A6270` | **6.15:1** ✅ AA | 时间、教练、门店、说明 |
| 文本-辅助 / 占位 | `#6B7280` | **4.83:1** ✅ AA | 小字说明、输入占位（占位文字不用更浅的灰） |

| 页面底色 | `#F5F6F8` | — | 全站背景 |
| 卡片底色 | `#FFFFFF` | — | 卡片、弹窗、底部操作栏 |

规则：
- 一张卡片里**最多一个**实心主色按钮，其余用描边或文字按钮，避免"哪个都能点"。
- **不只用颜色传达信息**：状态一律"颜色 + 文字标签"（如"已满"配灰红底 + 文字，不靠变灰）；错误提示一律"颜色 + 图标 + 文字"。
- 教师/会员头像为图片，缺失时降级为首字母色块（`#E8F4EF` 底 + 主色首字），不显示破图。

### 4.3 字体

微信小程序默认系统字体：iOS = PingFang SC，Android = 系统默认（MiSans/思源黑体/Roboto）。**不引入自定义字体**（体积与首屏性能）。

| 层级 | 字号 / 行高（px） | 字重 | 用途 |
|---|---|---|---|
| 页面标题 H1 | 20 / 28 | 600 | 页面顶部标题（"约课""我的预约"） |
| 区块标题 H2 | 17 / 24 | 600 | "进行中""历史"、卡片主标题（课程名） |
| 正文 Body | 15 / 22 | 400 | 时间、教练、门店、规则说明正文 |
| 数值强调 | 17 / 24 | 600 | 剩余名额 `3/20`、倒计时 |
| 次要说明 Caption | 13 / 18 | 400 | 补充说明、规则摘要、时间戳 |
| 标签 Tag | 11 / 16 | 500 | 状态标签（"已约""已满"） |
| 按钮文字 | 15 / 20 | 500 | 主/次按钮；大按钮可用 17/24 |

- **不随系统字号缩放的做法**：小程序中 `rpx` 不随系统字号变化；为确保"跟随系统大字号"的用户也能读，正文容器使用 `text` 的自然换行 + **禁止单行省略关键信息**（时间、地点、名额必须完整可见，允许换行不省略）。
- 数字使用等宽对齐（名额、倒计时），避免跳动。

### 4.4 间距 / 圆角 / 阴影 / 层级

- 基础单位 **4 px**；常用间距：`4 / 8 / 12 / 16 / 20 / 24 / 32`（rpx：`8 / 16 / 24 / 32 / 40 / 48 / 64`）。
- 页面左右安全边距 **16 px（32rpx）**；小于 375 pt 的机型降为 12 px。
- 卡片内边距 **16 px**；卡片间距 **12 px**；区块间距 **24 px**。
- 底部固定操作栏高度 **64 px**（含 `env(safe-area-inset-bottom)` 内边距），列表底部必须预留等高空白，避免最后一张卡片被遮住。
- 圆角：卡片 **12 px**、按钮 **12 px**（小标签按钮 8 px、胶囊 chip **全圆角**）、标签 **4 px**、弹窗 **16 px**、输入框 **8 px**、头像 **圆形**。
- 阴影（克制使用，只做层级暗示）：
  - 卡片：`0 1px 2px rgba(0,0,0,0.04)`
  - 底部操作栏：`0 -2px 8px rgba(0,0,0,0.06)`
  - 弹窗：`0 8px 24px rgba(0,0,0,0.12)`
- 触控区域：**所有可点元素 ≥ 44 × 44 px（88 × 88 rpx）**；图标按钮实际图标 24 px 但热区扩到 44 px；卡片整块可点，卡片内的按钮需 `catchtap` 阻止冒泡。

### 4.5 基础组件与状态

通用状态集合：**默认 / 按下（小程序无 hover，用 `hover-class` 实现按下态，桌面端用 `:focus`）/ 聚焦 / 禁用 / 加载中 / 成功 / 失败**。

- 不用自定义 `view` 假装按钮而不加 `aria-role`/`aria-label`（会毁掉键盘与读屏可达性，见 §7）。

- 单行点【已到】→ 立即变"已到 ✓"（主色实心，右侧可点【未到】纠正）；点【未到】→ 变红描边"未到"；**窗口内可反复修改**，以最后一次为准（S8）。
- 批量：【全部到场】/【全部未到】需二次确认（"将把 12 位会员全部标记为已到"），只影响**未标记**行，不覆盖已修改过的行（避免误伤）。
- 无网络：行内显示"待提交"，底部栏显示"3 条待提交"，恢复网络自动重试；**重试失败时明确提示"未提交成功，请重试"，不得静默丢弃**（S8 P1）。
- 窗口未开：整页可进入但动作按钮禁用 + 顶部条"开课前 30 分钟开放点名"（S8）。
- 窗口已关（> start_at + 15min）：整页只读 + 顶部条"点名窗口已关闭，如需修改请联系门店运营"（S8）。
- 名单变化：自动刷新列表并插入"补位加入"标记，已标记记录不丢失（S8）。
- 运营进入同页时，顶部多一行"你正在代教练操作，操作将记录到日志"（S8 边界 + R7 审计）。

**状态**：加载中（`名单加载中…` + 骨架 5 行）/ 空（"暂无预约"，不阻塞）/ 出错（[重试] + "名单加载失败"）/ 提交失败（行内红点 + 底部栏红字）/ 窗口已关只读。

## 7. 无障碍检查

### 7.1 对比度（WCAG AA）

- 正文（15/22）与次要文本（13/18）全部 ≥ 4.5:1：§4.2 表中已逐项标注（最低为辅助文本 `#6B7280` = 4.83:1）。
- 大字（≥ 18.66 px 粗体 / 24 px 常规）按 3:1 要求，本设计中最小的"数值强调"为 17 px 600——**按正文标准 4.5:1 执行**，标准更严。
- 唯一低于 4.5:1 的 `#9AA1AC` **只用于禁用控件**（WCAG 1.4.3 对禁用控件豁免），且禁用态**必须**同时给出可见的原因文案。
- 彩色标签（已约/已满/候补中/已开课）都是"浅底 + 深字"组合，**实测对比度 4.54:1 ~ 7.12:1，全部 ≥ 4.5:1（11 px 属小字口径）**；**且都有文字**，不靠颜色单独传达。逐项实测值见下条。
- 标签实测（底色 × 文字色 → 对比度）：已约 `#E6F4EC` × `#165B3F` = **7.12:1** ✅；候补中/待确认 `#FDEDE4` × `#C2410C` = **4.54:1** ✅（余量仅 0.04，四色中最紧）；已满 `#FBE9E9` × `#C62828` = **4.80:1** ✅；已开课/已取消/已截止 `#F0F1F4` × `#5A6270` = **5.45:1** ✅。
  **反例（禁止实现）**：语义-成功 `#14804A` 落在 `#E6F4EC` 上只有 **4.39:1，低于 AA**——所以"已约"标签必须用 `#165B3F`；`#C2410C` / `#C62828` 两个标签余量 ≤ 0.3，实现时不得加 `opacity`、不得换更浅的底或更浅的字色。

### 7.2 键盘与焦点

- 所有可点元素优先使用**原生组件**（`button`、`input`）以获得系统焦点与读屏支持；必须自定义时加 `aria-role="button"` + `aria-label`，并保证 `focus` 时有 2 px `#1A5FB4` 可见描边。
- 焦点顺序 = 视觉顺序：B1（日期条 → 筛选 chip → 卡片 1..n）；B2（信息区 → 规则可展开 → 底部主按钮）；C2（批量按钮 → 行 1..n → 底部提交）。
- 弹窗打开时焦点进入弹窗首按钮，关闭后回到触发元素；弹窗**不可**通过点遮罩意外触发危险操作（遮罩点击 = 取消，仅对非危险弹窗）。
- `假设：PC 微信小程序对 Tab 键焦点移动的支持程度不确定（验证方式：PC 微信真机走查 + 开发者工具无障碍面板，P1 验证）`。若不支持，至少在"阅读顺序 + 大热区 + 不依赖悬停"上保证可操作。

### 7.3 触控与可读性

- 所有热区 ≥ 44 × 44 px（88 × 88 rpx）；卡片内小按钮（32 px 高）通过 `padding` 把热区撑到 44 px；相邻按钮间距 ≥ 8 px，避免误触。
- 所有图片（教练头像、课程封面）有 `aria-label` 或 `alt` 等价文本；纯装饰图不加。
- 关键信息不省略：时间、地点、剩余名额、倒计时**禁止** `text-overflow: ellipsis` 截断，允许换行。
- 不依赖颜色、不依赖悬停、不依赖手势（**不设计**左右滑动取消预约等隐藏手势——手势无可见入口，键盘与读屏用户无法发现）。
- 动效：仅使用 150–200 ms 的淡入/位移，尊重系统"减弱动态效果"（微信端通过 `wx.getSystemInfoSync().enableDebug` 无法直接读取时，**默认不播放自动轮播/长动画**）。

### 7.4 性能与慢网络

- 首屏（B1）优先：先渲染日期条 + 骨架，再拉课程列表；课程封面图 **不做**大图（MVP 用纯文字卡片，无封面），避免首屏图片阻塞。
- 头像使用 CDN 缩略图（≤ 96 px）+ 圆角裁切，懒加载；列表分页 20 条（B3 历史）。
- 乐观更新仅用于**幂等且可回滚**的操作（点名标记、入队/退出候补），失败必须回滚并提示；预约/取消**不做乐观更新**（价格与名额不能猜）。
- 弱网：提交类按钮统一 loading + 5 秒超时 + 明确失败提示"，不出现"点了没反应"。
