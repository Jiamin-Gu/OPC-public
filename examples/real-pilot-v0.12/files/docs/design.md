**v1.1 返工修订摘要（针对产品经理第 1 轮审查的 3 条意见）**：

1. **统一全部示例数值**：转正示例课程改为「11月18日 20:00-21:00 瑜伽拉伸」，转正 18:32、取消截止 18:47、卡片倒计时「还有 1 小时 28 分」，并在 2.3 增加自校验表（18:32 距开课 88 分钟 ≥ 30 分钟 ✅、18:47 ≤ T-30 = 19:30 ✅），全文同一组数值。
2. **取消预约后不保留条目**：自助取消成功即从「我的预约」移除，MVP 不做「已取消」历史条目（对齐 PRD 故事 4 验收标准）；`[已取消]` 标签只表示「课程被门店取消」这点在 5.3 / 6.1 写清。
3. **补齐「店长补签后核对窗口重开」**：5.6 加核对入口可用性与核对结果区、5.7 把只读态拆成「签到异常未补签」与「补签后重开」两态、6.3 教练端时间轴与流程 5 同步。

**本版相对上一轮（PRD v0.3）的设计变更摘要**（因为上游改了口径，界面必须跟着改）：

1. **候选确认环节全部删除**：会员端不再有「确认预约 / 放弃」按钮、不再有 15 分钟确认倒计时、不再有「待确认」标签。名额释放即自动转正，界面直接跳成「已预约」。
2. **新增「退出候补」入口**（F5）：课程详情页与「我的预约」条目上固定位置提供，二次确认后生效，退出不释放名额、位次前移。
3. **新增「宽限期取消截止时间」的展示**：自动转正得到的预约要显示「可在 X 前取消」，取值 = max（开课前 120 分钟，转正时间 + 15 分钟），上限 T-30。
4. **加入候补前的告知文案升级为常驻必显**：「有人退课时，系统会自动帮你约上这节课……」（PRD 7.3 MUST），且不弹「同意」窗、不作为订阅授权的前提。
5. **T-30 之后的样子变了**：不再是「待确认超时」，而是「不再转正、名额回公开可约、队列统一置已关闭」，界面文案为「本课候补已结束（如仍有余位可直接预约）」。
6. **店长端概览去掉「待确认人数」**，换成「候补中人数」+「已自动转正人数」。

# 1. 用户与核心任务

本设计只承载 PRD 第 4 章 P0 清单（F1–F10），下面每条任务都能对到一个或多个用户故事。

| 任务 | 对应的用户故事 | 成功标准（界面上可验证） |
| --- | --- | --- |
| 微信登录 + 绑定会员卡 | 故事 1（F1） | 授权手机号后 1 屏内到达课表页；查不到会员时不进课表，显示「未查到会员信息，请联系门店前台」+ 门店电话 |
| 查看未来 7 天课表 | 故事 2（F2） | 首屏见今天课程；每张卡显示课程名、教练、时间、门店、剩余名额或「已满（候补 n 人）」；我已约/候补的课显示对应状态 |
| 预约团课 | 故事 3（F3） | 点「预约」→ 1 次确认 → 卡片立即变「已预约」；并发抢位失败时给出「名额已被抢完，是否加入候补？」 |
| 取消预约 | 故事 4（F4） | 距开课 ≥ 120 分钟可点「取消预约」→ 确认 → 列表移除该课；< 120 分钟按钮置灰并给出前台提示 |
| 满员时加入候补 | 故事 5（F5） | 点「加入候补」一步生效 → 显示「候补中 · 第 n 位」；加入前看见自动转正告知文案 |
| 主动退出候补 | 故事 5（F5） | 「退出候补」→ 二次确认 → 变「已退出候补」，位次不再占用，退出后仍可重新加入 |
| 被自动转正并收到通知 | 故事 6（F6） | 零操作变「已预约」；首页出现「已自动为你约上…」提醒条（含倒计时与取消入口）；无任何「待确认」中间态 |
| 教练看自己的课与名单 | 故事 7（F7） | 教练账号打开默认落在「我的课程」；课程详情列出全部已预约会员，候补中会员不出现在名单里 |
| 教练签到 | 故事 8（F8） | 签到窗口内可点「签到」→ 状态变「已签到（19:02）」；窗口外按钮置灰并给出对应文案 |
| 教练核对到场 | 故事 9（F9） | 默认全「到场」+ 顶部与提交按钮都显示计数；提交后 10 秒内可「撤销」；「未核实」只读、不可选 |
| 店长兜底 | 故事 10（F10） | 概览显示报名/容量、候补中、已自动转正、已签到/缺席/未核实；异常课可补签、可直接提交/修改核对 |

**三类用户的界面关系**：同一小程序，进入时按账号角色**整页分流**（故事 2 验收标准），三端复用同一套设计规范与组件，不共享同一套信息架构——教练不需要看会员课表，会员看不到教练端任何元素（含「教练已签到」，故事 8）。

假设：会员端信息架构只做「课表」与「我的预约」两个 tab，**不设「我的」页**——会员历史出勤统计属 P1（PRD 第 4 章），MVP 里会员卡状态靠课表页顶部状态条 + 按钮被拦时的提示呈现（验证方式：上线后看「会员卡过期」被拦场景的客服工单量，若集中则考虑加「我的」页，属 P1）。

# 2. 信息架构

## 2.1 页面清单与层级（会员端 / 教练端 / 店长端三个入口）

```
小程序（启动时按角色分流，落地页不同）
│
├── 【入口 A｜会员端】会员卡有效且未绑定的会员 → 先走授权页
│   ├── 会员课表页（Tab1，默认落地页）           F2
│   ├── 我的预约页（Tab2）                        F4/F6
│   └── 课程详情与预约页（从课表、我的预约、转正提醒条、订阅消息进入）
│       ├── 预约确认面板（同一页内的底部弹层）    F3
│       ├── 加入候补（同一页内，告知文案常驻）    F5
│       ├── 退出候补二次确认弹窗                  F5
│       └── 取消预约二次确认弹窗                  F4/F6
│
├── 【入口 B｜教练端】教练手机号白名单账号 → 落地「我的课程」
│   ├── 我的课程页（Tab1，默认落地页）           F7
│   └── 课程详情页（学员名单 + 签到 + 核对入口）  F7/F8
│       └── 到场核对面板（详情页内展开/滑入）     F9
│
└── 【入口 C｜店长端】店长账号 → 落地「今日概览」
    └── 今日概览页（默认落地页）                  F10
        └── 课程明细页（补签 / 直接提交或修改核对）F10
```

**没有独立页面的两处，说明原因**：

1. **候补状态没有独立页面**。候补是「我的预约」里的一种条目状态 + 课程详情页里的一个状态区，两处同源同文案（见 5.4）。不新增页面是为了不给会员多一条找不到的路径；PRD 也只要求状态可在小程序内看到（7.3 权威路径）。
2. **转正通知没有独立页面**。它是课表页顶部的一条提醒条 + 「我的预约」里的状态卡（PRD 7.3 要求「首页与我的预约都有入口」）。

## 2.2 导航结构

| 端 | 导航 | 说明 |
| --- | --- | --- |
| 会员端 | 底部 TabBar 两个 tab：`课表` / `我的预约` | 图标 + 文字，选中态主色；不用抽屉、不用顶部多级 tab |
| 教练端 | 底部 TabBar 一个 tab：`我的课程`（也可不放 TabBar，仅顶部标题栏） | MVP 教练只有 1 个入口，不放多余 tab |
| 店长端 | 顶部标题栏 `今日概览` → 点课程进 `课程明细` | 单层下钻，返回箭头固定左上 |

**跳转关系（会员端）**：课表页 `课程卡` → 课程详情页；我的预约页 `条目` → 课程详情页；课程详情页返回 → 回到来源页（保留来源页滚动位置与已选日期）。转正提醒条 → 对应课程详情页（返回后提醒条仍可再次进入，直到该课结束或已取消）。

## 2.3 三端一致性约定

- 同一概念全站同一个词：**已预约 / 候补中（第 n 位）/ 已自动转正为预约 / 已退出候补 / 本课候补已结束 / 已完成 / 已缺席 / 未核实 / 签到异常**。禁用「待确认」「待你确认」「待确认中」等词（PRD v0.4 起该状态不存在）。
- 时间格式统一 `11月18日（周三）19:00-20:00`；倒计时统一 `还有 1 小时 28 分`；截止时间统一 `可在 18:47 前取消`。
- 所有「名额已锁定但你看不到」的情况都不复存在：课表永远显示服务端实时剩余名额。

**示例数值的约定（全文所有示例只用这一组；已按 PRD 7.4/7.6 自校验，实现与测试不要另换一组）**

| 示例用途 | 取值 | 自校验 |
| --- | --- | --- |
| 转正示例课程 | 11月18日（周三）20:00-21:00 瑜伽拉伸（张教练 · 2F 瑜伽室）——与 5.1 课表线框 ⑥ 同一节课 | — |
| 自动转正时刻 | 18:32 | 距开课 88 分钟 ≥ 30 分钟，发生在 T-30（19:30）之前 ✅ |
| 转正后的取消截止 | 18:47 | = max（开课前 120 分钟 = 18:00，转正 18:32 + 15 分钟 = 18:47）= 18:47，且 18:47 ≤ T-30（19:30）✅ |
| 转正卡片上的倒计时 | 「还有 1 小时 28 分」 | 20:00 − 18:32 = 1 小时 28 分，与同屏的「可在 18:47 前取消」不矛盾 |
| 普通预约示例课程 | 11月18日（周三）19:00-20:00 搏击操（王教练 · 3F 团操房），取消截止 = 开课前 120 分钟 = 17:00，该课 T-30 = 18:30（PRD 7.5） | 与 5.1 ⑤、5.2 线框同一节课 |
| 时间冲突示例课程 | 19:30-20:30 动感单车（5.1 课表线框 ⑦ 的同一节课） | 与 19:00-20:00 搏击操、20:00-21:00 瑜伽拉伸都存在真实交集（半开区间口径，PRD 7.5）→ 冲突成立 |

> 竞态/边界示例若需要另一组数值，**必须同样满足**：转正时刻距开课 ≥ 30 分钟、截止 = max（T-120，转正 + 15）且 ≤ T-30、倒计时与截止同屏自洽。

# 3. 用户流程

图中 `[决策]` 表示分支判断点，`!` 表示异常分支。

## 3.1 流程 1：首次进入 → 授权 → 课表（F1→F2）

```
打开小程序
  → [决策] 角色判定（服务端）
      ├─ 会员 → 是否需要手机号授权？
      │    ├─ 是 → 授权页（说明用途 + 「微信一键授权」按钮 + 「先看看课表」次要入口）
      │    │        → [决策] 门店系统能否匹配到会员卡？
      │    │             ├─ 能   → 课表页（成功）
      │    │             ├─ 查不到 → ! 停在授权页：「未查到会员信息，请联系门店前台」+ 门店电话
      │    │             └─ 手机号不一致 → ! 走「联系前台核验」引导，不自动猜测绑定
      │    └─ 否 → 课表页（可直接浏览，只读）
      ├─ 教练 → 我的课程页
      └─ 店长 → 今日概览页
```

成功标准：会员从点击到看见今天课表 ≤ 2 次点击（1 次授权 + 落地）。**不设注册表单**（PRD 第 2 章）。

## 3.2 流程 2：课表 → 预约（F2→F3）

```
课表页 → 点课程卡 → 课程详情页
  → [决策] 这节课的可用状态？
      ├─ 剩余名额 ≥ 1 → 点「预约」→ 底部确认面板（课程名/时间/教练 + 「确认预约」）
      │     → [决策] 服务端结果
      │          ├─ 成功 → toast「预约成功」+ 卡片变「已预约」+ 名额 -1
      │          ├─ ! 名额已被抢完 → 弹窗「名额已被抢完，是否加入候补？」→「加入候补」→ 见流程 3
      │          ├─ ! 与已预约课程时间冲突 → 提示「与已预约课程时间冲突：<课程名>」，不产生预约
      │          └─ ! 会员卡无效/过期 → 按钮本就置灰，提示「会员卡已过期，请到前台办理续卡」
      ├─ 剩余名额 = 0 → 按钮为「加入候补（队列 n 人）」→ 见流程 3
      └─ 已开始/已结束 → 无预约入口，显示「进行中 / 已结束」
```

步骤数：**查看 → 点卡 → 点预约 → 确认 = 2 次点击 + 1 次确认**。会员端不做座位/时段选择、不做人数选择（团课固定 1 人 1 位）。

## 3.3 流程 3：满员 → 加入候补 → 自动转正 → （取消 或 到场）（F5→F6）

```
课程详情页（已满）→ 按钮上方常驻告知：「有人退课时，系统会自动帮你约上这节课，
请及时查看；如不去请在可取消截止时间前自行取消」
  → 点「加入候补」（一步生效，不弹确认；订阅消息授权是可选的引导，拒绝也能加入）
  → 卡片变「候补中 · 第 3 位」；我的预约页同步出现该条目
  → 等待期间有两种选择：
      ├─ 我改主意 → 点「退出候补」→ 二次确认 →「已退出候补」（不释放名额、我后面的位次前移 1）
      └─ 什么都不做
  → 有人取消（且距开课 ≥ 30 分钟）→ [决策] 服务端冲突预检
      ├─ 我无时间冲突 → 我立即自动转正：
      │     零操作变「已预约」→ 首页提醒条 + 订阅消息「已自动为你预约」→ 卡片显示
      │     「可在 18:47 前取消」→ 我若不去就在该时刻前点「取消预约」
      └─ 我有时间冲突 → 不转正给我 → 移出队列 → 提示「因与已预约课程时间冲突，已退出本课候补」
                                    → 名额继续顺延给下一位（我什么都不用做）
  → ! 距开课 < 30 分钟（T-30）仍未被转正 → 队列统一置「已关闭」→ 我收到
       「本课候补已结束（如仍有余位可直接预约）」→ 我的条目变只读，不再有退出入口
```

设计要点：**这条流程上会员要做的事最多只有 1 件——「不想去就退出候补」**。不存在「必须 15 分钟内点确认」的时间压力（PRD v0.4 CEO 指令）。

## 3.4 流程 4：我的预约 → 取消（F4）

```
我的预约页 → 找到该课条目
  → [决策] 这节课我的可取消截止时间到了吗？
      ├─ 未到 → 点「取消预约」→ 二次确认（说明「名额将立即让给候补会员或回到可预约」）
      │        → 成功 toast「已取消预约」+ 条目移除 + 该课名额已释放给候补
      └─ 已到 → 按钮置灰，文案：
               · 普通预约：「距开课不足 2 小时，已过可自助取消时间，如需取消请联系门店前台」
               · 转正得到的预约：「已过本课取消截止时间，如需取消请联系门店前台」
  → ! 重复点击/刷新后再提交 → 提示「该预约已取消」（不报错、不重复释放名额）
  → ! 课程已开始/已结束 → 只能看到「已完成 / 已缺席 / 未核实」，无取消入口
```

会员端始终展示**这节课对我而言的取消截止时间**（普通预约 = 开课前 120 分钟；转正得到的 = max（开课前 120 分钟，转正时间 + 15 分钟）且不晚于 T-30），把「什么时候还能取消」从规则变成界面上的一个具体时刻。

## 3.5 流程 5：教练签到 → 核对（F7→F8→F9）

```
教练账号打开小程序 → 我的课程（今日 + 未来 7 天，按时间升序）
  → 点某节课 → 课程详情页（学员名单 + 签到区）
  → [决策] 当前时间在签到窗口（开课前 15 分钟 ～ 开课后 15 分钟）内吗？
      ├─ 未到窗口 → 按钮置灰：「开课前 15 分钟开放签到」
      ├─ 在窗口内 → 点「签到」→ 变「已签到（19:02）」
      ├─ 已超窗口且未签到 → 按钮置灰：「签到已超时，请联系店长补签」+ 店长电话
      └─ 我已签到 → 按钮变只读「已签到（19:02）」；重复点击 toast「已签到（19:02）」
  → 核对：签到完成后（不强制等到课后）详情页出现「核对到场」入口 → 核对面板
      默认全「到场」+ 顶部计数「8 人预约 · 未标记：8 到场 / 0 缺席」
      → 点掉没来的人（整行点击切换）→ 计数实时更新
      → 点「提交核对」→ 按钮与顶部都带计数「确认 6 到场、2 缺席」
      → 成功 → toast + 底部 Snackbar「已提交：6 到场、2 缺席 · 撤销」（10 秒内可撤销）
      → ! 有未标记的人 → 不允许提交，提示「还有 n 人未标记」
      → ! 提交时断网 → 页面显式失败 + 「重试」，本地保留我的标记，重试成功后以最后一次成功提交为准
  → 事后修改：课程结束 + 60 分钟内随时可改，留「原状态 → 新状态」日志
  → ! 超过 60 分钟 → 教练端不可改：「请联系店长，由店长在课程结束后 24 小时内提交或修改」
  → ! 本课被标「签到异常」（我漏签到）→ 核对面板只读：「本课签到异常，待店长补签后方可核对」；
       店长补签后窗口重开（5.7 态 B），我可提交或修改至 min（补签时间 + 60 分钟，课程结束 + 24 小时）
```

# 4. 视觉风格与设计规范

## 4.1 色彩

采用微信小程序里最常见的白底 + 单一主色体系，主色选绿色（健身/健康语境，与微信品牌环境不冲突）。**所有用于承载文字的颜色组合都满足 WCAG AA：正文 ≥ 4.5:1、≥ 24px 大字 ≥ 3:1。**

| 用途 | 色值 | 用在哪些地方 | 对比度（对 #FFFFFF 白底） |
| --- | --- | --- | --- |
| 主色（品牌绿） | `#0E7A4A` | 主按钮底、TabBar 选中、「已预约」标签文字、进度条 | 5.38:1（白字在其上同为 5.38:1）✅ |
| 主色·按下 | `#0B5C38` | 主按钮 pressed 态 | 8.07:1 ✅ |
| 主色·浅底 | `#E8F5EE` | 选中卡片背景、转正提醒条背景 | 与 `#0B5C38` 文字对比 7.20:1 ✅ |
| 文字·主 | `#1A1A1A` | 课程名、标题、数字 | 17.4:1 ✅ |
| 文字·次 | `#5A5F66` | 教练名、时间、地点 | 6.43:1 ✅ |
| 文字·说明 | `#6B7075` | 提示文案、规则说明、「未核实」标签 | 5.00:1 ✅ |
| 文字·禁用/占位 | `#8A8F96` | 禁用按钮文字、占位（**只用于禁用与装饰，不承载正文**） | 3.26:1 ⚠️ 仅限禁用态 |
| 状态·成功/已预约 | `#0E7A4A` + 底 `#E8F5EE` | 已预约、预约成功、已完成 | 5.38:1 ✅ |
| 状态·警示/候补中 | `#A15C00` + 底 `#FFF4E5` | 候补中、已满、签到异常、即将到截止时间 | 5.19:1（底上 4.78:1）✅ |
| 状态·危险/错误 | `#C4321E` + 底 `#FDECEA` | 时间冲突、名额被抢完、已缺席、退出确认弹窗主按钮 | 5.49:1（底上 4.81:1）✅ |
| 状态·中性 | `#6B7075` + 底 `#F2F3F5` | 未核实、已结束、已退出候补、课程已取消、不可用 | 5.00:1（底上 4.50:1）✅ |
| 描边/分隔 | `#E5E7EB` | 卡片 1px 描边、列表分隔线 | 装饰，无对比要求 |

**不只用颜色传达信息**（无障碍硬要求）：每个状态标签都是「图标 + 文字 + 颜色」三重表达，例：

- 已预约 = ✔ 图标 + 「已预约」 + 绿
- 候补中 = ⏳ 图标 + 「候补中 · 第 2 位」 + 橙
- 已自动转正 = ⇪ 图标 + 「已自动转正为预约」 + 绿
- 已退出候补 = ↩ 图标 + 「已退出候补」 + 灰
- 已缺席 = ✕ 图标 + 「已缺席」 + 红
- 未核实 = ─ 图标 + 「未核实」 + 灰（**不等于缺席，不用红**，见 6.4）

## 4.2 字体

系统字体栈（微信小程序默认）：iOS `PingFang SC`、Android `Source Han Sans / 思源黑体`、兜底 `-apple-system, sans-serif`。单位用 px 描述（小程序内 1px = 2rpx，750rpx = 屏宽）。

| 层级 | 字号 / 行高 / 字重 | 用途 |
| --- | --- | --- |
| H1 页面标题 | 20 / 28 / 600 | 课程详情页课程名、页标题 |
| H2 区块标题 | 17 / 24 / 600 | 「今天 11月18日」「学员名单」 |
| 卡片主标题 | 16 / 22 / 500 | 课表卡片课程名、我的预约条目课程名 |
| 正文 | 15 / 22 / 400 | 说明、学员姓名、按钮文字（大按钮 17/24/500） |
| 次要说明 | 13 / 18 / 400 | 教练/门店/房间、截止时间、规则说明 |
| 标签/徽标 | 12 / 16 / 500 | 状态标签、倒计时徽标 |
| 关键数字 | 22 / 28 / 600 | 剩余名额「剩 4」、倒计时「还有 1 小时 28 分」 |

规则：正文不小于 15px；说明文字不小于 13px、且用 `#6B7075` 而非更浅灰；行高不低于字号的 1.4 倍；不使用 300/200 细字重；数字用等宽 tabular 效果（`font-variant-numeric: tabular-nums`）避免倒计时跳动。

## 4.3 间距、圆角、阴影

- **间距基础单位 4px**；常用值 `4 / 8 / 12 / 16 / 24 / 32`。
  - 页面左右边距 **16px**；卡片内边距 **16px**；卡片之间 **12px**；区块之间 **24px**；标签与文字间距 **8px**；图标与文字 **8px**。
  - 列表行上下内边距 12px，行高 **≥ 56px**（满足 44×44px 触控下限，整行可点）。
  - 底部固定操作栏高 **56px**，另加 `padding-bottom: env(safe-area-inset-bottom)`。
- **圆角**：卡片 12px；按钮 8px（大按钮 12px 仅在底部确认面板内）；标签 4px（可读数字徽标用 999px 胶囊）；弹窗 16px；头像圆形。
- **阴影**：
  - 卡片默认**不用阴影**，用 1px `#E5E7EB` 描边 + 白底（弱网/低端机上更省性能，层级也更清楚）。
  - 弹层/浮层：`0 8px 24px rgba(0,0,0,0.12)`。
  - 底部固定操作栏：上边框 1px `#E5E7EB`，背景 `rgba(255,255,255,0.98)`。
  - 转正提醒条：`0 4px 16px rgba(14,122,74,0.12)`（绿色淡影，唯一用于强调的阴影）。
- **动效**：只用于状态切换（标签淡入 150ms、Snackbar 上滑 200ms、折叠展开 200ms）；不做首屏入场动画、不自动轮播；尊重系统「减弱动态效果」。

## 4.4 断点与响应式（移动优先）

| 断点 | 宽度 | 布局 |
| --- | --- | --- |
| 手机（默认） | ≤ 599px | 单列；页面左右 16px；底部 TabBar + 底部固定操作栏；课表 1 列卡片 |
| 平板 / 桌面（微信小程序大屏） | ≥ 600px | 内容区最大宽 **720px** 居中，左右留白；课表卡片 **2 列**（gap 16px）；课程详情页信息区与操作区同宽堆叠，底部操作栏跟随内容区宽度 |

字号不随断点缩放；所有可点区域在任何断点 ≥ 44×44px。

## 4.5 核心组件

**按钮**

| 类型 | 样式 | 尺寸 | 状态 |
| --- | --- | --- | --- |
| 主按钮 | 底 `#0E7A4A`、白字、圆角 8 | 大 48px 高/全宽；中 40px；小 32px（列表内） | default / hover（`#0B5C38`）/ pressed（不透明度 0.9）/ focus（2px `#0E7A4A` 外描边 + 2px 偏移）/ disabled（底 `#F2F3F5` + 字 `#8A8F96`）/ loading（按钮内 16px 旋转指示 + 文案「提交中…」，**宽度不变**避免布局跳动） |
| 次按钮 | 白底 + 1px `#0E7A4A` 描边 + 绿字 | 同主按钮 | 同上；disabled 时描边与字都变 `#8A8F96` |
| 危险主按钮 | 底 `#C4321E`、白字 | 仅用于退出候补/取消预约的确认弹窗 | 同上 |
| 文字按钮 | 绿字无底 | 高 ≥ 44px 的点击区 | pressed 下划线 |
| 禁用按钮必带原因 | —— | —— | 置灰按钮下方或点击后 toast 必须给出**为什么不能用 + 怎么办**（例：「本课不再接受候补」「距开课不足 2 小时……请联系门店前台」） |

用法约定：一屏内主按钮最多 1 个；不用纯图标按钮承载关键动作（返回箭头除外，且带 aria-label）。

**输入框**：MVP 只在店长补签原因处使用。高 48px（多行 96px），1px `#D0D5DB` 描边、圆角 8；聚焦时 2px `#0E7A4A` 描边 + 标签加粗；错误时 1px `#C4321E` + 下方红字提示；右下角字数计数（上限 100 字）。

**卡片（课程卡）**：白底 + 12px 圆角 + 1px `#E5E7EB`；结构固定为「第一行：课程名 + 状态标签 / 右侧名额」「第二行：教练 · 门店 · 房间」「第三行（如有）：倒计时/截止时间 + 主次操作」。整卡可点进详情，右侧操作按钮独立可点（`stopPropagation`）。

**状态标签（Badge）**：图标 + 文字 + 底色，4px 圆角，内边距 4×8px，字号 12px。同一状态全站同色同文案（见 6.2 词表）。

**列表行（学员行）**：头像 40px + 姓名 + 行内状态切换；整行可点即切换；切换后行右侧标签在「到场 ✔ 绿」与「缺席 ✕ 红」间变化，**同时**在顶部计数中体现。

**弹窗（二次确认）**：标题 + 一句说明 + 结果影响 + 双按钮（左「再想想」次按钮 / 右「确认」主按钮；危险动作用红色主按钮）。仅用于两类动作：取消预约、退出候补。

**Snackbar（撤销）**：底部（浮在固定操作栏之上）8px 圆角深色底，文案 + 「撤销」文字按钮，10 秒后自动消失；同时向屏幕阅读器播报。

**空状态组件**：居中图标 64px + 一句话说明（15px `#1A1A1A`）+ 可选的下一步按钮 + 可选的辅助说明（13px）。

**加载组件**：骨架屏（课表 3 张卡片骨架、列表 3 行骨架）+ 下拉刷新 + 按钮内 loading。

**区域说明与交互**

- ① 分组：`待参加`（已预约含转正、候补中、已退出候补但课程未开始）与 `已结束`（已完成 / 已缺席 / 未核实）。**取消后的预约不保留条目**：自助取消成功即从本页移除（PRD 故事 4 验收标准「我的预约列表移除该课」），MVP 不提供「已取消」历史条目；想再看这节课请回课表页（课表实时显示剩余名额）。`[已取消]` 这个标签在本设计里只表示「课程被门店取消」，不表示「我的预约被取消」（见 6.1）。两个分组都可折叠；默认展开「待参加」。
- 为什么「已退出候补」条目保留、而「已取消」条目不保留：PRD 故事 5 要求会员在「我的预约」中看到「已退出候补」记录并带「重新加入候补」入口（候补不占名额，保留记录不影响名额口径）；故事 4 则要求取消后移除该课。这两处不同处理都是 PRD 明确要求，不是实现分歧。
- ② 转正卡片置顶：一是让「系统帮我约上了」这件事不可能被忽略（订阅消息可能没送到，PRD 7.3 权威路径就是这里），二是把「可在 18:47 前取消」和倒计时放在同一视线内。
- ④ 候补卡片：显示服务端返回的实时位次；不显示任何「确认倒计时」（自动转正无确认环节）。
- ⑤ 已退出候补：区分两种退出原因，文案不同（见 5.4）。有「重新加入候补」按钮，条件 = 该课仍未满 且 距开课 ≥ 30 分钟；点击走与首次加入相同的流程（含告知文案）。
- ⑥ 终态卡片：`已完成 / 已缺席 / 未核实` 一律**不挂操作按钮**、不出现「已扣次 / 影响信用」等后果暗示；`未核实` 副文案固定「本次未计入缺席，不影响你的记录」，「如有疑问请联系门店前台」只作为说明文案、**不是申诉入口**（PRD 故事 9）。
- 会员端**不展示**「教练已签到」任何信息（故事 8 MUST）。

**状态**

- 加载中：3 张列表骨架；下拉刷新保留旧数据。
- **空状态**：无任何预约 → 居中「还没有预约的课程」+「去看课表」主按钮；只有已结束记录 → 「待参加」分组位置显示「暂无待参加的课程」+「去看课表」。
- 请求失败：整页「加载失败」+「重试」；单条取消失败 → 卡片就地回滚原状态（不乐观更新，直接以服务端返回为准）+ 错误条「取消失败，请重试」。
- **取消成功**：条目**立即从列表移除**（不留灰色「已取消」卡片）+ toast「已取消预约」+（若名额给了候补）不额外提示他人信息（不暴露他人）。移除后该课回课表页按实时名额显示：名额已转正给他人 → 仍显示「已满（候补 n 人）」；无人接 → 显示「可预约（剩 1 个）」。

- 超过本课核对截止时间（正常课 = 课程结束 + 60 分钟；补签后重开的课 = min（补签时间 + 60 分钟，课程结束 + 24 小时））→ 面板只读 + 「请联系店长，由店长在课程结束后 24 小时内提交或修改」。
- 弱网：提交失败 → 顶部红色错误条「提交失败，请重试」+「重试」按钮；本地保留标记；重试成功后以最后一次成功提交为准。

## 6.3 时间轴与按钮可用性矩阵（会员端）

| 距开课 | 预约（有余位） | 加入候补 | 退出候补 | 取消预约（普通） | 取消预约（转正来的） |
| --- | --- | --- | --- | --- | --- |
| > 120 分钟 | 可用 | 可用（队列未满且未在队中） | 可用 | 可用 | 可用（此刻必然未到截止） |

| 取消成功 | toast + 条目移除 | 「已取消预约」 |
| 自动转正（浏览中被转正） | Snackbar 8 秒 + 卡片变绿 | 「⇪ 已自动为你约上这节 20:00 的瑜伽拉伸」 |
| 核对提交成功 | Snackbar 10 秒可撤销 | 「已提交：6 到场、2 缺席 · 撤销」 |
| 签到成功 | 按钮变只读标签 | 「已签到（19:02）」 |
| 操作失败 | 顶部错误条（红）+ 重试 | 「操作失败，请重试」/「名额已被抢完，是否加入候补？」 |
| 禁止操作 | 按钮禁用 + 一行原因（并保留点击时的 toast 解释） | 见 6.3 矩阵右列 |

# 7. 异常与空状态

四类必答的异常态逐条给出处理方式，另附无权限与竞态。

## 7.1 加载中

| 位置 | 处理 |
| --- | --- |
| 课表页首屏 | 日期条立即渲染（本地可算），课程区显示 3 张卡片骨架；数据到齐前不禁用日期条（可先切日期） |
| 课程详情页 | 课程信息区骨架 + 底部主按钮为 **loading 且不可点**（绝不先在「可预约」状态下暴露按钮，避免误导） |
| 我的预约页 | 3 行骨架；下拉刷新保留旧内容 + 顶部小 spinner |
| 教练签到/核对 | 签到区骨架（高度固定，避免按钮跳动）；名单 3 行骨架 |
| 慢网（> 3 秒） | 骨架上方出现「网络较慢，正在重试…」；提供「重新加载」入口 |
| 提交类动作 | 按钮内 loading + 文案「提交中…」，宽度不变；提交期间按钮不可重复点（幂等由服务端保证，界面同时做防抖） |

## 7.2 空状态（每一处都有对应文案与下一步）

| 位置 | 文案 | 下一步动作 |
| --- | --- | --- |
| 课表某天无课 | 「今天暂无课程」 | 「看明天 ›」 |
| 课表 7 天全空 | 「本周暂无课程，请联系门店前台」 | 门店电话（可点拨打） |
| 我的预约为空 | 「还没有预约的课程」（或分组内「暂无待参加的课程」） | 「去看课表」主按钮 |
| 课程详情 0 人预约（教练端） | 「本课暂无预约会员」 | 仍可签到（不放「加人」按钮） |
| 教练「我的课程」为空 | 「暂无排给你的课程，请联系店长」 | 无（不报错） |
| 店长概览当天无课 | 「今天没有排课」 | 无 |
| 候补队列为空 | 「暂无人在排队，你可以直接预约」（若有余位） | `预约` |
| 搜索/筛选 | MVP 无搜索功能，不适用（见第 9 章范围说明） | — |

## 7.3 请求失败

| 场景 | 处理 |
| --- | --- |
| 课表加载失败 | 整页错误态：「课表加载失败」+「重试」+「课程信息以门店现场为准」；保留日期条 |
| 我的预约加载失败 | 「加载失败」+「重试」；不清空已有内容，避免用户以为预约丢了 |
| 详情页课程不存在（被后台改/删） | 「课程信息已更新，请重新查看」+「返回课表」；**不残留预约按钮** |
| 预约/取消/退出候补请求失败 | 不做乐观更新：卡片保持原状态 + 顶部错误条 +「重试」；不出现「本地已成功但服务端没有」 |
| 教练提交核对失败（弱网） | 「提交失败，请重试」+ 重试按钮；本地暂存标记；成功后以最后一次有效提交为准 |
| 签到请求失败 | 按钮回到可点状态 + 错误条「签到失败，请重试」；刷新后以服务端为准（已签到则显示已签到） |
| 会员卡校验接口不可用（PRD 第 8 章决策 6 的降级） | 详情页按钮禁用 + 说明「暂时无法校验会员卡，请稍后重试或联系门店前台」；不使用「卡已过期」这类误导文案 |

## 7.4 名额已满

| 场景 | 处理 |
| --- | --- |
| 详情页看到满员 | 主按钮从 `预约` 换成 `加入候补（队列 n 人）`，并显示告知文案；**已满不是死路** |
| 只剩 1 位并发抢位失败 | 弹窗「名额已被抢完，是否加入候补？」→ 「不用了 / 加入候补」；点击「加入候补」直接进队列，不要求重新找课 |
| 候补队列已满（上限 min（容量，20）） | `加入候补` 置灰 + 点击 toast「候补人数已满」 |
| 距开课 < 30 分钟或课程已开始 | `加入候补` 置灰 + 「本课不再接受候补」 |
| T-30 后有名额释放 | 课表/详情页名额实时 +1（先到先得）；列表在本页的会员下拉刷新即可看到；同时给原候补会员发「本课候补已结束（如仍有余位可直接预约）」 |
| 我已被自动转正但席位于其实是空 | 不会出现：详情页显示「剩余 0（名额已归你）」，与服务端实时余位一致 |

## 7.5 无权限与身份类异常

| 场景 | 处理 |
| --- | --- |
| 手机号在门店系统查不到 | 停在授权页：「未查到会员信息，请联系门店前台」+ 门店电话；不生成账号、不进课表 |
| 手机号与门店记录不一致 | 「我们无法确认你的会员信息，请联系前台核验」；不自动猜测绑定 |
| 会员卡过期/停卡 | 课表页顶部警示条「会员卡已过期，预约功能暂不可用」；预约/加入候补按钮不出现或禁用 + 「会员卡已过期，请到前台办理续卡」 |
| 教练打开非本人课程（代班） | 详情页整页提示「你不是该课教练，请联系店长处理」；无签到/核对按钮 |
| 店长访问非本门店 | 「无权查看该门店数据」；不返回任何名单数据 |
| 角色分流错误（教练看到会员课表） | 启动时按服务端角色整页分流；会员端元素不出现在教练/店长端（反之亦然） |

## 7.6 竞态与幂等（界面必须给出确定反馈）

| 竞态 | 界面行为 |
| --- | --- |
| 2 秒内连点 3 次「预约」 | 第一次后按钮进入 loading 并禁用；结果只有 1 条预约，名额只减 1 |
| 重复取消 | 「该预约已取消」，条目已移除，不报错、不重复释放名额 |
| 退出候补与自动转正同时发生 | 以服务端先落库者为准：先退出 → 彻底离队（此后任何释放都不转正给我）；先转正 → 我的「退出」按取消预约处理（走宽限期，成功则名额按分配顺序处置，失败提示已过本课取消截止时间）。**不允许出现「我退出了却仍被约上」或同一名额给两个人** |
| 我正在页面停留时被转正 | 从后台恢复（`onShow`）或下拉刷新时拿到新状态，卡片就地变绿 + Snackbar；不弹需要确认的窗口 |
| 两次取消在同一秒发生 | 两次释放各自独立分配（第一位转正给 A，第二位转正给 B），界面上 A/B 各自看到自己的转正卡片，无共享名额 |

# 8. 无障碍检查

| 检查项 | 本设计的具体做法 |
| --- | --- |
| 正文对比度 ≥ 4.5:1 | 全部文字色见 4.1，最低 4.50:1（`#6B7075` 于 `#F2F3F5`）；`#8A8F96`（3.26:1）仅用于禁用态与装饰，不承载正文，且禁用态一定配文字原因 |
| 大字 ≥ 3:1 | 关键数字 22px 600、页面标题 20px 600 均 ≥ 5:1，满足 |
| 不只用颜色传达 | 所有状态 = 图标 + 文字 + 颜色三重编码（见 4.1、6.1）；「未核实」与「已缺席」用图标（─ / ✕）与文案区分，不靠红/灰 |
| 键盘/外设可完成全部功能 | Tab 顺序 = 视觉顺序（顶部 → 内容 → 底部固定操作栏）；焦点态为 2px 主色外描边 + 2px 偏移，任何时候清晰可见；弹窗打开后焦点锁在弹窗内，Esc / 「再想想」可关闭；Snackbar 的「撤销」可聚焦 |
| 触控区域 ≥ 44×44px | 主按钮 48px 高、列表行 ≥ 56px、TabBar 项 ≥ 56px、签到/核对按钮 ≥ 48px；日期格 56×56px；学员行整行可点 |
| 图标与图片有文字替代 | 头像 `aria-label="张三"`；状态图标 `aria-label` 与可见文字一致（如「已自动转正为预约」）；装饰性图标 `aria-hidden`；无纯图标承载的关键动作 |
| 状态变化有播报 | 预约成功、自动转正、提交核对结果、错误提示均通过小程序无障碍能力向读屏播报（对应的 `aria-live` 等效处理） |
| 动效可控 | 动效 ≤ 200ms、只用于状态切换；不做自动轮播、不做闪烁；跟随系统「减弱动态效果」关闭动效 |
| 文案可读性 | 不用双重否定；禁用按钮一定写「为什么 + 怎么办」；时间一律写到具体时刻（「可在 18:47 前取消」），不说「请及时取消」这类模糊话 |
| 不依赖精确操作 | 候补/预约都以整个按钮生效，不做滑动手势承载关键操作（退出候补必须点按钮 + 确认，不用左滑） |

# 10. 待确认与假设

**假设（本设计已按此落地，需要确认后可能微调）**

1. **假设**：会员端信息架构只做「课表 / 我的预约」两个 tab，不做「我的」页（出勤统计属 P1）。验证方式：上线后看「我的出勤记录在哪」类客服工单量与课表页到我的预约页的点击率。
2. **假设**：课程卡右侧不显示「剩余 n / 容量」的进度条，只在详情页显示。理由：课表要一眼扫过 7 天，信息密度优先。验证方式：可用性测试中观察会员是否在课表页尝试寻找容量信息。
3. **假设**：加入候补不弹二次确认（PRD 要求「不要求任何确认动作」），只用常驻告知文案 + 成功 toast。风险是误点后需要自己退出；用「退出候补」入口 + 二次确认兜住。验证方式：观察加入候补后 1 分钟内即退出的比例（**假设**阈值 > 10% 则考虑加确认）。
4. **假设**：转正提醒条可关闭（仅本机隐藏），且该课的下一次状态变化（如取消）会重新出现。验证方式：可用性测试。
5. **假设**：课表页不做筛选与搜索（MVP 单店 7 天课量小）。验证方式：数据观察「会员在课表页停留时长与滑动距离」，若明显偏向长列表再评估。
6. **假设**：深色模式不做（PRD 未定义，MVP 只做浅色）。验证方式：上线后看用户反馈。
7. **假设**：核对面板用「整行点击切换状态」而不是右侧小开关（行高 56px、热区更大、单手更好点）。验证方式：可用性测试中观察教练误触后使用「撤销」的比例。
8. **假设**：课表页 ⑦ 的「动感单车」示例排课放在 19:30-20:30，使时间冲突示例与课表线框能对上（同一份文档内自洽）。验证方式：不涉及产品功能，仅为文档示例，可与门店真实排课时间对齐后替换。

**待确认（需要同事或 CEO / 店长回答）**

1. **转正订阅消息文案的最终措辞**（含「可在 X 前取消」是否会因额度/模板限制而无法带变量）——需**工程**确认订阅消息模板字段，逐字稿可能需按模板能力改写（我按「课程名 + 开课时间 + 取消截止时间」三个变量设计）。
2. **教练端是否要放底部 TabBar**（只有 1 个入口）——需**工程**确认小程序 TabBar 在单 tab 场景的实现取舍，我按「顶部标题栏 + 无 TabBar」写，若工程要求统一 TabBar 则教练端加 1 个 tab（视觉上不变）。
3. **会员端课表页顶部是否显示门店名**（MVP 单门店，跨店属 P1）——需**产品**确认是否会给会员造成「可以切换门店」的误解，我按「显示但不可切换 + 点击给提示」写。
4. **「空课」在店长端是否需要推送提醒**（PRD 只要求突出显示）——需**店长**确认，我按「只突出显示、不推送」写。
5. **自动转正后的取消截止时间是否要在卡片上给到「分钟级」倒计时**——需**产品/店长**确认，我按「倒计时（还有 1 小时 28 分）+ 具体时刻（可在 18:47 前取消）」两者都给写，因为宽限窗口可能只剩几分钟。
6. **取消预约后是否要保留「已取消」历史条目**——需**产品**确认。我按 PRD 故事 4 验收标准（取消后从列表移除）实现，MVP 不留历史条目；若产品希望在 P1 提供历史记录，需要另立功能（属 PRD 第 4 章 P1「会员历史预约与出勤统计页」范围）。
7. **补签后重开态的截止时间提示文案**（「店长已于 20:15 补签，请在 21:15 前提交核对」）是否要在教练端同时用订阅消息提醒一次——需**产品/工程**确认，MVP 我按「只在页面内提示、不加推送」写。
