## 1. 用户与核心任务

### 1.1 三类用户与他们在界面上的诉求

| 用户 | 在界面上的核心诉求 | 设计上的对应取舍 |
| --- | --- | --- |
| 会员 | 「这节课还有没有位置」「我点下去到底约上了没有」 | 课表卡片一眼出状态；所有提交都有明确成功/失败反馈；不出现「看起来成功其实没约上」 |
| 教练（可能不是会员） | 「15 秒内把点名做完，别让我课前折腾」 | 一个页面完成到岗 + 点名；默认未勾选；勾选行整行可点、行高 56px |
| 会员兼教练 | 「两个身份别互相干扰」 | 底部 Tab 分入口，会员页与教练页状态互不影响 |

### 1.2 核心任务与成功标准（对应 PRD 用户故事）

| # | 任务 | 对应用户故事（PRD 第 8 节） | 成功标准（可在界面上验收） | 承载页面 |
| --- | --- | --- | --- | --- |
| T1 | 微信一键登录并落到正确身份首页 | P0-1 故事 1 / 故事 2 | 授权后 3 秒内落到正确首页（会员→课表；教练→工作台）；未查到信息有兜底页且无预约入口 | 5.1 / 5.2 |
| T2 | 看课表，一眼判断能不能约 | P0-2 | 每张卡片含开始时间、课程名、教练、时长、剩余名额 / 已满 / 候补 N 人；已停课卡片置灰 | 5.3 |
| T3 | 看详情并预约 | P0-3 | 课表→详情→预约共 **3 次点击**（含确认弹窗内 1 次点击）；重复点击不产生第二条记录；失败必给原因 | 5.4 / 5.5 |
| T4 | 满员时加入候补并知道位次 | P0-5 | 加入前明示「有空位将自动为你预约并通知你」；加入后位次可见；可随时退出、不计数 | 5.4 / 5.5 |

| T6 | 计划变化时取消 | P0-4 | 可不可取消只由 `cancelable_until` 决定；取消后不计数、状态立刻变「已取消」 | 5.6 / 5.4 |
| T7 | 教练到岗 + 点名（含 24h 内补录） | P0-7 | 到岗 1 次点击；点名 ≤3 步；窗口外按钮置灰并说明原因 | 5.7 / 5.8 |
| T8 | 看懂限制期与异常，并能找到人 | P0-8 / P0-S4 | 置灰文案含具体到期时间精确到「日 + 时:分」；门店电话可一键拨号 | 5.4 / 5.6 / 5.9 |

### 1.3 任务与 PRD 的边界（不新增功能）

本设计**没有**增加任何 PRD 未定义的功能。以下内容在本稿中刻意不做，理由写在右侧：

| 不做 | 理由 |
| --- | --- |
| 会员自助签到 / 扫码核销 | PRD 第 3 节明确本期不做（P1-2）；会员端只显示「已预约」 |
| 支付、次卡、评价、教练主页、消息中心 | PRD 第 3 节不做范围 |
| 门店切换、多门店入口 | PRD 7.5「MVP 单门店，不做门店切换」 |
| 候补「是否接受转正」弹窗 / 确认倒计时 | PRD 7.1 与 0 节：转正一律自动生效，**界面上不允许出现任何确认入口** |
| 预约日历式选课、课程收藏、筛选排序 | PRD 未定义（P1-4 的每日上限也未做） |
| 内部停课工具界面 | 非小程序，由工程提供最小受保护入口（P0-S4），本稿不设计 |
| 逐页埋点方案 | 不在本次任务范围；指标 A–G 的埋点需求请产品单独提 |

### 2.2 导航结构（按身份分支）

```
微信入口
  └─ 登录/授权页（未登录时唯一入口）
       └─ 服务端返回 is_member / is_coach
            ├─ 会员、非教练        → TabBar：课表 ｜ 我的预约
            ├─ 会员 + 教练         → TabBar：课表 ｜ 我的预约 ｜ 教练工作台
            ├─ 教练、非会员        → TabBar：课表(只读) ｜ 教练工作台（默认落地）
            └─ 两者都不是          → 未查询到会员信息页（无 TabBar，只有门店信息与拨号）
```

- TabBar 高度 52px + 安全区内边距；图标 24×24，文字 11px。
- 「课表」为默认选中项；非会员教练登录后默认选中「教练工作台」（PRD P0-7 要求直接落在工作台）。
- 登录态有效期内（≥30 天）再次打开：跳过登录页，直接落到上次身份对应的默认 Tab。

```
课表页 ──点课程卡──▶ 课程详情页 ──点主按钮──▶ 自绘弹窗（预约/候补/取消）
   ▲                     │                        │
   └──────系统返回────────┘◀────弹窗「取消」关闭────┘
我的预约页 ──点预约卡──▶ 课程详情页
教练工作台 ──点课程卡──▶ 签到·点名页 ──点会员行──▶（本页内勾选，不跳页）
任何页面 ──失败/超时──▶ 页内错误条「重试」（不跳页、不白屏）
```

**返回规则（统一）**：所有二级页（详情、签到页）顶部左侧 44×44 返回热区；系统返回键与手势返回行为一致；弹窗关闭不触发页面返回；提交中禁用返回二次确认（提交结果以服务端为准，不阻塞用户退出）。

## 3. 用户流程

> 点击计数口径（与 PM 确认）：确认弹窗内那一次点击**计入**「预约 / 加入候补」这一步，不算新增一步。因此主流程 = 3 步。

### 3.1 流程 1：正常预约（P0-2 → P0-3）

```
[入口] 打开小程序
  └─ 未登录 → 登录授权页 →（服务端返回 is_member=true）→ 课表页（默认今天）
  └─ 已登录 → 课表页
课表页
  ├─ 步骤①：点课程卡（「剩 3 位」）─────────────────── 1 次点击
  ▼
课程详情页（状态块：剩 3 位；底部主按钮：立即预约）
  ├─ 步骤②：点「立即预约」───────────────────────── 2 次点击
  ▼
预约确认弹窗（自绘）
  ├─ 内容：课程名 / 时间 / 教练 / 教室
  ├─ 若当前处于「迟到预约期」（cancel_deadline ~ start_at-30min）
  │   → 弹窗追加服务端下发的警示：「已过取消截止时间，未到场将计爽约；预约后可在创建后 30 分钟内自助取消一次」
  ├─ 步骤③：点「确认预约」───────────────────────── 3 次点击
  │     └─ 同一 tap 内：先同步调 requestSubscribeMessage（不 await、不先发业务请求）
  │        ※ 授权只发生在这**类**点（= 自绘确认弹窗的确认按钮 tap；详情页的「立即预约」/
  │          「加入候补」主按钮只负责打开弹窗，不请求授权；见 4.7 第 5 条）
  └─ 分支
      ├─ 用户点「再看看」→ 关闭弹窗，留在详情页，不发请求、不请求授权
      └─ 确认 →
           按钮进入「预约中…」（loading + 禁用，防重复点击；同一意图重试沿用同一 request_id）
           ▼
      服务端结果
        ├─ 成功 → Toast「预约成功」（2s）+ 详情页状态块变「已预约」+ 主按钮变「取消预约」
        │          → 我的预约页出现该记录（可在 Tab 切换后看到）
        │          → 授权成功的会员 5 分钟内收到「预约成功」订阅消息
        ├─ 已满（名额被抢）→ 「名额刚刚被约满」弹窗：「你可以加入候补（当前第 N 位）」
        │                    + 按钮[加入候补] / [再等等]
        │                    └ 点[加入候补] → 进入流程 2 的候补确认弹窗（不返回上一页；
        │                       授权发生在该弹窗的「加入候补」确认按钮 tap 内，见 4.7 第 5 条）
        ├─ 时段重叠 → 弹窗/toast：「该时段你已有预约：XX 课 19:00-20:00」+ 文字按钮[查看我的预约]
        ├─ 限制期 → 提示含到期时间：「你本月已爽约 3 次，预约权限已被限制至 X 月 X 日 12:00」
        ├─ 场次已锁定 / 已开课 → 提示「本场次已停止预约」+ 自动刷新详情（按钮置灰）
        ├─ 会员身份失效 → 「你的会员身份已失效，请联系门店」
        └─ 网络失败 / 超时 → 页内错误条「预约请求未完成，请重试」+ [重试]
                             ※ 不显示任何「成功」字样；用户可切到「我的预约」看服务端真实结果
[返回路径]
  弹窗「再看看」→ 留在详情页；详情页左上/系统返回 → 课表页（课表卡片同步刷新为已预约态）
```

**边界说明**
- 预约按钮在「限制期」「场次已锁定」「我已预约」「已停课」时**根本不出现可用态**，可挡掉大部分无效授权（PM 已确认可接受「授权了但没约上」）。
- 授权结果为「拒绝」或「拒绝且不再询问」或回调失败：**不弹错误提示、不打断主流程**，仅在「我的预约」页顶部保留兜底提示条（见 5.6）。

### 3.2 流程 2：满员候补 → 自动转正（P0-5 → P0-6）

```
课表页（卡片 chip「已满」+ 附加行「候补 4 人」）
  └─ 点卡片 → 课程详情页（状态块：已满 · 候补 4 人；主按钮：加入候补【琥珀色】）
       └─ 点「加入候补」→ 只打开弹窗，**不请求订阅授权**（与 3.1 的授权时点一致）
            ▼
       候补确认弹窗（自绘，**全流程唯一一次二次确认**）
         ├─ 文案：「当前已满（20/20），你将排第 5 位。」
         ├─ 文案：「有空位将自动为你预约并通知你，不需要你再确认。」
         └─ 文案：「候补期间可随时退出，不计数。」
            ├─ [算了] → 关闭，不发请求、不请求订阅授权
            └─ [加入候补] → 同一 tap 内第一件事：同步调 requestSubscribeMessage（不 await、
                 不先发业务请求）→ 按钮 loading → 服务端结果
                 ├─ 成功 → Toast「已加入候补，当前第 5 位」
                 │          + 状态块变「候补中 · 第 5 位」+ 主按钮变「退出候补」
                 │          + 「我的预约」出现该场次（即将开始 Tab，标签「候补中 · 第 5 位」）
                 ├─ 候补已满（已达 capacity）→ 按钮置灰「候补已满」
                 ├─ 我已预约（互斥）→ 按钮「已预约」
                 ├─ 已过锁定点 → 按钮消失/置灰，文案「候补已结束」
                 └─ 失败 → 页内错误条 + [重试]
  ▼ 名额释放（他人取消 / 宽限取消），服务端事务内自动递补
【会员视角，全程 0 次操作】
  ① 无需任何确认：没有弹窗、没有按钮、没有倒计时（PRD 7.1，v1.2 CEO 已定）
  ② 「我的预约」同一条记录由「候补中 · 第 N 位」→「已预约（候补转正）」+ 展示服务端下发的可自助取消截止时刻
  ③ 收到「候补转正成功」订阅消息（内容与「预约成功」区分）
  ④ 未授权 / 额度用尽 / 消息未达 → 下次打开「我的预约」即可看到（唯一兜底入口）+ 顶部兜底提示条
【位次变化】他人退出 / 有人被跳过 → 下拉刷新后位次更新（以服务端为准，前端不自己减）
【未轮到】start_at-30min 到点仍未转正 → 状态变「候补已结束（未轮到）」，无惩罚、无按钮
【被跳过 SKIPPED】显示「候补已结束」+ 原因（服务端下发，示例：时段冲突 / 账号受限）
```

### 3.3 流程 3：取消与递补（P0-4 → P0-6）

```
入口 A：我的预约卡片[取消预约]    入口 B：课程详情页（已预约态）[取消预约]
  ▼
取消确认弹窗（自绘）
  ├─ 基础文案（示例）：「取消后名额会立即释放给候补会员，本次取消不计爽约。」
  ├─ 宽限取消场景（created_at ≥ cancel_deadline - 30 分钟）追加服务端下发文案
  │   （示例）：「这是本场次唯一一次宽限取消机会，用完后再建立的预约不可自助取消。」
  ├─ [再想想] → 关闭，不发请求（留在原页，状态不变）
  └─ [确认取消] → 按钮 loading（禁用防重复）→ 服务端结果
       ├─ 成功（now < cancelable_until）
       │    → Toast「已取消」
       │    → 卡片状态变「已取消」，按钮消失；详情页状态块变「可预约/已满（按剩余名额）」
       │    → 名额 +1（界面只在下次刷新后体现，不本地自增）
       │    → 若在锁定点之前：服务端同事务递补，候补会员自动转正（对本人无额外提示）
       │    → 若在锁定点之后：名额不再顺延（页面显示服务端下发的说明文案）
       ├─ 已过截止（now ≥ cancelable_until）→ 按钮置灰
       │    文案：「已过取消截止时间，如需取消请联系门店前台：400-000-0000」（可拨号）
       └─ 失败 / 超时 → 页内错误条「取消失败，请重试」；卡片状态保持原状（以服务端为准）
【并发与幂等，界面上的要求】
  · 同一次点击的重试沿用同一 request_id；用户重新点击（新意图）生成新 request_id
  · 连续两次提交只成功 1 次：界面不出现「已取消」两次的动画/双 Toast
【被取消者的视角】不通知取消者以外的任何人；候补转正者按流程 2 的通知路径
【门店停课 / 教练缺勤（会员侧）】
  停课（reason=STORE_CLOSED）→ 卡片「已停课」+「门店已取消本课」+「名额不占用、不计爽约」，无取消按钮
  未开课（reason=COACH_ABSENT）→ 卡片「未开课」+ 中性归因句 + 同一承诺句，无取消按钮（见 5.6 / 7.2）
```

### 3.4 流程 4：教练到岗签到 + 会员核销（P0-7）

```
[入口] 教练登录
  ├─ 非会员教练 → 直接落地教练工作台首页（不出现「未查询到会员信息」页）
  └─ 会员 + 教练 → 落地课表页，点 TabBar「教练工作台」
教练工作台首页（今日课程列表）
  ├─ 每张卡：时间 / 课程名 / 教室 / 有效预约人数（BOOKED + ATTENDED）/ 状态行 / 主按钮
  └─ 点课程卡 → 教练签到·点名页
教练签到·点名页
  ├─ 步骤①：点[我已到岗] ───────────────────────── 1 次点击
  │     ├─ 窗口未开（早于 start_at-30min）→ 按钮置灰 + 说明「开课前 30 分钟可开始点名」
  │     ├─ 成功 → 按钮变为「已到岗 19:02」（不可再点，防止重复）
  │     └─ 失败 → 提示失败 + 保持可点（可重试；服务端幂等）
  ├─ 步骤②：勾选到场会员（整行 56px 可点，默认未勾选）── N 次点击（N = 到场人数）
  ├─ 步骤③：点[提交点名] ───────────────────────── 1 次点击（提交动作 ≤3 步，15 秒内可完成）
  │     ├─ 成功 → 顶部状态「已提交 19:35」+「可在开课后 24 小时内补录」
  │     │          名单进入「已提交」态，仍可在 24h 内修改并再次提交（覆盖为最新名单）
  │     ├─ 失败 / 网络中断 → 明确提示「提交失败，请重试」+ **不显示"已提交"**
  │     │                    保留已勾选状态，可重试（服务端以最终提交内容为准）
  │     └─ 窗口关闭（start_at+15min 之后）→ 不可提交（补录除外）
  ├─ 补录（开课后 24 小时内）：同一页面，名单切换为「补录名单」（口径见 5.8.1），可再次勾选/取消勾选并提交
  │     ├─ 名单含未到场者（`NO_SHOW`）与教练缺勤场次的 `CANCELLED_BY_STORE(COACH_ABSENT)`，两者都可勾选
  │     ├─ 勾选「未到场 / 未开课」者 → 状态变「已到场」，爽约计数回滚（界面只显示状态变更，不显示计数）
  │     └─ 取消勾选已勾选者 → 由服务端重判（开课后 15 分钟内回 `BOOKED`，之后重判 `NO_SHOW`），前端不本地判定
  └─ 24 小时后：列表与按钮全部只读（灰），文案「补录已截止」
【教练缺勤（系统行为，界面上要能表达）】
  窗口内既无到岗签到也无点名 → 场次标记 COACH_ABSENT
  会员端：start_at+15min ~ end_at 之间仍显示「已预约」（不显示任何归因，避免误判）
          end_at 后显示「未开课」+ 中性归因句 + 「名额不占用、不计爽约」
  教练端：工作台卡片显示「未签到（已通知运营）」+ 按钮「查看 / 补录」；补录窗口内仍可正常补录出席
          （`end_at` 后这些预约变为 `CANCELLED_BY_STORE(COACH_ABSENT)`，仍留在补录名单里且可勾选，见 5.8.1）
```

## 4. 设计规范

### 4.1 色彩

设计基准：375px 宽（小程序 `750rpx`），浅色主题（小程序深色模式本期不做，跟随微信时会以浅色渲染）。

**品牌与主色**

| 用途 | 色值 | 对比度（对白底） | 说明 |
| --- | --- | --- | --- |
| 主色（可预约 / 主按钮 / 选中态 / 链接） | `#0A7D62` | 5.09:1 ✅ AA（白字压主色底同样 5.09:1） | 医疗感太强，所以偏一点绿松石；与微信绿区分，避免和微信原生元素混淆 |
| 主色深（按下 / 浅绿底上的文字） | `#08664F` / `#06614C` | 深绿文字在 `#E6F4EF` 底上 6.57:1 ✅ | 浅底上的文字必须用深绿，不能直接用 `#0A7D62`（4.50:1，贴线不够稳） |
| 主色浅底（chip / 状态块） | `#E6F4EF` | — | 仅作底，不承载文字 |

**候补与满员的区分色（本设计的重点之一）**

| 语义 | 实心色（白字对比度） | 浅底 + 文字色（对比度） | 用在哪 |
| --- | --- | --- | --- |
| 候补（可候补 / 候补中） | `#B25E00` 琥珀（白字 4.68:1 ✅） | 底 `#FDF3E3` + 文字 `#8A4A00`（6.24:1 ✅） | 「加入候补」按钮（实心琥珀）、chip「候补中 · 第 N 位」、候补人数文字 |
| 满员（已满 / 候补已满 / 已停止预约） | — | 底 `#F1F3F5` + 文字 `#4B5563`（6.79:1 ✅） | chip「已满」「已停止预约」「候补已满」 |
| 无位、需等待（与「错误」区分） | — | 同上 | 满员表示「你现在不能约」，不是错误，所以用**中性灰而不是红色**；红色只留给「失败 / 爽约」 |

> 为什么候补用琥珀、满员用灰：会员在看课后要做两个判断——「现在能不能约」和「不能约但我还能做什么」。「已满」是前者（灰=关闭），「候补」是后者（琥珀=还有机会）。两者颜色必须不同，且**都不能用主色绿**（绿=可以直接约）。

**语义色**

| 语义 | 色值 | 对比度 | 用在哪 |
| --- | --- | --- | --- |
| 成功 | `#0A7D62`（复用主色） | 5.09:1 ✅ | Toast「预约成功」、chip「已预约」「已到场」 |
| 警示（含迟到预约提示） | 文字 `#8A4A00` / 底 `#FDF3E3` | 6.24:1 ✅ | 迟到预约确认弹窗的警示句、候补相关说明 |
| 错误 / 危险 | `#B3261E` | 白字压红底 6.53:1 ✅；红字压白底 6.53:1 ✅；红字压 `#FCEBE9` 底 5.66:1 ✅ | 「爽约」chip、提交失败文案、危险描边按钮文字、迟到预约警示可加红色图标 |
| 信息（中性提示条） | 底 `#F1F3F5` + 文字 `#4B5563` | 6.79:1 ✅ | 「我的预约」顶部兜底提示条、页内说明块 |

**中性色**

| 用途 | 色值 | 对比度 | 说明 |
| --- | --- | --- | --- |
| 文字主色 | `#222222` | 白底 15.9:1 ✅ | 标题、正文、数字 |
| 文字次级 | `#5C6670` | 白底 5.85:1 ✅；`#F5F6F7` 底 5.41:1 ✅ | 说明文字、教练/教室、辅助行 |
| 文字三级 | `#6B7280` | 白底 4.83:1 ✅；`#F5F6F7` 底 4.47:1 ❌ **禁止在浅灰底上使用** | 角标、时间戳；浅灰底一律改 `#5C6670` |
| 禁用文字 | `#4B5563` | `#E9ECEF` 底 6.38:1 ✅ | 禁用按钮、只读行 |
| 分隔线 | `#E5E7EB` | — | 1px，不用阴影 |
| 页面底 / 卡片底 | `#F5F6F7` / `#FFFFFF` | — | 页面底浅灰、卡片纯白，靠明度差分层 |
| 禁用底 | `#E9ECEF` | — | 禁用按钮、只读卡片 |

> 停课卡片**不使用整体透明度置灰**（会同时降低对比度）：改用「底 `#F5F6F7` + 文字 `#5C6670` + 去掉阴影」。

### 4.2 字体层级

字体：小程序默认字体（iOS 用系统 Sans，Android 用系统默认），**不引入自定义字体**（首屏性能）。数字一律 `font-variant-numeric: tabular-nums`，避免名额数字跳动。

| 层级 | 字号 / 行高 | 字重 | 颜色 | 用途 |
| --- | --- | --- | --- | --- |
| 页面主标题 H1 | 20 / 28 | 600 | `#222222` | 详情页课程名 |
| 导航栏标题 | 17 / 24 | 500 | `#222222` | 导航栏、弹窗标题 |
| 区块标题 H2 | 17 / 24 | 600 | `#222222` | 「课程简介」「取消规则」「门店与联系」 |
| 卡片标题 | 16 / 22 | 600 | `#222222` | 课程名（课表卡 / 预约卡） |
| 强调数字 | 17 / 24 | 600 | `#222222` | 开课时间、剩余名额、已勾选人数 |
| 正文 | 15 / 22 | 400 | `#222222` | 弹窗正文、课程简介 |
| 辅助说明 | 13 / 18 | 400 | `#5C6670` | 时长、教练、教室、规则说明 |
| 角标 / 极小 | 11 / 16 | 500 | `#6B7280`（仅白底） | TabBar 文字、chip 内小字、时间戳 |

**字号规则**：正文最小 13px，不用 12px 以下承载信息；系统字体放大时允许换行，禁止用 `<text overflow:hidden>` 裁掉说明文案。

| 卡片内边距 | 16 |
| 卡片之间 | 12 |
| 卡片内行与行 | 8（紧密信息 4） |
| 区块与区块 | 24 |
| 弹窗左右内边距 / 内容与按钮区 | 20 / 20 |
| 底部固定操作区 | 上 12 + 按钮 48 + 下 12（+ 安全区） |
| 顶部导航 | 44（+ 状态栏） |
| TabBar | 52（+ 安全区） |
| 列表行高（点名 / 门店电话） | 56 |

| 元素 | 圆角 | 阴影 |
| --- | --- | --- |
| 卡片 | 12 | `0 1px 2px rgba(17,24,28,0.06)` |
| 按钮（高 48） | 8 | 无（靠色块区分） |
| 小按钮（高 36，用于卡片内操作） | 6 | 无 |
| chip / tag | 6 | 无 |

### 4.5 基础组件规范

#### 4.5.1 按钮

| 类型 | 样式 | 用在哪 | 禁止怎么用 |
| --- | --- | --- | --- |
| 主按钮 Primary（绿实心 `#0A7D62` / 白字 16/600 / 高 48 / 圆角 8） | 默认 / 按下 `#08664F` + 缩放 0.98 / 聚焦 2px `#0A7D62` 外描边偏移 2px / 加载（前置 16px spinner + 文案「预约中…」，禁用点击）/ 禁用（底 `#E9ECEF` + 字 `#4B5563`） | 「立即预约」「我已到岗」「提交点名」「确认预约」 | 一屏内不得超过 1 个主按钮；禁用态**必须**在按钮下方或上方给出原因文案 |
| 候补按钮 Waitlist（琥珀实心 `#B25E00` / 白字 / 同尺寸） | 状态同主按钮，按下 `#8A4A00` | 「加入候补」 | 不得与主按钮同时出现在同一屏的两个位置（同一场次只会有一个主操作） |
| 次级按钮 Secondary（白底 + 1px `#D0D5DA` 边框 + 字 `#222222`） | 同上四态 | 弹窗左侧按钮「再看看 / 算了 / 再想想」 | 不用在页面级主操作 |
| 危险描边按钮 Danger-outline（白底 + 1px `#E7C4C1` 边框 + 字 `#B3261E`） | 同上 | 「取消预约」 | 不做实心红（避免把「取消」的视觉权重压过主操作） |
| 中性描边按钮（白底 + 1px `#D0D5DA` + 字 `#222222`） | 同上 | 「退出候补」 | — |
| 文字按钮 Text（`#0A7D62` 15/600，热区 ≥44×44） | 默认 / 按下加下划线 | 「查看我的预约」「重试」「拨打」 | 不用在需要明确后果的动作上（如「确认取消」） |

**所有按钮的规则**：最小热区 44×44（高 36 的小按钮需用 `padding` 或 `hit-area` 撑到 44）；提交类按钮在提交中必须禁用并显示 loading，**绝不出现「连点 2 次产生 2 条记录」的可能**。

#### 4.5.2 状态 chip（Tag）

| chip 文案 | 底 / 字 | 出现在 |
| --- | --- | --- |
| 剩 N 位 | `#E6F4EF` / `#06614C` | 课表卡、详情页 |
| 已预约 / 已预约（候补转正） | `#0A7D62` 实心 / 白字 | 课表卡、详情页、我的预约卡 |
| 候补中 · 第 N 位 | `#FDF3E3` / `#8A4A00` | 同上 |
| 已满 / 候补已满 | `#F1F3F5` / `#4B5563` | 课表卡、详情页 |
| 已停止预约 | `#F1F3F5` / `#4B5563` | 课表卡、详情页（锁定态） |
| 已停课（STORE_CLOSED） | `#F1F3F5` / `#4B5563` | 课表卡、我的预约卡 |
| 未开课（COACH_ABSENT） | `#F1F3F5` / `#4B5563` | 我的预约卡 |
| 已到场 | `#E6F4EF` / `#06614C` | 我的预约卡 |
| 已取消 | `#F1F3F5` / `#4B5563` | 我的预约卡 |
| 爽约 | `#FCEBE9` / `#B3261E` | 我的预约卡 |
| 候补已结束 | `#F1F3F5` / `#4B5563` | 我的预约卡、详情页 |
| 限制期 / 只读教练账号 | `#FCEBE9` / `#B3261E`（限制期）；`#F1F3F5` / `#4B5563`（只读） | 详情页 |

**chip 规则**：状态一律「颜色 + 文字」双通道，不存在只有颜色没有文字的 chip；文字不用缩写（不写「候」）。

#### 4.5.3 课表卡片（最关键的信息容器）

```
┌────────────────────────────────────┐
│ 19:00   搏击燃脂            [剩 3 位]│ ← 行1：时间 17/600 ｜ 课程名 16/600 ｜ 状态 chip
│ 19:00-20:00 · 45 分钟               │ ← 行2：时间区间 + 时长（13/400 #5C6670）
│ 教练 张三 · 教室 A · 容量 20 人       │ ← 行3：教练 · 教室 · 容量
│ 候补 4 人                            │ ← 行4（按需，可能为空）：候补人数 / 已停止预约 / 已停课说明
└────────────────────────────────────┘
```

- 整卡可点（热区即整卡，≥96px 高），点击进详情；按下背景 `#F7F8F9`。
- chip 优先级（只显示 1 个，高优先级覆盖低优先级）：`已停课/未开课` > `已预约` > `候补中 · 第 N 位` > `已停止预约` > `已满` > `剩 N 位`。
- 第 4 行显示规则：有候补人数 →「候补 N 人」；已锁定 → 服务端下发的 `card_hint_text`（示例「已停止预约」）；已停课/未开课 → 归因句。
- 卡片上的所有数字（剩余名额、候补人数）都来自服务端，**前端不做加减**。

#### 4.5.4 预约卡片（我的预约）

### 4.7 交互硬规则（工程照着实现，别猜）

1. **提交防重**：所有写操作按钮在提交中禁用 + loading；同一次点击的重试沿用同一 `request_id`，重新点击生成新 `request_id`。
2. **不做本地判定**：前端不判「能不能约」「能不能取消」「能不能点名」，一律用服务端返回的枚举/时间戳；本机时间不参与任何判定。
3. **不做本地数字运算**：剩余名额、候补人数、位次、已勾选人数（勾选人数是本地计数，但**不与服务端数字做比较运算**）。
4. **不阻塞**：除提交中的按钮态外，不使用全屏 loading 遮罩；页面失败用页内错误条。
5. **订阅授权**（PM 已确认，**全稿只有这一类授权时点**）：在自绘弹窗「确认预约 / 确认加入候补」的 tap 处理函数里**第一件事同步调 `requestSubscribeMessage`**（不 await、不先发业务请求）；拒绝/失败不弹错误提示、不打断流程；授权与业务结果完全解耦。**详情页主按钮（「立即预约」/「加入候补」）与「名额刚刚被约满」弹窗内的「加入候补」都不请求授权**（它们只负责打开弹窗）。一次流程里可能出现**两个**确认类按钮（例：`确认预约` → 名额被抢 → `加入候补`（打开候补弹窗）→ `加入候补`（确认）），**每个确认类按钮的 tap 各发一次授权请求**（PM 第 1 轮审查答复）；是否用内存标记去重见 8.3。
6. **下拉刷新**：课表页（重取当天）、我的预约页（重取两条 Tab）、详情页（重取名额/状态）、点名页（重取名单）均支持。
7. **可点区域**：一律 ≥44×44；卡片内操作按钮与卡片点击热区不重叠。
8. **动效**：仅 3 处——页面切换（系统默认）、弹窗（200ms）、按钮按下（100ms）；无自动轮播、无循环动画。
9. **兜底提示条**：「我的预约」页顶部在「订阅未授权 / 授权失败 / 额度用尽」时显示一次提示条，文案「你可能收不到微信通知，请在本页查看预约状态」，可手动关闭，本会话内不再出现。

#### 5.8.1 名单口径（**点名名单 vs 补录名单**；工程与测试按此实现）

| --- | --- | --- | --- | --- |
| 点名窗口（`start_at-30min` ~ `start_at+15min`） | **点名名单 = 该场次全部有效预约**（`BOOKED` + `ATTENDED`） | `ATTENDED` 已勾选、`BOOKED` 未勾选 | 可勾选 | PRD 7.6 / P0-7 |
| 补录窗口（`start_at+15min` ~ `start_at+24h`） | **补录名单 = 有效预约（`BOOKED`+`ATTENDED`）+ `NO_SHOW` + `CANCELLED_BY_STORE`（reason = `COACH_ABSENT`）** | 同上；`NO_SHOW` 与 `CANCELLED_BY_STORE` 一律未勾选 | 可勾选 | PRD 7.3 教练补录条与教练缺勤条 ④、P0-7、10.2 状态机 |
| `start_at+24h` 之后 | 同补录名单（只读快照） | 同最后一次提交结果 | 不可勾选 | PRD 7.3 |

补充规则（每条都对应一处 PRD 口径，未新增功能）：

1. **为什么补录名单必须包含 `CANCELLED_BY_STORE`**：教练缺勤（`COACH_ABSENT`）场次在 `end_at` 会被场次结束任务把仍为 `BOOKED` 的预约整批置为 `CANCELLED_BY_STORE`（PRD 7.3 ②、10.3）。若名单只取「有效预约」，这些会员就从名单里消失、页面显示空态，教练无法按 P0-7 在 24h 内把实际到场的人补录为 `ATTENDED`，PRD 10.2 的 `CANCELLED_BY_STORE → ATTENDED` 这条路径在界面上就没有入口。
2. **只有 `reason = COACH_ABSENT` 的 `CANCELLED_BY_STORE` 可勾选**：门店停课（`reason = STORE_CLOSED`）意味着这节课没有发生，该场次整场不提供补录（列表行只显示状态标签、无勾选框）；与 PRD 10.2「`CANCELLED_BY_STORE → ATTENDED` 仅限 `COACH_ABSENT` 场次的 24h 内教练补录」一致。
3. **名单里不含**：会员已自助取消（`CANCELLED_BY_MEMBER`）的预约；本场次没有产生预约记录的人（例如候补 `SKIPPED` / `EXPIRED` 者）。
4. **点错人的回退**：取消勾选一名已勾选者并提交 → 由服务端重判（开课后 15 分钟内回 `BOOKED`，之后重判 `NO_SHOW`），前端不本地判定，按服务端返回刷新标签（PRD P0-7 点错人条）。
5. 每一行必须由服务端下发**预约状态枚举**（`booking_status`，建议同时下发 `reason`）；前端只做「枚举 → 标签 / 勾选初值」映射，**不得按姓名或本地记录推断谁该在名单里**，也不得本地计算爽约计数。
6. 「补录名单」与场次锁定无关：锁定点只冻结**点名窗口内的名单**（`start_at-30min` 起名单不再因新预约而变动，见 PRD 7.6）；补录名单按 `booking` 的实时状态取，教练自己在 24h 内改动也实时生效。

**补录态线框（同一页面，进入补录期后）**

│ ┌──────────────────────────────────┐ │
│ │ ☑ 张三    138****0001   自助预约  │ │ ← ATTENDED：已到场
│ │ ☐ 李四    138****0002   候补转正  │ │

### 6.2 键盘与焦点（PC 端小程序 / 外接键盘）

- 所有可点元素都是原生可聚焦组件（`button` / `view` + `tabindex`），焦点顺序 = 视觉顺序：导航返回 → 日期条 → 卡片列表 → 底部主按钮。
- 焦点样式：2px `#0A7D62` 外描边 + 2px 偏移，**任何组件都不允许 `outline: none`**。
- 弹窗打开后焦点进入弹窗首个可聚焦元素（关闭按钮或主按钮），`Esc` 关闭、`Tab` 在弹窗内循环；关闭后焦点回到触发按钮。
- 点名列表支持空格键切换勾选。

### 6.3 触控与尺寸

- 所有可点元素热区 ≥44×44px（含文字按钮，用 padding 撑开）；小按钮（高 36）额外加 4px 透明内边距。
- 底部固定操作区与系统手势条保持 ≥16px 间距（`env(safe-area-inset-bottom)`）。
- 相邻可点元素间距 ≥8px（点名列表整行 56，无此问题）。

### 6.4 不只用颜色传达信息

- 每个状态 chip 都有文字（`已满` / `已停止预约` / `候补中 · 第 5 位`），色盲用户可读。
- 名额信息同时有数字（`剩 3 位`）而不是只用颜色块。
- 错误提示同时给出「原因 + 出路」（例：「名额刚刚被约满 → 加入候补」）。
- 点名勾选状态用「勾选图标 + 浅绿底」，不用只有颜色变化。

### 6.5 替代文字与朗读

- 图标按钮（返回、关闭、拨打、TabBar）设置 `aria-label`（例：`返回`、`拨打门店电话`、`课表`）。
- 课表卡片整体做为一个朗读单元，`aria-label` 例：「搏击燃脂，今天 19:00 到 20:00，教练张三，剩余 3 位」。
- 状态 chip 的朗读文本不使用缩写（「候补中，第 5 位」）。
- 本设计**不使用任何图片承载信息**（本期无课程图片字段），避免替代文字缺失。

### 6.6 其他

- 不使用 `text-size-adjust: none` 等禁止系统字体缩放的写法；放大字号后允许换行与列表增高。
- 动效仅 200ms 级别且无循环动画，不触发前庭不适风险；弹窗淡入可被系统「减弱动效」偏好跳过。
- 提交中、加载中状态都通过文字表达（「预约中…」「提交中…」），不只靠转圈。

## 7. 交付给工程的口径清单（照此实现）

### 7.1 由服务端决定的 7 件事（前端不得自行判断）

1. 能不能预约 / 能不能加入候补（场次锁定点 `start_at - 30 分钟`）；
2. 能不能自助取消（唯一依据 `cancelable_until`）；
3. 剩余名额、候补人数、我的候补位次；
4. 各状态文案（含所有时间表述）；
5. 会员/教练身份与只读态；
6. 门店名称、电话、地址；
7. 候补转正结果（自动生效，前端只渲染状态变化）。

### 7.2 教练缺勤（`COACH_ABSENT`）的文案结构（按 PM 答复实现）

服务端下发 `reason` 枚举 + 文案段，前端只按 `reason` 切归因句，「承诺句」两类共用：

| `reason` | 状态标签 | 归因句 | 统一承诺句（复用） |
| --- | --- | --- | --- |
| `STORE_CLOSED` | 已停课 | 门店已取消本课 | 名额不占用、不计爽约 |
| `COACH_ABSENT` | 未开课 | 本课因故未能开课（如需了解原因请联系门店：400-000-0000） | 名额不占用、不计爽约 |

- **不使用「教练缺勤」这类归因到个人的措辞**（判定口径是「系统未观测到签到」，不等于教练人没来）。
- 中间态（`start_at + 15min` ~ `end_at`）：**不显示任何归因**，卡片仍为「已预约」，`end_at` 后才显示最终文案。
