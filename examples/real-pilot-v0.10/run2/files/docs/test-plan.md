## 1. 测试范围

### 1.1 本轮实际检查的内容

1. `docs/tech-design.md` 是否覆盖 CEO 任务点名的 7 项（架构、选型与理由、数据模型、接口设计、关键难点、里程碑工期、缓存结论）。
2. 技术方案的规则是否与 PRD v1.1 的 16 条业务规则（R-01~R-16）和全部验收标准（AC-\*）一致，尤其：候补"零确认"（AC-6.1/6.1b/6.1c）、不超卖（AC-2.6）、T-2h/T-15min 临界（AC-2.7/AC-6.5/R-08/09）、冻结（R-11）。
3. 文档之间是否一致：PRD ↔ 技术方案 ↔ 交互设计（状态枚举、状态标签、错误文案、接口字段）。
4. 工程师汇报中的"已完成""已修掉"等声明是否有文件依据（第 5 节）。
5. 用具体数字和情形对核心规则做推演（重点：状态派生是否覆盖全部组合、时间点、并发时序、任务漏跑）。

### 1.2 本轮不测（及原因）

| 不测 | 原因 |
|---|---|
| 代码、接口、SQL 的真实执行结果 | 本阶段公司只写文档、无代码；无法运行，只能审设计 |
| 并发/性能/压测数字 | 无运行环境；`tech-design.md` 7.3 已声明为估算 |
| 真机定位精度、微信订阅消息到达率、小程序备案 | 需真实设备 / 公众号后台权限，工程师已在 11.5 声明无法验证 |
| 运营后台与教练端的视觉细节 | 属设计师/后台独立范围（UX-design.md 2.4 已排除后台） |
| 里程碑能否按期完成 | 依赖人员到位与外部审核周期，非质量项 |

## 2. 重点与风险

| 风险点 | 为什么重要 | 测试方式 |
|---|---|---|
| 并发预约超卖（同一名额两人成功） | PRD 第 11 节把"出现超卖"定义为**回滚触发条件**；会员到店没位置会摧毁信任 | 容量 1 + 20 并发连接（真实 MySQL）；幂等并发 5 连击 |
| 候补转正的时序与幂等 | AC-6.1 要求 5 秒内自动转正、AC-6.4/6.6 要求 FIFO、AC-6.7 要求跳过不卡队列；错一次就丢名额或超卖 | 取消/退队/转正并发交错；一次释放 N 个名额；队首冲突/冻结 |
| "零确认"是否被违反 | AC-6.1b 是 CEO 复审的硬要求，中间态、确认按钮、倒计时都会导致名额空置 | 静态检查状态枚举、接口清单、全部前端文案（含消息模板） |
| T-2h / T-15min 临界 | AC-2.7 要求 T-15min 整点拒绝；R-09 要求 T-2h 关队列；临界点算错会让会员约不上或被算爽约 | 秒级临界数据（17:44:59 / 17:45:00 / 18:00:00 / 18:00:01）+ 可控时钟 |
| 定时任务漏跑/重启后的自愈 | R-09/AC-6.9/AC-7.2 依赖到点动作；本方案用扫描式幂等设计，前提是"条件永远能再次命中" | 停机演练：在 T-2h~T+15min 之间停机后恢复，检查队列结算与名单默认提交 |
| 冻结与爽约口径 | R-11 的 30 天累计决定会员能不能约课；口径不一致会误处罚会员 | 30 天窗口第 2/3/4 次、撤销重算、临期取消是否计数（口径待 PM 确认） |
| 教练 24h 内修改名单后的数据一致性 | AC-7.2 允许修改，但爽约记录一旦生成不撤回就会误罚 | 二次提交（先标记后改回）后核对 `no_show_records` 与 `attendance` |
| 状态标签覆盖不全 | 会员判断"能不能约"完全靠卡片标签（AC-1.2），缺一种组合就会出现空白/歧义 | 穷举 7 种标签 × 容量/时间组合（含 `T-2h ≤ now < T-15min` 满员；问题 1 已修，见 4.4） |
| 通知失败不得影响业务 | R-15 / AC-6.2：链路必须在"通知全拒收"下 100% 通 | 模拟 43101 全拒 + 模板缺失，跑完整转正流程 |
| 防代签 | AC-4.8 要求非本人执教不能签到；定位可伪造 | 用他人 JWT、伪造经纬度、窗口外批量签到 |

### 4.3 值得保留的做法（不是问题）

- `pending_promote_seats`（只由"名额释放"事件 +1，扩容量不加）用事件驱动替代状态驱动，**正面解决了 R-04 与 R-08 的冲突**：直觉写法"有名额就转正"会踩 R-04。这是本方案里最有价值的设计之一。
- 用"会员行锁"覆盖"跨行区间相交"这一类唯一约束表达不了的竞态（ADR-4），并明确了锁粒度只到会员行、不同会员之间无争抢。
- 防代签一节主动写明"能防住什么、防不住什么"（6.4），并给出可观测的反作弊指标，没有夸大。
- 定时任务统一"扫描式 + 幂等键 + 条件更新"，并把 T-2h/T-15min 的**判定放请求路径、任务只做收尾**，这个划分让"任务延迟不影响正确性"成立。
- 明确写出未验证事项（11.5）与 ADR 的"触发条件/放弃的代价"，可审计、可复用。
- 45 人日的里程碑加总正确（3+5+6+9+7+3+4+5+3=45），并标注"M2/M4/通知拒收专项不可跳过"。
