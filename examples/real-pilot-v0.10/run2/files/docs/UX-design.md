## 1. 用户与核心任务

### 1.1 核心任务与成功标准

| # | 任务 | 对应 PRD 功能点 / 验收标准 | 成功标准（可被测试核对） |
|---|---|---|---|
| T1 | 找到并约上还有名额的课 | P0-1（AC-1.1~1.7）、P0-2（AC-2.1~2.10） | 从课表首屏到「预约成功」**≤ 3 次点击**（卡片 → 详情 → 立即预约），本地网络正常时 3 秒内有结果文案 |
| T2 | 满员时排上候补，并知道排第几位 | P1-1（AC-5.1~5.7） | 加入候补 **≤ 2 次点击**；成功后同屏可见「第 N 位」「前面还有 N-1 人」 |
| T3 | 取消预约，且知道会不会被算爽约 | P0-3（AC-3.1~3.7）、R-03 | ≤ 3 次点击；确认前必须看到「计 / 不计爽约」的明确文案 |
| T4 | 知道自己已被自动补位（零操作） | P1-2（AC-6.1/6.1b/6.1c、AC-6.3） | 会员不需要任何操作；打开「我的预约」或「消息中心」即可看到状态已变为 `已预约`；界面无确认入口 |
| T5 | 教练在窗口内一键签到 | P0-4（AC-4.1~4.11） | 窗口内 **≤ 3 次点击**完成（进课表 → 打开课 → 签到）；失败必须给出原因 + 替代路径 |
| T6 | 教练课后 1 次操作确认谁没来 | P1-3（AC-7.1/7.2） | 默认全部「已到场」，教练只勾掉未到场者；提交 ≤ 2 次点击 |

### 1.2 设计假设（无真实调研，附验证方式）

| 假设 | 对设计的影响 | 验证方式 |
|---|---|---|
| A1：会员 80% 的使用发生在「今晚或明早要上课」这一即时场景，看课表时会先扫时间与剩余名额，再决定看不看详情 | 课表卡片把「时间 + 剩余名额 + 状态标签」放在视觉前两位；教练名与教室降一级 | 灰度期查 `课表页浏览 → 预约提交` 转化路径；5 人可用性测试观察首屏注视顺序 |
| A2：会员担心「取消了会不会被记鸽子」，这是取消流程的第一决策点 | 取消入口旁直接显示「16:30 前取消不计爽约」；确认弹窗把爽约后果写进标题行而不是小字 | 5 人可用性测试提问「你觉得这次取消会被算爽约吗」，答错即视为设计失败 |
| A3：教练在上课前 5 分钟内、站着、单手操作手机 | 签到页主按钮做成 56px 高、置于拇指热区（屏幕下半部）；窗口内进入页面主按钮自动获得焦点 | 灰度期 2 位教练实测；观测「签到页停留时长」与「异常签到占比」 |
| A4：候补会员可能完全没收到通知就已被补位 | 「我的预约」里候补卡片被替换为 `已预约` 卡片时，加一个浅色文字标记「候补补位」帮助理解（**不是状态、不需要操作**，AC-6.1b 不受影响） | 灰度期查看「转正后 2 小时打开小程序比例」（O7）与候补转正到场率（O4） |

## 2. 信息架构与页面清单

### 2.1 导航结构（依据 PRD 5.3）

底部 3 个 Tab，**教练端不占用 Tab**（避免会员看到无关内容），运营后台是独立 Web。

```
会员端（底部 Tab）
├─ Tab1 课表
│    └─ 课程详情 ──┬─（可约）预约结果反馈
│                  ├─（满员）候补态 [P-05] ── 加入候补结果
│                  ├─（已约）取消确认 Sheet [P-04]
│                  └─（服务端）课程取消
├─ Tab2 我的预约（待上课 / 历史）
│    ├─ 课程详情（复用 P-02 / P-05 各状态）
│    ├─ 取消确认 Sheet [P-04]
│    └─ 消息中心 [P-07]（未读角标）
└─ Tab3 我的
     ├─ 登录 / 手机号授权 [P-10]
     ├─ 消息中心 [P-07]
     ├─ 我的爽约记录 [P-09]（含冻结提示态）
     └─ 教练入口（仅当手机号匹配到教练身份时显示）
          ├─ 教练今日课表 [C-01]
          │    └─ 签到页 [C-02]（含异常签到表单）
          └─ 课后点名 [C-03]
```

跳转规则：
- **不设独立「候补排队页」**：候补排队信息是**课程详情页的候补态**（P-05），可从课表卡片或「我的预约」的候补卡片进入。理由：会员在候补场景下只有两个诉求——「我排第几」「我不排了」，同一页足够，多一个页面就多一次跳转与一次加载（与 T2 的「≤2 次点击」冲突）。**待 PM 确认项，见第 9 节。**
- 所有二级页返回上一级用系统返回；不设全局「首页」按钮（小程序无此惯例）。
- 取消确认、异常签到表单用底部 Sheet（Bottom Sheet），不用整页，减少页面层级。

## 3. 用户流程

### 3.1 流程 1：会员预约（含满员走候补分支）

```
[打开小程序]
   │
   ├─ 未登录 ──▶ [P-10 手机号授权]
   │                ├─ 拒绝 ──▶ 仍可浏览课表（AC-1.6）；点「立即预约」时再弹一次
   │                └─ 同意 ──▶ 匹配门店会员名单（R-13）
   │                              ├─ 匹配失败 ──▶ 可浏览；点预约时提示「未查到你的会员信息，请联系门店开通会员」+ 门店电话（AC-2.2）
   │                              └─ 匹配成功 ──▶ 继续
   ▼
[P-01 课表页] 默认选中「今天」，展示 今天~未来第 6 天（AC-1.1）
   │  卡片上直接给出：时间 / 课程名 / 教练 / 教室 / 已约人数与容量 / 状态标签
   │  状态：骨架加载 / 空（「近期暂无课程」+ 下拉刷新）/ 失败（「课表加载失败，请下拉刷新」+〔重试〕）
   ▼ 点课程卡片（第 1 次点击）
[P-02 课程详情页] 名额进度 + 报名截止时间 + 取消规则三段（决策所需信息全在首屏）
   │
   ├─ 已满 且 now < T-2h ──▶ CTA「加入候补」──▶ [P-05] 加入成功 = 第 N 位
   │                                           + 一次性订阅授权（勾 0 个也成功，AC-6.11）
   ├─ 已满 且 T-2h ≤ now < T-15min ──▶ 标签「已满·候补已结束」+ CTA 禁用（AC-5.3、R-09）
   ├─ now ≥ T-15min / 已开课 / 课程已取消 ──▶ CTA 禁用 + 原因文案（无第 2 次点击）
   ├─ 我已是「已预约」且 now < T-2h ──▶ 标签「已预约」+ 次要按钮〔取消预约〕+「16:30 前取消不计爽约」（AC-2.5、AC-3.1）
   ├─ 我已是「已预约」且 T-2h ≤ now < T ──▶ 标签「已预约」+〔取消预约〕+「此时取消将记 1 次爽约」（AC-3.2）
   ├─ 我已是「已预约」且 now ≥ T ──▶ 标签「已预约」+「课程已开始，无法取消」，**不展示**取消按钮（AC-3.3、R-03）
   ├─ 我已是「候补中」──▶ 进入 P-05 候补态（AC-5.1）
   └─ 可预约 ──▶ CTA「立即预约」（第 2 次点击）
                     │ 无二次确认（理由见下）；按钮内 loading「预约中…」并禁用防重复（AC-2.10）
                     ├─ 成功 ──▶ [P-03] 卡片即时变「已预约」+ 页内结果条「预约成功，已加入我的预约」
                     │            +〔查看我的预约〕（第 3 次点击进入 P-06；结果条常驻到离开本页，不用 Toast，因为 Toast 不能带按钮，见 5.8）
                     ├─ 名额被抢（AC-2.6）──▶ 内联提示「名额刚刚被约满」
                     │                        + 主按钮就地变〔加入候补〕（不跳走，1 次点击继续）
                     ├─ 时间冲突（AC-2.4）──▶ 「与你已预约的《空中瑜伽》冲突（今天 18:30-19:30）」
                     ├─ 未匹配会员（AC-2.2）──▶ 「未查到你的会员信息，请联系门店开通会员」+ 门店电话
                     ├─ 报名已截止（AC-2.7）──▶ 「报名已于开课前 15 分钟截止」
                     ├─ 权限冻结（AC-2.9）──▶ 「因连续爽约，预约功能暂停至 8月16日 21:05」+〔查看爽约记录〕（冻结到期 = 第 3 次记录生成时刻 + 7 天，见 6.8）
                     └─ 网络失败 ──▶ 「预约失败，请重试」+〔重试〕；原状态不变（AC-3.6 同理）
```

**决策点与取舍**
| 决策 | 结论 | 理由 |
|---|---|---|
| 预约要不要二次确认？ | **不要** | 预约可免费取消（R-03），无不可逆损失；二次确认会多一次点击、降低 T1 转化。误触的代价用「取消入口显眼 + 名额立即释放」弥补 |
| 满员被抢后怎么办？ | **就地变候补按钮**，不跳转、不弹窗关闭 | AC-2.6 要求「可直接进入候补」，就地变更省一次点击一次加载 |
| 预约请求超时（无法判断成败）怎么办？ | 提示「结果确认中，请稍后在『我的预约』查看」+ 拉取一次「我的预约」 | 避免出现「提示失败但实际成功」的信任事故；与服务端幂等配合（工程师侧，见 AC-2.6/AC-2.10） |

### 3.2 流程 2：取消 → 候补加入 → 自动转正（含转正后取消的闭环）

```
[A] 取消者路径
[P-06 我的预约] 点〔取消预约〕──▶ [P-04 取消确认 Sheet]

[B] 候补者路径（可与 A 同时发生）
[P-02 满员课] 点〔加入候补〕──▶ 校验

[C] 自动转正（系统单方面动作，R-08 / AC-6.1，会员零参与）
名额释放 && now < T-2h && 队列非空

        ▼ 按 FIFO 逐位转正，释放 N 个就转正 N 人（AC-6.4）

   │           + 写站内消息中心（会员下次打开必然看得到，AC-6.3）

   │           ✗ 无确认页  ✗ 无确认按钮  ✗ 无倒计时  ✗ 无「待确认」状态  ✗ 不以通知送达为前提（AC-6.1b）
```

**决策点与取舍**
| 决策 | 结论 | 理由 |
|---|---|---|
| 转正后给会员看什么？ | 只给**结果**（已预约）+ **出口**（T-2h 前免费取消） | AC-6.1b：不允许确认类交互。会员的下一步动作只有「来」或「取消」，界面不提供第三种 |
| 是否给「候补补位」加标记？ | 加一个浅色文字标记，**不生成新状态、不产生交互** | 服务 A4：会员可能从未打开小程序就被补位，需要一句人话解释这条记录从哪来。标记只解释来源，不带按钮 |
| 退出候补要不要二次确认？ | 不要，但给出「退出后重新加入会排到队尾」的提示 | AC-5.5 退出无惩罚；但 R-07 说明重新加入排队尾，这个后果要提前告知，避免会员误操作 |

## 4. 设计规范

### 4.1 色彩

对比度按 WCAG 2.1 相对亮度公式计算，均为**实测值**（不是估计）。正文/说明文字一律要求 ≥ 4.5:1。

| 用途 | 色值 | 对比度（实测） | 使用位置 |
|---|---|---|---|
| 主色 Primary | `#2563EB` | 白字在其上 5.17:1 | 主按钮底、选中日期、链接、焦点框 |
| 主色·按下 | `#1E40AF` | 白字在其上 8.72:1 | 主按钮 pressed |
| 主色·浅底 | `#E8EFFD` | 配文字 `#1E40AF` = 7.56:1 | 主色标签底、信息条 |
| 强调 / 警示 Accent | `#B54708` | 白底作文字 5.43:1；白字在其上 5.43:1 | 「仅剩 N 位」「已满可候补」「候补中」、待处理 |
| 强调·浅底 | `#FDF3E7` | 配文字 `#B54708` = 4.95:1 | 警示标签底 |
| 成功 Success | `#067647` | 白底作文字 5.69:1 | 「可预约」「已预约」「已签到」 |
| 成功·浅底 | `#E7F5EE` | 配文字 `#067647` = 5.06:1 | 成功标签底 |
| 错误 / 危险 Danger | `#B42318` | 白底作文字 6.58:1；白字在其上 6.58:1 | 「未到场」、危险按钮、失败提示 |
| 错误·浅底 | `#FDECEA` | 配文字 `#B42318` = 5.75:1 | 错误标签底 |
| 文字·主 | `#1F2937` | 白底 14.68:1 | 课程名、正文 |
| 文字·次 | `#6B7280` | 白底 4.83:1 | 时间、教练、规则说明 |
| 文字·次（浅灰底上） | `#5C6470` | 在 `#F5F6F8` 上 5.51:1 | 灰底区块内的说明文字（`#6B7280` 在灰底只有 4.45:1，**不达标，禁止使用**） |
| 文字·禁用 | `#5C6470` | 在禁用底 `#E5E7EB` 上 4.83:1 | 禁用按钮文字（同时保证可读，不靠灰度传达信息） |
| 背景·页 / 分组 | `#F5F6F8` | — | 页面底、分区底 |
| 背景·卡 | `#FFFFFF` | — | 卡片、Sheet |
| 描边·强（输入框） | `#6B7280` | 与白 4.83:1（满足 1.4.11 的 3:1） | 输入框默认描边 1px |
| 分割线 / 弱描边 | `#E5E7EB` | 与白 1.24:1 | **只作装饰**，绝不承载信息（不满足 3:1） |
| 禁用底 | `#E5E7EB` | 与禁用文字 4.83:1 | 禁用按钮底 |

规则：
1. **不只用颜色传达信息**：每个状态标签都是「底色 + 文字 + 图标」三件套（如 `⚠ 仅剩 2 位`、`✓ 已预约`）。色盲用户仅凭文字即可判断。
2. 品牌方向：主色蓝代表「可信、确定」（配合约课这种需要信任的场景），强调橙只用于「名额紧张 / 需要我关注」的场景，全页橙色面积不超过 15%，避免到处报警。
3. 不使用渐变作为信息载体；不使用纯色红铺满整屏。

### 4.2 字体层级

小程序默认字体（iOS：SF/苹方，Android：思源/系统默认）。字号同时给 px 与 rpx（1px = 2rpx @375 宽）。

| 层级 | 字号 / 行高 | rpx | 字重 | 用途 |
|---|---|---|---|---|
| H1 | 20 / 28 px | 40 / 56 | 600 | 页面标题、详情页课程名 |
| H2 | 17 / 24 px | 34 / 48 | 600 | 列表卡片课程名、弹窗标题 |
| Body | 15 / 22 px | 30 / 44 | 400 | 正文、规则说明 |
| Body·强调 | 15 / 22 px | 30 / 44 | 600 | 时间、`12/20` 名额数字 |
| Caption | 13 / 18 px | 26 / 36 | 400 | 教练、教室、辅助说明 |
| Micro | 12 / 18 px | 24 / 36 | 500 | 状态标签、未读角标 |

规则：
- **最小字号 12px**，承载业务信息（时间、规则、后果）的文字不得小于 13px；不用 < 400 的细体承载信息。
- 行高 ≥ 1.4 × 字号；中文长文本（规则说明）行高 22px 起。
- 数字（`已约/容量`、倒计时、剩余位）用等宽数字（`font-variant-numeric: tabular-nums`），避免刷新时跳动。
- 支持系统字体放大：所有文本容器用 `min-height` 而非固定高度，放大到系统最大字号时不得截断（自查见 8.6）。

### 4.3 间距体系

基础单位 **4px（= 8rpx）**。只用下列档位，不自创中间值。

| Token | 值 | 典型用法 |
|---|---|---|
| S1 | 4px | 标签与文字间距、图标与文字 |
| S2 | 8px | 卡片内行间距、标签之间 |
| S3 | 12px | 卡片之间、列表项之间 |
| S4 | 16px | 页面左右边距、卡片内边距、区块间距 |
| S5 | 20px | 区块上下留白 |
| S6 | 24px | 大区块间距、空态插图与文案 |
| S8 | 32px | 空态上下留白 |

固定值：
- 页面左右内边距 **16px**；内容区最大宽度见 4.6。
- 卡片：内边距 16px，卡片间距 12px。
- 列表项：上下 12px，分隔线 1px `#E5E7EB`，左缩进 16px。
- 底部固定 CTA 上方的可滚动区域，必须预留 **≥ 88px** 的下边距（CTA 48 + 上下 padding 20×2），避免最后一条被遮住。
- 安全区：底部 `env(safe-area-inset-bottom)`；自定义导航栏时顶部避让微信胶囊（约 88px）。

| Bottom Sheet 顶部 | 16px |
| 头像 | 50% |

### 4.5 动效

| 场景 | 时长 / 曲线 |
|---|---|
| 按钮按下、标签切换 | 120ms ease-out |
| 弹层 / Sheet 进出 | 240ms ease-out |
| 预约成功后卡片状态变更 | 标签 120ms 淡入（**不做弹跳**） |
| 骨架屏 shimmer | 1.2s 循环 |

规则：动效只做「解释变化」，不承担唯一信息（状态必须有文字，见 8.5）；尊重系统「减少动态效果」，开启时把所有位移改为纯淡入。

### 4.6 断点与响应式（移动优先）

| 断点 | 宽度 | 布局 |

### 5.1 按钮

**用法 / 不该怎么用**
- ✅ 一个屏幕（P-02 底部 CTA 区）**只放一个主按钮**；需要第二个操作时用次要按钮或文字按钮。
- ✅ 禁用按钮旁边**必须**有原因文案（如「报名已于开课前 15 分钟截止」），且禁用文字保持 4.83:1 可读 —— 用户要知道「为什么点不了」，不是「这里坏了」。
- 🚫 不用按钮承载状态信息（「已预约」不作为按钮文案，而是标签 + 次要按钮〔取消预约〕）。
- 🚫 不做「预约」和「加入候补」两个并列按钮（一个状态只有一个主操作，避免误点）。

### 5.8 Toast / 内联反馈

- 成功类优先用**页内结果条**（常驻在本页，可承载一个操作入口，如 P-03 的〔查看我的预约〕）；只有不含操作入口的轻提示才用 Toast（1.5s 自动消失）。两者都**必须**同时在页面上留下持久状态变化（标签变绿），因为自动消失的提示会被读屏和分心用户错过。**Toast 里不放按钮。**

### 8.1 对比度（WCAG 2.1 AA）

| 分割线 `#E5E7EB` | 仅装饰 | 1.24:1，**不承载信息**，不作为唯一分组依据 |

### 8.2 键盘与焦点（桌面微信 / 外接键盘）

- 全部功能可键盘完成：Tab 顺序 = 页面标题 → 日期条 → 课程卡片（列表顺序）→ 底部 CTA → Tab 栏；弹层打开后焦点移到弹层第一个可操作项，`Esc` 关闭并把焦点还给触发元素。
- 焦点状态可见：`2px #1E40AF` 外框 + `2px` 白色间隔（不使用 `outline: none`）。
- 焦点不依赖颜色：同时加粗描边宽度（1px → 2px）。
- 卡片整卡可点 + 内部有按钮时，内层按钮单独可聚焦，避免嵌套点击区域冲突。

### 8.3 触控

- 所有可点元素 ≥ 44×44px；卡片内小按钮（〔取消预约〕〔退出候补〕）用 44px 高热区 + 视觉 32px 高。
- 相邻可点元素间距 ≥ 8px；「再想想 / 确认取消」两按钮间距 ≥ 12px，防止误触危险操作。

### 8.4 屏幕阅读器与替代文字

- 每个课程卡片给出完整朗读标签：「18:30 到 19:30，空中瑜伽初级，教练小林，3 号教室，已约 12 人，共 20 人，可预约」。状态不只是颜色，必须读出来。
- 图标全部有 `aria-label` 或伴随可见文字；纯装饰图标 `aria-hidden`。
- 按钮文案动词开头：「立即预约」「加入候补」「退出候补」「取消预约」「申请异常签到」。
- 候补排名不只显示数字，「第 3 位」需整体朗读为「候补第 3 位，前面还有 2 人」。
- 动态变化（转正后状态变化、序号前进）用 `aria-live=polite` 播报，同时页面有持久文字结果（8.5）。

### 8.5 不只用颜色传达信息

| 信息 | 颜色之外的第二通道 |
|---|---|
| 课程状态 | 文字标签 + 图标（✓ / ⚠ / ⏳ / ✕） |
| 名额紧张 | 文字「仅剩 2 位」+ 进度条长度 |
| 未读消息 | 数字角标 + 加粗标题（不只红点） |
| 免费取消 / 计爽约 | 弹窗标题文字 + 按钮文案差异（「确认取消」/「仍然取消」） |
| 迟到签到 | 文字「（迟到）」+ 标签 |
| 冻结 | 图标 + 文字 + 到期时间 |
| 表单错误 | 文字提示 + 图标 + 描边变色 |

### 8.6 文本与缩放

- 支持系统字体放大：容器用 `min-height`，文本不截断、不重叠；验证方式：iOS 最大辅助字号下逐页走查（列入测试用例）。
- 长课程名最多 2 行后省略，省略时整卡可点进入详情查看全名（不丢失信息）。
- 不使用全大写、斜体、< 400 字重承载业务信息。

### 8.7 动效与时间

- 尊重系统「减少动态效果」：关闭位移、仅保留淡入；不使用循环闪动超过 3 次的动画。
- 不使用自动消失且承载关键结果的提示（成功用页内结果条或 Toast + 持久状态变化，见 5.8；失败用常驻内联提示）。
- 倒计时同时给出绝对时间（「16:30 前取消不计爽约」而不是只有「还有 2 小时」），便于认知障碍与时间敏感用户理解。
