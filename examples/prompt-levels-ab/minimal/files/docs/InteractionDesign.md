## 1. 设计原则（所有页面取舍的依据）

1. **主流程不被打断**：记账是 3 步，任何一步都不允许出现弹窗、加载页、二次确认（删除/取消预算这类破坏性操作除外）。
2. **一屏一个视觉中心**：首页是「剩余可用」，记账页是「金额」，统计页是「本月支出」。其余元素一律降级。
3. **数字必须可信**：金额统一 `¥ + 千分位 + 2 位小数`，等宽数字对齐，不做滚动动画、不做四舍五入以外的处理。
4. **颜色不是唯一信息载体**：收入/支出同时用「颜色 + 正负号 + 文字标签」三重区分（PRD §9.4、US-05）。
5. **状态先于样式**：每个页面先定义加载/空/错误/禁用，再定义"好看的样子"。

### 2.3 导航规则

- **3 个 Tab 用自定义 TabBar**（PRD §9.4 要求避免整屏转圈与原生样式不一致，自定义可统一字号/颜色/无障碍标签）。TabBar 高度 `100rpx + 安全区`。
- **Tab 之间切换保留各自页面状态**（`switchTab` 不重载）：账单页保持上次浏览的月份；统计页每次显示时重新拉取（数据可能已变）。
- **记账页/预算设置页是二级页**，`navigateTo` 进入，保存成功用 `navigateBack` 返回，不新开页面栈。
- **深链路兜底**：若因开发态/分享进入记账页而首页不在栈底，保存成功后 `navigateBack` 前先判断页面栈长度，长度不足时 `switchTab` 到首页（避免白屏）。
- 页面栈最大 10 层，本 MVP 最深 2 层（首页 → 记账页），无风险。

> 单位说明：**rpx**，设计基准宽度 `750rpx`（= 375pt 逻辑像素）。所有尺寸用 rpx，微信会自动按屏宽等比缩放；对 ≥430pt 大屏的额外约束见 §3.9。

### 3.2 字体与字号

字体族（含数字等宽，保证列表上下对齐、金额不跳动，PRD §9.2-6）：

```css
/* 小程序 WXSS 无自定义字体文件，使用系统字体栈 + 等宽数字 */
font-family: -apple-system, "PingFang SC", "Helvetica Neue", "Source Han Sans SC", sans-serif;
/* 金额/百分比等数字元素额外加： */
font-feature-settings: "tnum" 1;
font-variant-numeric: tabular-nums;
/* 兜底：若机型不支持 tnum，数字元素改用下方 font-family，靠等宽字形对齐 */
font-family: "DIN Alternate", "Menlo", "Roboto Mono", -apple-system, sans-serif;
```

> ⚠️ 给工程师：iOS/Android WebView 对 `font-feature-settings` 支持不一致，**必须真机对比 iPhone + 安卓各 1 台**，若不支持则采用等宽字体栈方案（见 §11-Q9）。

| `--font-h1` | 76rpx | 700 | 1.15 | 首页「剩余可用」金额（**一屏内最大层级**，PRD §9.4） |
| `--font-h2` | 64rpx | 700 | 1.15 | 记账页金额输入区 |

### 3.5 图标

- **分类图标（15 个）**：预置分类直接用字符/矢量图标，尺寸 `56rpx`，置于 `80rpx` 圆形或圆角方形底上，底色为分类专用浅色（10 个支出色 + 5 个收入色，详见 §9.2 图标表）。
- **功能图标**：TabBar 3 个（首页/账单/统计）、返回箭头、月份左右箭头、删除、重试、日期、提示信息 `ⓘ`。均为线性风格，线宽 2rpx，尺寸 `44rpx`。
- **硬性要求**：**所有图标必须有文字说明或 `aria-label`**，不得只放图标（PRD 无障碍要求 + §9.4）。TabBar 每个 Tab 都是「图标 + 文字」。
- 图标资源形态由工程师确认（字体图标 / base64 SVG / 图片），设计师只提供形状与语义描述。

### 3.7 动效

| 场景 | 参数 | 说明 |
| --- | --- | --- |
| 进入记账页 | ≤ `300ms`，无加载页 | PRD §9.2-1 硬性要求 |
| 分类选中切换 | `120ms` 底色 + 描边过渡 | 不做位移/缩放，避免抖动 |
| 主按钮按下 | `80ms` 底色变化 | — |
| 弹窗出现/消失 | `160ms` 淡入 + 上移 `24rpx` | 遮罩同时淡入 |
| 进度条首次渲染 | `200ms` 从 0 到目标值 | 从其他页返回时**不重复动画**（避免"数字在跳"） |
| 金额数字变化 | **不做滚动/计数动画** | 数字必须立刻可读（PRD 目标「1 秒内知道还剩多少」） |
| Toast | 出现 `120ms`，停留 `1500ms` | PRD §9.2-3 |

### 3.8 无障碍（Accessibility）

1. **对比度**：§3.1 已逐色标注，正文全部 ≥4.5:1；`--color-text-aux`（3.25:1）**禁止用于正文**，只用于单位符号、装饰、禁用态、空态占位数字。
2. **点击区域**：所有可点元素触达区 ≥ `88rpx × 88rpx`（≈44pt，PRD §9.2-7）；主按钮高 ≥ `88rpx`。
3. **图标必带文字**：TabBar、分类九宫格、列表行、月份箭头、删除，全部有可见文字或 `aria-label`。
4. **不靠颜色传达**：收支区分 = 颜色 + `+/-` 符号 + 文字标签；选中态 = 底色 + 描边 + 对勾；超支 = 红色 + 「已超支」文字。
5. **字号下限**：`24rpx`（≈12pt，含 TabBar 文字）；正文 `28rpx`（≈14pt）。
6. **读屏**：为自绘键盘按键、金额显示区、分类项、列表行补 `aria-label` / `aria-role`。**微信小程序对 `aria-*` 的支持程度依赖基础库版本与读屏模式，请工程师按官方无障碍文档实现并真机验证（列入 §11-Q11）**；若某机型不支持，退化为「所有交互元素可见文字自解释」。
7. **弱网/无网**：错误态必须给「重试」，不允许只有一个死掉的白屏。
8. **不做纯手势操作**：左滑删除的同时，编辑页底部也保留「删除」按钮，保证手势不可用也能删（PRD §9.1 页面 6 明确要求编辑页含删除按钮）。

### 3.9 响应式与断点

| 级别 | 屏宽（逻辑像素） | 规则 |
| --- | --- | --- |
| S 小屏 | ≤ 320pt（iPhone SE 1/2、小屏安卓） | 键盘行高 `100rpx → 88rpx`；九宫格单元高 `130rpx → 118rpx`；记账页金额字号 `64rpx → 56rpx`；页面边距 `32rpx → 24rpx`；列表行高 `112rpx → 104rpx`。**必须保证记账页首屏（顶部→保存键）不滚动、分类 10 个一屏可见**（PRD §9.2-2） |
| M 主流 | 321~430pt | 按 §3 基准值 |
| L 大屏 | ≥ 431pt（Plus/Pro Max、折叠屏展开、平板窗口运行小程序） | 内容区最大宽度 `686rpx` 居中；`--font-h1` 上限 `84rpx`（不再随屏放大）；**不做横屏、不做平板/PC 布局重排**（PRD §4-11） |

**其他适配规则**
- 锁定竖屏（小程序 `pageOrientation` 设为竖屏），不做横屏。
- 顶部使用自定义导航栏时，高度 = 状态栏高度 + `88rpx`；用 `wx.getWindowInfo()` 的 `safeArea` 计算，不写死。
- 底部 TabBar 与记账页「保存」键均加 `env(safe-area-inset-bottom)` 内边距。
- **自绘键盘不调起系统键盘**，因此页面高度不变化、不产生"键盘遮挡分类九宫格"的机型差异（这是选自绘键盘的主要原因之一）。
- 记账页整体不滚动（`height: 100vh; overflow: hidden`），只有分类区在 S 级屏上允许 `20rpx` 的内边距压缩，不允许出现滚动条。

## 4. 主要用户流程

> 流程中的每个触点都标注了对应的 PRD 埋点（§2.3），便于工程师对齐。

### 4.1 流程一：首次进入（US-01）

```
[用户点击小程序图标]
        │
        ▼
 启动即并行两件事（不显示任何登录页 / 授权弹窗）
   ├─ A. wx.login → code → 服务端换 openid → 创建或读取用户      (埋点 app_open)
   └─ B. 拉取首页数据：本月预算 / 本月支出合计 / 本月收入合计 / 最近 3 笔
        │
        ├─ A、B 均成功（PRD 目标：1.5s 内可交互）
        │     ▼
        │   [首页·正常态]
        │     ├─ 无预算（新用户必然如此）→ 卡片 A 显示「设置本月预算，看清这个月还能花多少」+ [设置本月预算]
        │     └─ 卡片 D 显示空态「还没有记录，记一笔试试」+ [记一笔]
        │
        ├─ B 失败（超时 3s / 网络错误）
        │     ▼
        │   [首页·错误态] 卡片级灰底占位 + 「网络开小差了，请重试」+ [重试]
        │     ※ 不要整屏转圈（PRD §9.4）；TabBar 仍可点击，切到账单/统计同样各自走错误态
        │
        └─ A 失败（静默登录失败）                              (埋点 login_silent_fail)
              ▼
           [首页·可浏览态] 顶部 `72rpx` 细提示条「网络开小差了，请重试」+ [重试]
           ※ 允许浏览；进入记账页可输入，但保存时鉴权必失败 → toast「网络开小差了，请重试」，
             该笔不写本地缓存、不进离线队列（PRD §7.5、§4-13）
```

**设计说明**
- **不做新手引导页/浮层**：与「1.5s 内可交互」冲突，且记账只有 3 步（假设 U1：引导不会显著提升首次记账完成率；验证见 §10）。
- 新用户首页天然是"引导态"：卡片 A 是预算引导，卡片 D 是空态 + 记一笔按钮，不需要额外引导。

### 4.2 流程二：记一笔支出（US-02，核心流程）

```
[首页] 点击 [＋ 记一笔]                                        (埋点 record_page_open, entry=home)
        │  ≤300ms：进入记账页 + 金额区聚焦（自绘键盘直接可见），无加载页、无中间页
        ▼
[记账页] 初始态：金额 ¥0.00（灰）· 类型=支出 · 分类默认「餐饮」· 日期=今天
        │
        ├─ 步骤 1｜输入金额（自绘键盘：数字 / 小数点 / ⌫）
        │      ├─ 合法：¥18.50 → 保存键变可用（主色）
        │      └─ 非法：空、0、>2 位小数、>¥999,999.99 → 保存键置灰
        │              但**置灰仍可点击**，点击时给对应提示（PRD §7.2.1 文案）
        │
        ├─ 步骤 2｜选分类（可跳过，默认餐饮）  ← 假设 A4 待验证
        │      └─ 切「收入」：分类区换成 5 个收入分类、默认「生活费」，已输入金额保留
        │
        ├─ 步骤 3｜点 [保存]（键盘底部通栏，拇指不移动）
        │      ▼
        │   保存键 → loading「保存中…」且禁止再次点击（client_record_id 幂等）  (埋点 record_save_success / record_save_fail)
        │      ├─ 成功 → navigateBack 返回上一页 + toast「已记 ¥18.50 · 餐饮」1.5s
        │      │          └─ 首页立刻刷新：本月支出、剩余可用、日均可用、最近 3 笔
        │      └─ 失败 → 保存键恢复可用 + toast「网络开小差了，请重试」
        │                └─ **保留已输入的金额/分类/日期**，用户可直接再点保存
        │
        ├─ 日期补记：点日期行 → 原生 picker（范围：上月 1 日 ~ 今天，未来置灰）
        │      └─ 选「上月 10 日」→ 归属上月，本月剩余可用不变（PRD §7.3-7）
        │
        └─ 返回（未保存）：**直接返回，不做二次确认**（推荐方案，见 §11-Q4）
                 理由：只有 3 步可重输、弹窗会打断主流程；代价是误触返回要重输。
                 备选：二次确认「放弃这笔记录？」（新增文案，未采用）
                 ※ 中途杀掉小程序（E10）：不做草稿保存，重进后金额/分类/日期回默认，不产生半条脏数据（详见 §5.2.5 边界⑦）
```

## 5. 关键页面布局与交互说明

> 每个页面按「目标 → 线框图 → 交互细节 → 状态 → 边界」组织。所有金额格式：`¥ + 千分位 + 2 位小数`。

### 5.1 首页（Tab 1）

**目标**：打开 1 秒内知道「这个月还剩多少、还剩几天」；1 次点击开始记账。（US-04、US-02 入口、US-03 展示）

> **示例数据自检（v0.2 修订）**：以下三个线框图统一使用同一组示例：预算 ¥1,500.00、本月支出 ¥627.50、本月收入 ¥1,500.00、今天 3 月 18 日。

#### 5.2.4 保存按钮状态机（必须实现）

```
[金额非法：空 / 0 / >2 位小数 / >¥999,999.99]
        │  置灰（底 #C9CDD4），文案仍为「保存」
        │  点击 → 不发起请求，toast 提示对应文案：
        │         「请输入金额」/「金额最多两位小数」/「单笔金额不能超过 ¥999,999.99」
        ▼
[金额合法] → 保存键变主色，可点
        │  点击
        ▼
[loading] → 键内白色 loading + 文案「保存中…」，整键不可点（防重复提交）
        │  并行：服务端以 client_record_id 幂等（PRD US-02 / E6）
        ├─ 成功 → navigateBack + toast「已记 ¥18.50 · 餐饮」1.5s  → 首页数据刷新
        └─ 失败 → 回到「金额合法」态 + toast「网络开小差了，请重试」，输入内容全部保留
```

> **E6（重复点击保存 / 弱网重试）的界面表现就在这里**：点击后按钮立即进入 `loading` 且 `disabled`，弱网下用户无法二次提交；服务端以 `client_record_id` 幂等兜底，最终只产生 1 条记录。

#### 5.2.6 金额输入规则（给工程师的伪逻辑）

```
1. 接受字符集：0-9 与 "."（其他字符丢弃，不报错、不阻塞）
2. 若当前值为 "0" 且新输入是数字 → 用新数字替换（"0"+"5" = "5"）
3. 若当前值为空且新输入是 "." → 显示为 "0."
4. 已含 "." 时再输入 "." → 忽略（不提示）
5. 小数位已达 2 位 → 再输入数字忽略（不提示）
6. 整数位已达 6 位且数值 > 999999.99 → 忽略并 toast「单笔金额不能超过 ¥999,999.99」
7. ⌫ 单击删最后一位；长按 400ms 清空为 "0.00"（灰色空态）
8. 展示始终为「¥ + 千分位 + 2 位小数」，但输入过程中允许 "18." 中间态显示为 "18."
```

### 9.3 金额与数字格式化（必须统一实现，禁止各页各写一套）

```
formatMoney(cents)     → "¥1,500.00"      // 千分位 + 2 位小数
formatExpense(cents)   → cents > 0 ? "-¥18.50" : "¥0.00"     // 仅 >0 的支出加 "-"；零值不带符号（v0.2 统一）
formatIncome(cents)    → cents > 0 ? "+¥1,500.00" : "¥0.00"  // 仅 >0 的收入加 "+"；零值不带符号（v0.2 统一）
formatZero             → "¥0.00"          // 零值统一入口，不带正负号
formatPercent(part,total) → 1 位小数 "66.9%"；total 为 0 时显示 "0.0%"（不得 NaN）
formatDay(date)        → "今天"/"昨天"/"3 月 10 日"/"2 月 10 日"
```

- **零值规则（v0.2 明确，修正 v0.1 三处不一致）**：`本月支出 = 0` 显示 `¥0.00`（**不带 `-`**）、`本月收入 = 0` 显示 `¥0.00`（**不带 `+`**）；与 PRD §10 E8「首页本月支出为 ¥0.00」、本表 `formatZero` 一致。
- 全部用「分」的整数运算，展示时才除 100（PRD §7.2.3、D11）。
- 所有金额、百分比元素加 `tabular-nums`（§3.2）。

### 9.4 交互实现要点（真机坑位提醒）

1. **自绘键盘**：不使用 `<input>` 聚焦触发系统键盘（否则会双键盘叠加、页面被顶起）。金额用 `<text>` 渲染，键盘为 `view` 按钮。**必须真机验证 iPhone + 安卓各 1 台**。
2. **页面高度**：记账页 `height: 100vh; overflow: hidden`，键盘区固定在底部；`env(safe-area-inset-bottom)` 兜底部。
3. **防重复提交**：保存键点击后立刻置 disabled + loading，同时业务层用 `client_record_id` 幂等（PRD US-02）。
4. **三处同步刷新**：首页、账单、统计的 `onShow` 都重新拉取；不要只依赖本地状态。
5. **骨架屏闪屏**：请求 <300ms 完成时不显示骨架（§6 通用规则 1）。
6. **原生 picker + 跨天**：`picker mode="date"` 的 `start`/`end` 用「上月 1 日 / 今天」动态计算；**跨天时（用户停留过夜）重新计算今天与剩余天数**（PRD E3）。
7. **无障碍属性**：`aria-label` / `aria-role` 的支持依赖基础库与读屏，按官方文档实现并真机验证（§11-Q11）。
