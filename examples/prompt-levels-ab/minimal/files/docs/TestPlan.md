## 0. 结论摘要（先看这段）

1. **文档可测性结论**：PRD v0.2 / TechPlan v0.2 / 设计 v0.2 三份文档已具备派生可执行用例的完整度——P0 六个用户故事的验收标准、§10 边界 E1~E18、接口错误码与幂等契约均已定义到"可直接写步骤和预期"的程度。**本测试计划可用**。
2. **不能冻结用例的 4 项前置决策**（详见 §8 F1~F4）：沿用预算写入时机（PRD vs TechPlan 字面差异，PM 定）、「我的」页与清空账目是否 MVP（CEO/PM 定）、首页最近记录是否可点进编辑（PM 定）、统计/日期组"仅收入"展示口径（PM 定）。其中 **F1、F2 建议在 M1 开工前答复**，否则对应用例组（US-04 沿用、账单历史月浏览、"我的"页/清空账目）会按两套预期摇摆。
3. **本阶段无运行证据**：所有用例状态为「待执行」。计划的执行验证分层（单测→集成→端到端→灰度）、造数/对账/错误注入工具依赖工程师在 M0~M4 交付（§2.3），测试届时只采信运行结果。
4. **最大的验证风险**：时间相关（跨天/跨月/跨年/月末）与并发幂等用例严重依赖"服务端 UTC+8 唯一时间源 + 唯一索引"两项实现正确性；唯一索引能否创建（TechPlan T4）是**M0 第一验证项**，若失败需走退化方案，相关幂等用例的预期要重写。

### 1.3 测试策略（分层验证，对齐 TechPlan §12）

| 层 | 手段 | 谁执行 | 本计划的作用 |
| --- | --- | --- | --- |
| 静态层 | ESLint（本地）、代码评审强制项：**每条 DB 查询必须带 `user_id`** | 工程师 + 测试复核 | 测试提供检查清单（TS 组用例），作为代码评审输入 |
| 单元层 | `node --test` 跑 `common/{time,money,validate,stat,record}.js` 纯函数 | 工程师（M0~M3 补齐，TechPlan §12.3） | 测试提供边界取值表：金额/分桶/日期/闰年/月末/除零/排序 |
| 集成层 | `scripts/seed.js` 造数（含单月 1000/1200 条）+ `scripts/verify.js` 对账 + `MOCK_FAIL=1` 错误注入 | 工程师提供工具，**测试设计用例并执行/复核** | 本文 §3~§5 的主体用例在此层跑 |
| 端到端层 | 真机手测（iPhone + 安卓各 1） | 测试 + 工程师共同 | 四态、自绘键盘、等宽数字、无障碍、跨天/时区（§2.4） |
| 灰度层 | 埋点看板 + 对账脚本每日跑 | 工程师执行、测试复核（TechPlan Q10 建议） | 只验证链路，不判定业务指标达标 |

**核心策略**：
- **数据再造 + 对账**：所有聚合/分页/统计用例用 `seed.js` 造确定性数据，用 `verify.js` 校验"读接口返回 == 库内求和"，不接受手算截图作为唯一证据。
- **边界值分析**：金额（0 分、1 分、100 分、1000 分、5000 分、10000 分、99999999 分、100000000 分）、日期（上月 1 日、昨天、今天、明天、月底最后一天、跨年 1 月）、月份（当前月、最早账目月、未来月）。
- **幂等/并发专项**：同 id 并发、不同 id 并发、沿用预算并发 —— 断言"最终条数"而非"返回结果"。
- **分页完整性断言（写入可测）**：翻到 `has_more=false` 后，Σ 支出 == `month_totals.expense_cents`、Σ 收入 == `month_totals.income_cents`、`_id` 去重条数 == `total_count`、每组日期组头合计 == 组内可见条目之和（TechPlan §7.4）。
- **时间用例的真实性**：跨天/跨月/跨年用例必须真机 + 改设备时区/系统时间配合服务端视角执行；记录服务端 `server_date` 作为锚点，不信任客户端时间。
- **缺陷管理约定**：每条缺陷写清【位置 / 实际情况 / 期望情况 / 严重度 / 证据（复现步骤+日志+截图）】；严重度定义：**P0 阻塞上线**、P1 严重（核心功能错误或数据错误）、P2 一般（体验/非核心）、P3 轻微（风格/文案偏好不报，除非违反 §9.3 文案口径）。没有运行证据的"通过"一律不得写。

## 5. 异常情况用例（登录失效 / 数据加载失败 / 云函数报错 / 鉴权与数据隔离）

#### TX01 静默登录失败（1002/AUTH_FAILED）：不阻塞浏览、保存被拦截（P0）
- **关联**：US-01 Given 2/5；TechPlan §5.1 错误码 1002

- **状态**：待执行

#### TX02 数据加载失败（首页/账单/统计任一读接口）
- **关联**：PRD §9.4；设计 §6 状态总表（P1）
- **分组用例**：
  - **TX02a 首页**：`home.summary` 失败 → 卡片级错误态 + 重试；已有旧数据时**保留旧数据 + 顶部细提示**，不清空数字；TabBar 与「记一笔」仍可用
  - **TX02b 账单**：`record.list` 失败 → 列表区错误态 + 重试；月份切换器仍可用
  - **TX02c 统计**：`stat.monthly` 失败 → 错误态 + 重试
  - **TX02d 预算页**：`budget.get` 失败 → 页面错误态 + 重试，**隐藏保存按钮**（避免用旧值覆盖）
- **步骤**：断网/注入失败后依次打开各页
- **预期**：见各分组；所有错误态都带重试出路，不允许白屏
- **状态**：待执行

#### TX03 云函数内部错误（2001 INTERNAL）（P0）
- **前置**：`MOCK_FAIL=1` 让写接口返回 2001
- **步骤**：1) 记账保存（被注入失败）；2) 查库
- **预期**：客户端 Toast「网络开小差了，请重试」，输入保留；服务端**不落任何脏记录**；日志含 `err_msg` 但**不含金额/备注**；埋点 `record_save_fail(reason=server)`
- **状态**：待执行（需错误注入开关，TechPlan §12.2）

#### TX04 错误码映射全表抽查（P1，接口层）

- **状态**：待执行

#### TX05 越权与数据隔离（P0，安全）
- **前置**：账号 A、账号 B 各有数据
- **步骤**：1) 用 B 的会话构造查询 A 的 `record_id`/月数据请求；2) 检查所有集合权限设置；3) 检查服务端是否接受客户端传的 `user_id`

- **状态**：待执行（代码评审 + 运行时验证双证据）

#### TX06 日志脱敏抽查（P1）

- **状态**：待执行

## 10. 结论（能否交付）

**10.1 文档阶段结论（本次）**

- **测试计划本身可用**：PRD/TechPlan/设计 v0.2 已提供足够的验收口径，可派生并冻结 70+ 条可执行用例（P0 核心、P1 重要、P2 次要），覆盖正常/边界/异常三类，并与 §8 验收标准矩阵一一对应。
