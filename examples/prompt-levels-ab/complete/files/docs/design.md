## 1. 设计目标与原则

| 原则 | 具体含义 | 设计上的落地方式 |
|------|----------|------------------|
| **① 一步到输入** | PRD 6.5：从任意 tab 到「开始输入金额」≤ 1 次点击 | 记账不设独立页面，做成**全局半屏弹层**；首页与账单页右下常驻 FAB；金额输入框打开即自动聚焦唤键盘 |
| **② 面板内闭环** | PRD S2：全程不切页、不丢上下文 | 类型 / 金额 / 分类 / 日期 / 备注全部在同一个弹层内完成，日期与分类用弹层/网格内联，**不跳二级页** |
| **③ 不制造焦虑** | PRD 6.5 文案语气：克制、不说教 | 支出金额用**深色**而非红色；红色只保留给「超支」与「删除」；主卡文案用「本月还剩」而非「已超支！」 |
| **④ 数字不骗人** | PRD AC-4.12 / 6.5 写失败态 | 所有数字必须有加载态（骨架屏），禁止先显示 `¥0.00` 再跳变；所有写操作失败时界面数值保持与云端一致 |
| **⑤ 状态先行** | PRD 6.4.1 主卡 4 态、14.1 状态清单 | 首页主卡按状态机出 4 套稿（A/B/C/H），不共用一套渲染；每个页面单独给出加载 / 空 / 错误 / 异常态规格 |

## 3. 全局视觉风格指南

### 3.1 色彩系统

**主色选择理由（设计决策）**：
- **不用绿色做主色**：绿色已承载「收入 / 正向」语义（PRD AC-3.13 要求收入用绿色）。若主色也是绿，按钮与收入金额会互相干扰。
- **不用微信品牌绿 `#07C160`**：微信自身的「授权」「支付」按钮就是该绿，用户会误以为主操作是授权/付费。
- **选蓝色**：蓝色在小程序内具备「工具 / 数据 / 可信」的调性，与「收入绿」「超支红」「警示橙」三者都不冲突，且与微信原生链接蓝属同一色相家族，生态感一致。

| Token | 色值 | 用途 | 白底对比度（WCAG 2.1） |
|-------|------|------|------------------------|
| `--brand-50` | `#EEF4FF` | 极浅底、选中行底 | 装饰用，不承载文字 |
| `--brand-100` | `#DCE8FF` | 分类选中底、标签底 | 装饰用 |
| `--brand-200` | `#B9D1FF` | 进度条底（历史月/空态） | 装饰用 |
| `--brand-400` | `#4C8CFF` | 图表/图标次要色 | 3.0:1（仅图形/大号） |
| **`--brand-500`（主色）** | **`#1E6BFF`** | 主按钮底、FAB、选中描边、链接 | **4.56:1 ✅ 正文可用** |
| `--brand-600` | `#1557D1` | 按下态、正文强调、tabBar 选中色 | 6.10:1 ✅ |
| `--brand-700` | `#0F3F9C` | 深色强调（极少用） | 8.7:1 ✅ |
| `--brand-300`（暗底用） | `#8AB2FF` | 提示条（深色底）上的动作文字 | 暗底 8.2:1 ✅ |

### 3.2 字体层级（基准 750rpx / 375pt）

字体族：`-apple-system, "PingFang SC", "Helvetica Neue", Roboto, "Noto Sans CJK SC", sans-serif`（跟随微信系统字体，不引入自定义字体以控制包体，PRD 9 章包体 ≤ 1.5MB）。
**所有金额与数字启用 `font-variant-numeric: tabular-nums`**，保证右对齐不跳动、列表金额纵向对齐。

| 层级 | 字号 | 字重 | 行高 | 用途 |
|------|------|------|------|------|
| `display` | 72rpx（36px） | 600 | 1.15 | 主卡主数值（本月还剩 / 历史月结余） |
| `h1` | 40rpx（20px） | 600 | 1.3 | 首页三列数字、账单页月度合计金额、统计详情合计 |
| `h2` | 36rpx（18px） | 600 | 1.4 | 卡片标题、弹层 Tab 文字、弹窗标题 |
| `title` | 32rpx（16px） | 500 | 1.4 | 分组头、列表主文字、按钮文字 |
| `body` | 28rpx（14px） | 400 | 1.5 | 正文、表单、明细行 —— **正文最小字号，不得再小** |
| `caption` | 24rpx（12px） | 400 | 1.4 | 辅助说明、字段标签、字数计数、副信息 |
| `micro` | 22rpx（11px） | 400 | 1.3 | 仅 tabBar 文字（框架控制，不可自定义）、角标 —— 不承载必读信息 |

**字号使用硬约束**：任何用户必须读到才能完成任务的信息（金额、分类名、日期、校验提示、按钮文案）**不得低于 `body`（28rpx）**。

### 3.3 间距、圆角、阴影、动效

| Token | 值 | 用途 |
|-------|-----|------|
| `--space-1 ~ 8` | 8 / 16 / 24 / 32 / 48 / 64 / 96 / 128 rpx | 4px 基准间距系统（页面左右边距 32rpx，卡片内边距 32rpx，卡片间距 24rpx，列表行高 ≥ 112rpx） |

| Token | 值 | 用途 |
|-------|-----|------|
| `--radius-sm` | 8rpx | 小标签、进度条 |
| `--radius-md` | 16rpx | 按钮、输入框、分类项 |
| `--radius-lg` | 24rpx | 卡片、提示条 |
| `--radius-xl` | 32rpx | 二次确认弹窗、半屏弹层顶部圆角 |
| `--radius-full` | 999rpx | FAB、头像、胶囊标签 |

| Token | 值 | 用途 |
|-------|-----|------|
| `--shadow-1` | `0 2rpx 8rpx rgba(0,0,0,.04)` | 卡片（以 1px 描边为主，阴影极轻，省性能） |
| `--shadow-2` | `0 8rpx 24rpx rgba(0,0,0,.08)` | 弹层、弹窗 |
| `--shadow-fab` | `0 8rpx 24rpx rgba(30,107,255,.32)` | FAB |

| 动效 | 规格 |
|------|------|
| 弹层上滑 / 下滑 | 240ms `cubic-bezier(.32,.72,0,1)` |
| 遮罩淡入 | 200ms `ease-out` |
| 骨架屏 shimmer | 1200ms 循环（尊重「减弱动态效果」系统设置时降级为静态灰块） |
| 数值变更 | 200ms 透明度交替替换（**不做数字滚动动画**，避免被误读为持续变化） |
| 按钮态 | 150ms；按下态用 `--brand-600` + 缩放 0.98 |
| 校验失败 | 分类区抖动 300ms + 描边变红；不做全屏震动 |

### 3.4 组件风格（关键规格）

| 组件 | 规格 |
|------|------|
| **主按钮** | 高 88rpx，`--brand-500` 底 + 白字 `title`（32rpx/500），`--radius-md`；按下 `--brand-600`；行宽 = 容器宽 − 64rpx |
| **主按钮 · 加载态** | 左侧 spinner 24rpx + 文案「保存中…」，**禁用点击**（PRD AC-2.15 防重复提交的前端一层） |
| **主按钮 · 禁用态** | 底 `#EDEEF0` + 文字 `--text-disabled`，无阴影、无按下反馈 |
| **次按钮 / 文字按钮** | 白底 + 1px `--border`；文字按钮只用 `--brand-600` 文字，无底色 |
| **危险按钮** | 文字色 `--color-overdraft`（用于「删除」）；**不做红色实心按钮**，避免误触心理压力 |
| **FAB** | 直径 112rpx，`--brand-500` + 白色「＋」，右下距 32rpx、距 tabBar 上沿 32rpx；阴影 `--shadow-fab`；自带热区 ≥ 88rpx ✅ |
| **卡片** | 白底 + `--radius-lg` + 1px `--border`（+ 极轻阴影），内边距 32rpx |
| **分类项（网格）** | 图标底 64rpx 圆角方（未选中底 `--bg-page`、图标 `--text-2`；选中底 `--brand-100` + 图标 `--brand-600` + 1px `--brand-500` 描边），下方文字 `body`/28rpx（选中 `--brand-600` 600 字重）；单元热区 ≥ 88×88rpx |
| **列表行** | 高 ≥ 112rpx：左 64rpx 分类图标 → 主文字（`title`，有备注时显示备注）→ 副文字（`caption` 显示分类名）→ 右金额（`title`，tabular-nums，右对齐）；支出 `-¥12.00` `--color-expense`，收入 `+¥1,500.00` `--color-income` |
| **进度条** | 高 12rpx，底 `#EEF0F3`，填充 `--brand-500`（超支 `--color-overdraft`），右/上方附百分比 `caption`；填充宽度封顶 100%（不溢出容器） |
| **提示条 snackbar** | 宽 = 容器宽，高 96rpx，`--snackbar-bg` + `--radius-lg`，白字 `body`，动作按钮 `--brand-300`（暗底 8.2:1 ✅）；位于 tabBar 上方、**右侧避开 FAB 160rpx** |
| **二次确认弹窗** | 宽 560rpx 居中，`--radius-xl`，标题 `h2` + 正文 `body`；按钮「取消」（`--text-2`）/「确认删除」（`--color-overdraft`）；遮罩点击 = 取消 |
| **骨架屏** | 灰块 `#EDEEF0` + shimmer，结构必须与真实内容一一对应（首页：主卡块 + 三列块 + 3 行列表；账单：3 组「组头 + 2 行」） |
| **空态** | 线性 SVG 插画（≤ 8KB）+ 主文案 `body` + 副文案 `caption` + 主按钮；**必须含「为什么空」+「下一步怎么做」两句话**（PRD 6.5） |
| **错误态** | 图标 + 原因文案 + 「重新加载」主按钮；**禁止只显示「出错了」**（PRD 6.5） |

### 3.5 金额、日期与文案格式

| 项 | 规格 |
|----|------|
| 金额（通用） | `¥1,200.00`：千分位 + 固定两位小数；负数 `-¥50.00`（负号在 ¥ 前） |
| 金额（列表/详情） | 支出 `-¥12.00`，收入 `+¥1,500.00`（`+` 只在列表与详情出现） |
| 首页主卡 | 不显示正号：正常态 `¥300.00`、超支态 `-¥120.00`、空态 `¥0.00` |
| 日期（列表组头） | `9月12日 周五` |
| 日期（详情/创建时间） | `2025-09-12 12:30` |
| 日期（记账面板） | 今天显示「今天（9月12日 周五）」；昨天显示「昨天（9月11日 周四）」；其他显示「9月10日 周三」 |

### 3.6 微信小程序设计规范符合性

| 规范项 | 本设计做法 |
|--------|-----------|
| 导航栏 | 使用**原生导航栏**（白底、黑色标题），不下沉自定义导航栏。原因：① 右上角胶囊按钮（··· ○）占据约 88×88pt 区域，自定义导航栏右侧不能放可点击元素；② PRD 首页 ASCII 稿把「小账本」与「2025年9月 ▾」放在同一行，在原生导航栏下不可实现，故做**布局下沉**（详见 8.1 待确认项） |

| tabBar | 2 个 tab（首页 / 账单），图标 81×81px 源图（设计稿 40×40pt @2x/@3x 导出），选中色 `--brand-600`，未选中 `--text-3`；tabBar 文字由框架控制，不自定义字号 |
| 底部安全区 | 所有吸底元素（FAB、提示条、弹层保存按钮）`bottom = 内容底 + env(safe-area-inset-bottom)`（iPhone X+ 34pt） |
| 键盘避让 | 记账弹层开启键盘避让：弹层可视高度 = 屏幕高 − 键盘高，**金额输入区与保存按钮始终可见**（PRD AC-2.17，需在 375×667 与 320×568 双尺寸验证） |
| 尺寸单位 | 全部使用 rpx；设计稿 375pt 基准；提供 320pt 降级校验（文字不截断、按钮不换行折断） |
| 原生能力使用 | 提示条含动作按钮 → 使用**自定义组件**而非 `wx.showToast`；删除二次确认 → 自定义弹窗而非 `wx.showModal`（保证视觉一致与文案可控） |
| 隐私合规 | P0 不采集昵称/头像/手机号/位置，无需《用户隐私保护指引》中的对应声明；若后续引入需同步配置 |
| 暗色模式 | **MVP 不做**（PRD 未要求）。但 Token 已按语义命名（如 `--text-1`、`--bg-card`），后续只需新增 `[data-theme="dark"]` 覆盖层即可，无需改动组件 |
| 分享 / 订阅消息 / 朋友圈 | 不做（PRD 11 章不做社交；订阅消息为 P2） |

### 5.2 主卡：4 套状态稿（PRD 6.4.1 / 6.4.2 硬要求）

> **必须按状态分别出稿，工程不得用同一套渲染逻辑处理**（PRD 6.4 明确）。

#### 状态 A · 空账本态（本月收入 = 0 且 支出 = 0）

```
┌──────────────────────────────────────────┐

```

- 这是本产品**最关键的增长触点**：设计上给它 `--brand-600` 文字色 + 箭头，与状态 A 的被动空态区分开，视觉权重高于普通副文案。

- 主数值 = 收入 − 支出；结余为负时切换为超支样式（`-¥50.00` + `--color-overdraft`，AC-4.3）。

### 10.4 流程 4：主卡状态迁移（设计需保证各态之间无残留）

```
状态 A（空账本）
   │ 记一笔支出（如 1 号话费 ¥120）
   ▼
状态 B（无收入基线：-¥120.00 + 引导记收入；无进度条、无日均）

   ▼
状态 C·超支（-¥500.00 + 超支色 + 进度条 100% 红色 + 「已超支」）
   │ 切换到历史月
   ▼
状态 H（{N}月结余 + 当月支出 · 共 N 天；无进度条、无日均、无剩余天数）
```

**迁移硬要求**：每次迁移必须清除上一态的元素（如从 C 切到 H 时进度条必须消失，不能只改文字）；C·超支态下「平均每天可用」若为负数**按 PRD 6.4 定义照实展示负值**（不取绝对值）。
