## 三、本轮新发现（**非阻塞**，建议在编码前或下一版轻量处理）

> 以下两项不需要再走一轮评审，但请工程在 W1 评审时口头同步，或在下次改动文档时顺带落笔。

### 🟡 3.1 档位 B 的裁剪项 ②③ 实质变更了 P0 交付内容，登记不充分

- **事实**：8.3 档位 B 含「② 记录详情由独立页 → 复用弹层组件（省 0.5）」「③ 埋点先做 7 个核心事件（省 0.3）」。
  - ②与 `design.md` 8.3（记录详情为**二级整页** `pages/record/detail`，编辑态内联）不一致；
  - ③与 PRD **10 章「埋点需求（P0 必须）」**（14 行事件）及 **13 章发布前置检查「埋点全部上线并验证数据可查」** 不一致——而 0.3 的余量 **+0.3 恰好等于 ③ 省下的 0.3**。
- **风险**：0.1 / 0.2 均称「P0 功能上全部可行（**无需削减任何 P0 功能**）」，与 8.3 档位 B 自相矛盾；若 CEO 采纳档位 B，W4/W5 的发布 Gate 会因埋点不全而卡住，且无 PM 决策留痕。
- **建议**：在 0.2 / 11 章把 ②③ 与 WR-11 绑定，注明「采纳档位 B = 需 PM/设计确认的降级项」（①分类排序已由 0.2 #2 登记，无需重复）；或把 ③ 从裁剪项中去掉（保留 11 类事件），接受余量归零。

### 🟡 3.2 「孤儿键」同步分支在退化路径（R-9）下缺少时序保护

- **事实**：4.8 / 5.4.3 规定，命中窗口内的键但 `txnId` 无对应记录 → 视为孤儿键 → **同步删除并放行新建**；而 5.4.3 的写入流程是「先 `add txn_dedup{txnId:null}` → 再 `add transactions` → 最后 `update txnId`」。在**事务不可用的退化路径**下，这条流程存在 `txnId` 尚未回填的时间窗：并发到达的同 `clientRequestId` 请求会把它判为孤儿键、删键并新建 → **产生 2 条记录**，与 ADR-009 / R-9 声称的「AC-2.15 仍可满足」不符（AC-2.15 的场景恰是「连续快速点击保存 3 次」）。
- **建议**：给同步孤儿判定加宽限条件（如 `createdAt + 10s < now`，与定时任务的「5 分钟」策略同源），窗口内的新鲜键一律按「重复/冲突」返回（fail-closed，宁可让前端重试，不产生重复数据）；并在 10.2 补一条「退化路径下并发同 id 提交」用例。
- **备注**：主路径（事务可用）下该分支不可达，故本轮不阻塞。

### 💭 3.3 两处小口径建议

1. **12 个月窗口的定义**：5.4.4 规则 3 定义为 `[serverDate 所在月 − 11 个月的首日, 今天]` 共 12 个自然月，并标注「与 PRD 6.2 一致」。PRD 6.2 原文是「最近 12 个月内任意日期」，未规定自然月边界（字面读法从今天往前推 12 个月，会在“月初 vs 月末”产生 9 天级差异）。建议在 11 章登记一句「窗口边界按自然月取整，请 PM 知悉」，避免测试对边界日（如 2024-09-30）出现两种预期。
2. **页面清单与工作量的覆盖**：2.1 / 8.1 的前端只列了 4 个页面组（首页 / 记账面板 / 账单与详情 / 登录全局），未包含 `design.md` 6 章的**统计详情页 `pages/stat/detail`** 与 9.1 的**「我的」页**（两者均为 design 的 P0【设计细化】，design 14 章 8.2/8.3 正等 PM 确认）。在余量仅 +0.3 人日的前提下，建议在 0.2 待确认项里加一条：若 PM 确认两页纳入 P0，需追加约 1.0 人日并重算 8.2.1。

## 四、值得肯定（不要求修改）

1. **幂等的「判窗与清理解耦」**：把 24h 窗口的语义依据放在 `expireAt` 判读上，而非依赖清理任务按时执行——这是把「定时任务不可靠」这一常见运维现实提前挡在正确性之外，写法专业。
2. **`month` 每次 update 无条件重算 + CI 红线 5**：既满足「date 变化必须重算」的必须性，又顺带治愈历史脏数据；用 CI 门禁把这类易漏的一致性约束固化，比写在文档里更有约束力。
3. **历史月示例的数字做到自洽**（金额求和、百分比取整、主数值与 AC-4.13 对齐），这类「示例即契约」的严谨度会直接减少实现与验收的口径打架。
4. **新增 R-9 / R-10 / WR-11 / WR-12 并给出可验证路径**：风险不只是登记，还配了 10.2 用例、10.3 调试能力、8.5 实测清单，可执行性好。
5. **产能账户 + 缓冲去向 + 「禁止压缩 W3 自测」硬规则**：把排期风险显式量化并对账，避免「文字提示型缓冲」在真实排期中被无声吃掉。
