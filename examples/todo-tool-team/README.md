# 示例：三人团队做命令行待办工具（v0.1）

OPC v0.1 的第一次真实运行（模型 `deepseek-flash`）。这一版的工程师只写代码、不运行。

- **团队**：📋 产品经理、💻 工程师、🧪 测试
- **CEO 的指令**：做出第一版：需求文档、技术方案，以及可以直接运行的 Python 代码（支持添加、列出、完成、删除待办，数据存到 JSON 文件），再由测试同学写测试计划并审查代码

## 过程

1. 规划助手 8 秒给出 4 个任务：产品经理写 PRD → 工程师写技术方案 → 工程师实现代码 → 测试写测试计划并审查代码（测试同时依赖 PRD 和代码）
2. CEO 批准后按依赖顺序执行，全程约 12.7 分钟、约 35 万 token
3. 汇报助手总结：四个角色的交付物都齐了，但代码没有实际运行验证，有 1 个 P0 缺陷和 1 个默认路径冲突需要决定

## 产出（[files/](files/)）

| 文件 | 作者 | 内容 |
|---|---|---|
| `docs/PRD.md` | 产品经理 | 优先级、7 组验收标准、退出码约定 |
| `docs/TECH_DESIGN.md` | 工程师 | 架构、数据模型、错误处理 |
| `code/todo.py`、`code/README.md` | 工程师 | 可以直接运行的命令行工具 |
| `docs/TEST_PLAN.md` | 测试 | 48 条测试用例 |
| `docs/CODE_REVIEW.md` | 测试 | 代码审查 |

**值得一看**：测试通过静态审查发现了一个真实缺陷：不带子命令运行时会打印异常堆栈（DEF-01），实际运行确认确实如此。这也说明了只写不运行的局限，v0.2 因此让工程师接入了编码 agent。
