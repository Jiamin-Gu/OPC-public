## 3. 测试策略

### 3.1 分层策略

| 层次 | 手段 | 覆盖对象 | 理由 |
| --- | --- | --- | --- |
| 黑盒（主，约 80%） | `subprocess.run([sys.executable, "code/todo.py", ...], env=..., capture_output=True, text=True, encoding="utf-8")` | AC-1~AC-7 全部：真实退出码、真实 stdout/stderr、真实文件落盘 | 退出码与文案就是对外接口（技术方案 P5），只有起进程才能断言 |
| 白盒（辅，约 20%） | `import todo` 直接调 `cmd_*` / `normalize_state` | 边界值密集场景、畸形数据结构 | 命令层不碰 IO、不打印（技术方案 §3.1 的强制分层），无需起进程，快 |

### 3.2 断言四要素（每条用例都必须齐）

1. **stdout**（逐字，含中文与标点）
2. **stderr**（含 `错误：` 前缀；错误场景下还应含帮助的 `usage:`）
3. **退出码**
4. **数据文件内容**（解析后断言字段；涉及「不覆盖」的场景额外断言**字节级不变**）

### 3.3 隔离原则（重要）

- 每个用例使用**独立数据文件**（`tmp_path/todos.json`），生命周期内不复用，避免顺序耦合。
- **必须**显式设置 `--file` 或 `TODO_FILE`；测「默认路径」的用例必须同时改 `cwd` 和 `HOME` 到临时目录。
- ⚠ 因为当前默认路径是「当前目录 `./todos.json`」，**任何忘记隔离的用例都会在仓库根目录生成 `todos.json`**，请把 `todos.json` 加入 `.gitignore`（建议工程侧处理）。
- 起进程时传完整环境副本：`{**os.environ, "TODO_FILE": ..., "PYTHONIOENCODING": "utf-8"}`。

### 3.4 用例编号约定

`TC-N` 正常流程、`TC-B` 边界、`TC-E` 异常、`TC-D` 数据文件健壮性、`TC-P` 默认路径（待决策）、`TC-M` 手工/半自动。

### 3.5 执行准备（可复制）

```bash
# 约定：$W 临时工作目录，$T 临时数据文件，PYTHONIOENCODING=utf-8
export W="$(mktemp -d)" T="$W/todos.json"
export PYTHONIOENCODING=utf-8
cd "$(git rev-parse --show-toplevel 2>/dev/null || pwd)"      # 仓库根，使 code/todo.py 可达
todo() { python code/todo.py --file "$T" "$@"; }              # 用例统一带 --file 隔离
```

## 11. 风险与缓解

| ID | 风险 | 影响 | 缓解 |
| --- | --- | --- | --- |
| R-1 | 默认路径为「当前目录」，用户在不同 cwd 下操作会「看起来数据丢了」 | 用户困惑/数据分散，多文件 | 用 `--file` 或 `TODO_FILE` 固定路径；建议 README 顶部用醒目提示，或默认改回家目录（D-1） |
| R-2 | 默认文件可能被误提交到仓库 | 数据泄漏 | 建议把 `todos.json`、`.todo-*.tmp` 加入 `.gitignore` |
| R-3 | 测试忘记隔离 → 写真实家目录或仓库根 | 污染真实用户数据、用例互相干扰 | 强制每条用例独立 `tmp_path`；TC-P 组显式改 cwd/HOME |
| R-4 | 「全部已完成」与「清单为空」都输出 `暂无待办事项`，用户无法区分 | 体验小坑（可能误以为记录丢了） | 观察项：建议 v1.1 区分文案（如 `暂无未完成待办`）；PRD 未定义，本次不作为缺陷 |
| R-5 | Windows 控制台非 UTF-8 → 中文乱码/断言失败 | 跨平台用例假红 | CI 设 `PYTHONIOENCODING=utf-8`；subprocess 显式 `encoding="utf-8"` |
| R-6 | 以 root 运行 → 权限类用例不触发 | 假绿 | `os.geteuid()==0` 时跳过 TC-E18/E19/D12 |
| R-7 | 时区/时钟跳变 → `done_at >= created_at` 偶发失败 | 假红 | 用 `>=`；不做秒级严格递增断言 |
| R-8 | 文档三方不一致（X-1~X-7）未被同步 | 后续开发/测试按旧文档做，返工 | 决策后在 CODE_REVIEW 第 8 节的清单中逐条同步 |
