## 1. 背景与目标

开发者在终端里工作时，切换 App 或网页记录待办会打断心流。我们希望提供一个**零依赖、上手即用**的命令行工具，让用户在不离开终端的情况下管理自己的待办清单。

**第一版目标（一句话）**：用户能在终端完成「添加 / 列出 / 完成 / 删除」四类操作，数据自动持久化到本地 JSON 文件，重启终端后数据不丢失。

**成功判据**：
- 新用户看一次 `todo --help` 就能完成首次「添加 + 列出」。
- 四条核心命令（add/list/done/delete）全部可用，数据写入 JSON 文件并可被重新读取。

## 2. 目标用户与使用场景

### 2.1 目标用户

| 用户画像 | 描述 | 核心诉求 |
| --- | --- | --- |
| 主力用户：终端开发者 | 长时间在终端工作，习惯命令行 | 快速记录、不打断心流、无需安装依赖 |
| 次要用户：运维/脚本使用者 | 需要在简单环境（如服务器）记录待办 | 单文件可运行、数据是纯文本可读 |

### 2.2 典型使用场景

- **场景 A（快速记录）**：正在跑测试，突然想起「改一下 README」，输入 `todo add "改 README"`，2 秒内完成。
- **场景 B（查看清单）**：开始一天工作时输入 `todo list`，看到未完成事项，心里有数。
- **场景 C（标记完成）**：做完一项输入 `todo done 3`，清单里该项消失（默认只看未完成）。
- **场景 D（清理）**：误记或用不着了，输入 `todo delete 3` 删除。
- **场景 E（持久化）**：关闭终端后重新打开，`todo list` 仍能看到之前的待办。

## 5. 核心功能详述（P0）

### 5.1 添加待办 `todo add`

- **命令**：`todo add "<内容>"`
- **行为**：
  1. 校验内容非空（去掉首尾空白后长度 > 0），否则报错退出（见 6.3）。
  2. 生成新的自增 ID（当前最大 ID + 1，不复用已删除的 ID）。
  3. 写入数据文件。
  4. stdout 输出：`已添加 #<id>: <内容>`
- **示例**：见 7.2。

### 5.2 列出待办 `todo list`

- **命令**：`todo list`（P0 默认只显示**未完成**待办）
- **P1 扩展**：`todo list --all` 显示全部（含已完成）
- **行为**：
  1. 读取数据文件。若文件不存在，视为空清单（不报错）。
  2. 无匹配条目时输出：`暂无待办事项`
  3. 有条目时，每行按 ID 升序输出，格式统一为：

     ```
     <id>. [ ] <内容>     # 未完成
     <id>. [x] <内容>     # 已完成
     ```

     示例：
     ```
     1. [ ] 买牛奶
     2. [x] 写周报
     ```

### 5.3 完成待办 `todo done <id>`

- **命令**：`todo done <id>`（`id` 为正整数）
- **行为**：
  1. 查找该 ID。不存在 → 报错退出（6.3）。
  2. 若已是完成状态 → 输出：`#<id> 已是完成状态`（不算错误，退出码 0）。
  3. 否则将 `done` 置为 `true`，记录 `done_at`，写回文件。
  4. stdout 输出：`已完成 #<id>: <内容>`

### 5.4 删除待办 `todo delete <id>`

- **命令**：`todo delete <id>`（`id` 为正整数）
- **行为**：
  1. 查找该 ID。不存在 → 报错退出（6.3）。
  2. 从列表中移除该条，写回文件。
  3. stdout 输出：`已删除 #<id>: <内容>`
- **说明**：第一版删除**不做二次确认**；删除后 ID 不复用。

### 5.5 数据持久化（JSON）

- **数据文件位置**（按优先级）：
  1. 环境变量 `TODO_FILE` 指定的路径；
  2. 默认 `~/.todo.json`。
- **文件格式**（UTF-8，JSON）：

  ```json
  {
    "version": 1,
    "next_id": 3,
    "todos": [
      {
        "id": 1,
        "text": "买牛奶",
        "done": false,
        "created_at": "2025-01-01T09:00:00",
        "done_at": null
      },
      {
        "id": 2,
        "text": "写周报",
        "done": true,
        "created_at": "2025-01-01T09:05:00",
        "done_at": "2025-01-01T18:00:00"
      }
    ]
  }
  ```

- **字段说明**：

  | 字段 | 类型 | 必填 | 说明 |
  | --- | --- | --- | --- |
  | `version` | int | 是 | 数据格式版本，第一版固定为 `1` |
  | `next_id` | int | 是 | 下一个可用 ID |
  | `todos` | array | 是 | 待办列表，可为空数组 |
  | `id` | int | 是 | 唯一正整数 |
  | `text` | string | 是 | 待办内容 |
  | `done` | bool | 是 | 是否完成 |
  | `created_at` | string | 是 | 创建时间，`YYYY-MM-DDTHH:MM:SS` 本地时间 |
  | `done_at` | string \| null | 是 | 完成时间，未完成时为 `null` |

- **读写规则**：
  - 每次命令执行「读 → 改 → 写」。
  - 写入需保证文件不损坏（工程师采用「先写临时文件再原子替换」）。
  - 文件不存在时按空清单处理；首次 `add` 时自动创建文件。

### 5.6 错误处理与退出码

| 情况 | 输出（stderr） | 退出码 |
| --- | --- | --- |
| 成功 | 正常信息（stdout） | 0 |
| 找不到 ID（done/delete） | `错误：找不到 ID 为 <id> 的待办` | 1 |
| 内容为空（add） | `错误：待办内容不能为空` | 2 |
| 参数缺失或非法 | 帮助信息 + `错误：<原因>` | 2 |
| 数据文件损坏（JSON 解析失败） | `错误：数据文件已损坏，路径：<path>` | 3 |

> `todo --help` 与 `todo <子命令> --help` 输出帮助并退出码 0。

## 6. CLI 交互与参数示例

### 6.1 命令总览

```
todo add <内容>          添加待办
todo list [--all]        列出待办（默认仅未完成）
todo done <id>           标记待办为完成
todo delete <id>         删除待办
todo --help              查看帮助
```

### 6.2 正常示例

```bash
$ todo add "买牛奶"
已添加 #1: 买牛奶

$ todo add "写周报"
已添加 #2: 写周报

$ todo list
1. [ ] 买牛奶
2. [ ] 写周报

$ todo done 1
已完成 #1: 买牛奶

$ todo list
2. [ ] 写周报

$ todo list --all
1. [x] 买牛奶
2. [ ] 写周报

$ todo delete 2
已删除 #2: 写周报

$ todo list
暂无待办事项
```

### 6.3 错误示例

```bash
$ todo done 99
错误：找不到 ID 为 99 的待办
$ echo $?
1

$ todo add ""
错误：待办内容不能为空
$ echo $?
2

$ todo done
错误：缺少参数 <id>
$ echo $?
2
```

### 6.4 参数与约束

| 参数 | 位置/形式 | 必填 | 约束 |
| --- | --- | --- | --- |
| `<内容>` | 位置参数 | 是 | 去空白后非空；允许空格、中文、标点；建议长度上限 500 字符 |
| `<id>` | 位置参数 | 是 | 正整数 |
| `--all` / `-a` | `list` 选项 | 否 | 显示含已完成的全部条目 |

> 含空格的内容需用引号包裹。

## 8. 验收标准

> 以下为可测试的验收清单，供测试同学直接转成用例。

**AC-1 添加**
- 连续执行 `add A`、`add B`，分别返回 `已添加 #1: A`、`已添加 #2: B`。
- `~/.todo.json` 中 `todos` 长度增加，`next_id` 递增。

**AC-2 列出**
- 默认 `list` 只显示未完成项，按 ID 升序，格式为 `<id>. [ ] <内容>`。
- `list --all` 同时显示已完成项，已完成项格式为 `<id>. [x] <内容>`。
- 空清单输出 `暂无待办事项`。

**AC-3 完成**
- `done <有效id>` 后该项从默认 `list` 中消失，`list --all` 中显示 `[x]`，退出码 0。
- 对已完成项再次 `done`，输出 `#<id> 已是完成状态`，退出码 0，数据不变。
- `done 99`（不存在）输出错误到 stderr，退出码 1。

**AC-4 删除**
- `delete <有效id>` 后该项在 `list --all` 中消失，退出码 0。
- 删除后再 `done/delete` 同一 ID 返回「找不到」错误，退出码 1。
- 删除后新增的待办 ID 不复用已删除的 ID。

**AC-5 持久化**
- 添加数据后，重新调用命令（新进程）能读到相同数据。
- 通过 `TODO_FILE=/tmp/x.json` 可指定数据文件位置。
- 数据文件为合法 JSON，UTF-8 编码，中文正确保存与读取。

**AC-6 错误处理**
- 空内容 `add ""` 返回退出码 2 与明确提示。
- 参数缺失/非法（如 `done abc`、`done`）返回退出码 2 与帮助信息。
- 数据文件被写入非法 JSON 时，命令返回退出码 3 且**不覆盖**原文件。

**AC-7 帮助**
- `todo --help` 与 `todo add --help` 输出可用帮助，退出码 0。

## 9. 非功能需求

- **运行环境**：Python ≥ 3.8，**仅使用标准库**（`argparse`、`json`、`os`、`sys`、`pathlib`、`datetime`）。
- **交付形态**：单文件 `code/todo.py`，`python todo.py ...` 可直接运行。
- **性能**：单次命令耗时 < 200ms（千条规模以内）。
- **健壮性**：任何异常都不应导致数据文件损坏或留下半写文件。
- **可读性**：输出简洁、中文提示友好；错误信息走 stderr。

## 10. 明确不做的范围（Out of Scope）

第一版**不做**以下内容，避免范围蔓延：

1. **不做多用户 / 多清单 / 项目分组**，只维护单一清单。
2. **不做网络同步、云存储、账号系统**。
3. **不做图形界面、Web 界面、TUI 交互式界面**。
4. **不做自然语言解析**（如 `todo 明天买牛奶`）。
5. **不做提醒 / 定时通知 / 系统通知**。
6. **不做截止日期、优先级、标签、搜索、排序、分页**（其中优先级、日期属 P2，本版不实现）。
7. **不做数据导入导出与第三方格式兼容**。
8. **不做删除二次确认与回收站/撤销**。
9. **不做并发写锁与多进程同步**（第一版假设单用户顺序使用）。
10. **不做配置管理命令**（仅支持 `TODO_FILE` 环境变量）。
