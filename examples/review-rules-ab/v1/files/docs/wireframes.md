**入口**：后台左侧导航「待通知任务」。**默认排序**：`距 confirm_deadline 升序`（最紧急在最上）。

### 区域说明

| 区域 | 规则 |
|---|---|
| 门店切换 | 门店运营：**不显示**下拉（只能看本店）；总部管理员：显示全部门店 + "全部门店" |
| 状态筛选 Tab | 默认选中「待通知」。各 Tab 数字为当前条数 |
| 到期高亮行 | 距 `confirm_deadline ≤ 10 分钟` 且状态 = 待通知 → 整行左 4px 橙色边（`#EA580C`）+ 截止列加 `⚠` 与"剩 8 分钟"（`#B91C1C`）。≤3 分钟时截止列文案加"**即将过期**"（不只靠颜色） |
| 截止列 | 显示**剩余分钟（分钟粒度）+ 绝对时间 HH:mm**；`confirm_deadline` 与会员端同源，后台**不允许**自行计算或修改 |
| 状态列 | `● 待通知` / `● 已通知（电话 / 微信 / 前台面告）` / `✓ 已转正（会员自助确认 / 运营代确认）` / `✕ 已过期（未通知 / 已通知）` / `– 已取消（课程取消）` |
| 位次 | 该会员在当前队列中的位次；待确认的队首显示 1 |
| 操作列 | **只有 2 个写操作**：`标记已通知`、`代为转正`。终态行不显示任何按钮（只读，满足 PRD P0-⑦"自动置终态后运营不可再操作"） |
| 导出 | 导出当前筛选：创建时间、状态流转时间、操作人、通知方式、是否代确认、是否超时（PRD P0-⑦ 最后一条） |
| 刷新 | 每 30s 轮询刷新（P0 不做推送）；页面顶部显示"最后更新 HH:mm:ss" |
| 分页 | 每页 20 条 |

### 交互：标记已通知

```
点 [标记已通知] → 弹窗：
┌────────────────────────────────────┐
│ 标记已通知                          │
│ 会员：李*明 138****1234             │
│ 课程：燃脂单车 初级 · 望京店 20:30   │
│ 确认截止：19:12（剩 8 分钟）         │
│                                    │
│ 通知方式 *   ( ) 电话 ( ) 微信 ( ) 前台面告
│ 备注         [ 电话未接，已发微信 ]  │
│                                    │
│ 〔 取消 〕           〔 确认标记 〕  │
└────────────────────────────────────┘
```
- 通知方式**必选**（未选时"确认标记"禁用 + 说明"请选择通知方式"）；备注可选、最长 100 字。
- 成功后：状态变 `已通知（电话）`，行内出现"最后操作：王运营 19:04"，留痕写入服务端。
- **重复提交**：按钮 loading 期间禁用；服务端幂等（同 `X-Request-Id` 重放返回首次结果），不产生第二条留痕。
- 若在弹窗打开期间该会员已自行确认 → 提交时返回 `TASK_NOT_ACTIONABLE(409)`，弹窗内提示"该会员已自行确认，无需再通知"，并刷新行为 `已转正`。

### 交互：代为转正

```
点 [代为转正] → 弹窗（二次确认，必填备注）：
┌────────────────────────────────────────────┐
│ 代为转正                                    │
│ 请确认你已与会员沟通并获其同意。              │
│ 会员：李*明 138****1234                     │
│ 课程：燃脂单车 初级 · 望京店 20:30–21:30      │
│ 该操作会占用这个名额，等同于会员本人确认。     │
│                                            │
│ 备注 *  [ 电话确认，会员同意参加 ]           │
│                                            │
│ 〔 取消 〕                 〔 确认转正 〕    │
└────────────────────────────────────────────┘
```
- 备注**必填**（PRD 要求），空则按钮禁用。
- 成功 → toast `已代为转正`，任务置 `已转正（运营代确认）`，会员端状态同步（来源 = 运营代确认，用于统计）。
- 失败 `SEAT_UNAVAILABLE` → 弹窗内红字 `名额已不可用`（不关闭弹窗，提示"请刷新列表"），**不产生预约记录**。
- 失败 `TASK_NOT_ACTIONABLE`（该任务已被系统置为终态）→ 弹窗内提示"该任务已结束（会员已确认 / 已超时 / 课程已取消），请刷新列表"，不关闭弹窗。
- 越权（他店任务）→ `STORE_SCOPE_FORBIDDEN(403)` 整页：`你没有操作该门店任务的权限`（不展示任务内容），并留痕。

### 状态清单

| 状态 | 表现 |
|---|---|
| 加载 | 表格 5 行骨架（行高 48px） |
| 空（待通知 0 条） | `当前没有待通知的会员` + `有会员候补到名额时，任务会自动出现在这里` |
| 空（全部 0 条） | 同上，副文案改为 `可以导出历史明细检查` |
| 403 | 仅本店提示 + "返回我的门店" |
| 接口错误 | 表格上方错误条 `任务加载失败，请重试` + `重新加载`（保留筛选条件） |

| 交互 | 规则 |
|---|---|
| 顶部当前状态区 | 三点必显：**当前值 + 最近变更人 + 变更时间**（PRD 要求）。门店运营看到的是同一区域，但无「变更设置」按钮 |

| 开关状态语义 | 关闭期间违约**照常计数**；关闭**不**自动解除既有冻结（这两条必须写在生效说明里，运营会问） |
| 人工解冻 | 弹窗：显示会员、门店、违约次数、原解冻时间；**备注必填**（如"线下申诉通过"）；确认后 toast `已解除冻结，该会员已可预约`。目标会员已不在冻结中 → `NO_ACTIVE_FREEZE(409)` → 弹窗提示 `该会员当前不在冻结中` 并刷新。会员端下次进入仅显示"预约权限已恢复"，不显示操作人 |
| 越权 | 门店运营调 `PUT /admin/settings/violation-freeze` → `HQ_ONLY_FORBIDDEN(403)` + 留痕 |
| 幂等 | 同一 `request_id` 重复提交只生效一次、只产生 1 条留痕 |
| 状态 | 加载 / 空（无冻结会员 → `当前没有处于冻结中的会员`）/ 错误 / 403 |

## 4. 后台 H5 全局规范（与小程序端共用色彩 token）

| 项目 | 规范 |
|---|---|
| 字号 | 正文 14px/22px；表格内容 14px；表格表头 13px/`#4B5563`；页面标题 20px/600；弹窗标题 17px/600；辅助文字 12px |
| 颜色 | 完全复用 `docs/design.md` 4.1 的 token；语义色同名同值（成功/警示/错误/满员/待确认） |
| 表格 | 行高 48px（触控/点击舒适），表头吸顶，斑马纹**不用**（用 1px `#E5E7EB` 下划线），数值列右对齐并用等宽数字 |
| 按钮 | 主按钮高 36px（桌面鼠标，不需要 44px 触控）；**但所有按钮的键盘焦点环必须可见**（2px `#1D4ED8` + 2px offset）。触控为主的场景（若在平板上用）改 44px |
| 弹窗 | 宽 480px 居中，圆角 16px，`shadow-dialog`；打开时焦点移入，`Esc` 关闭（代为转正确认除外：必须显式点按钮，防止误操作）；关闭后焦点回到触发按钮 |
| 危险操作 | `停用教练`、`代为转正`、`变更开关`、`人工解冻` 均需「二次确认 + 备注必填」；**必须说明后果与不可逆性** |
| 留痕展示 | 统一格式：`MM-DD HH:mm  操作人  动作（前值 → 后值）  备注：…`；列表默认显示最近 5 条 + 导出全部 |
| 权限提示 | 403 三类码（`FORBIDDEN` / `STORE_SCOPE_FORBIDDEN` / `HQ_ONLY_FORBIDDEN`）统一页面文案：`你没有查看该数据的权限` + `请联系总部管理员`；**不暴露他店数据的存在** |
| 时间 | 全站显示门店本地时区的 `MM-DD HH:mm`；涉及截止时间必须同时显示"剩余分钟"与"绝对时间" |

## 5. 错误码 → 文案 → 展示位置总表（工程按此实现，前端不散落文案）

> **契约（v1.1 定版）**：错误码常量以 `docs/tech-design.md` §5.6 与 §5.2–5.4 接口列表为**唯一来源**——后端生成、小程序/后台从同一份 TS 常量导入，前端**不自行定义错误码名**。本表 code 全部与 tech 同名，展示形式 / 逐字文案 / 界面动作由设计侧给出。
> **每个业务错误码有且只有一套文案**，集中在一个 `errorMessages` 配置里，会员端与后台共用同一份（差异项用括注）。文案改动不需要改业务代码。
> **不属于错误的情况**（不出现错误文案，直接按返回体更新界面）：幂等重放（`X-Idempotent-Replay: true` 返回首次响应体）；签到重复（不同 ID 但已签到 → `200 {"alreadySigned":true, ...}` 返回首次时间）；候补确认重复（→ `alreadyPromoted`）；取消重复（→ `alreadyCancelled`，违约不重复计数）。
> **邀请码防枚举**：`INVITE_CODE_INVALID` 对"不存在 / 已使用 / 已过期"统一一条文案（tech §5.3.1 定案），前端与界面不得拆分，避免被攻击者枚举探测邀请码状态。

| `cancel_submit` / `cancel_result` | 取消 | penalty_mode, 是否计违约, 距开课分钟 | 开课前 120 分钟内取消占比 |
| `checkin_click` / `checkin_result` | 教练签到 | course_id, signIn.uiState, result, is_late | 签到率、迟到次数 |
| `coach_bind_submit` / `coach_bind_result` | 绑定邀请码 | result(错误码) | 教练邀请码绑定成功率 |
| `message_center_view` | 打开消息中心 | unread_count | D-1 是否需要该页 |
| `task_mark_notified` / `task_force_convert` | 后台运营操作 | task_id, 通知方式, 是否成功 | 运营未在截止前通知的任务数、代确认占比 |
| `penalty_mode_change` / `member_unfreeze` | 管理员操作 | 前值/后值, 操作人, 备注非空 | 规则开关与解冻的审计 |
| `api_perf` | 所有关键接口 | endpoint, p95, 错误码 | 抢位/候补接口 P95 ≤500ms、超卖 = 0（后端侧校验） |

> 埋点只上报服务端已确认的结果，**不上报"用户点了但被前端拦下"的点击**（避免污染成功率分母）。
