## 2. 信息架构与页面清单

### 2.1 导航结构（单小程序、多视角）

```
微信小程序「约课」
│
├─ 【会员视角】默认落地（AC-12-5、D9）
│   ├─ Tab1 课表 ────────────→ 课程详情 ──→ 预约确认（半屏）──→ 结果反馈（成功/失败）
│   │                                └──→ 候补确认（半屏）──→ 候补中（详情内状态区）
│   ├─ Tab2 我的预约
│   │     ├─ 待上课（booked / promote_pending / waitlisted）
│   │     │     ├─→ 取消预约确认（弹窗）
│   │     │     ├─→ 转正确认（弹窗：确认参加 / 放弃）
│   │     │     ├─→ 会员签到页（输入 6 位码）
│   │     │     └─→ 课程详情
│   │     ├─ 历史（checked_in / no_show / cancelled / expired / auto_closed）
│   │     └─ 我的信誉（AC-08-3）
│   ├─ Tab3 我的 ──→ 我的信誉 / 消息中心 / 联系门店 / 切换到教练视角 / 关于与规则
│   ├─ 全局入口：消息中心（课表页 + 我的预约页右上角铃铛，AC-09-2）
│   └─ 全局弹层：登录与手机号授权（AC-12-1~3）
│
├─ 【教练视角】仅 roles 含 coach 时出现 Tab4（AC-10-3）
│   └─ Tab4 教练 ──→ 今日课程 ──→ 课次签到与名单页（签到码 / 名单 / 标记已到 / 补发起签到）
│
└─ 【运营视角】P0-D，待 CEO 确认
    └─ 我的 → 运营中心（非 tab，见 §6.10 与技术方案 §11.3-C7）
        └─ 排课列表 ──→ 新建 / 编辑 / 改期 / 取消课次 / 课次名单 / 待处理提醒
```

**导航要点**

- 会员视角 TabBar **固定 3 项（课表 / 我的预约 / 我的）**；教练角色追加第 4 项（AC-12-5：tab 顺序 课表 / 我的预约 / 教练）。**最多 4 个 tab，为将来留 1 个余量**。
- 教练视角切换入口放**两处**：`我的` 页列表第一项 + 教练 tab 右上角胶囊按钮（AC-12-5 要求"显式切换"，避免教练找不到签到）。
- **消息中心不做成 Tab**（v1.1 明确）：用铃铛入口 + 红点，满足 AC-09-2。**与工程师口径统一**：技术方案 §11.3-C7 假设"会员端 4 个 tab（含消息）"，实际按 PRD AC-12-5 的 tab 顺序应为"课表 / 我的预约 / 教练"，消息不做 tab —— 已列入 §11 待办请工程师同步（不要按 4+1=5 顶格实现，避免运营入口被迫挪走）。
- 会员端与教练端共用同一套组件与语义色，只有数据范围不同（D8、AC-12-6）。

## 3. 用户流程

> 每个流程标注：入口 → 步骤 → 决策点（D）→ 出错路径（E）→ 返回路径（B）。设计原则：**能一步完成的绝不做两步；每一次失败都必须给出下一步可点的动作**。

### 流程 1：查看课表 → 课程详情 → 预约（US-01 / US-02 / US-03）

**入口**：微信小程序冷启动 / Tab1 / 分享卡片 / 消息中心跳转。

| 步骤 | 界面动作 | 系统反馈 | PRD 对应 |
| --- | --- | --- | --- |
| S1 | 打开小程序 | 骨架屏 ≤1.5s（AC-01-9）；未登录也能看课表（AC-12-1） | AC-01-9、AC-12-1 |
| S2 | —（无需操作） | 默认日期=今天、默认门店=最近一次约课门店（首次=系统默认门店），按开始时间升序 | AC-01-1 |
| S3 | 切换日期 / 门店 / 课程类型 | 列表局部刷新（骨架只替换列表区，日期栏与筛选条不闪） | AC-01-3/4/5 |

### 4.6 动效与性能

- 动效时长 **150–250ms**，缓动 `cubic-bezier(0.2, 0, 0, 1)`；只用于：半屏/弹层进出、状态切换高亮、卡片加入/移除列表。
- 禁止：闪烁频率 >3Hz 的动画、无限循环的装饰动画、阻塞操作的入场动画。
- 提供"减弱动效"跟随（能力允许时读系统设置；否则提供开关），开启后所有动效变为 ≤100ms 淡入。
- 性能预算：课表首屏 **≤1.5s**（AC-01-9）；列表分页 20 条/页，滚动到距底部 300px 预加载；**教练头像：卡片内 24×24（2x 48×48）、详情页/我的页 40×40（2x 80×80）**，懒加载 + 占位块；**课表卡片不使用课程配图**（MVP 无图源，且可省流量）；不使用视频/大图作背景；慢网（弱网 ≤200kbps）下必须出现骨架屏而不是白屏。
- 失败可恢复：任何列表请求失败，保留已加载内容 + 顶部/底部错误条 + "重新加载"，不清空（AC-01-10）。

### 4.7 文案规范（工程师与测试可直接引用）

1. 按钮：动词开头（"立即预约""确认参加""标记已到"）；**禁止**"确定/提交/是"这类无信息量词；主按钮 2–6 字。
2. 错误信息三段式：**发生了什么 → 为什么 → 怎么办**（例："手慢了，名额刚被抢完。该课程已满员。你可以加入候补。"）。
3. 时间格式：一律 `HH:mm`；日期：今天显示"今天"，明天显示"明天"，其他显示 `M月D日`；跨天必须显式写日期。
4. 名额：有名额写"剩余 3"；满员写"已满 · 候补 4 人"；候补中写"候补中 · 第 3 位 / 共 8 人"。
5. 候补人数为 0 时，按钮文案为**"加入候补"**（不带人数）；≥1 时写"加入候补（当前 X 人排队）"（AC-02-3）。
6. 倒计时：≥1 小时用"1 小时 20 分"；<1 小时用 `12:34`。
7. 距开课时间：**≥24 小时**显示"1 天 9 小时"；**<24 小时**显示"9 小时 49 分"（两者都只精确到分，不显示秒）。
8. **取消规则的统一表述（v1.1 修订，与 6.3.4 一致）**："开课前 2 小时前可自助取消；之后不能取消，未到场将记为爽约"。**全站不得出现"之后取消将记爽约"这类暗示逾期仍可取消的写法**（原文案已删除，见 v1.1-5）。
9. **候补位次两种口径（v1.1 新增，与工程师 §11.1-A1 对齐）**：未被跳过 → "候补中 · 第 X 位 / 共 Y 人"（X 为实时排名）；`skip_count ≥ 1` → "**等待中 · 前面 N 人 / 共 Y 人**" + 顺延原因（禁止对曾被跳过的会员继续单独显示"第 1 位"，否则会员会一直等待一个不会发生的转正）。
10. 禁止用"超时"单字（含歧义）；用"已过期/已结束/已截止"三种明确说法，且分别只对应：候补 `expired`、签到窗结束、预约窗结束。
11. 所有金额/支付相关文案不出现（MVP 无支付）。
12. 免责与规则文案与 PRD 第 6 章数值**完全一致**（2 小时 / 30 分钟 / 15 分钟 / 7 天 / 30 天累计 2 次 / 限制 7 天），不允许界面出现与规则不一致的表述。

### 4.8 图标与图片

- 图标统一 24×24 线性、1.5px 描边，颜色继承父级文字色；小程序内用矢量/字体图标，不用位图。
- **状态角标专用图标（v1.1 新增）**：锁形=未开放预约、时钟斜杠=已截止预约、时钟=待确认、三条横线=候补中、对勾=已预约/已签到、斜杠圆=已取消。这套图标是"未开放"与"已截止"的主要区分手段（不是靠颜色）。
- 装饰性图标：`aria-hidden`；功能性纯图标按钮（返回、关闭、铃铛）必须有 `aria-label` 或可见文字标签。
- **教练头像（v1.1 统一尺寸）**：卡片内 24×24（圆角 12，无头像用姓名首字 + 主色浅底占位）；详情页与"我的"页 40×40（圆角 20）。缺图/加载中显示占位块，不留空白。
- 空状态插画：可选，尺寸 ≤120×120；**没有插画也要有文字 + 行动按钮**（AC-01-6 / AC-08-5）。
- 图片替代文字：课次无图；若 P1 加课程配图，必须填 `alt`（课程名 + 时间）。

### 5.4 状态角标（v1.1 重写）

高 20，圆角 6，横向内边距 8，字号 12/16 字重 500；颜色与图标映射见 §4.1。

**规则 1：同一卡片只出现一个角标；角标由服务端 `badge` 字段决定，前端不推导（AC-01-12、PRD §13.2）。**

**规则 2（v1.1 修订）：优先级以服务端口径为唯一标准**，即 `docs/Tech-Design.md` §6.3：

```
my_status(promote_pending > booked > waitlisted)
  > cancelled / finished（按课次状态）
  > not_open（now < T-7天）
  > closed（now > T-30min）
  > full（remaining = 0）
  > available
```

> 本文 v1.0 曾自定一套排序（把"已满"排在"已截止"之前），会与实现算出不同角标（例：19:00 的满员课在 18:40 会被设计稿算成"已满 · 候补 4 人"、服务端算成"已截止"），**该自定排序已删除**。

**规则 3：三种"不可约"角标的时间互斥定义（补 §5.4 与 §7.5 的一致性）**

| 时间区间（相对 T） | 我的记录 | 会员端角标 |
| --- | --- | --- |
| `now < T - 7天` | — | 未开放预约（`not_open`） |
| `T-7天 ≤ now ≤ T-30min` | 无记录，`remaining ≥ 1` | 可预约（`available`） |
| `T-7天 ≤ now ≤ T-30min` | 无记录，`remaining = 0` | 已满 · 候补 X 人（`full`） |
| `T-30min < now < 课次结束（end_at）` | 无记录 | 已截止预约（`closed`） |
| `now ≥ end_at`（课次 `status=finished`） | 无记录 | 已结束（`finished`） |
| 任意 | 我 `booked` | 已预约（`booked`，我的状态优先，不受上面时间行影响） |
| 课次 `status=cancelled` | 任意 | 已取消（课表不展示，UX-D01） |

> **待 PM/工程师确认的边界**：课次进行中（`T ≤ now < end_at`）会员端会显示"已截止预约"；教练端"已结束"按 AC-10-2 是 `now > T+15min`，与会员端按课次状态（`now ≥ end_at`）不一致 —— 两处差异已列入 §11 待办，设计侧不擅自改口径。

### 5.5 筛选 chip 与日期栏

- **chip**：高 32，圆角 999，未选：白底 + 1px `#D6D9DE` + 字 `#4B5563`；已选：底 `#E8F0FE` + 1px `#1F6FEB` 边框 + 字 `#1552B8` + 字重 600（**边框+字重+底色三重区分，不只靠颜色**）；横向可滚动，滚动条隐藏。
- **日期栏**：每项宽 ≥44（高度 56），今天项显示"今天"+ 日期数字；当天有课时在数字下方显示 4px 圆点；选中项为主色药丸底 + 白字（4.64:1），并带 `aria-selected`。仅渲染"今天 ~ 今天+7"共 8 项（AC-01-3、AC-01-12），第 8 天及以后不出现。

### 5.6 底部操作条（详情页）

高 64（含内边距，另加安全区），白底 + 顶部 1px `#EBEDF0`，内容为单个大按钮（宽 100%）或"主 + 次"两按钮（主占 60%）。按钮态由服务端 `actions` 驱动（§6.2.3）。

### 5.7 弹层：半屏 / 弹窗

- **半屏（bottom sheet）**：顶部圆角 16，最大高 80vh，可滚动；顶部有 36×4 拖拽条 + 标题 17/24；支持下滑关闭 —— **但破坏性操作（取消预约、放弃转正、退出候补、标记已到）不允许下滑关闭**，必须点明确按钮。
- **弹窗（dialog）**：居中，宽 min(80%, 320–480)，圆角 16；标题 17/24，正文 14/20，最多两行 + 可滚动；按钮纵向排列（主上、次下）或横排（主左/次右，按平台习惯）。
- 关闭动作统一在右上角 ×（命中区 44×44）与"取消/再想想"按钮。

> **为什么「未开放预约」只能出现在"今天+7"**（写给测试，直接决定能不能造出该状态）：
> 可见范围 = 今天 ~ 今天+7（8 个自然日），开放时刻 = `now ≥ T-7天`。对"今天+k（k ≤ 6）"的课次，`T-7天` 最晚也就是"昨天"，必然早于今天 00:00 → **永远已开放**；只有 k = 7 时 `T-7天` 落在"今天"的同一时刻，若课次开课时刻晚于当前时刻，才会出现未开放。
> 构造方法（示例）：现在 = `8/12 09:41`，取 `8/19 19:00` 的课次 → `T-7天 = 8/12 19:00 > 09:41` → 未开放，开放时刻显示"8月12日 19:00"。

**6.4.3 关键交互规则**

1. **位次口径（与工程师 §11.1-A1 对齐）**：`queue_no` 加入时分配、永不变化；对外展示的位次 = **实时排名 `position`**（当前 `waitlisted` 队列中 `queue_no ≤ 我的` 的记录数）。这样 AC-05-8（有人退出 → 位次前移）与 AC-06-14（被跳过者不被踢出队列、后续仍可转正）同时成立。
2. **位次刷新口径（补 AC-05-10）**：位次在"进入页面 / 下拉刷新 / 任一操作返回后"刷新，最长 10 秒内与后端一致；**不做实时推送**（PRD 允许下次进页面刷新）。刷新时只替换位次与点阵，不重建卡片（避免闪动）。
3. **被跳过时的文案（v1.1 改为工程师建议口径）**：`skip_count ≥ 1` 的记录，卡片主文案由"候补中 · 第 X 位"改为「**等待中 · 前面 N 人 / 共 Y 人**」，并附黄色提示条：「本次名额已顺延给他人 · 原因：{你已有 3 节待上课程 / 你处于限制期}。你在等待中：前面 N 人，条件解除后下次有座位释放仍会转正你。」（避免出现"显示第 1 位却始终不转正"的困惑）
4. 被跳过 ≥2 次时：提示条升级为可展开说明（列全部原因与时间）+ 消息中心同步一条（6.5.9、AC-05-11）。
5. 倒计时基于服务端返回的 `confirm_deadline` 与**服务端当前时间**计算，客户端只展示；本地时间不可信（PRD 6.0）。
6. 倒计时到 0 后：按钮禁用 → 3 秒内自动刷新状态；若服务端返回已过期，则弹轻提示"候补已过期，名额已让给下一位"，卡片变"候补未成功"（AC-06-5/06-7）。
7. 点"放弃"必须二次确认，确认弹窗文案含"本次放弃不计爽约"（AC-06-4、6.3.5）。
8. `T-15min` 队列清空：卡片变"本次未排上"，不再显示位次（AC-06-9）。
9. **加入候补成功后立即请求订阅授权**（§6.3.2 时机 2），拒绝不影响排队、位次与计时（AC-06-6）。

**埋点**：`waitlist_join`、`waitlist_quit`、`waitlist_promoted`、`waitlist_confirmed`、`waitlist_expired`、`waitlist_skipped(reason=ban/limit/duplicate)`；`subscribe_msg_result`（本节新增上报点）。

## 8. 无障碍检查（WCAG 2.1 AA 为目标）

| 项 | 要求 | 本设计的落地 |
| --- | --- | --- |
| 文字对比度 | 正文 ≥4.5:1，大字 ≥3:1 | 全部文本色已实测：主文字 15.78、次要 7.56、弱化 4.83、禁用 6.69、主色 4.64、语义色 4.86–6.45，全部达标（§4.1）。**未使用低对比度的浅灰禁用样式；"未开放/已截止"两种状态的底色与文字色相同（6.62:1），区分不依赖颜色** |
| 非文字对比度 | 图标/边框/焦点环 ≥3:1 | 焦点环 4.64:1；进度条、圆点、条状图标均 ≥3:1（用主色或语义深色，不用浅色边） |
| 不只用颜色传达信息 | — | 角标带文字 + **专属图标**（锁形=未开放、时钟斜杠=已截止、时钟=待确认、对勾=已预约/已签到）；日期有课加圆点；剩余名额带数字与文案；禁用按钮加锁形小图标；错误不只红边框，还有图标 + 文案 |
| 触控目标 | ≥44×44px | 日期项 44×56、卡片行内按钮 40 高（上下 padding 扩到 44）、铃铛/关闭/返回 44×44、chip 高 32 但间距 8 保证有效命中区 ≥44（chip 组整体可滑） |
| 键盘可达 | 功能可仅用键盘完成 | 微信小程序手机端以触屏为主，**运营端必须完整键盘可达**：Tab 顺序 = 筛选 → 列表 → 行内操作 → 分页；所有可点元素 `tabindex` 正确；焦点环 2px 主色 + 白内衬；弹窗打开时焦点进入弹窗、关闭后回到触发按钮（focus trap）；不用键盘也能完成（不要求长按/双击/手势） |
| 焦点顺序 | 与视觉顺序一致 | 课表：导航 → 筛选 → 日期 → 列表（按时间升序）→ TabBar；详情页：导航 → 内容 → 规则 → 底部操作条；弹层焦点局限在弹层内 |
| 屏幕阅读器 | 有属性可读 | 假设（验证方式：真机 + iOS VoiceOver 实测，§11 待办 10）微信小程序支持 `aria-role` / `aria-label` / `aria-disabled`：状态角标读作"状态：已满，候补 4 人"；倒计时读作"剩余确认时间 12 分 34 秒"（`aria-live="polite"`，**仅整分钟播报**，避免每秒打断）；签到码输入每格 `aria-label="第 1 位数字"`；**禁用按钮**统一 `aria-disabled="true"` + `aria-label="取消预约，当前不可用：距开课不足 2 小时"`，并在同一屏保留可见原因文案（§5.10）；若宿主不支持，降级为"可见文案 + 点击弹层" |
| 替代文字 | 图标与图片有文字替代 | 装饰图标 `aria-hidden`；功能图标必须有 `aria-label` 或可见文字；教练头像 `alt="王教练"`；空状态插画 `alt` 或 `aria-hidden` + 文字说明 |
| 字号与放大 | 支持系统字体放大 | 布局用弹性（不写死高度、允许换行、文本不截断）；最小字号 12px；系统字号放大 1.3× 后不得出现文字被裁切（列为测试用例） |
| 动效 | 可减弱、不闪烁 | 动效 150–250ms；提供"减弱动效"（≤100ms 淡入）；无 >3Hz 闪烁；不用视差/自动轮播 |
| 时间压力 | 不制造焦虑且给足时间 | 候补确认 15 分钟（PRD 固定值），倒计时在**四处**可见（消息中心、我的预约、详情/弹窗、首页横幅），且不因页面停留或未授权而中断；不弹强制倒计时打断操作 |
| 语义结构 | 标题层级正确 | 每页一个 H1；H2/H3 不跳级；列表用列表语义（运营端） |
| 语言 | — | 全站简体中文；时间/日期格式统一（§4.7） |

**已知局限（诚实说明）**：微信小程序对屏幕阅读器与键盘的支持能力受宿主限制，本设计只能保证"属性正确 + 可读性 + 对比度 + 触控区"，无法保证所有第三方读屏器行为一致；建议内测期用 iOS VoiceOver + 微信读屏各跑一遍主流程（记 1 条待办，见 §11）。
