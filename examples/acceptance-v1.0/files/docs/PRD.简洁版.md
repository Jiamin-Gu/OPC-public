# PRD：轻记 CLI 记账工具（v1）

- 版本 v1.1（2026-10-23）｜负责人：产品经理 Alex｜审查：工程师。v1.1 按 CEO 指示去掉「导出 CSV」（原 F4），需求/方案/代码/测试均不含该功能；除本条外其余口径与 v1.0 一致。
- 本 PRD 是 v1 唯一需求依据，工程按第 5 章命令行契约直接开工；技术方案见 `docs/技术方案.md`，代码在 `code/`。
- 强制口径依据：知识库公司资料《记账规范（2026 版）》（金额/日期/分类）和此前任务《确认记账工具的记账口径》结论，已比对无冲突，合并为本期统一口径。

## 1. 问题与目标

- 问题：手机 App 要注册登录、看广告、抢权限；Excel 要维护公式且易算错。想一条命令完成记账的人没有趁手工具。
- 目标：做本地 CLI 记账工具，把「记一笔 → 看当月 → 看分类」最短闭环做到一条命令完成，数据留本地，不做账号、不做网络。
- 无现网行为数据和访谈样本，以下为推断假设：单月记录量 30~200 笔；命令行用户最在意「快」和「不丢数据」。上线 30 天后用真实数据与访谈验证。
- 指标：add/summary/stats 端到端 100%；金额自动化用例 100%、代码 float 0 次；add 必需参数 ≤4 个、单条命令 <1 秒；数据为可读 JSON 单文件、可直接复制备份；上线 30 天内 ≥1 人、≥20 笔。目标值为自定基线；若 30 天无人使用，视为假设未验证，按复盘处理。

## 2. 功能范围与优先级

- P0：F1 `add` 记一笔收入或支出；F2 `summary` 按月汇总收入、支出、结余、笔数；F3 `stats` 指定月份+类型，按 8 类统计金额、笔数、占比；F5 `add --note` 备注为 P0。
- 本期不做：F4 导出 CSV，按 CEO 指示移出本期范围；编号保留不复用，本期无 `export`。
- 统一约束：仅支持人民币 CNY，不做多币种/汇率；金额以「分」为单位的整数存储和计算，禁止浮点，展示为元并保留两位小数。
- 日期用 `YYYY-MM-DD`，月份用 `YYYY-MM`。分类固定 8 类：餐饮、交通、购物、居住、娱乐、医疗、教育、其他，不允许自定义。
- 数据默认存 `./data/ledger.json`，可用 `--data PATH` 覆盖，写在子命令之后；测试必须用 `--data` 指向临时文件。只读命令在文件不存在时按 0 条记录处理，退出码 0，不自动创建文件。

## 3. 目标用户

- 有记账习惯、常用终端的个人用户（开发者、财务/运营等久坐电脑前岗位），每周记 5~20 笔，最在意一条命令记完、口径统一不错账、数据在自己机器上。

## 4. 用户故事与验收标准（按优先级）

### 故事 1（P0）记一笔收入或支出

- `add` 参数：`--type {income,expense}`、`--amount 元`、`--category 分类` 必填；`--date YYYY-MM-DD` 可选，默认今天；`--note 文本` 可选，未传时存为空字符串，不是 `null`。
- 金额禁止浮点，按字符串解析成「分」。合法如 `35`、`35.8`、`35.80`、`0.05`；整数部分 1~12 位，小数最多 2 位，上限 999999999999.99 元。非法包括空、`0`、`0.00`、负数、带 `+/-`、`¥`、千分位逗号、空格、科学计数法、小数超 2 位。
- 验收：成功退出 0，输出确认行含新记录 id、支出/收入金额且不带负号、分类、日期；`amount_cents` 为整数分，如 35.80 → 3580。已有 3 条再记收入，新记录 id 从 1 起严格自增不重复，即 id=4，原记录不改。
- 验收：备注保存原文，未传存空字符串，summary/stats 不受备注影响。未传日期用本机当天并回显。非法分类/空分类、非法日期（如 2026-02-30、2026-2-3、2026/10/23）退出 2 且不写入；2024-02-29 闰年合法。非法金额退出 2 不写入。
- 金额精度：`0.10` 与 `0.20` 各记一笔支出，summary 支出合计应为 `0.30`，不得出现 `0.30000000000000004`。

### 故事 2（P0）按月汇总

- `summary` 参数：`--month YYYY-MM` 必填。输出不使用千分位，含月份汇总（人民币 CNY）、收入笔数与合计、支出笔数与合计、结余（收入减支出，可为负）。
- 验收：只统计该月记录；文件不存在时输出收入 0 笔 0.00 元、支出 0 笔 0.00 元、结余 0.00 元，退出 0，不创建文件；只有支出时收入显示 0，结余为负并带 `-` 号。
- 非法月份（如 2026-13、2026-1、202610、空）报错「月份格式应为 YYYY-MM」，退出 2；该月无记录但其他月份有记录，按空数据显示全 0，退出 0，不报「无数据」错误。

### 故事 3（P0）按分类统计

- `stats` 参数：`--month YYYY-MM` 必填，`--type {expense,income}` 可选，默认 `expense`。按金额降序，金额相同按固定 8 类顺序；仅列有记录分类，占比保留 1 位小数四舍五入，末行合计。
- 占比 = 分类金额 ÷ 合计金额，四舍五入，不做补差；各分类占比之和可能不等于合计行显示的 100.0%，合计行固定 100.0%，金额以合计行为准。
- 验收：只统计该月该类型；该月无该类型记录时输出「该月没有支出记录」，退出 0，不输出表格、不报错；并列金额按固定 8 类顺序排列；非法月份或 `--type transfer` 退出 2。
- 示例期望：合计 3456.78 元，餐饮 1200.00=34.7%、交通 900.00=26.0%、购物 1356.78=39.2%，三者之和 99.9% 与合计 100.0% 不等，属允许差异。金额恒为正整数分，无记录分支外不除零。

## 5. 命令行契约与调用示例

- 运行：在 `code/` 目录执行 `python cli.py <子命令> [参数]`；`--data PATH` 为公共参数，写在子命令之后。
- 成功示例：`add --type expense --amount 35.80 --category 餐饮` 默认今天；`add --type income --amount 1200 --category 其他 --date 2026-10-01 --note "项目款"`；`summary --month 2026-10`；`stats --month 2026-10 --type expense`。
- 异常示例：金额 `1.005`、分类 `旅行`、日期 `2026-02-30`、月份 `2026-13` 均报错且不写入数据。
- 退出码：`0` 成功（含空数据）；`2` 参数或校验错误（非法分类、非法日期、非法月份、金额格式错误、类型非法）；`3` 文件/IO 错误；`1` 未预期错误。
- 输出格式与完整示例详见完整版。

## 6. 方案概述

- 核心流程：`add` 把一笔记录写入本地数据文件，`summary`/`stats` 读该文件做按月汇总与分类统计；三个子命令共用同一记录模型与同一套校验函数。
- 记录模型 JSON 含 `version` 字段用于将来升级，records 含 id、type、amount_cents、category、date、note、created_at。金额只以 `amount_cents` 整数分存在，元金额仅在输出时由整数运算换算，全程不出现浮点。
- 关键决策：用参数式 argparse 而非问答式交互，便于脚本化与测试；用本地 JSON 单文件而非 SQLite，便于人工查看与备份，但高并发与大数据量不适用；只读命令不自动建文件，避免查询副作用；展示不带千分位，便于精确断言和复制，可读性略差。

## 7. 风险与待解决问题

- 风险：误用浮点导致金额误差（可能性中、影响高）。应对：字段命名 `amount_cents`；代码审查禁止 float；测试断言类型为 `int`，且 `0.10+0.20=0.30`。
- 风险：默认日期依赖本机时区/时钟（中/低），文档写明本地日期并输出回显；数据文件被手工改坏或写入中断（中/中），写入采用临时文件+原子替换，解析失败明确报错并保留原文件。
- 风险：多进程同时写入（低/中），v1 声明单用户单进程，不实现锁；记录增长后 JSON 全量读写变慢（低/中），万条以内可接受，超出后评估迁移 SQLite；`--data` 用错路径污染真实数据（中/低），README 与测试用临时目录，`add` 首次写入前回显路径。
- 待确认：数据文件默认路径定为 `./data/ledger.json`（相对当前工作目录）是否可行，需要工程师确认；前提是 `--data` 可覆盖。
- 待确认：`add --note` 是否保留 P0。原 P0 理由随 F4 移出失效，现依据是「备注是记账常见诉求、实现成本极低且不依赖其他功能」；若 CEO 认为没有导出需求就不必保留，可降为 P1；`note` 暂定不限制长度，需 CEO 决定。
- 待确认：退出码约定 `0/2/3/1` 是否被工程与测试采纳，需要工程师确认，PRD 与测试用例须一致。

## 8. 不做的范围

- 导出 CSV：本期不做。原 F4 内容整体移除；将来若恢复，需重新确认列定义、编码和筛选参数。本期备份数据直接复制 `data/ledger.json`。
- 删除记录：本期不做，不提供 `delete`。将来若实现删除，必须二次确认：先展示待删记录摘要，要求用户输入确认（如 `y`/`--yes`）后才执行；未确认退出码 0 且数据不变。
- 不做多币种/汇率、自定义分类、图形界面/Web、云同步/账号/多用户/联网、编辑修改已有记录、预算与超支提醒、图表可视化、定期/自动记账、银行账单导入、数据库 SQLite 和多设备并发写入锁。

## 9. 上线与度量

- v1 是本地 CLI，无服务端，交付即上线：工程师在 `code/` 实现并按第 5 章自测，测试同学独立编写用例并运行出报告，PRD 验收标准为主要来源。
- 回滚：以代码版本 tag 回退；升级前手工备份 `cp data/ledger.json data/ledger.json.bak`。
- 出现 `add` 写入后金额与输入不一致、`summary`/`stats` 合计与明细不符、数据文件解析报错且原文件被改写，按「回滚 + 修」处理。
- 上线后 30 天对照第 1 章指标复盘真实记录数与用户数，并把「假设未被验证」的结论写回发现清单。
