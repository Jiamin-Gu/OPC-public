# 技术方案：轻记 CLI 记账工具（v1）

- v1.1 修订：行序统一金额降序；路径规范化；适应度检查正则不误伤 `//100`；`add` stdout 只有确认行，路径提示走 stderr。
- 强制口径依据：《记账规范（2026 版）》一金额、二日期、三分类，以及《确认记账工具的记账口径》，已比对无冲突；冲突时以口径为准。
- PRD 第 7 章待解决问题确认：默认路径 `./data/ledger.json` 沿用；退出码 `0/2/3/1` 采纳；`add --note` 为 P0 确认（见 ADR-5）。

## 1. 需求映射
- F1 记一笔收入或支出（P0）：`add`，经 `money.py`、`validators.py`、`store.py`；先全量校验、后写入，校验失败不触碰数据文件。
- F2 按月汇总（P0）：`summary`，按月汇总收入/支出/结余笔数与合计，按 `YYYY-MM` 过滤。
- F3 按分类统计（P0）：`stats`，按 8 类聚合金额/笔数/占比，金额降序，并列按固定类序。
- F4 导出 CSV：本期不做，编号保留不复用，见 ADR-6。
- F5 `add --note`（P0）：`note` 字段未传存 `""`；依据为备注是常见诉求且成本极低，与导出无关。
- 统一约束与范围外：金额以分整数存储、禁止浮点；日期 `YYYY-MM-DD`/月份 `YYYY-MM`；仅人民币、固定 8 类；退出码 `0/2/3/1`；只读命令无副作用。不实现 `delete`/`edit`、不多币种、不做仪表盘与网络请求、不引入数据库。

## 2. 架构与技术选型

### 2.1 架构与模块划分
- v1 为单进程、无网络、单用户本地 CLI，采用分层小模块 + 单一入口；三个子命令共用同一记录模型与同一套校验函数。
- 模块：`cli.py` 入口；`ledger/money.py` 金额；`validators.py` 校验；`model.py` 数据结构与不变量；`store.py` JSON 读/原子写/损坏处理；`reports.py` 汇总统计渲染；`tests/`。
- 依赖方向单向：`cli.py → reports.py/store.py → money.py/validators.py/model.py`；域层不得 `import json/os/argparse`，基础设施细节不得泄漏到输出文本。
- 硬规则：域层引用 `cli` 即拒绝，纳入 M1 评审。

### 2.2 技术选型
- Python 3.9+、仅标准库；CLI 用 `argparse` 子命令；数据持久化用本地 JSON 单文件 `./data/ledger.json`。
- 金额用 `int`，单位分（`amount_cents`）；日期用字符串 + `datetime.strptime` 校验；测试建议 `unittest`，用 `--data` 隔离。
- 放弃项：SQLite/CSV 作主存储、`float`/`Decimal`、click/rich、问答式交互等；理由详见完整版。

### 2.3 如何满足「金额以分为单位的整数存储与计算、禁止浮点」
- 唯一金额表示是 `amount_cents: int`，全链路整数加减；元→分按字符串正则解析，拒绝 `0`、空、负数、`+`/`-`、`¥`、千分位逗号、空格、科学计数法、超过 2 位小数、整数部分超过 12 位。
- 分→元只在输出瞬间做整除与取余：`f"{cents//100}.{cents%100:02d}"`；负结余加 `-`，避免 `-0.00`。
- 占比是唯一涉及除法的场景，改用整数半进位，全程无浮点。
- CI/人工适应度检查：`float(` 或 `float` 类型注解必须零命中；金额真除以 `100` 的写法必须零命中；`//100` 整除合法且不误伤；命中阻塞合并。
- 测试硬断言：`isinstance(rec.amount_cents, int)`；`0.10 + 0.20` 两笔支出后 summary 合计显示 `0.30`。

### 2.4 容量与性能估算（估算，非实测）
- 按 10 年 × 2400 笔估算约 2.4 万条、文件约 3.6 MB；全量读写为几十毫秒，满足单条命令 < 1 秒。
- `add` 每次全量重写，是 O(n) 操作。
- 结论需在 M3 用 1 万条实测确认；若超 1 秒或文件超约 10 MB，按 ADR-1 将 `store` 换 SQLite，上层不动。

## 3. 数据模型

### 3.1 文件结构（`./data/ledger.json`，UTF-8 无 BOM，2 空格缩进）
- 顶层为 `{"version": 1, "records": [...]}`；记录包含 `id`、`type`、`amount_cents`、`category`、`date`、`note`、`created_at`。示例详见完整版。
- 写入时按 `id` 升序追加；读取时记录顺序不参与任何计算。

### 3.2 字段定义
- `version`：固定 `1`；读取到未知版本报错退出码 3，不尝试修复。
- `id`：从 1 起严格自增、不重复，写入时 `max(已有 id)+1`；全局唯一，不因月份/类型区分。
- `type`：只允许 `income`/`expense`，内部存英文枚举值，中文只在输出时渲染。
- `amount_cents`：金额，单位分，恒为正整数 `>=1`；上限 `99999999999999`（= 999999999999.99 元）；禁止字符串、禁止小数。
- `category`：固定 8 类之一：餐饮、交通、购物、居住、娱乐、医疗、教育、其他；收入与支出共用。
- `date`：`YYYY-MM-DD`，必须补零且真实存在；`note` 未传为 `""` 不是 `null`，不参与统计筛选；`created_at` 为 ISO 8601 本地时间，仅排查问题。

### 3.3 不变量与状态流转
- 不变量：`amount_cents > 0`；`type ∈ {income, expense}`；`category ∈ CATEGORIES`；`date` 严格合法；`note` 为 `str`；`id` 唯一正整数。
- 只能新增 append-only；v1 无 `edit`/`delete`，写错再记反向记录；仅「文件不存在 → 首次 `add` 创建」一条迁移。
- 读取逐条校验；任一条不合格或 `version` 未知 → 输出「错误：数据文件格式不正确（<路径>）：<原因>」，退出码 3，绝不改写原文件。
- 内存模型：`@dataclass Record(...)` + `Ledger(version, records)`；序列化格式变更只改 `store.py`。

## 4. 命令行接口设计

### 4.1 公共约定
- 在 `code/` 下 `python cli.py <子命令> [参数]`；`--data PATH` 写在子命令之后，默认 `./data/ledger.json`；测试必须用 `--data` 指向临时文件。
- 错误一律 stderr、单行、以「错误：」开头；所有错误信息在写入之前产生，校验失败数据文件内容不变。
- 退出码：`0` 成功（含空数据）；`2` 参数或校验错误；`3` 文件或 IO 错误（数据文件损坏、版本未知、目录不可写）；`1` 未预期错误。
- `summary`/`stats` 在数据文件不存在时按 0 条记录处理，退出码 0，且不创建数据文件。

### 4.2 内部模块接口（供工程与测试导入）
- `money.py`：`parse_amount_to_cents(text) -> int`、`format_cents(cents) -> str`；如 `3580 -> "35.80"`，负值如 `"-2256.78"`。
- `validators.py`：`validate_date`、`validate_month`、`validate_category`、`validate_type`，非法抛 `ValidationError`。
- `model.py`：`CATEGORIES` 8 类；`TYPE_LABEL`。
- `store.py`：`load(path, missing_ok=True)`、`append_record(path, record)`。
- `reports.py`：`monthly_summary`、`category_stats`、`render_summary`、`render_stats_table`。

### 4.3 `add` — 记一笔（F1、F5）
- 参数：`--type {income,expense}`、`--amount 元`、`--category 分类` 必填；`--date` 默认本机今天；`--note` 默认 `""`；`--data` 默认 `./data/ledger.json`。
- `--data` 路径创建：取 `os.path.dirname(os.path.abspath(PATH))` 规范化目录，再 `makedirs(..., exist_ok=True)`；不得直接用 `os.path.dirname(PATH)`。
- 输出契约：成功时 stdout 只有一行确认行，含新 id、「支出/收入 X.XX 元」、分类、实际写入日期；有备注时行尾以全角括号回显。
- 若本次新建数据文件，额外向 stderr 打 `（已新建数据文件：<规范化后绝对路径>）`；该行不是 stdout 契约，成功用例只断言 stdout 与退出码，不断言 stderr 为空。
- 非法金额/分类/日期返回退出码 2，数据不变；示例详见完整版。

### 4.4 `summary` — 按月汇总（F2）
- 参数：`--month YYYY-MM` 必填；`--data PATH` 可选。输出不使用千分位分隔符。
- 输出四行：月份汇总标题、收入笔数与金额、支出笔数与金额、结余；结余=收入合计−支出合计，按分做整数减法，可为负。
- 该月无记录或数据文件不存在：收入/支出/结余三行全 0，退出码 0，不创建文件、不报「无数据」错误。
- 月份格式非法（如 `2026-13`、`2026-1`）→ `错误：月份格式应为 YYYY-MM（如 2026-10）`，退出码 2。

### 4.5 `stats` — 分类统计（F3）
- 参数：`--month YYYY-MM` 必填；`--type {expense,income}` 可选，默认 `expense`；`--data` 可选。
- 只统计该月该类型；按金额降序，金额并列按固定 8 类顺序；只列有记录的分类；占比保留 1 位小数，四舍五入不做补差；合计行占比恒 `100.0%`。
- 「金额降序」是硬契约；PRD 故事 3 示例行序餐饮→交通→购物与此冲突，本方案以规则为准，正确行序为购物、餐饮、交通；请 PM 同步修正 PRD。
- 示例：2026-10 支出 3456.78 元/12 笔：购物 3 笔 1356.78 39.2%，餐饮 5 笔 1200.00 34.7%，交通 4 笔 900.00 26.0%，合计 12 笔 3456.78 100.0%。
- 该月无该类型记录：只输出「该月没有支出记录」/「该月没有收入记录」，退出码 0，不输出表格。
- 表格空白口径：列宽为分类 6 左对齐、笔数 6 右对齐、金额 10 右对齐、占比 8 右对齐，列间 1 个半角空格；数值、列名、列顺序、行顺序是硬契约，列宽是排版细节；测试对空白弹性匹配。

### 4.6 `export` — 本期不做（原 F4）
- 不提供 `export` 子命令，也不实现 CSV 生成；参数与列定义本期不定义。
- 用户自查或备份数据时直接复制 `data/ledger.json`。
- 将来恢复需重新确认列序、`utf-8-sig` 编码、RFC 4180 转义，并补 Excel/WPS 中文乱码验收，见 ADR-6。

## 5. 关键难点与风险

**5.1 难点：金额的整数化与「禁止浮点」**
- 解析不用 `float(text)`，换算只用 `//` 与 `%`；`// 100` 整除是唯一允许的除法写法，禁止 `/ 100`、`float(`、`round(x, 2)`。

**5.2 难点：分 → 元的显示**
- 只用 `format_cents(cents) = f"{cents//100}.{cents%100:02d}"`；`add` 确认行、`summary` 三行、`stats` 金额列共用此函数。

**5.3 难点：按月过滤（`YYYY-MM`）**
- 用字符串前缀比较 `rec.date[:7] == month`，不解析成 `datetime`；汇总与分类统计基于同一筛选集，`stats` 的月份/类型筛选与汇总在同一遍循环完成。

**5.4 难点：`add` 的输出契约（stdout 与 stderr 分离）**
- 成功时 stdout 只有一行确认行；环境提示/路径提示走 stderr；任何提示/警告都不许写 stdout。写入用同目录临时文件 + `os.replace` 原子替换。

**5.5 难点：无数据 / 空结果场景（`summary` 与 `stats` 行为不同）**
- `summary` 无文件或该月无记录均输出全 0，退出码 0，不创建文件；`stats` 无该类型记录只输出提示，退出码 0，不输出表格。
- 数据文件损坏、版本未知、字段类型错误：退出码 3，不改写原文件。除零恒不发生。

**5.6 难点：占比的四舍五入与「合计 100.0%」**
- 四舍五入到 0.1% 用整数半进位：`tenths = (cents * 2000 + total) // (2 * total)`，输出 `f"{tenths//10}.{tenths%10}%"`。
- 例：购物 39.2%、餐饮 34.7%、交通 26.0%（各分类之和 99.9%）；不做补差，合计行固定打印 `100.0%`。

**5.7 难点：`id` 生成与并发写入**
- `id = max(已有 id) + 1`，不用 `len(records)+1`；写入用读→追加→临时文件→`os.replace`，保证不出现半截 JSON。
- 多进程并发写入 v1 不加锁，声明为单用户单进程；首次新建数据文件时向 stderr 提示路径，降低 `--data` 写错风险。

**5.8 风险清单**
- 误用浮点导致金额误差（高）：整数规则 + `grep` 卡口 + 测试断言。
- 数据文件被手工改坏或写入中断（中）：读取全量校验退出码 3，写入临时文件 + 原子替换。
- 记录增长后 JSON 全量读写变慢（中）：M3 用 1 万条实测，超阈值按 ADR-1 换 SQLite。
- `--data` 用错路径污染真实数据（低）：`add` 首次建文件时 stderr 提示实际路径；README 与测试统一用临时目录。
- 域层被基础设施污染/循环依赖（中）：依赖方向硬规则纳入 M1 评审。

## 7. 决策记录

### ADR-1：数据持久化用本地 JSON 单文件，而不是 SQLite
- 决策：JSON 单文件 `./data/ledger.json`，`store.py` 实现读整份→追加→原子替换写。
- 影响：放弃并发写与高效增量更新，换来可人工查看/备份/恢复、零依赖、出错可自救；迁移路径为接口不变、内部换 SQLite，上层不动。

### ADR-2：命令行用 argparse 子命令，不用问答式交互
- 决策：`argparse` + `add`/`summary`/`stats`，参数式调用。
- 影响：用户需记住参数名，靠 `--help` 与示例兜底；换来零依赖、退出码与错误信息可控、测试可用 `subprocess` 稳定断言。

### ADR-3：金额用 int 分，不用 Decimal
- 决策：唯一金额表示 `amount_cents: int`；元→分走字符串正则，分→元走 `//`/`%`，占比走整数半进位。
- 影响：金额代码必须走 `money.py`，不能写 `amount/100`；换来 `0.10+0.20=0.30` 这类错账从根上不可能发生。

### ADR-4：只读命令不自动创建数据文件
- 决策：`store.load(missing_ok=True)` 返回空账本；只有 `add` 首次写入时 `makedirs` 并创建文件。
- 影响：`add` 承担首次创建职责，错误分支更多（目录不可写退出码 3）；换来查询无副作用、不误建空账本。

### ADR-5：确认 PRD 的三项待确认（数据路径、退出码、`--note` 归属）
- 决策：默认路径 `./data/ledger.json` 采纳，前提是 `--data` 可覆盖；退出码 `0/2/3/1` 采纳，数据文件损坏/版本未知归 `3`；`add --note` 为 P0 确认。
- 影响：不同工作目录会看到不同账本，README 需写清楚，`add` 新建文件时向 stderr 提示实际路径。

### ADR-6：本期不做导出 CSV（原 F4）
- 决策：删除 `export` 子命令、`exporter.py` 模块与全部 CSV 相关验收；备份改为复制 `data/ledger.json`。
- 影响：失去一行命令交 Excel 透视的能力，换来更小实现与验收面；恢复需 CEO 立项并重新确认列序、`utf-8-sig`、RFC 4180 转义、排序口径。
