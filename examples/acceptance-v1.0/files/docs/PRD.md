# PRD：轻记 CLI 记账工具（v1）

- 版本：v1.1（2026-10-23）｜负责人：产品经理 Alex｜审查：工程师
- v1.1 修订（CEO 指示）：本期去掉「导出 CSV」（原 F4），需求/方案/代码/测试均不含该功能；除本条外其余口径与 v1.0 一致。
- 交付物：本 PRD 是 v1 的唯一需求依据，工程按第 5 章命令行契约直接开工；技术方案见 `docs/技术方案.md`，代码在 `code/`。
- 强制口径依据：知识库公司资料《记账规范（2026 版）》（一、金额／二、日期／三、分类）和此前任务《确认记账工具的记账口径》结论（已比对，无冲突，合并为本期统一口径）。

## 1. 问题与目标

**问题**：个人用户想记账时，手机 App 需要注册登录、看广告、抢权限；Excel 记账要自己维护公式，且很容易把金额算错（浮点误差、分类不统一、月份靠手工汇总）。想只用一条命令把事情做完的人，目前没有趁手的工具。

**目标**：做一个本地命令行记账工具，把「记一笔 → 看当月 → 看分类」这条最短闭环做到一条命令完成，数据留在本地，不做账号、不做网络。

**依据**：无现网行为数据与用户访谈样本，以下为推断假设：
- 假设：目标用户单月记录量在 30~200 笔量级（验证方式：v1 上线 30 天后统计真实数据文件的记录数分布）。
- 假设：命令行用户最在意「快」和「不丢数据」，其次才是统计维度丰富（验证方式：上线后访谈 3~5 名真实用户）。

### 目标与衡量指标

| 目标 | 指标 | 目标值 | 观察时间 |
| --- | --- | --- | --- |
| 三个 P0 功能可用 | 3 条子命令（add/summary/stats）端到端跑通 | 100% | 交付验收时 |
| 金额不出错 | 涉及金额的自动化用例通过率；代码中 float 出现次数 | 100%；0 次 | 交付验收时 |
| 记账足够快 | 记一笔的必需参数个数；单条命令耗时 | ≤ 4 个；< 1 秒 | 交付验收时 |
| 数据可自查备份 | 数据文件为可读 JSON 单文件，用户可直接复制备份（本期无导出） | 100% | 交付验收时 |
| 真实使用 | 数据文件中出现记录的用户数 / 记录总数 | 上线 30 天内 ≥ 1 人、≥ 20 笔 | 上线后 30 天 |

说明：目标值为我方自定基线（无现网数据支撑），不是用户调研结论。若 v1 上线 30 天无人使用，视为「假设未被验证」，按第 7 章复盘。

## 2. 功能范围与优先级

| 编号 | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| F1 | 记一笔收入或支出（`add`） | P0 | 写入一条记录，含类型、金额、分类、日期 |
| F2 | 按月汇总（`summary`） | P0 | 按 `YYYY-MM` 汇总收入、支出、结余与笔数 |
| F3 | 按分类统计（`stats`） | P0 | 指定月份 + 类型，按 8 类统计金额、笔数、占比 |
| F4 | 导出 CSV（`export`） | 本期不做 | v1.1 按 CEO 指示移出本期范围（见第 8 章）；编号保留不复用 |
| F5 | 记一笔带备注（`add --note`，F1 的可选参数） | P0 | 未传时 `note` 为空字符串；备注是记账的常见诉求、实现成本极低且不依赖其他功能，故保留 P0（原 P0 理由「F4 的 CSV `note` 列依赖它」随 F4 移出失效，见第 7 章） |

统一约束（本期所有功能都必须满足）：
- **币种只支持人民币（CNY）**，不做多币种、不做汇率换算；输入与展示都以「元」为单位。
- **金额一律以「分」为单位的整数存储和计算**，禁止浮点数；展示时换算成元并保留两位小数。
- 日期一律 `YYYY-MM-DD`（如 `2026-10-23`，必须补零），月份用 `YYYY-MM`（如 `2026-10`）。
- 分类固定 8 类，不允许自定义：餐饮、交通、购物、居住、娱乐、医疗、教育、其他。
- 数据默认存本地 JSON 文件 `./data/ledger.json`，可用 `--data PATH` 覆盖（写在子命令之后，与子命令参数同级，如 `add ... --data /tmp/t.json`）；测试务必用 `--data` 指向临时文件，避免污染真实数据。
- 只读命令（`summary`/`stats`）在数据文件不存在时按 0 条记录处理，退出码 0，且不自动创建文件。

## 3. 目标用户

主要用户：有记账习惯、常用终端的个人用户（开发者、财务/运营等久坐电脑前的岗位），每周记 5~20 笔，最在意「一条命令记完、口径统一不错账、数据在自己机器上」。

## 4. 用户故事与验收标准（按优先级）

### 故事 1（P0）记一笔收入或支出

作为记账的用户，我想要用一条命令记录一笔收入或支出（金额、分类、日期，可选的备注），以便账目即时落盘、不用打开表格手工填。

`add` 参数契约：`--type {income,expense}`（必填）、`--amount 元`（必填，正数字符串）、`--category 分类`（必填）、`--date YYYY-MM-DD`（可选，默认今天）、`--note 文本`（可选，P0，见 F5；未传时存为空字符串，不是 `null`）。

金额解析规则（禁止浮点，按字符串解析成「分」）：
- 合法：`35`、`35.8`、`35.80`、`0.05`；整数部分 1~12 位，小数最多 2 位；上限 999999999999.99 元。
- 非法：空、`0`、`0.00`、负数、带 `+/-` 符号、带 `¥`、带千分位逗号、带空格、科学计数法、小数超 2 位（如 `1.005`）。

#### 验收标准
- Given 空数据文件，When 执行 `add --type expense --amount 35.80 --category 餐饮 --date 2026-10-23`，Then 退出码 0，输出确认行（含新记录 id、`支出 35.80 元`、分类、日期，金额不带负号），数据文件中该记录 `amount_cents` 为整数 `3580`。
- Given 传入 `--note "午餐,外带"`，When 执行 add，Then 记录的 `note` 字段保存该原文，输出回显备注；Given 未传 `--note`，When 执行 add，Then `note` 存为空字符串（不是 `null`），summary/stats 的输出不受备注影响。
- Given 已有 3 条记录，When 再记一笔收入 1200 元，Then 新记录 id 从 1 起严格自增且不重复（即 id=4），原有记录不被改写。
- Given 分类 `旅行`（不在 8 类内）或分类为空，When 执行 add，Then 报错并列出合法 8 类，退出码 2，数据文件内容不变。
- Given 日期 `2026-02-30`、`2026-2-3`、`2026/10/23`，When 执行 add，Then 分别报错「日期格式或日期不存在」，退出码 2，不写入。边界合法例：`2024-02-29`（闰年）必须接受。
- Given 金额 `1.005`、`0`、`-5`、`abc`、`1,200`，When 执行 add，Then 报错「金额必须是正数（单位：元），最多两位小数」，退出码 2，不写入。
- Given 未传 `--date`，When 执行 add，Then 使用本机当天日期（本地时区），并在输出中显示实际写入的日期。
- Given `--amount 0.10` 与 `--amount 0.20` 各记一笔支出，When 执行 summary，Then 支出合计显示 `0.30` 元（不得出现 `0.30000000000000004`）。

### 故事 2（P0）按月汇总

作为记账的用户，我想要按月查看收入合计、支出合计和结余，以便知道这个月到底花了多少、剩多少。

`summary` 参数契约：`--month YYYY-MM`（必填）。

输出格式（不使用千分位分隔符，便于断言与复制）：
```
2026-10 汇总（人民币 CNY）
收入：3 笔   1200.00 元
支出：12 笔  3456.78 元
结余：-2256.78 元
```

#### 验收标准
- Given 数据文件中有 2026-10 的 3 笔收入与 12 笔支出，When 执行 `summary --month 2026-10`，Then 收入笔数与合计、支出笔数与合计、结余（收入减支出，可为负）均正确，且只统计该月记录（其他月份记录不计入）。
- Given 数据文件不存在，When 执行 `summary --month 2026-10`，Then 输出 `收入：0 笔 0.00 元`、`支出：0 笔 0.00 元`、`结余：0.00 元`，退出码 0，不创建文件。
- Given 该月只有支出无收入，When 执行 summary，Then 收入显示 `0 笔 0.00 元`，结余为负值并带 `-` 号。
- Given 月份为 `2026-13`、`2026-1`、`202610`、空值，When 执行 summary，Then 报错「月份格式应为 YYYY-MM」，退出码 2。
- Given 该月无记录但文件里有其他月份记录，When 执行 summary，Then 按空数据显示全 0，退出码 0（不报「无数据」错误）。

### 故事 3（P0）按分类统计

作为记账的用户，我想要看某个月某类型下各分类的金额与占比，以便定位钱主要花在哪。

`stats` 参数契约：`--month YYYY-MM`（必填）、`--type {expense,income}`（可选，默认 `expense`）。

输出格式：按金额降序，金额相同时按固定 8 类顺序；仅列出有记录的分类，占比保留 1 位小数（四舍五入），末行给合计。
```
2026-10 支出分类统计（共 3456.78 元 / 12 笔）
分类   笔数  金额(元)  占比
餐饮      5  1200.00   34.7%
交通      4   900.00   26.0%
购物      3  1356.78   39.2%
合计     12  3456.78  100.0%
```
注明：占比 = 该分类金额 ÷ 合计金额，保留 1 位小数（**四舍五入，不做任何凑数的补差**）；各分类占比之和可能不等于合计行显示的 100.0%（本例 34.7% + 26.0% + 39.2% = 99.9%），合计行固定显示 100.0%，金额以合计行为准。

#### 验收标准
- Given 2026-10 有 12 笔支出跨 3 个分类，When 执行 `stats --month 2026-10`，Then 每个分类的笔数、金额等于明细求和，且只统计该月该类型的记录（收入不计入支出统计）。
- Given 同一月既有收入又有支出，When 执行 `stats --month 2026-10 --type income`，Then 只统计收入一侧，结果与支出统计互换可验证。
- Given 该月无该类型记录，When 执行 stats，Then 输出「该月没有支出记录」提示，退出码 0，不输出表格、不报错。
- Given 分类金额存在并列（两分类同为 500.00 元），When 执行 stats，Then 顺序按固定 8 类顺序排列，输出可重复。
- Given 月份格式非法（`2026-13`）或 `--type` 传 `transfer`，When 执行 stats，Then 报错并提示合法取值，退出码 2。
- Given 该月支出合计 3456.78 元，明细为餐饮 1200.00、交通 900.00、购物 1356.78，When 执行 stats，Then 占比依次为 34.7%、26.0%、39.2%（1200.00÷3456.78=34.7063%、900.00÷3456.78=26.0357%、1356.78÷3456.78=39.2498%，各保留 1 位小数四舍五入，不做补差），三者之和 99.9% 与合计行的 100.0% 不等——此为允许的正常差异，测试按上述期望值直接断言。
- Given 该月该类型有记录，When 执行 stats，Then 不出现除零错误（金额恒为正整数分，分母为 0 只可能出现在「无记录」分支，按上一条处理）。

## 5. 命令行契约与调用示例

运行方式：在 `code/` 目录下执行 `python cli.py <子命令> [参数]`；`--data PATH` 为公共参数，写在子命令之后（例：`add ... --data /tmp/t.json`）。

```bash
# F1 新增一笔支出（默认今天）
$ python cli.py add --type expense --amount 35.80 --category 餐饮
已记录 #1：支出 35.80 元 餐饮 2026-10-23

# F1 指定日期 + 备注
$ python cli.py add --type income --amount 1200 --category 其他 --date 2026-10-01 --note "项目款"
已记录 #2：收入 1200.00 元 其他 2026-10-01（项目款）

# F2 按月汇总
$ python cli.py summary --month 2026-10
2026-10 汇总（人民币 CNY）
收入：1 笔   1200.00 元
支出：1 笔   35.80 元
结余：1164.20 元

# F3 按分类统计
$ python cli.py stats --month 2026-10 --type expense
2026-10 支出分类统计（共 35.80 元 / 1 笔）
分类   笔数  金额(元)  占比
餐饮      1    35.80  100.0%
合计      1    35.80  100.0%
```

异常示例（均不写入数据）：
```bash
$ python cli.py add --type expense --amount 1.005 --category 餐饮
错误：金额必须是正数（单位：元），最多两位小数，例如 35.80

$ python cli.py add --type expense --amount 10 --category 旅行
错误：分类必须是以下 8 类之一：餐饮、交通、购物、居住、娱乐、医疗、教育、其他

$ python cli.py add --type expense --amount 10 --category 餐饮 --date 2026-02-30
错误：日期不存在或格式应为 YYYY-MM-DD（如 2026-10-23）

$ python cli.py summary --month 2026-13
错误：月份格式应为 YYYY-MM（如 2026-10）
```

退出码约定（工程与测试统一使用）：`0` 成功（含空数据）；`2` 参数或校验错误（非法分类、非法日期、非法月份、金额格式错误、类型非法）；`3` 文件/IO 错误；`1` 未预期错误。

## 6. 方案概述

核心流程只有一条：`add` 把一笔记录写入本地数据文件 → `summary`/`stats` 读该文件做按月汇总与分类统计。三个子命令共用同一份记录模型与同一套校验函数，避免「有的入口校验、有的不校验」这类错账来源。

记录模型（JSON，`version` 字段用于将来升级）：`{"version":1,"records":[{"id":1,"type":"expense","amount_cents":3580,"category":"餐饮","date":"2026-10-23","note":"午餐","created_at":"2026-10-23T12:30:00"}]}`。金额字段只以 `amount_cents` 整数分存在，元金额只在输出瞬间由整数运算换算（分除 100 取整、余数补零），全程不出现浮点。

关键决策：
- 选择「参数式命令（argparse）」而不是「问答式交互」，因为命令行用户要的是可脚本化、可测试（测试可断言退出码与输出），代价是首次使用需要记住参数——用 `--help` 与本文示例兜住。
- 选择「本地 JSON 单文件」而不是 SQLite，因为 v1 数据量小、要能人工查看与备份，代价是高并发写入与大数据量不适用（见第 7 章风险）。
- 选择「只读命令不自动建文件」而不是「总是初始化文件」，因为查询不该产生副作用，代价是 `add` 需要负责首次创建目录与文件。
- 选择「展示不带千分位」而不是格式化美化，因为输出可被测试精确断言、便于复制到其他工具，代价是可读性略差。

## 7. 风险与待解决问题

| 风险 | 可能性 | 影响 | 应对 |
| --- | --- | --- | --- |
| 误用浮点导致金额误差 | 中 | 高（错账，动摇信任） | 金额字段命名 `amount_cents`；代码审查禁止 float；测试断言类型为 `int` 且 `0.10+0.20=0.30` |
| 默认日期依赖本机时区/时钟 | 中 | 低 | 文档写明使用本地日期；输出中回显实际写入日期 |
| 数据文件被手工改坏或写入中断 | 中 | 中（丢数据） | 写入采用「临时文件 + 原子替换」；解析失败时明确报错并保留原文件 |
| 多进程同时写入 | 低 | 中 | v1 声明为单用户单进程；不实现锁（列入不做范围） |
| 记录增长后 JSON 全量读写变慢 | 低 | 中 | 万条以内可接受；超出后评估迁移 SQLite（本期不做） |
| `--data` 用错路径导致测试污染真实数据 | 中 | 低 | README 与测试用临时目录；`add` 首次写入前回显数据文件路径 |

待解决问题：
- 数据文件默认路径定为 `./data/ledger.json`（相对当前工作目录）是否可行——需要工程师确认（若不合适，按技术方案调整，前提是 `--data` 可覆盖）。
- `add --note` 的归属：保留 P0（见第 2 章 F5）。原 P0 理由「F4 的 CSV `note` 列与转义验收依赖它」随 F4 移出本期而失效，现依据是「备注是记账的常见诉求、实现成本极低且不依赖其他功能」；若 CEO 认为没有导出需求就不必保留备注，可降为 P1——需要 CEO 决定。另 `note` 是否有长度上限（暂定不限制，超长由用户自负）——需要 CEO 决定。
- 退出码约定 `0/2/3/1` 是否被工程与测试采纳——需要工程师确认，PRD 与测试用例须一致。

## 8. 不做的范围

- **导出 CSV：本期不做**（CEO 指示：这一版先不做导出 CSV，需求、方案、代码、测试均不含该功能）。原 F4 内容已整体从本 PRD 移除；将来若恢复，需重新确认列定义、编码（Excel/WPS 中文乱码）与筛选参数，本 PRD 不再为其保留验收标准。本期需要备份数据时，用户直接复制 `data/ledger.json` 即可。
- **删除记录：本期不做**（CEO 指令未包含删除功能），代码与命令都不提供 `delete`。将来若实现删除，**必须二次确认**——先展示待删记录摘要，要求用户输入确认（如 `y`/`--yes`）后才真正执行删除，避免误删；未确认时退出码 0 且数据不变。
- 不做多币种、不做汇率换算（只支持人民币 CNY）。
- 不做自定义分类（固定 8 类）。
- 不做图形界面（无 GUI、无 Web 界面）。
- 不做云同步、不做账号与多用户、不做联网能力。
- 不做编辑/修改已有记录（写错就再记一笔反向记录，或将来随删除功能一起评估）。
- 不做预算与超支提醒、不做图表可视化、不做定期/自动记账、不做银行账单导入。
- 不做数据库（SQLite 等）与多设备并发写入锁。

## 9. 上线与度量

v1 是本地 CLI，没有服务端，交付即上线：由工程师在 `code/` 实现并按第 5 章自测，测试同学独立编写用例并实际运行出报告，本 PRD 的验收标准即为测试用例的主要来源。

回滚方式：以代码版本 tag 回退；数据文件在升级前手工备份一份（`cp data/ledger.json data/ledger.json.bak`）。出现下列情况按「回滚 + 修」处理：`add` 写入后读到金额与输入不一致、`summary`/`stats` 的合计与明细不符、数据文件被解析报错且原文件被改写。

上线后 30 天对照第 1 章指标复盘（真实记录数与用户数），并把「假设未被验证」的结论写回发现清单。
