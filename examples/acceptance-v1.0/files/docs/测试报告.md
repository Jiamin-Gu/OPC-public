共 49 条，全部实际执行；下表逐条列出（「状态」均为本轮真实结果，非预期推断）。**计数构成：正常流程 15 + 边界 13 + 异常 11 + 模块级单元 10 = 49**，与运行证据 `Ran 49 tests … OK` 一致；测试文件中实际 `def test_` 方法数经 `grep -c` 核对为 49。

**`stats` 输出的断言口径（空白弹性，不逐字符比对）**：列宽与列间空格是排版细节，PRD 示例本身就不等宽（`餐饮      5  1200.00` 与 `合计     12  3456.78` 间距不同），因此**不把示例里的空格逐字符固化成规格**——否则必然假失败，且真出数值 bug 时会被整行 diff 淹没。硬断言项：① 标题行内容（月份、类型中文、合计金额、笔数）；② 表头行 `line.split() == ["分类","笔数","金额(元)","占比"]`；③ 只列有记录的分类、金额降序、金额并列时按固定 8 类顺序；④ 每个数据行取 4 字段，金额匹配 `^\d+\.\d{2}$` 且与分值对应，占比匹配 `^\d+\.\d%$`；⑤ 合计行金额 = 明细之和、占比固定 `100.0%`。对应实现：T10/T11/T24/T25（正则用 `\s+`，不写死空格数）。

## 4. 缺陷与风险

### 4.1 口径一致性核对（《记账规范（2026 版）》与 PRD 统一约束）

| 口径要求 | 实现实际情况 | 结论 |
| --- | --- | --- |
| 金额以「分」为单位整数存储与计算，禁止浮点 | `amount_cents` 全链路 `int`；T01/T22/T40 断言类型；T49 源码卡口零命中 `float(`、`: float`、`/100` | **一致**（T25 实证 `0.10+0.20=0.30`） |
| 显示时换算成元、保留两位小数 | `format_cents` 全程 `//`/`%`；T42/T43 覆盖，无千分位 | 一致 |
| 日期 `YYYY-MM-DD`（必须补零、真实存在）、月份 `YYYY-MM` | `validate_date`/`validate_month` + 正则；T30/T31/T44~T46 覆盖 | 一致 |
| 分类固定 8 类（餐饮…其他） | `CATEGORIES` 恰 8 类，收入与支出共用；T47 断言顺序与取值 | 一致 |
| 仅人民币（CNY），不做多币种 | 只输出「人民币 CNY」，无币种参数；未发现多币种入口 | 一致 |
