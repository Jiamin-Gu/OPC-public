# 测试报告：轻记 CLI 记账工具（v1）

- 测试执行：测试（TestingRealityChecker）｜2026-10-23
- 被测对象：`code/cli.py`（sha256 `2f49cadf…f25e`）、`code/ledger.py`（sha256 `70271870…07cd`），本轮测试未修改这两个文件
- 依据：`docs/PRD.md` v1.1、`docs/技术方案.md` v1.2、公司《记账规范（2026 版）》
- 环境：Python 3.12.15（Docker 沙箱），数据文件一律放 `mktemp -d` 临时目录，未创建 `code/data/`

## 1. 测试范围与重点

- 覆盖四类：正常流程 15 + 边界 13 + 异常 11 + 模块级单元 10 = 49 条，全部实际执行。
- 正常流程：`add`/`summary`/`stats`、备注写入回显、id 严格自增、按月汇总不串月、分类统计（金额降序、并列按 8 类序、占比 1 位小数、合计 100.0%）、数据文件结构（version=1、UTF-8 无 BOM、2 空格缩进）。
- 边界：无任何记录、查询无记录月份/类型、金额 0 与 0.01、上限 999999999999.99 及超限拒绝、跨月多笔（3 个月 6 笔）、闰年 2024-02-29、未传 `--date` 取本机当天。
- 异常：非法分类/日期/月份/金额格式/`--type`、缺必需参数、路径不可写、数据文件损坏或 `version` 未知；每条都断言退出码、stderr 前缀「错误：」、数据文件 sha256 不变。
- 金额整数化：`amount_cents` 必须为 `int`（且非 `bool`）；`0.10+0.20=0.30`；分↔元往返无损；源码零浮点卡口（禁 `float(`、`: float`、`/100`）。
- 退出码口径：`0` 成功（含空数据）、`2` 参数/校验错误、`3` 文件/IO 错误（含数据文件损坏）。
- 不测：导出 CSV（本期不做，仅由 T36 断言 `export` 子命令不存在）、性能压测与并发、Python 3.9~3.11、删除/编辑/多币种/GUI/网络、安全渗透与真实用户端到端。
- 重点：金额整数化（错账风险最高）、按月汇总与分类统计的过滤边界（串月最难发现）、校验失败时数据文件必须原样不动（PRD 回滚条件）。

## 2. 测试用例

共 49 条全部通过，计数与运行证据 `Ran 49 tests … OK` 一致。`stats` 输出按「空白弹性」断言，不逐字符比对：列宽与列间空格属排版细节，PRD 示例本身不等宽；硬断言标题行内容、表头 `["分类","笔数","金额(元)","占比"]`、只列有记录分类且金额降序（并列按固定 8 类序）、金额匹配 `^\d+\.\d{2}$`、占比匹配 `^\d+\.\d%$`、合计金额=明细之和且占比固定 `100.0%`。

### 2.1 正常流程

- `add` 成功输出 `已记录 #1：支出 35.80 元 餐饮 2026-10-23`，落盘 `amount_cents=3580`（`int`）；`35.8`/`35`/`0.5` 等价落盘 3580/3500/50。
- id 严格自增且已有记录完全不变；备注原文入盘、确认行以全角括号回显，显式 `--note ""` 不回显括号、note 存 `""`。
- `summary` 按月正确统计收入/支出/结余/笔数，其他月记录不计入；只有支出时收入显示 `0 笔`、结余带负号；收入与支出相等时结余 `0.00 元`，不出现 `-0.00`。
- `stats` 行序按金额降序、占比 1 位小数、合计 100.0%；并列时按固定 8 类序（餐饮→交通→购物）；`--type income` 只统计收入，不传默认支出。
- 数据文件无 BOM、2 空格缩进、`version=1`、字段集合与 id 升序正确；`--data` 指向不存在目录时自动建目录。

### 2.2 边界情况

- 文件不存在时 `summary` 输出三行全 0、`stats` 输出「该月没有支出记录」，退出码 0 且都不创建文件；文件存在但该月/该类型无记录同样退出码 0。
- 金额 0（`0`/`0.00`/`00`/`0.0`）一律退出码 2、stdout 空、不建文件；0.01 正确落盘 1 分；0.10+0.20 汇总 `0.30 元`，无浮点尾巴。
- 上限 `999999999999.99` 可写入并正确显示；超上限退出码 2、提示「金额必须是正数」、不写文件。
- 跨月 3 个月 6 笔各月汇总互不串月（300.00 / 300.51 / 收入 1000.00、支出 400.40、结余 599.60），9 月统计不含 10 月分类。
- `2024-02-29` 通过、`2025-02-29` 退出码 2；不传 `--date` 时落盘与输出均为本机当天。
- 输出分支差异已固化（T28）：无记录月 `summary` 仅 3 行、无标题行；有记录月带 `YYYY-MM 汇总（人民币 CNY）` 标题（见 R1）。

### 2.3 异常情况

- 非法分类（`旅行`、空串、`餐饮 ` 带空格、`dining`）→ 退出码 2、stderr 列出合法 8 类、文件 sha256 不变。
- 非法日期（`2026-02-30`、`2026-2-3`、`2026/10/23`、空白等）与非法月份（`2026-13`、`2026-1`、`202610` 等）→ 退出码 2、固定提示、不写入。
- 非法金额（`abc`、负数、`+5`、`1.005`、`1,200`、`¥35`、含空格、`1e3` 等）→ 退出码 2、提示「金额必须是正数（单位：元），最多两位小数」。
- 非法 `--type`（`transfer`、`EXPENSE`、空串、`支出`）由 argparse 拦截，退出码 2；缺必需参数退出码 2、stderr 打印 usage + 「错误：」。
- `export` 子命令不存在（退出码 2），锁定本期无导出 CSV。
- `--data` 父路径是普通文件 → 退出码 3、不留半截文件；数据文件损坏（`version=2`、JSON 截断、`amount_cents` 小数、非法分类）→ 退出码 3、原文件 sha256 不变；损坏文件上 `add` 也不覆盖坏文件。

### 2.4 模块级单元用例（10 条）

- `parse_amount_to_cents` 合法样本返回 `int`（含上限），14 种非法样本抛 `ValidationError`。
- `format_cents` 覆盖 `35.80`/`1200.00`/`0.01`/`0.00`/`-2256.78`/`-0`→`0.00`/上限值；分↔元 7 个样本往返无损。
- `validate_date`（含 `2024-02-29`、`None`、`int`）、`validate_month`、`validate_type` 的通过与拒绝均符合契约。
- `CATEGORIES` 恰为 8 类且顺序为 餐饮/交通/购物/居住/娱乐/医疗/教育/其他，收入与支出共用，`旅行` 被拒。
- 源码零浮点卡口：`ledger.py`、`cli.py` 均无 `float(`、无 `: float` 注解、无 `/100` 真除法。

## 4. 缺陷与风险

### 4.1 口径一致性核对

- 金额以「分」为单位整数存储与计算、显示换算成元保留两位小数、无千分位、上限一致 —— 一致（T25 实证 `0.10+0.20=0.30`）。
- 日期 `YYYY-MM-DD`、月份 `YYYY-MM` 的格式与真实存在性校验、固定 8 类分类、仅人民币 CNY —— 一致。
- 导出 CSV 本期不做：子命令不存在、代码无 CSV 生成逻辑 —— 一致（按 CEO 指示）。
- 未发现与《记账规范（2026 版）》或 PRD 冲突之处，也未发现指向不存在文稿的版本引用。

### 4.2 问题与风险清单

- **[P3] R1 无记录分支 `summary` 缺标题行**：与有记录分支格式不一致；不违反 PRD，但按标题行切分的下游脚本会失效。建议零记录也走 `render_summary`，或 PM 在 PRD 明确「零记录不输出标题行」；已用 T28 固化当前行为。
- **[P3] R2 零记录三行间距与正常分支不同**（1 个空格 vs 按列宽填充 3 个空格）：属排版细节，建议脚本化解析统一走 `_summary_line`，或在 PRD 注明行内间距为示意。
- **[P3] R3 模块划分与技术方案 2.1 不一致**：方案规划 `ledger/` 包，实际为单文件 `code/ledger.py`；对外功能与接口与方案 4.2 完全一致，测试按 4.2 导入通过。建议方案作者确认「v1 合并为单文件」，不阻塞交付。
- **[P3] R4 三项未验证**：① Python 3.9~3.11 兼容（沙箱只有 3.12.15）；② 1 万条记录性能（工程师自测 summary 0.23s / stats 0.24s / add 0.33s，本轮未复现）；③ 多进程并发写（方案声明单用户单进程、不加锁）。
- **[P3] R5 上游文档缺口**：技术方案 4.3 未写 `--date` 空串/纯空白行为；实现为按非法日期报错、退出码 2、不静默改成今天（T30 已实测），建议方案补一行。
- **[P3] R6 并发无锁、JSON 全量重写**：读整份→追加→临时文件→`os.replace` 原子替换（T38/T39 证明损坏文件不被改写、中断不留半截 JSON）；多进程并发可能丢记录，属方案已声明的取舍。
- **[P2] R7 金额上限可读性（提示，非缺陷）**：`999999999999.99` 元可写入并正确显示，但超过 1e12 元已无实际意义且 `add` 不提醒；是否对 >1e8 元给出提醒由 CEO 决定。
- 已关闭风险：CSV 编码/Excel 乱码与 RFC 4180 转义（随导出 CSV 移出本期消失，T36 锁定范围）；金额浮点误差（整数实现 + 卡口 T49 + T25 实证）；坏文件被覆盖（T38/T39 证明 sha256 不变）。
