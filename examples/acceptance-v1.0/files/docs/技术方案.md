## 2. 架构与技术选型

### 2.1 架构与模块划分

v1 是**单进程、无网络、单用户**的本地 CLI，采用「分层小模块 + 单一入口」的模块化单体。三个子命令共用同一份记录模型与同一套校验函数，避免出现「有的入口校验、有的不校验」的错账来源（PRD 第 6 章）。

```
code/
  cli.py            # 入口：argparse 子命令、参数编排、异常 → 退出码映射
  ledger/
    money.py        # 元字符串 ⇄ 分整数（int）、金额格式化（域）
    validators.py   # 日期/月份/分类/类型校验（域）
    model.py        # Record / Ledger 数据结构与不变量、CATEGORIES（域）
    store.py        # JSON 读、原子写、文件损坏处理（基础设施）
    reports.py      # 按月汇总、分类统计、表格渲染（应用）
  tests/            # 测试（由测试同学编写；工程保证可导入、可用 --data 隔离）
  README.md
```

依赖方向（单向，无循环）：

```
cli.py  ──→  reports.py / store.py  ──→  money.py / validators.py / model.py
（入口）      （应用 + 基础设施）         （域，不 import 上层任何模块）
```

硬规则：域层（`money`/`validators`/`model`）不得 `import json`、`os`、`argparse`；基础设施细节（文件路径、BOM、临时文件名）不得泄漏到输出文本里（错误信息只说明「哪个参数/哪个文件」出了什么问题）。

### 2.2 技术选型

| 选项 | 选择 | 理由 | 放弃的备选 |
| --- | --- | --- | --- |
| 语言与运行环境 | **Python 3.9+，仅标准库** | 目标用户是终端用户，零安装依赖才能「下载即用」；避免依赖漂移与被依赖库的破坏性升级；单条命令启动 < 1 秒可达（PRD 指标） | Node/Go 单文件（团队与用户环境更熟悉 Python）；引入 click/rich 等（体验更好，但引入依赖） |
| CLI 框架 | **argparse 子命令**（`add`/`summary`/`stats`） | 标准库、自动生成 `--help`、参数校验与错误退出码可预测、测试可直接断言 stdout/退出码；子命令结构天然对应 PRD 的三个 P0 功能 | 问答式交互（不可脚本化、难断言）；click（额外依赖） |
| 数据持久化 | **本地 JSON 单文件**（`./data/ledger.json`） | v1 单月 30~200 笔、总量万条以内；JSON 可人工查看/编辑/备份，出错时用户能自救；无并发与事务需求，无需数据库 | **SQLite**：查询与并发更强，但需把记录拆成表、备份与人工检查变难，且 PRD 已明确 v1 不做数据库；CSV 作主存储：无 schema、无原子性 |
| 金额表示 | **`int`，单位为分**（字段 `amount_cents`） | 与《记账规范（2026 版）》一致；整数加减无误差（`0.10+0.20` 必得 `0.30`）；Python int 任意精度，上限 999999999999.99 元（≈1e14 分）远未溢出 | `float`（禁止，误差会算错账）；`Decimal`（无误差但引入类型转换与序列化复杂度，v1 无除法场景，不必付这个代价） |
| 日期处理 | 字符串 + `datetime.strptime` 校验 | 存储与过滤都按字符串即可（见 5.3）；只在「默认今天」一处用 `datetime.now()` | 引入 pendulum/arrow（依赖）；存时间戳（人工不可读） |
| 测试 | `unittest`（建议，测试同学定） | 标准库，CI 无安装成本；用 `--data` 指向临时目录隔离 | pytest（可选，如环境已有） |

### 2.3 如何满足「金额以分为单位的整数存储与计算、禁止浮点」

1. 唯一的金额表示是 `amount_cents: int`，全链路（解析 → 存储 → 汇总 → 统计）都是 `int` 加减，不做任何乘法除法以外的换算。
2. 元 → 分：**按字符串解析**，不做 `float(text)*100`（那会引入误差）。正则 `^(\d{1,12})(?:\.(\d{1,2}))?$` → `cents = int(int_part)*100 + int(frac.ljust(2,"0"))`；拒绝 `0`、空、负数、`+`/`-`、`¥`、千分位逗号、空格、科学计数法、超过 2 位小数、整数部分超过 12 位（上限 999999999999.99 元）。`1.005` 因正则不匹配被拒。
3. 分 → 元：只在输出瞬间做**整除与取余**：`f"{cents//100}.{cents%100:02d}"`；负结余用 `"-" + fmt(abs(cents))`，不出现 `-0.00`。
4. 占比是唯一涉及除法的场景，改用**整数半进位**（见 5.6），全程无浮点。
5. 适应度检查（CI 或人工复查，PRD 指标为「代码中 float 出现 0 次」）。要求**按本方案实现的代码能稳定零命中**，两条检查都只针对真正的浮点用法与非法换算（检查范围 `code/ledger` 与 `code/cli.py`；本期无 `exporter.py`，范围不因导出功能移除而变化）：
   ```bash
   # ① 真正的浮点用法（float(...) 或 float 类型注解）→ 必须零命中
   grep -rnE "float\(|:[[:space:]]*float" code/ledger code/cli.py
   # ② 金额除以 100 的写法（`//100` 是整除、合法；命中说明有人绕过了整数换算）→ 必须零命中
   grep -rnE "(^|[^/])/[[:space:]]*100([^0-9]|$)" code/ledger code/cli.py
   # 任一命中：打印命中处 + 「金额换算只允许 money.py 内的 int // 与 %（见 2.3）」，阻塞合并
   ```
   说明：②的模式要求 `/100` 的前一个字符不是 `/`，因此 5.2 规定的 `f"{cents//100}.{cents%100:02d}"` 中的 `//100` **不会**被误判（这是 v1.0 正则 `/ ?100` 的缺陷：会把正确写法判为违规）；该模式也不会命中 `// 100`（整除）。辅助检查：`grep -rl "//[[:space:]]*100" code/ledger code/cli.py | grep -v money.py` 应为空（`//100` 换算出 `money.py` 之外即说明有人在别处做金额换算，需评审）。v1.1 已用样例文件实测这两条命令（GNU grep 与 Python `re` 双引擎结果一致）：按 5.2 写法的样例在①②下均零命中，`y = amount / 100` 被②命中、`round(float(amount), 2)` 与 `def f(a: float)` 被①命中——既能卡住浮点，又不误伤正确实现。
6. 测试侧硬断言：`isinstance(rec.amount_cents, int)`；`0.10 + 0.20` 两笔支出后 summary 合计显示 `0.30`。

### 2.4 容量与性能估算（估算，非实测）

依据 PRD 假设「单用户单月 30~200 笔」，按 10 年 × 2400 笔估算约 2.4 万条、文件 ≈ 3.6 MB（单条约 150 字节）；该量级全量读写为几十毫秒，满足「单条命令 < 1 秒」。`add` 每次全量重写文件，是 O(n) 操作。**结论需在 M3 用 1 万条实测确认**；若超 1 秒或文件超 ~10 MB，按 ADR-1 换 `store` 到 SQLite，上层不动。

## 3. 数据模型

### 3.1 文件结构（`./data/ledger.json`，UTF-8 无 BOM，2 空格缩进）

```json
{
  "version": 1,
  "records": [
    {
      "id": 1,
      "type": "expense",
      "amount_cents": 3580,
      "category": "餐饮",
      "date": "2026-10-23",
      "note": "午餐",
      "created_at": "2026-10-23T12:30:00"
    },
    {
      "id": 2,
      "type": "income",
      "amount_cents": 120000,
      "category": "其他",
      "date": "2026-10-01",
      "note": "项目款",
      "created_at": "2026-10-01T09:05:11"
    },
    {
      "id": 3,
      "type": "expense",
      "amount_cents": 90000,
      "category": "交通",
      "date": "2026-09-28",
      "note": "",
      "created_at": "2026-09-28T20:12:00"
    }
  ]
}
```

### 3.2 字段定义

| 字段 | 类型 | 含义与约束 |
| --- | --- | --- |
| `version` | `int` | 文件格式版本，v1 固定 `1`。读取到未知版本 → 报错退出码 3，不尝试修复 |
| `records` | `array` | 记录列表，写入时按 `id` 升序追加；读取时顺序不参与任何计算 |
| `records[].id` | `int` | 从 1 起严格自增、不重复（写入时 `max(已有 id)+1`）。`id` 全局唯一，不因月份/类型区分 |
| `records[].type` | `str` | 只允许 `income` / `expense`（内部一律存英文枚举值，中文只在输出时渲染） |
| `records[].amount_cents` | `int` | **金额，单位「分」，恒为正整数**（`>= 1`）；上限 `99999999999999`（= 999999999999.99 元）。禁止字符串、禁止小数 |
| `records[].category` | `str` | 固定 8 类之一（支出与收入共用）：餐饮、交通、购物、居住、娱乐、医疗、教育、其他 |
| `records[].date` | `str` | `YYYY-MM-DD`（必须补零，如 `2026-10-23`）；真实存在的日期（`2024-02-29` 合法，`2026-02-30` 非法） |
| `records[].note` | `str` | 备注，未传时为**空字符串 `""`（不是 `null`）**；不参与任何统计与筛选 |
| `records[].created_at` | `str` | 写入时刻，ISO 8601 本地时间 `YYYY-MM-DDTHH:MM:SS`；仅用于排查问题，不参与展示与统计 |

### 3.3 不变量与状态流转

- 不变量：`amount_cents > 0`；`type ∈ {income, expense}`；`category ∈ CATEGORIES`；`date` 严格 `YYYY-MM-DD` 且真实存在；`note` 为 `str`（可为空串）；`id` 唯一且为正整数。
- 流转：**只能新增（append-only）**。v1 不提供 `edit`/`delete`（PRD 第 8 章），写错就再记一笔反向记录。因此不存在状态机，只有「文件不存在 → 首次 `add` 创建」这一条迁移。
- 读取校验：`store.load()` 逐条校验上述不变量与字段类型/存在性。任一条不合格或 `version` 未知 → 输出「错误：数据文件格式不正确（<路径>）：<原因>」，退出码 **3**，**绝不改写原文件**（这是 PRD 回滚条件之一）。
- 内存模型：`@dataclass Record(id, type, amount_cents, category, date, note, created_at)`，配 `to_dict()`/`from_dict()`；`Ledger(version, records)` 提供 `next_id()`。序列化格式变更只改 `store.py` 的这两个方法。

## 4. 命令行接口设计

### 4.1 公共约定

- 运行方式：在 `code/` 目录下 `python cli.py <子命令> [参数]`（PRD 第 5 章）。
- `--data PATH` 为公共参数，**写在子命令之后**（与子命令参数同级），默认 `./data/ledger.json`（相对当前工作目录，**沿用 PRD，不做改动**）。测试必须给 `--data` 指向临时文件。
- 错误输出：一律 `stderr`、单行、以「错误：」开头、附可复制的示例；所有错误信息在**写入之前**产生，校验失败数据文件内容不变。`stderr` 仅有一类非错误输出：`add` 本次新建数据文件时的路径提示（见 4.3），因此**成功用例只断言 stdout 与退出码，不断言 stderr 为空**。
- 退出码（**采纳 PRD 约定**）：`0` 成功（含空数据）；`2` 参数或校验错误（分类/日期/月份/金额格式/类型非法）；`3` 文件或 IO 错误（数据文件损坏或版本未知、数据文件目录不可写）；`1` 未预期错误（兜底 `except Exception`）。
- 只读命令（`summary`/`stats`）在数据文件不存在时按 0 条记录处理，退出码 0，且**不创建**数据文件。

### 4.2 内部模块接口（供工程与测试导入）

### 4.3 `add` — 记一笔（F1、F5）

| 参数 | 必填 | 默认值 | 约束 |
| --- | --- | --- | --- |
| `--type {income,expense}` | 是 | — | 非法值 argcparse 报错 → 退出码 2 |
| `--amount 元` | 是 | — | 正数字符串，最多两位小数，上限 999999999999.99 |
| `--category 分类` | 是 | — | 8 类之一（中文原文） |
| `--date YYYY-MM-DD` | 否 | **本机今天**（本地时区） | 真实存在的日期，必须补零 |
| `--note 文本` | 否 | `""` | 不限制长度（见待确认 1） |
| `--data PATH` | 否 | `./data/ledger.json` | 文件不存在时由 `add` 负责创建：目录取**规范化目录** `os.path.dirname(os.path.abspath(PATH))`（`--data ledger.json` 这类纯文件名等价当前工作目录），再 `makedirs(..., exist_ok=True)`；**不得**直接用 `os.path.dirname(PATH)`（纯文件名时返回 `""`，`makedirs("")` 会抛错） |

输出（`金额` 不带负号，回显实际写入日期；有备注时以全角括号回显）：

```bash
$ python cli.py add --type expense --amount 35.80 --category 餐饮
已记录 #1：支出 35.80 元 餐饮 2026-10-23

$ python cli.py add --type income --amount 1200 --category 其他 --date 2026-10-01 --note "项目款"
已记录 #2：收入 1200.00 元 其他 2026-10-01（项目款）

$ python cli.py add --type expense --amount 1.005 --category 餐饮
错误：金额必须是正数（单位：元），最多两位小数，例如 35.80      # 退出码 2，数据不变

$ python cli.py add --type expense --amount 10 --category 旅行
错误：分类必须是以下 8 类之一：餐饮、交通、购物、居住、娱乐、医疗、教育、其他  # 退出码 2

$ python cli.py add --type expense --amount 10 --category 餐饮 --date 2026-02-30
错误：日期不存在或格式应为 YYYY-MM-DD（如 2026-10-23）        # 退出码 2
```

**输出契约（与 PRD 第 5 章 add 示例一致，测试据此断言）**：
- **stdout 只有一行确认行**（含新 id、「支出/收入 X.XX 元」、分类、实际写入日期；有备注时行尾以全角括号回显）。
- `--data` 指向的文件**此前不存在**（即本次新建）时，额外向 **stderr** 打一行 `（已新建数据文件：<规范化后绝对路径>）`；该行**不是输出契约**、不计入 stdout：成功用例只断言 stdout 与退出码，**不断言 stderr 为空**（见 4.1）。
- 数据文件路径在正常路径下不进入 stdout，避免与 PRD 示例的一行输出冲突。

### 4.4 `summary` — 按月汇总（F2）

参数：`--month YYYY-MM`（必填）；`--data PATH`（可选，同上）。输出不使用千分位分隔符，便于断言与复制：

```bash
$ python cli.py summary --month 2026-10
2026-10 汇总（人民币 CNY）
收入：3 笔   1200.00 元
支出：12 笔  3456.78 元
结余：-2256.78 元
```

- 结余 = 收入合计 − 支出合计（按分做整数减法，可为负，带 `-` 号）。
- 该月无记录（或数据文件不存在）：输出 `收入：0 笔 0.00 元`、`支出：0 笔 0.00 元`、`结余：0.00 元`，退出码 0，不创建文件、不报「无数据」错误。
- 月份格式非法（`2026-13`、`2026-1`、`202610`、空）：`错误：月份格式应为 YYYY-MM（如 2026-10）`，退出码 2。

### 4.5 `stats` — 分类统计（F3）

参数：`--month YYYY-MM`（必填）、`--type {expense,income}`（可选，**默认 `expense`**）、`--data PATH`（可选）。
只统计该月该类型的记录；**按金额降序**排列，金额并列时按固定 8 类顺序（稳定排序实现，输出可重复）；只列出有记录的分类；占比保留 1 位小数（四舍五入，**不做补差**），末行为合计、合计行占比恒为 `100.0%`。

**「金额降序」是硬契约，示例行序必须服从它**：PRD 故事 3 的示例把「餐饮→交通→购物」按笔数排，与它自己的「按金额降序」规则冲突（购物 1356.78 > 餐饮 1200.00 > 交通 900.00），本方案**以规则为准**，正确行序是购物、餐饮、交通；测试的行序断言按下面这版示例写（该冲突已列入第 8 章第 6 条，请 PM 同步修正 PRD 示例）。

```bash
$ python cli.py stats --month 2026-10 --type expense
2026-10 支出分类统计（共 3456.78 元 / 12 笔）
分类     笔数   金额(元)     占比
购物        3    1356.78    39.2%
餐饮        5    1200.00    34.7%
交通        4     900.00    26.0%
合计       12    3456.78   100.0%
```

该月无该类型记录时只输出一行提示，退出码 0、不输出表格：

```bash
$ python cli.py stats --month 2026-11
该月没有支出记录
```

`--type income` 时提示为「该月没有收入记录」，标题为「2026-10 收入分类统计」。月份非法或 `--type transfer` → `错误：…`，退出码 2。

**表格空白口径（对测试的唯一依据）**：列宽按显示宽度计算（中文按 2 列宽，其余按 1 列）：分类 6（左对齐）、笔数 6（右对齐）、金额(元) 10（右对齐）、占比 8（右对齐），列间 1 个半角空格。**数值、列名、列顺序、行顺序是硬契约；列宽是排版细节**（PRD 故事 3 示例的列间距为示意，不是契约）。已与测试同学确认：测试对块的空白做弹性匹配（如 `re.fullmatch(r"合计\s+12\s+3456\.78\s+100\.0%", line)`），不逐字符断言空格，格式用例与数值用例分开。

### 4.6 `export` — 本期不做（原 F4）

按 CEO 指示，导出 CSV 整体移出本期范围：**不提供 `export` 子命令，也不实现 CSV 生成**。参数与列定义本期不定义（将来恢复时需重新确认列序、`utf-8-sig` 编码与 RFC 4180 转义，并补 Excel/WPS 中文乱码的验收，见 ADR-6）。用户要自查或备份数据时直接复制 `data/ledger.json`（对应 PRD 指标「数据可自查备份」）。

## 5. 关键难点与风险

### 5.1 难点：金额的整数化与「禁止浮点」

处理：见 2.3——解析不用 `float(text)`，换算只用 `//` 与 `%`（**`// 100` 整除是唯一允许的除法写法，禁止 `/ 100` 这类真除法**，它会产生浮点），占比走 5.6 的整数半进位。评审禁止出现 `float(`、`round(x, 2)`、`/ 100`。

### 5.2 难点：分 → 元的显示

处理：`format_cents(cents) = f"{cents//100}.{cents%100:02d}"`，天然保留两位小数、不带千分位（如 `3580 → "35.80"`、`120000 → "1200.00"`）。结余为负时先取绝对值再拼 `-` 前缀，避免 `-0.00`；金额本身恒为正，展示永不带负号。`add` 的确认行、`summary` 的三行、`stats` 的金额列全部走这一个函数，保证三处口径一致。

### 5.3 难点：按月过滤（`YYYY-MM`）

处理：`date` 写入时已强校验为 `YYYY-MM-DD`，因此**过滤用字符串前缀比较**：`rec.date[:7] == month`（不解析成 `datetime`，避免时区与解析开销），按**年月**汇总与按类型分类统计都基于这一步。用同一条件筛选的记录集做金额整数求和。`stats` 的月份、类型筛选与汇总在同一遍循环里完成，只读一次文件。

### 5.4 难点：`add` 的输出契约（stdout 与 stderr 分离）

处理：`add` 成功时 **stdout 只有一行确认行**（PRD 第 5 章示例即契约，测试逐字断言）；「已新建数据文件：<绝对路径>」这类环境提示走 **stderr**（满足 PRD 第 7 章「`add` 首次写入前回显数据文件路径」的应对，见第 8 章第 7 条），不进 stdout。纪律：任何提示/警告都不许写 stdout；成功用例只断言 stdout 与退出码、**不断言 stderr 为空**。写入侧的「不留半截文件」要求（同目录临时文件 + `os.replace` 原子替换）同样适用于 `add`，见 5.7。

### 5.5 难点：无数据 / 空结果场景（`summary` 与 `stats` 行为不同）

| 场景 | 行为 | 退出码 |
| --- | --- | --- |
| 数据文件不存在 + `summary` | 输出收入/支出/结余三行全 0（`0 笔 0.00 元`） | 0（不创建文件） |
| 数据文件存在但该月无记录 + `summary` | 同上，全 0，不报「无数据」错误 | 0 |
| 该月无该类型记录 + `stats` | 只输出「该月没有支出记录」，**不输出表格**、不报错 | 0 |
| 数据文件损坏、`version` 未知、字段类型错误 | 输出「错误：数据文件格式不正确（<路径>）：<原因>」，**不改写原文件** | 3 |
| 除零 | 恒不发生：金额分恒 `> 0`，分母为 0 只可能出现在「无记录」分支，已在上面拦住 | — |

### 5.6 难点：占比的四舍五入与「合计 100.0%」

处理：四舍五入到 0.1% 用**整数半进位**，不碰浮点：`tenths = (cents * 2000 + total) // (2 * total)`，再输出 `f"{tenths//10}.{tenths%10}%"`。例（输出顺序按 4.5 的金额降序）：购物 `135678/345678 → 392 → 39.2%`、餐饮 `120000/345678 → 347 → 34.7%`、交通 `90000/345678 → 260 → 26.0%`（各分类之和 99.9%），**不做任何凑数补差**，合计行固定打印 `100.0%`，以合计行金额为准。测试可独立复算这三处期望值。

### 5.7 难点：`id` 生成与并发写入

处理：`id = max(已有 id) + 1`（不是 `len(records)+1`，避免将来删除功能上线后 id 复用）。写入用「读 → 追加 → 临时文件 → `os.replace`」，保证中断时要么旧文件、要么新文件，不出现半截 JSON。多进程并发写入 v1 不加锁（PRD 不做范围），文档声明为单用户单进程；`add` 在**本次新建数据文件**时向 stderr 打一行「（已新建数据文件：<路径>）」（见 4.3），降低 `--data` 写错位置的风险——该行不属于 stdout 输出契约，stdout 始终只有确认行。

### 5.8 风险清单

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 误用浮点导致金额误差 | 高（错账，动摇信任） | 2.3 的整数规则 + `grep` 卡口；测试断言 `int` 与 `0.10+0.20=0.30` |
| 数据文件被手工改坏或写入中断 | 中（丢数据） | 读取全量校验（退出码 3，不改写）；写入临时文件 + 原子替换 |
| 记录增长后 JSON 全量读写变慢 | 中 | 估算见 2.4；M3 用 1 万条实测；超阈值按 ADR-1 换 SQLite 实现 |
| `--data` 用错路径污染真实数据 | 低 | `add` 首次建文件时向 stderr 提示实际路径（不进 stdout 契约，见 4.3）；README 与测试统一用临时目录 |
| 域层被基础设施污染 / 循环依赖 | 中（后续难维护） | 2.1 的依赖方向硬规则纳入 M1 评审（`ledger/*.py` 引用 `cli` 即拒绝） |

## 7. 决策记录

### ADR-1：数据持久化用本地 JSON 单文件，而不是 SQLite

背景：v1 单用户单进程、单月 30~200 笔，需求只有全量过滤（按月、按类型）与汇总统计，无联表查询、事务与并发。
决策：JSON 单文件 `./data/ledger.json`，`store.py` 内实现「读整份 → 追加 → 原子替换写」。
备选方案：① SQLite（查询/并发更好，但要建表与迁移、备份与人工排查变难，且 PRD 明确 v1 不做数据库）；② CSV 作主存储（无 schema、无原子性、备注转义来回易损）。
影响与代价：放弃并发写与高效增量更新，超大数据量性能上限低；换来文件可人工查看/备份/恢复、零依赖、出错可自救。迁移路径已留：`store.py` 接口不变，内部换 SQLite 即可，上层不动。

### ADR-2：命令行用 argparse 子命令，不用问答式交互

背景：PRD 要求三个子命令可脚本化、可测试（断言退出码与 stdout）。
决策：`argparse` + 三个子命令（`add`/`summary`/`stats`），参数式调用。备选：问答式交互（不可断言、CI 不可测）；第三方 CLI 框架（违反「仅标准库」）。
影响与代价：用户需要记住参数名，靠 `--help` 与 PRD 示例兜底；换来零依赖、退出码与错误信息完全可控、测试可用 `subprocess` 稳定断言。

### ADR-3：金额用 int 分，不用 Decimal

背景：《记账规范（2026 版）》要求金额以分为单位的整数存储与计算、禁止浮点；PRD 要求代码中 `float` 出现 0 次。
决策：唯一金额表示是 `amount_cents: int`；元→分走字符串正则，分→元走 `//`/`%`，占比走整数半进位。
备选方案：`Decimal`（无误差，但引入类型转换与 JSON 序列化的额外复杂度；v1 只有加法与一次占比除法，不值得付）。
影响与代价：金额代码必须走 `money.py`，不能图快写 `amount/100`；换来 `0.10+0.20=0.30` 这类错账从根上不可能发生。

### ADR-4：只读命令不自动创建数据文件

背景：`summary`/`stats` 在数据文件不存在时要按 0 条处理（PRD 统一约束）。
决策：`store.load(missing_ok=True)` 返回空账本；只有 `add` 在首次写入时 `makedirs` 并创建文件。备选「任何命令都初始化文件」会让查询产生副作用、测试与环境更脏。
影响与代价：`add` 承担首次创建职责，错误分支更多（目录不可写 → 退出码 3）；换来查询无副作用、不误建空账本。

### ADR-5：确认 PRD 的三项待确认（数据路径、退出码、`--note` 归属）

背景：PRD 第 7 章列了三项需要工程师确认的事项。
决策：① 默认数据路径 `./data/ledger.json`（相对当前工作目录）**可行，采纳**，前提是 `--data` 可覆盖（测试一律用临时文件）；② 退出码 `0/2/3/1` **采纳**，并补充一条归属：**数据文件损坏/版本未知判为 `3`（文件错误）**，测试用例按此编写；③ `add --note` 为 P0 **确认**（依据改为「备注是记账常见诉求、成本极低」，与导出无关；F4 已移出本期）。
备选方案：默认路径改为用户主目录（`~/.lightnote/ledger.json`）——对个人工具更符合直觉，但数据放项目目录便于 v1 验收与备份，且 `--data` 已能覆盖；如后续用户反馈「换目录后数据找不到」，再评估切主目录（属于可逆决策）。
影响与代价：用户在不同工作目录执行命令会看到不同账本，需在 README 的「数据文件在哪」一节写清楚，并要求 `add` 在新建文件时向 stderr 提示实际路径（见 4.3）。

### ADR-6：本期不做导出 CSV（原 F4）

背景：CEO 指示「导出 CSV 这一版先不做」，PRD v1.1 已把 F4 标为「本期不做（编号保留不复用）」。
决策：技术方案同步删除 `export` 子命令、`exporter.py` 模块与全部 CSV 相关验收（列定义、`utf-8-sig` 编码、RFC 4180 转义）；数据自查/备份的方式改为用户直接复制 `data/ledger.json`。
备选方案：① 保留 `export` 但不验收（不被验证的功能等于没做，还要维护列与编码口径）；② 改成 `export --format json`（等于新增功能，超出本期范围）；③ 上 SQLite 让用户自己查（PRD 明确本期不做数据库）。
影响与代价：本期失去「一行命令交给 Excel 做透视」的能力，需要时得手工解析 JSON；换来更小的实现与验收面（少一个子命令、少一套列与编码契约）。恢复成本已量清：列序、`utf-8-sig` 编码、RFC 4180 转义、`date` 升序 + 同日 `id` 升序——恢复前需 CEO 立项并重新确认这些口径。

## 8. 假设与待确认

1. **`note` 长度上限**：PRD 定为「暂不限制」，本方案实现为不截断。需 **CEO 决定**是否设上限（如 500 字符），若定上限，`add` 超限时按退出码 2 报错。
2. **`stats` 表格列宽是否算对外契约**：本方案按 4.5 的固定宽度模板，并已与测试同学确认「空白做弹性匹配、数值为硬断言」。建议 PM 在 PRD 故事 3 补一句「示例列间距为示意」，避免后续被当成规格。
3. **数据文件损坏的退出码**：PRD 未明确，本方案定为 `3`（见 ADR-5②），如测试用例按 `2` 编写需对齐——本方案以 `3` 为准。
4. **`version` 未知时的兼容策略**：v1 直接报错退出（不猜测、不迁移）；将来加字段时按 `version` 分支兼容，新增字段必须有默认值。
5. **性能结论待实测**：2.4 的容量估算是推算值，M3 用 1 万条记录实测并把结果回填本文档；未实测前不声称「性能已达标」。
6. **PRD 故事 3 的示例行序需 PM 修正**：PRD 第 4 章故事 3 的示例按「餐饮→交通→购物」排列，与它自己的「按金额降序」规则冲突（PRD v1.1 修订未涉及该处：示例行序与验收标准里的占比顺序仍是餐饮 34.7%、交通 26.0%、购物 39.2%，本条继续有效）；工程按规则实现（降序）、测试照 PRD 示例写断言必然失败。本方案以规则为准，行序为**购物 39.2% → 餐饮 34.7% → 交通 26.0%**（数值与占比口径不变）。建议 PM 同步修正 PRD 故事 3 示例行序（并可在 PRD 补一句「示例列间距为示意」，见第 2 条）。
7. **`add` 路径提示的落点**：PRD 第 7 章的风险应对提到「`add` 首次写入前回显数据文件路径」，但 PRD 第 5 章 add 示例只有一行确认行。本方案落地为「stdout 只有确认行；路径提示仅在本次新建文件时打到 stderr」（见 4.3），不影响 PRD 示例，测试成功用例不断言 stderr 为空。若 PM 要求该提示进 stdout，需同步修改 PRD 第 5 章示例并告知测试同学。
8. **导出能力与备份口径**：本期按 CEO 指示不做导出 CSV（原 F4，见 ADR-6），备份方式=用户直接复制 `data/ledger.json`（对应 PRD 指标「数据可自查备份」）。若上线后用户需要 Excel 透视，需 **CEO 决定**是否立项恢复导出（恢复前重新确认列序、编码与转义口径）。
