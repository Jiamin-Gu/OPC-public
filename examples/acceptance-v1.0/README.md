# v1.0 验收运行

一次真实运行里把 v0.18 以后加的功能放在一起跑：长期记忆、资料库、注入防护、Docker 沙箱、链路追踪、
测试角色运行测试（v0.25）、审批时编辑计划（v0.26）、中途插话。模型 `deepseek-v4-flash`，投入档位"标准"。
CEO 的操作由脚本模拟（计划编辑一处后批准、插话一次、调整建议确认、裁决接受）。

## 场景

- **公司**："轻记"，产品经理、工程师、测试；允许运行代码（有 Docker 进沙箱），知识库打开，不联网
- **公司资料**（资料库里的 Word《记账规范》）：金额以"分"为单位的整数；日期 YYYY-MM-DD；分类只能是固定的 8 类
- **第 1 条指令**："先定个口径，记住就行不用写文档：记账工具只支持人民币，不做多币种；删除记录要二次确认。"
- **第 2 条指令**："做一个命令行记账工具（Python）：记一笔收入或支出、按月查看汇总、按分类统计、导出 CSV。要需求文档、技术方案、
  能运行的代码和测试；测试同学要自己写测试用例、实际运行，出测试报告。"
- **CEO 的操作**：计划出来后用"编辑计划"给测试任务加一条验收标准"测试报告列出每条测试命令和退出码"，再批准；
  工程师开始写代码时插话"导出 CSV 这一版先不做，需求、方案、代码和测试里都去掉这部分"

## 发现的问题

1. **编码 agent 在 Docker 沙箱里以为自己在 Windows 上**：每次调用开头先用 `dir`、`where`、`%TEMP%` 这类 Windows 命令，失败后才改用 Linux 命令；还在工作区里留下一个叫 `nul` 的文件（以为 `2>nul` 是丢弃输出），这是 Windows 的保留名。原因：Coding-agent 告诉模型的运行环境是主机的系统，没考虑命令其实在 Linux 容器里执行
2. **执行到一半 Docker 停了，命令悄悄改在本机执行**：这次运行中 Docker Desktop 退出过，编码 agent 的命令就改在本机执行（又因为下面的原因全部失败）。从安全上看，不应该没有任何提示就从沙箱降级到本机
3. **注入检测误报**（见第 8 项，已修复）
4. **Coding-agent 的危险命令规则在沙箱里过严**：`rm -rf /tmp/xxx` 也会被拦（规则是 `rm -rf /…`），测试角色只好改用 Python 删除临时目录
5. **成果列表里出现 `__pycache__/*.pyc`**：运行测试产生的字节码缓存也显示成了产出文件
6. **演示模式的 3 人公司规划出错**（准备验收时发现，已修复）：假规划助手把提示词里的"- small（小任务）"当成了一个角色

## 过程

- 第一次运行约 32 分钟后，启动它的 Claude 会话结束了：运行脚本成了孤儿进程，之后启动的子进程全部失败（Windows 错误 0xC0000142，编码 agent 那 20 条退出码 3221225794 的命令就是这时的）；接着电脑睡了约 8.6 小时，脚本的止损按墙上时钟误判"超时"并点了"停止"，把还没做的代码、测试任务取消了。这几处是验收脚本的问题，不是 OPC 的：之后改成从独立窗口启动、只算实际运行时间、止损时直接退出不点停止，把误取消的两个任务改回待开始后接着跑，PRD 和技术方案没有重做
- 发现注入误报后先停下（结束进程，任务状态保留），修复后接着跑，测试的审查重新开始
- 输入到 800 万 token 时按止损退出，确认后提高到 1100 万跑完
- 每次接着跑都由 OPC 自己恢复：重新打开公司，没做完的任务重新派发（执行循环有检查点的从检查点接着做）
