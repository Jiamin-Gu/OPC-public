## 1. 问题与目标

### 1.1 问题陈述

会员到店上团课的完整链路是：看到课表 → 约上位置 → 临时有事取消 → 想上的课满了要排队 → 到点上课。目前这条链路（假设：门店主要通过会员微信群 + 前台电话 + 教练口头确认完成约课，尚未上线预约系统）存在四个具体问题：

1. **看不到真实名额**：课表靠群公告图片或教练在群里发排课，会员不知道还剩几个位置，只能"先到现场再说"，到了发现满员，白跑一趟。
2. **满员后没有官方队列**：想上的课满了，会员只能在群里喊"有人不去吗"，前台挨个私聊协调。谁先谁后没有依据，容易起争执，前台每天要花人力对齐名单。
3. **取消不被系统记录**：会员在群里说一句"我今天不来了"，前台可能没看到，名额也不会被有效利用——有人想上却约不到，位置却空着。
4. **教练到岗无可核**：教练是否准时到店、课程是否开始，门店只能靠纸质签到表或微信群打卡，事后无法核对。

不解决的代价：会员流失到有预约系统/更规范的门店；前台人力持续被约课协调占用（假设：每天 30~60 分钟）；门店无法解释"课为什么没上满"。

依据：
- 竞品情况：超级猩猩、乐刻运动等公开可访问的小程序，团课主流程均包含"课表 → 预约 → 满员候补 → 取消释放名额"的闭环，并普遍采用"开课前若干小时免费取消"的规则（仅基于公开可见产品流程的观察，未做定量采样，不作为数值依据）。
- 假设 1：门店当前主要依赖微信群/电话完成约课。（验证方式：向门店运营索取近 1 周微信群约课消息与前台登记记录，统计线上自主预约与人工协助的比例）
- 假设 2：会员"约不到课"的主因是名额被占用后未及时释放，而不是课程供给不足。（验证方式：上线前用门店现有排课表统计近 4 周每节课的上座率与开课前 2 小时的空位率）
- 假设 3：会员愿意让系统在候补转正时**自动占位**并通知自己，且愿意为此授权一次订阅消息。（验证方式：上线后统计转正通知授权率、转正后取消率与门店核对的未到场人次；首发阶段保留微信群兜底，观察人工通道是否还需要）
- 假设 4：门店已有会员/排课数据（会员手机号、会员卡状态、课程排期、教练排班），能够作为本小程序的数据来源。（验证方式：与门店运营确认现有系统的导出字段与更新频率，见 §6.4）

### 1.2 目标与衡量指标

| 目标 | 指标（精确定义） | 目标值 | 观察时间 |
| --- | --- | --- | --- |
| 会员能自主约课，不再依赖微信群 | 预约自助率 = 小程序内成功预约人次 / 同期门店团长课总预约人次 | 假设目标 ≥ 70%（无历史基线，上线后 2 周用真实数据校准） | 上线后 2~4 周 |
| 名额不被浪费 | 候补转化率 = 由会员取消直接触发的转正成功人次 /（发生会员自助取消且候补队列非空）的次数（分子与分母都**只统计会员取消**这一个来源：排课数据变更导致的自动转正不计入分子或分母，见 AC5.5、§9.4"空位"一行。MVP 中会员侧的名额释放只有自助取消一个来源，见 AC3.1、AC3.3；门店不释放名额，见 AC3.3a） | 假设目标 ≥ 50% | 上线后 4 周 |
| 取消被系统记录 | 取消留痕率 = 小程序自助取消次数 /（小程序自助取消次数 + 门店侧人工登记的取消请求次数）。MVP 没有门店后台，分母靠门店前台按日人工登记、每周汇总（取数与责任人见 AC3.3a、§9.4、§7 待解决问题 8），属**人工估算口径** | 假设目标 ≥ 80% | 上线后 4 周 |
| 排队规则被信任 | 候补相关投诉/人工协调请求次数 | 假设目标 ≤ 3 次/周/店 | 上线后 4 周 |
| 教练准时开课可核 | 教练签到率 = 已有签到记录的课程数 / 已开课课程数 | 假设目标 ≥ 95% | 上线后 4 周 |
| 实现正确性（硬底线，不是体验指标） | 超卖次数（同一课程"有效预约人数" > 课程容量）、重复预约条数（同一会员同一课程有效预约 > 1 条）。口径见 §9.4：自动转正成功的会员已计入"有效预约"，不得再按"已转正"重复计数 | 0 | 持续监控 |
| 自动转正机制是否合理 | 转正后取消率 = 转正后由该会员自助取消的转正人次 / 自动转正人次（均为**人次**口径；按周、按试点门店合计统计，不按人次去重到人；同一空位被取消→转正→再取消链条式传递时，每一次取消分别计入分子、其对应的那次转正计入分母） | 假设目标 ≤ 40%；若 4 周持续高于 40%，说明名额被派给了不需要的人，按 §6.3 决策 2 改为"通知内一键让位"或恢复确认制 | 上线后 4 周 |
| 通知触达情况（观察项，不设硬目标） | 转正通知下发成功率 = 下发成功人次 / 自动转正人次（口径见 AC5.2、AC5.3） | 记录实际值，用于判断是否需要其他通知渠道 | 上线后 4 周 |

说明：以上目标值均为假设，门店侧无可用历史基线，不做"达标/不达标"的对外承诺，仅作为上线后判断功能是否有效的阈值。

## 2. 目标用户与场景

### 2.1 目标用户

| 角色 | 一句话画像 | 使用频率 | 最在意什么 | MVP 中要做的事 |
| --- | --- | --- | --- | --- |
| 会员（主要用户） | 25~40 岁上班族，已办门店会员卡，每周到店 2~3 次，习惯用微信，不愿意为约课多装一个 App | 每周 3~5 次打开小程序（多为晚间） | "想上的那节 20:00 的课能不能约上"、"别白跑一趟"、"取消别太麻烦" | 看课表、预约、取消、排队候补、接收自动转正通知（无需任何确认操作） |
| 团课教练 | 兼职/全职团课教练，一天 1~3 节课，上课前 10 分钟到店 | 每节课 1 次 | "签到别耽误上课"、"别被误认为没来" | 扫门店那张码签到；若自己有两节课的签到时间窗重叠，在"我的课程"里点选本次要签的课（见 AC6.8） |
| 门店运营（店长/前台） | 管 1 家门店，每天处理几十条约课与取消消息，还要核开课情况 | 每天多次 | "名单要准"、"别让我挨个通知候补" | MVP 只消费系统记录（签到状态、名单数据），不做管理界面，见 §3.3、§4 |

主要用户：**已办卡的健身房会员**——每周到店 2~3 次，最在意"想上的课能约上、约不上的能排队、取消不麻烦"，所有操作希望在微信里 30 秒内完成。

| 跨门店 | 跨门店通用课表、跨店预约 | P2 | 否 |
| 其他 | 课程评价、晒图、分享邀请、优惠券营销、数据看板 | P2 | 否 |

**MVP 开发范围 = 上表中标记"是"的 5 个功能模块（课表、预约、取消、候补与转正、签到）+ 2 项前置依赖能力。** P1、P2 一律不做。

### 3.2 为什么是这 5 项（价值判断）

一句话价值：**让会员在微信里 30 秒看到一个真实的名额池——约上、取消、排队都当场生效，门店不再需要人肉对齐名单。**

这 5 项构成一个最小闭环，缺一环闭环就断：

- 没有**课表**，会员不知道有什么课，后面全部无法发生；
- 没有**预约**，课表只是展示页，不解决"占位"；
- 没有**取消**，名额只进不出，候补永远不会有位置，且取消行为继续留在微信群里（问题 3 未解决）；
- 没有**候补**，满员后链路断裂，会员流失到微信群（问题 2 未解决，也是本次最有差异化的功能）；
- 没有**签到**，门店无法验证"课上没上、教练到没到"，上线后连效果都无法评估（问题 4 未解决）。

### 3.3 P0 前置依赖（不属于独立功能，不做界面）

以下能力只为上述 5 个功能提供身份与数据，**不在 MVP 中开发任何管理界面或会员中心**：

1. **会员身份**：微信授权登录后，用手机号匹配门店现有会员记录（假设现有会员系统含手机号），校验"会员有效 + 归属门店"；不匹配时进入引导页（联系门店），不做在线开卡。
2. **教练身份与门店关系**：教练用微信登录后与教练档案绑定（假设由门店运营在现有后台维护绑定关系），并维护"教练 → 归属门店"关系（包括同一教练可在多家门店授课的情形，至少需覆盖试点门店）。系统据此做两件事：①校验"我是不是这节课的教练"；②签到时的课程归属匹配（教练 → 门店 + 当日处于签到时间窗内的课程，见 AC6.1/AC6.3/AC6.8）。
3. **课程数据**：课程名、开始/结束时间、容量、教练、门店、状态。假设由门店现有排课系统或人工导入提供，字段与更新频率见 §6.4。

## 4. 不做的范围

MVP 明确不做、且**不允许以"顺手做一下"的方式插进本期**：

| 不做的内容 | 理由 |
| --- | --- |
| 在线支付、单次付费课、课包扣次、退款 | 涉及资金与对账、合规与退款流程，工程量与风险远超"把约课做对"；MVP 的所有课程均为已办卡会员权益内课程，不产生交易 |
| 私教课（一对一等非团课） | 与团课的名额/候补模型完全不同（需要教练档期匹配），不共用同一套容量逻辑，会显著复杂化数据模型 |
| 会员卡售卖、续卡、卡权益展示 | 属于交易与会员体系，已有线下/现有系统承担；本期只需读会员有效性，不需要写 |
| 跨门店（跨店课表、跨店预约、跨店候补） | 需要统一门店库存与结算规则，会引入"名额属于哪个门店""违约如何算"的规则争议；MVP 只服务会员归属的单一门店 |
| 门店运营管理后台（排课、取消课程、补签、名单导出界面）**以及任何门店侧写接口** | 门店已有排课/会员系统；本期只提供只读数据与查询接口，**不提供门店取消预约、改名单、补签的写接口**。因此会员在开课前 2 小时内联系门店取消时，门店只能线下登记，系统内该预约保持"已预约"、名额不释放（口径与取数见 AC3.3a、§6.4）。代价：教练漏签、会员迟到取消只能线下找门店处理（见 §7 R5、R12） |
| 自动转正后的"一键让位／放弃名额"入口 | 自动转正后若会员不去，走与普通预约相同的"自助取消"路径（距开课 ≥2 小时可取消，取消后名额立即转正给下一位，见 AC5.4、AC5.14）；再做一个"让位"入口与取消语义重复，且会让"名额是否已释放"出现两个来源。代价：转正后不去又没取消的会员不产生任何处罚，只留记录（AC5.14、§6.3 决策 6） |
| 短信/电话/微信服务号等通知渠道 | 有成本、需手机号授权，且与订阅消息重复；MVP 只用小程序内提示 + 订阅消息（一次性配额限制见 §7 R2） |
| 会员侧签到/核销、缺勤扣次、违约惩罚（如三次不去禁止预约） | 惩罚规则需要与服务条款、门店政策对齐，且 MVP 先验证"能不能约"，不做处罚；本期取消无惩罚；候补被自动转正后不取消又不到场，同样只记录不处罚（AC5.14） |
| 课程评价、社交分享、优惠券、数据看板 | 与核心闭环无关，属于增长与运营工具，优先级排到 P2 |
| 多语言、多端（iOS/Android 原生 App、H5） | 本期只做微信小程序一端 |

范围保护规则：任何新增需求必须说明"对应哪一个 P0 目标失败"，并同步从本期移除等量工作量，否则排到 P1 之后。

## 5. 用户故事与验收标准（P0）

约定：文中"剩余名额"= 课程容量 − 有效预约人数。口径定义（全篇统一，§9.4 同）："有效预约人数"= 状态为"已预约"的记录条数（**含候补自动转正成功的会员**，转正后其状态即变为"已预约"，见 AC5.1）；课程占用数就等于有效预约人数，**不存在"待确认"这类中间占用态**（自动转正不引入确认窗口），也不得额外计算"已转正"，避免重复计数导致误判超卖。"开课时间"以课程开始时间为准，所有时间判定以**服务器时间**为准，不信任客户端本地时间。

### 5.1 会员：查看课表 —— 用户故事与验收标准

**用户故事**：作为已绑定的会员，我想在小程序里按日期看到未来 7 天的团课课表（含课程名、教练、时间、门店、剩余名额与状态），以便决定约哪节课。

**验收标准**：
- AC1.1 Given 我是已绑定且会员有效的会员、门店有排课，When 我打开小程序首页，Then 默认展示"今天"的课程，按开始时间升序排列，每节课显示课程名、教练姓名、开始—结束时间、门店名、剩余名额（格式"剩余 3/20"）。
- AC1.2 Given 某课程的有效预约人数 = 课程容量，When 我查看课表，Then 该课程状态显示"已满"，按钮文案为"候补"，不显示剩余名额数字。
- AC1.3（边界）Given 今天是可预约窗口的最后一天（第 7 天），When 我查看课表，Then 日期切换只能到第 7 天（含），第 8 天不可选且无数据请求；接口返回空列表时页面显示"暂无课程"文案，不出现空白页或报错弹窗。
- AC1.4（异常）Given 课表接口超时或返回错误，When 我打开课表，Then 页面显示"加载失败，点击重试"且可重试成功；不展示缓存中的旧名额数据（避免用过期名额误导预约，宁可显示无数据）。
- AC1.5（异常）Given 我不是有效会员或未绑定门店，When 我打开课表，Then 显示引导页要求联系门店完成绑定，且不返回任何课程数据。
- AC1.6（边界）Given 当前时间已过某课程的开始时间，When 我查看当天课表，Then 该课程显示"已开课"或"已结束"，预约与候补按钮均不可点击，且按钮置灰有对应文案说明，而不是点击后报错。

### 5.2 会员：预约团课 —— 用户故事与验收标准

**用户故事**：作为会员，我想一键预约还有名额的团课并立刻知道结果，以便确保自己占到一个位置。

**验收标准**：
- AC2.1 Given 课程剩余名额 ≥1 且距开课 ≥30 分钟，When 我点击"预约"并在确认弹窗（展示课程名、时间、教练、门店、取消规则"距开课 ≥2 小时可自助取消"）点击确认，Then 提交成功，按钮变为"已预约"，剩余名额减 1，"我的预约"列表出现该课程且状态为"已预约"。
- AC2.2（边界-并发）Given 某课程只剩 1 个名额、3 位会员在同一秒点击确认，When 请求到达服务端，Then 恰好 1 人预约成功，另外 2 人收到"名额已被抢完"提示，提示中提供"加入候补"入口；课程剩余名额为 0，不出现超卖（同一课程有效预约人数不超过容量）。
- AC2.3（边界-重复提交）Given 我已经预约成功这节课，When 我重复点击预约按钮、或网络重试导致同一请求重复到达，Then 系统返回"你已预约该课程"，不新增第二条预约记录、不重复扣减名额（服务端对"会员 + 课程"的有效预约做唯一约束）。
- AC2.4（边界-截止时间）Given 距开课时间不足 30 分钟，When 我查看或点击"预约"，Then 按钮不可点击并提示"已过预约截止时间"；直接调用接口也返回拒绝（不依赖前端拦截）。
- AC2.5（边界-时间冲突）Given 我已有一条未开始课程的占用记录（"有效预约／候补中"任一），When 我再预约与其时间重叠的课程（开始/结束时间有交集），Then 提示"与『课程名』『开始—结束时间』时间冲突"并阻止提交，不占用名额；冲突口径与 3 个校验点见 §6.2 B9。
- AC2.6（异常）Given 提交预约时网络中断或服务端返回 5xx，When 预约结果未知，Then 页面提示"预约结果未确认，请在'我的预约'中查看"，并以服务端最终记录为准；会员可重试且重试幂等（不产生重复预约）。

### 5.3 会员：取消预约 —— 用户故事与验收标准

**用户故事**：作为会员，我想在来得及的情况下自己取消预约，以便临时有事时不占着名额，也不必在群里解释。

**验收标准**：
- AC3.1 Given 我预约了某课程且距开课时间 ≥2 小时，When 我在"我的预约"点击"取消预约"并确认，Then 预约状态变为"已取消"，剩余名额立即 +1；若该课程候补队列非空，则**在同一事务内**立即触发队首**自动转正**（无需会员确认，见 AC5.1），该空位不再对其他会员开放。
- AC3.2（边界-临界值）Given 距开课时间恰好等于 2 小时，When 我取消，Then 允许取消（规则定义为"距开课 ≥2 小时可自助取消，<2 小时不可自助取消"）；判定用服务器时间，客户端改时间无效。
- AC3.3（边界）Given 距开课时间不足 2 小时，When 我点击"取消预约"，Then 按钮不可点击并显示"距离上课不足 2 小时，无法自助取消，请联系门店"；直接调用接口返回拒绝。
- AC3.3a（边界-门店侧口径，本期无门店后台）Given 会员在开课前 2 小时内联系门店要取消，When 门店处理，Then MVP 下门店**没有任何系统写能力**（无管理后台、无取消写接口，见 §4、§6.4）：门店只能线下登记（在现有纸质/工作群登记表按日记录），系统内该预约保持"已预约"、名额不释放、不触发候补转正、会员端不显示任何违约记录；该预约在开课时间到达后按 AC3.7 变为"已结束"。即便门店临时找到替补会员，系统内该课仍满员、名额不释放，替补会员能否拿到该名额取决于联系门店时的时点，按 2 小时时点分叉：**若距开课 ≥2 小时**，替补会员可由自己在小程序内操作——课程此刻已满，只能加入候补（AC4.1），等有人按 AC3.1 自助取消后由系统把空位自动转正给他（队列中若有其他候补，按 B2 先到先得排在他前面）；**若距开课 <2 小时**，预约入口因满员不可用、候补入口已按 AC4.7 显示"候补已截止"（不可点），替补会员**无法通过小程序取得该名额**，只能由门店在线下另行安排（如现场加位、或线下登记后自行协调）；该名额在原预约按 AC3.7 变为"已结束"之前都不会回到可预约状态。门店登记的人工取消请求量就是 §1.2"取消留痕率"的分母来源（取数口径见 §9.4）。
- AC3.4（异常-取消已签到课程）Given 教练已对该课程完成签到（此时必然已过开课时间、距开课 <2 小时），When 我尝试取消该预约，Then 系统拒绝并返回"课程已开始，无法取消"，该预约不进入"已取消"，其状态按 §6.2 C 在开课时间到达后变为"已结束"（不依赖教练是否签到）；该课程也不再触发任何候补转正（与 AC5.5 一致）。
- AC3.5（边界-重复取消）Given 我已取消过该预约，When 我再次提交取消请求（含网络重试），Then 返回"该预约已取消"，不重复释放名额（避免名额被重复 +1 而虚高）。
- AC3.6（边界）Given 我取消后该课程仍有名额，When 我重新预约，Then 允许，且无任何惩罚记录（本期不做取消次数限制、不做违约扣次）。
- AC3.7（异常-预约终态与签到解耦）Given 某课程的开课时间已经到达（无论教练是否签到、是否漏签），When 我打开"我的预约"，Then 该条预约显示"已结束"，不再出现可点击的"取消预约"按钮（位置保留但置灰，文案"课程已开始"）；教练是否签到不改变会员侧这条显示。教练漏签的场次不生成签到记录，只由门店按"未签到"在名单/签到数据中核对（AC6.2、§7 R5），**不会**让这条预约永远停在"已预约"。

### 5.4 会员：满员后排队候补 —— 用户故事与验收标准

**用户故事**：作为会员，我想在课程满员时加入候补队列，以便有人取消时我按顺序有机会补上。

**验收标准**：
- AC4.1（触发条件）Given 课程状态为"已满"（有效预约人数 = 容量）、候补队列未达上限且距开课 ≥2 小时，When 我点击"候补"，Then 我加入候补队列，页面显示我的位次（如"候补第 3 位"）与规则说明"有空位时系统自动为你占位，不需要你操作"，课程上显示"候补 3 人"。若课程未满员，则"候补"按钮不可见/不可点，点击只能走预约流程。位次显示口径见 B10：位次 = 我在队列中的当前顺序，"已自动转正／已退出／已失效"的记录不再占位次。
- AC4.2（排队规则）Given 多名会员先后加入同一课程的候补，When 展示队列或发生转正，Then 顺序严格按"加入候补成功"的服务器时间先到先得；时间相同（同秒/同毫秒）时按服务端接收请求的顺序号排序；**不使用**会员等级、到店次数、消费金额等任何加权或插队规则。
- AC4.3（边界-重复占位）Given 我已在该课程候补队列中，When 我再次点击候补或重复提交请求，Then 返回"你已在候补队列中"，不新增第二个候补位（同一会员 + 同一课程最多一个有效候补位）。
- AC4.4（边界-预约与候补互斥）Given 我已成功预约该课程，When 我尝试加入候补，Then 系统拒绝并提示"你已预约该课程"；反向同理：我在候补中时若通过其他路径占用了该课程名额，候补位自动作废。跨课程的时间重叠由 B9 的 3 个校验点拦住（AC2.5/AC4.9/AC5.8），本条件是并发兜底。
- AC4.5（边界-队列上限）Given 某课程候补人数已达上限（假设上限 = 课程容量，见 §6.2 A4），When 我点击"候补"，Then 按钮不可点击并提示"候补已满"，直接调用接口同样返回拒绝。
- AC4.6（边界-主动退出）Given 我在候补队列中，When 我点击"取消候补"并确认，Then 我立即退出队列，我之后的会员位次自动前移（显示位次 -1），我不产生任何惩罚或限制记录。若我刚被**自动转正**（已不在候补队列），候补卡片显示"已自动转正（已计入我的预约）"，点击进入"我的预约"，此后的取消行为见 AC5.4、AC5.14。
- AC4.7（边界-候补截止）Given 距开课时间不足 2 小时且课程仍满员，When 我查看该课程，Then 不再接受新的候补，按钮显示"候补已截止"（不可点）；已有队列按 AC5.5 处理（此后也不再发生自动转正）。候补截止时间与取消截止时间一致（原因见 §6.2 B3）。**"仍满员"的含义**：该时刻课程"有效预约人数 = 容量"，即该时刻课程没有任何空位；若课程此刻**本身已有空位**（来源只有两类：①截止前已释放但未被候补占用；②排课数据变更，如门店调大容量——**本 AC 的场景是"距开课 <2 小时"，因此这里的容量调大指发生在该时点之后的变更，按 AC5.5 只产生可被会员主动预约的空位、不触发自动转正**；若容量调大发生在距开课 ≥2 小时且队列非空，会先按 AC5.1 触发队首自动转正、不会留下空位；**不存在**截止点后有人取消或门店在系统内释放名额这条来源，见 AC3.3、AC3.3a、AC5.1、AC5.5、AC5.15），主按钮就应是可点的"预约"（距开课 <30 分钟时为不可点的"已过预约截止时间"），见 AC5.5、AC5.15。
- AC4.8（异常）Given 加入候补时未授权订阅消息（用户点了拒绝），When 我提交候补，Then 我仍能成功加入候补（**也仍会在有空位时被自动转正**），但候补卡片上显示"未开启提醒：排到后会为你自动占位，请自行到小程序查看，不能到场请在开课前 2 小时前取消"，转正后只能靠站内提示（见 AC5.3）。
- AC4.9（边界-加入候补时的时间冲突）Given 我已有一条时间重叠的占用记录（"有效预约／候补中"任一），When 我点击与该时间重叠课程的"候补"，Then 系统拒绝并提示"与『课程名』『开始—结束时间』时间冲突"，不加入队列；课程页该课的"候补"按钮置灰并显示同一原因；直接调用接口同样返回拒绝（口径见 §6.2 B9）。

### 5.5 会员：候补自动转正（无需确认，转正后通知）—— 用户故事与验收标准

> 本节 v1.3 按 CEO 意见重写：**删除"会员须在 15 分钟内确认"，改为系统自动转正、无需会员确认，转正完成后立即通知会员**。因此不再存在"待确认／倒计时／超时顺延"这类状态；名额的释放与转正在服务端同一事务内完成。

**用户故事**：作为候补中的会员，我希望排到我时系统自动把名额给我并通知我，以便我不用一直盯着手机抢确认，同时我也能自己决定去不去。

**验收标准**：
- AC5.1（触发与自动转正）Given 我是某课程候补队列第 1 位，When 课程出现 1 个空位（空位只有两个来源，见 AC5.5 与 §9.4"空位"一行：①有会员在开课前 ≥2 小时自助取消；②排课数据变更，如门店调大容量）、且此刻距开课 ≥2 小时，Then 系统在**同一事务内自动**把我转为"已预约"（不需要我做任何操作）：我的候补记录离开队列、终态记为"已转正（自动）"，我之后的会员位次全部前移 1 位，课程剩余名额回到 0（空位已归我；若该空位来自来源②容量调大，课表分母随排课数据同步变化，例如显示"剩余 0/21"）。**无论空位来自哪一个来源，转正规则完全相同**（先到先得、同一事务、无需会员确认）；因此 AC5.1 的触发条件是"课程出现空位"，不限于会员取消。触发过程不需要我打开小程序、不需要我点任何按钮。
- AC5.2（转正通知）Given 我已被自动转正，When 转正事务提交完成，Then 系统在 30 秒内尝试向我下发 1 条"候补已自动转正"订阅消息，文案必须包含课程名、开课时间、门店，以及"不能到场请于开课前 2 小时前在小程序内取消"；站内同时生成提示（首页横幅 + "我的预约"可见）。**顺序要求**：先落库转正、再发通知，通知失败不回滚转正结果（AC5.3）。**模板约束（需工程师在微信小程序后台核实）**：微信订阅消息模板文案不可自定义（§9.2），上述文案须由模板中可填的字段拼出；若模板字段不足以承载取消指引，则至少保证课程名与开课时间，取消指引改由站内横幅承载（AC5.3），并同步评估替代模板（§6.4）。
- AC5.3（降级-转正通知下发失败）Given 我未授权订阅消息，或消息因无配额/接口报错下发失败，When 转正已经发生，Then 转正结果**保持有效**（我仍在"我的预约"里、状态"已预约"），失败必须落库（记录原因：no_quota / not_authorized / api_error）；我下次打开小程序时，首页顶部显示横幅"你已被自动转正：『课程名』『开课时间』，不能到场请在开课前 2 小时前取消"，"我的预约"页与"我的候补"角标同步提示。
- AC5.4（与取消规则一致，重点）Given 我被自动转正，When 我想取消，Then 适用与普通预约**完全相同**的规则：距开课 ≥2 小时可自助取消（取消后名额立即释放并按 AC5.1 自动转正给下一位），距开课 <2 小时不可自助取消、只能联系门店（AC3.3、AC3.3a）。**规则自洽性保证**：自动转正只发生在"距开课 ≥2 小时"的时刻（AC5.5），因此每一个被自动转正的会员从转正那一刻起都至少拥有一段时间可以自助取消——不会出现"被系统派了名额、却已经没有取消权"的情况（这是自动转正方案能成立的前提；边界说明：若转正恰好发生在距开课 = 2 小时的那一刻，被转正者仍享有 AC3.2 定义的、距开课恰好 2 小时仍可取消的权利，但该可取消窗口只有约 1 分钟，实际很难用上——这属于规则边缘而非规则冲突，MVP 不改动参数；若上线后此类投诉增多，把自动转正截止提前到早于取消截止（如 3 小时）列入 P1）。
- AC5.5（边界-候补与自动转正的截止时间）Given 距开课时间不足 2 小时，When 课程仍有候补队列，Then 系统不再接受新的候补（AC4.7）、**不再发生任何自动转正**；队列中所有"候补中"记录同时进入终态"候补已截止（未排到）"（AC5.12）。此时若该时刻课程**本身已有空位**（有效预约人数 < 容量），该空位回到可预约状态：课程由"已满"回到"未满"、课表按 AC1.1 显示"剩余 x/y"，课程页主按钮为**可点**的"预约"（距开课 <30 分钟时为"已过预约截止时间"且不可点），可由其他会员主动预约；**空位来源必须写清（否则会被误认为存在截止后释放名额的新路径）**：MVP 中空位只有两个来源——①会员在开课前 ≥2 小时的自助取消之后未被候补占用（队列已空，或队首因时间冲突被跳过且其后无人可顺延，见 AC5.8）；②排课数据变更，例如门店把该课容量调大（§6.4）——**这一来源必须按发生时间分叉**，否则会与 §6.2 C、§6.3 决策 2③ 相反：发生在距开课 ≥2 小时且队列非空时，按 AC5.1 触发队首自动转正，课程保持"已满"、**不留下空位**（空位在产生的那一刻就被候补占用）；发生在距开课 ≥2 小时但队列已空时，留下的空位同样由会员主动预约；**只有发生在距开课 <2 小时时，才留下一个可被会员主动预约的空位且不触发自动转正**（即本 AC 上文描述的"主按钮为可点的『预约』"）。**不存在**开课前 2 小时后有人取消（AC3.3 直接拒绝）或门店在系统内释放名额（AC3.3a 只线下登记、名额不释放、不触发转正）这两条来源；因此本 AC 不引入任何截止后释放名额的新入口。若课程此刻仍满员（有效预约人数 = 容量，没有任何空位），按钮为"候补已截止"（不可点，AC4.7）。**为什么保留这个截止时间**：自动转正不需要会员操作，若在开课前 2 小时内还继续派名额，会员很可能根本不知道、也来不及到场，而取消截止已过，名额会被白占并引发"凭什么给我占位"的争议（§6.2 B3、§6.3 决策 2）。
- AC5.6（边界-多人同时取消）Given 同一课程 3 位会员几乎同时取消、释放 3 个名额且队列中有 ≥3 人，When 系统处理，Then 队列前 3 位**各自自动转正**（各自独立、无需任何人确认），3 条候补记录均记为"已转正（自动）"、3 条预约状态为"已预约"，课程立即回到"已满"，且有效预约人数 ≤ 容量（无超卖）。
- AC5.7（异常-转正与普通预约争同一个空位的并发）Given 某课程刚释放 1 个空位、队列第 1 位正在被自动转正，When 同一时刻有另一位会员通过旧页面/缓存提交预约请求，Then 以服务端事务顺序为准：转正先完成 → 该会员收到"名额已被抢完"，可在课程仍满员且未到截止时间时加入候补（AC4.1）；预约先完成 → 队列第 1 位不被转正、继续留在队列。两种结果都不得出现超卖（有效预约人数 ≤ 容量）。
- AC5.8（边界-自动转正前的时间冲突，跳过而非占位）Given 我排队时无冲突，但等待期间我通过其他路径占用了与该课时间重叠的时段，When 系统准备为我自动转正前执行 B9 校验，Then **不转正**：把我移出队列并记"因时间冲突失效"，该空位在**同一事务内立即**顺延给下一位候补（自动转正），我的候补卡片显示"因与『课程名』时间冲突，已跳过"；我不被计入任何违约统计、不产生通知、不受任何限制。
- AC5.9（异常-自动转正处理失败与对账）Given 一次取消与自动转正的处理中途失败（进程重启、依赖超时等；若二者在同一事务内实现，则事务未提交即整体回滚、不产生空位，本 AC 同时覆盖回滚后的重放与提交后队列读取等环节异常），When 系统恢复，Then 必须由重试任务在 1 分钟内把该空位收敛为已归队首（自动转正）的状态，且**在收敛完成前该空位不得被第三人预约**（与 B6 一致：对外不存在名额空着但尚未归属的状态）；**不允许出现**"名额已释放、队列第 1 位却未转正、名额被第三人约走而队列仍停在第 1 位"的中间状态；出现重试或对账差异必须告警（§7 R13），人工可查。
- AC5.10（边界-自动转正后同样受时间冲突约束）Given 我已被自动转正（"我的预约"里状态"已预约"），When 我尝试预约或候补一节与它时间重叠的课程，Then 与普通预约一致地被拒绝，提示"与『课程名』『开始—结束时间』时间冲突"（B9 第 1、2 个校验点）；自动转正不会给我额外占用多个时段的能力。
- AC5.11（边界-候补记录的终态枚举）Given 我查看"我的候补"里的任意一条记录，When 该记录已不再排队，Then 它必须且只能是以下五种终态之一：①"已转正（自动）"（AC5.1）②"主动退出"（AC4.6）③"因时间冲突失效"（AC5.8）④"候补已截止（未排到）"（AC5.12）⑤**自动作废**（并发兜底：我在候补期间通过其他路径占用了同一课程名额，见 AC4.4）；**不允许出现"待确认／超时未确认／确认中"等状态**，也不允许一条记录同时属于两种终态（v1.3 起取消确认制）。
- AC5.12（边界-候补截止后的队列终态与会员端表现）Given 开课前 2 小时到达时课程仍有候补队列，When 我打开"我的候补"，Then 我的记录显示终态"候补已截止（未排到）"，卡片文案为"该课程已停止候补，未排到你"，仍展示截止时的位次（便于解释顺序），且**不再显示"取消候补"按钮**（无需任何操作）；课程页此时若课程回到"未满"，按钮为可点的"预约"（距开课 <30 分钟时为"已过预约截止时间"）。该终态单独统计为"候补截止失效人次"，不计入任何"违约/超时"指标。
- AC5.13（边界-位次前移时我看到什么）Given 我是候补第 2 位，When 队首被自动转正（或主动退出、或因时间冲突失效），Then 我的位次立即前移为"候补第 1 位"，卡片可提示"下一有空位将自动为你占位（无需操作）"；我没有任何"确认／等待倒计时"的按钮或提示（原"队首正在确认中，请等待"的交互在 v1.3 已删除）。
- AC5.14（边界-转正后来不了怎么办）Given 我被自动转正后因故不能到场，When 我打开小程序，Then 我有两条路径：①距开课 ≥2 小时时在"我的预约"里自助取消（等同 AC3.1，取消后名额立即释放并自动转正给下一位）；②距开课 <2 小时时取消入口不可用，页面提示"距离上课不足 2 小时，无法自助取消，请联系门店"（门店只能线下登记，系统内名额不释放，AC3.3a）。若我既未取消也未到场，MVP **不做任何处罚或权益扣减**，只保留转正与签到记录供门店核对（§6.3 决策 6）；"一键让位"入口明确不做（§4）。
- AC5.15（边界-截止时间前后的空位处理，含对照）Given 一节 20 人容量的课 19:00 开课、当前满员（20 条有效预约）、候补队列中有 3 条"候补中"记录，Then：①若 16:50 有人取消（距开课 >2 小时），队首**自动转正**，课程保持"已满"（20 条有效预约），队列剩 2 人；②17:00（开课前 2 小时）到达时，剩余 2 条"候补中"记录进入终态"候补已截止（未排到）"（AC5.12），此后不再自动转正；③（另一种情形，用来说明空位来源）若 17:00 前释放的空位一直没有被候补占用（例如 16:50 的取消因队首时间冲突被跳过、其后无人可顺延，或队列在截止前已空），或门店在排课数据中调大了容量（§6.4）——**容量调大这一来源必须按发生时间分叉**：若在 17:00 之前（距开课 ≥2 小时）调大且当时队列中仍有"候补中"记录，队首会按 AC5.1 在同一事务内被自动转正、课程保持"已满"，17:01 不会再看到空位，**这个情形不构成本条要说明的对象**；只有在 17:00 之后（距开课 <2 小时）调大容量、或在 17:00 之前调大但当时队列已空时，才会留下空位——则 17:01 查看时该课程**本身已有空位**（有效预约人数 < 容量；**不可能来自 17:00 之后的会员取消或门店释放名额**：AC3.3 直接拒绝距开课 <2 小时的会员自助取消，AC3.3a 规定门店只线下登记、名额不释放、不触发转正），该空位**不由候补占用**：课程由"已满"回到"未满"、课表显示"剩余 1/20"（若空位来自容量调大，分母随排课数据同步变化，如显示"剩余 1/21"）、课程页主按钮为**可点**的"预约"（不是"候补已截止"），其他会员在 18:30（开课前 30 分钟）前可以成功自助预约并约走该名额（约成功后显示"0/20"，容量调大时为"0/21"；状态"已满"、按钮变"候补"）；④18:31 及以后查看时，按钮为"已过预约截止时间"（不可点）。反例（对照）：同一时刻若课程仍满员、没有任何空位，按钮才是"候补已截止"（不可点，AC4.7）。

### 5.6 教练：上课签到 —— 用户故事与验收标准

**用户故事**：作为团课教练，我想在到店后用自己的账号为这节课签到，以便门店知道我已到岗、课程准时开始。

**验收标准**：
- AC6.1 Given 我是某课程的绑定教练、当前时间在该课程的签到时间窗内（开课前 30 分钟至开课后 15 分钟）、且当前时间只落在我 1 节课的时间窗内，When 我扫描门店张贴的那张固定二维码（载荷只含门店标识），Then 系统按"教练 + 服务器时间"匹配出这 1 节课程并完成签到，页面显示"签到成功—『课程名』（签到时间 xx:xx）"，系统记录教练 ID、课程 ID、签到时间、设备标识与定位坐标；**课程归属由服务端判定，会员与教练都不能手动指定**。
- AC6.2（边界-时间窗）Given 当前时间早于开课前 30 分钟，When 我扫码签到，Then 提示"未到签到时间（开课前 30 分钟开始签到）"；Given 当前时间晚于开课后 15 分钟，When 我扫码签到，Then 提示"签到时间已过，请联系门店运营处理"，不生成签到记录（本期无线上补签，见 §4）。
- AC6.3（异常-无法确定课程归属）Given 我扫码时，我当日课程中没有任何一节的签到时间窗包含当前时间（我今日无课／全部未到时间／全部已过时间），或我不是该门店的教练，When 我提交签到，Then 系统拒绝并按原因返回具体文案（"你今日无课"/"未到签到时间（开课前 30 分钟开始签到）"/"签到时间已过，请联系门店运营处理"/"你与该门店无教练关系"），不生成签到记录。
- AC6.4（边界-重复签到）Given 我已成功签到这节课，When 我再次扫码，Then 提示"已签到（签到时间 xx:xx）"，不生成第二条签到记录（同一课程 + 同一教练只有一条有效签到记录）。
- AC6.5（代签风险）Given 我的定位与门店坐标距离 > 500 米、或我未授权定位，When 我扫码签到，Then 签到仍然允许，但记录被标记"疑似代签/无定位"并写入风控日志，供门店运营事后核对；MVP 不做阻断（理由与代价见 §6.3 决策 4）。
- AC6.6（异常-弱网）Given 门店网络差导致签到请求失败，When 我重试，Then 以服务端记录为准、重试不产生重复记录；连续失败时页面提示"网络异常，请重试；持续失败请联系门店运营"，并保留重试入口。
- AC6.7（与其他功能的一致）Given 我已完成本节课程签到，When 会员查看这节课，Then 会员端预约/取消按钮按 AC3.4、AC1.6 处理（不可取消、不再转正），签到记录可被门店按课程通过只读查询或导出（§6.4）。
- AC6.8（边界-签到时间窗重叠时的课程归属）Given 我连上相邻两节课（如 19:00-19:45 与 20:00-20:45，签到时间窗分别为 18:30-20:00 与 19:30-20:15，在 19:30-20:00 重叠 30 分钟），When 我在 19:45 扫同一张门店二维码，Then 系统判定"命中 2 节"，展示教练端"我的课程"列表让我点选（列表只列这两节），我选定后**只为被选课程**生成签到记录，另一节保持"未签到"；若我随后在 20:05 再扫一次并选定第二节，第二节也生成签到记录；若我扫码后不点选直接退出，则不生成任何签到记录（不默认归给任何一节）。同一节课重复点选签到只保留一条记录（AC6.4）。

## 6. 方案概述

### 6.1 核心流程

**会员主流程（微信小程序内）**：进入小程序 → 微信授权登录并校验会员/门店归属 → 看到"今天"的课表（可按日期切换到第 7 天，每节课显示课程名、教练、时间、门店、剩余名额或"已满"）→ 有名额时点"预约"（确认弹窗展示课程信息与取消规则"距开课 ≥2 小时可自助取消"；提交时校验时间冲突，与已有占用时段重叠则直接拒绝，见 B9）→ 预约成功，按钮变"已预约"，"我的预约"可见；无名额时点"候补"（同样做冲突校验），看到自己的位次与规则说明"有空位时系统自动为你占位，不需要你操作；不能到场请在开课前 2 小时前取消" → 排到第 1 位且有人取消时，系统**自动**把名额给我（无需我确认）并立即下发订阅消息 + 站内横幅提示，"我的预约"里直接出现该课程 → 若不能到场，距开课 ≥2 小时前可以自助取消，取消后名额立刻释放并自动转正给下一位；<2 小时不可自助取消，页面明确告知需联系门店（门店只能线下登记，系统内名额不释放，见 AC3.3a）；开课时间到达后该预约显示"已结束"（AC3.7）。

**教练流程（微信小程序内）**：教练用微信登录并与教练档案绑定 → 门店前台/教室张贴**一张固定的签到二维码**（全店同一张，载荷只含门店标识，不含课程信息）→ 到店后扫这张码，服务端按"教练 + 服务器时间"匹配出当前处于签到时间窗（开课前 30 分钟~开课后 15 分钟）内的我的课程：只命中 1 节 → 直接签到成功；命中 2 节及以上（连上相邻两节课）→ 展示教练端"我的课程"列表，由我点选一节后签到（AC6.8）；命中 0 节 → 拒绝并给出具体原因 → 签到成功记录课程 ID、签到时间、设备与位置（定位距离 >500 米或未授权定位时标记"疑似代签"），门店可通过只读查询接口或导出核对。

**门店运营流程（MVP 不含界面）**：沿用现有排课/会员系统提供课程与人员数据；通过查询接口或导出获得每节课的预约名单、候补队列、签到状态与"疑似代签"标记，用于核对开课情况与处理异常。

交付的价值：会员侧把"看课、占位、取消、排队"从微信群搬到 30 秒可完成的自助流程；门店侧第一次有了准确的名单与签到记录，前台不用再人肉对齐候补顺序。

### 6.2 关键规则与参数（候补 ↔ 取消一致性）

A. 时间与容量参数（**均为假设，需门店运营确认，见 §7**）

| 编号 | 参数 | 取值 | 说明 |
| --- | --- | --- | --- |
| A1 | 课表可见窗口 | 今天起 7 天 | 与门店排课周期对齐 |
| A2 | 预约截止 | 开课前 30 分钟 | 保证前台/教练拿到最终名单 |
| A3 | 自助取消截止 | 开课前 2 小时 | 与候补截止同一时刻，见 B3 |
| A4 | 候补队列上限 | = 课程容量（如 20 人课程最多 20 人候补） | 避免无限排队造成的期望落空 |
| A5 | 候补自动转正截止 | = 自助取消截止（开课前 2 小时），**无确认窗口** | 自动转正不需要会员操作，因此没有"多久内确认"这个参数；截止时间与取消截止对齐，保证被转正的会员一定还有自助取消权，见 B3、AC5.4、AC5.5 |
| A6 | 签到时间窗 | 开课前 30 分钟 ~ 开课后 15 分钟 | 覆盖早到与轻微迟到 |
| A7 | 疑似代签判定 | 定位距离门店 > 500 米或未授权定位 | 软校验，只标记不阻断 |

B. 候补与取消的一致性（这是本期最容易出错的规则，单独列出）

| 编号 | 规则 | 原因 |
| --- | --- | --- |
| B1 | 触发条件唯一：只有当课程"有效预约人数 = 容量"（即已满）时，才出现候补入口 | 避免未满员也被候补，导致名额和队列双轨 |
| B2 | 排队先到先得，只按加入候补的服务器时间排序，无任何加权 | 规则可解释、可复现，会员不会怀疑被插队 |
| B3 | **取消截止时间 = 候补自动转正截止时间 = 开课前 2 小时**；开课前 2 小时内不再自动转正（见 A5、AC5.5） | 自动转正不需要会员操作，因此更要保证"系统派给的名额都还有取消权"：若在开课前 1 小时才自动转正，会员可能根本不知道、来不了又无法取消，会产生"凭什么给我占位"的争议，名额实际被浪费。区分：会员**主动预约**（开课前 30 分钟前仍可约）不是被动分配，取消规则对所有主动预约者一致。代价：开课前 2 小时内**不再因会员取消或门店释放名额而产生新空位**（会员在距开课 <2 小时取消会被直接拒绝，AC3.3；门店不释放名额，AC3.3a），而截止前已释放却未被候补占用的既有空位只能靠其他会员主动预约填补，不再走候补（接受，见 §6.3 决策 2）。例外与口径：排课数据变更（如门店调大容量，§6.4）可能带来新空位，按时点分叉——发生在距开课 ≥2 小时且队列非空时，按 AC5.1 触发队首自动转正；发生在距开课 <2 小时时，只产生可被会员主动预约的空位、不触发自动转正（AC5.5、AC5.15③） |
| B4 | **自动**转正成功后即按普通预约对待：取消规则、冲突校验、签到后不可取消全部一致 | 候补只是获取名额的另一种途径，不产生特权或额外限制（AC5.4、AC5.10） |
| B5 | 会员取消后名额立即转给下一位（其本人若仍想上该课需重新排队，不保留原位次）；被自动转正后取消同理 | 队列公平性优先于个人补偿，也让"取消即让位"的语义唯一 |
| B6 | **无中间态**：自动转正与"取消／释放名额"在同一事务内完成，名额直接从取消者转到队首会员，不存在"名额锁定待确认"的中间状态 | 自动转正没有"通知—确认—超时"的过程，因此也不存在"通知期间名额被抢走"或"锁定超时名额悬空"的问题；对外任何时刻都不会出现"名额空着但已被锁定"的状态（AC5.1、AC5.7） |
| B7 | 教练签到（开课后）后，课程不再接受取消、不再触发转正、队列整体失效 | 已开课的名单需要稳定，避免上课期间名单变化 |
| B8 | 同一会员对同一课程：最多 1 条有效预约 + 1 个有效候补位，二者互斥 | 防止一个人占多个位置，保证公平 |
| B9 | **时间冲突的唯一口径**：同一会员在同一时间范围内（开始/结束时间有交集）最多只允许 1 条"占用"记录，"占用"= 有效预约 ／ 候补中（自动转正后的记录已属于"有效预约"）。共 3 个校验点：提交预约、加入候补、**自动转正前**。命中冲突时的行为：提交预约/加入候补 → 直接拒绝并提示冲突课程（AC2.5、AC4.9）；自动转正前 → 不转正、跳过该会员、名额在同一事务内立即顺延给下一位（AC5.8） | 堵住"候补期间偷偷占上两个重叠时段"的漏洞，让 AC2.5 与转正规则给出同一个结果，而不是互相打架；自动转正没有"点击确认"这个动作，校验点由 4 个减为 3 个；代价见 §6.3 决策 7 |
| B10 | **位次语义**：候补位次 = 会员在队列中的当前顺序；会员"已自动转正／主动退出／因冲突失效"的那一刻即离开队列，其后会员位次立即前移；队列中不存在"占着位次但不占名额"的中间状态 | 让队列第 2 位看到确定的位次，避免位次跳变引发对排队公平性的怀疑（AC5.13）；工程师与测试只需按"是否已离开队列"一个判断实现 |
| B11 | **自动转正后来不了**：走与普通预约相同的自助取消路径（距开课 ≥2 小时可取消，取消后名额立即自动转正给下一位，AC5.14）；不单独做"让位/放弃"入口（§4）；未取消又未到场不处罚，只留记录供门店核对 | 名额已经占用在该会员名下，唯一需要保证的是"他还有机会把名额还回来"，而现有取消入口已能完成这件事；与"取消无惩罚"的总体立场一致（决策 6） |

C. 状态机（供工程师与测试对齐）

- 课程：未满 → 已满 → 已开课 → 已结束；出现"已满"才允许候补；**已满 → 未满**（仅当课程**本身已有空位**、且该空位没有被候补占用时发生，见 AC5.5、AC5.15；空位的合法来源只有两个：①会员在开课前 ≥2 小时的自助取消之后未被候补占用（队列已空，或队首因时间冲突被跳过且其后无人可顺延）；②排课数据变更，例如门店调大容量（§6.4）——**该来源必须按发生时间分叉**：发生在距开课 ≥2 小时且队列非空时，按 AC5.1 **立即**触发队首自动转正，课程保持"已满"、状态不落到"未满"；只有在距开课 <2 小时、或在距开课 ≥2 小时但队列已空时，才真正落到"未满"（AC5.5）；**实现上不得新增截止后释放名额的入口**——会员在距开课 <2 小时取消时接口直接拒绝（AC3.3），门店侧没有任何写能力、不能取消预约或释放名额（AC3.3a、§4、§6.4）；回到"未满"后课程页主按钮随之变为可点的"预约"，直到开课前 30 分钟）；距开课 <2 小时时不再接受新候补、也不再自动转正（AC4.7）。
- 预约：已预约 → 已取消（**仅会员自助取消会触发取消写操作**；门店线下登记的取消不在系统内产生"已取消"记录，见 AC3.3a）/ 已结束（**开课时间到达即置**，与教练是否签到、是否漏签无关，见 AC3.7）；已预约期间受取消截止时间（距开课 ≥2 小时）约束。**教练是否签到不进预约状态机**：签到是独立字段（未签到 / 已签到 / 含疑似代签标记），仅用于门店核对与"签到率"指标，避免漏签把预约卡死（AC6.2、R5）。
- 候补：候补中（含位次，见 B10）→ **已转正（自动，无需会员确认；转正后其预约进入"已预约"，候补记录离开队列）** ／ 主动退出（AC4.6）／ 因时间冲突失效（自动转正前发现冲突，见 AC5.8）／ **候补已截止（未排到）**（开课前 2 小时到达时对全体"候补中"记录生效，见 AC5.5、AC5.12）／ **自动作废**（并发兜底：会员在候补期间通过其他路径占用了同一课程名额，见 AC4.4）。**不存在"待确认／超时未确认／确认中"这类状态**（v1.3 起取消确认制）。
- 签到：未签到 → 已签到（含疑似代签标记）；不会从已签到回退，重复签到不新增记录；签到归属由服务端按"教练 + 服务器时间"判定，重叠时由教练点选（AC6.8）。

### 6.3 关键决策

1. **选择"独立小程序"而不是"先做 H5 / 公众号菜单"**，因为目标用户是"不愿多装 App、日常只用微信"的会员，且订阅消息通知必须依赖小程序能力（H5 无法可靠触达）。代价：受小程序类目与订阅消息配额限制，通知能力受限（见 §7 R2）。
2. **选择"自动转正（无需会员确认）+ 转正后立即通知"（v1.3 按 CEO 意见确定），而不是"队首收到通知后在 15 分钟内确认"**，因为：① 确认制把"名额能不能被用上"绑定在会员是否刚好在 15 分钟内看到手机——微信订阅消息是一次性配额、到达率无承诺（§6.4），通知漏看一次名额就被顺延，白丢的是门店的上座率；② 确认制的状态最多（待确认／倒计时／超时未确认／顺延／确认时并发冲突），规则要向会员和门店解释的成本高，也最容易出现"我的位次到底还作不作数"的争议；③ 自动转正让"排队"的语义变简单：排到即自动占位，等于系统替会员完成了"看到通知立刻抢"这一步。代价：① 会把名额派给已经改主意的人，需要后续路径把名额还回来——用"转正后取消率 ≤40%"监控（§1.2），若 4 周持续高于 40%，说明名额派给了不需要的人，改为"通知内一键让位"或恢复确认制；② 会员若没看到通知又未到场，名额仍会浪费（不做处罚，只留记录供门店核对，AC5.14、R3）；③ 开课前 2 小时内**不再因会员取消或门店释放名额而产生新空位**（会员在距开课 <2 小时取消会被直接拒绝，AC3.3；门店不释放名额，AC3.3a），只有截止前已释放却未被候补占用的既有空位、以及排课数据变更（如门店调大容量）在 <2 小时产生的空位，能靠其他会员主动预约填补，不再由候补占用（B3、AC5.5、AC5.15③）；**排课数据变更若发生在距开课 ≥2 小时且队列非空，则按 AC5.1 先触发队首自动转正，不会留下无人认领的空位**。缓解：转正先落库再发通知（AC5.2）、站内横幅兜底（AC5.3）、通知文案明确"不能到场请在开课前 2 小时前取消"、"我的预约"里可直接看到并取消。
3. **选择"自动转正 + 一次性订阅消息 + 站内提示兜底"，而不是"短信/服务号"**，因为短信有成本与手机号授权问题，且会员拒绝授权订阅消息时仍需能正常加入候补、也仍会被自动转正（AC4.8、AC5.3）。代价：转正通知的到达率无官方承诺，只能保证"尽力下发 + 站内可查"。
4. **教练签到选择"扫门店现场一张固定二维码 + 定位软校验留痕"，而不是"一课一码"、"纯定位签到"或"口令签到"**，理由：
   - 纯定位：室内定位漂移大（商场里的健身房通常多层/信号弱），容易出现"人在教室却提示不在门店"，会直接挡住正常签到；且小程序定位需要额外授权，教练首次使用容易被卡住。
   - 口令：口令会通过微信群扩散，等于没有校验，且教练要记住口令、门店要定期更换，运营成本高。
   - 一课一码：要为每节课程生成、打印或投屏各自的码，还要定义"谁在什么时候把码放到现场"（门店每天几十节课，运营成本高），而防代签能力并不会变强（教练照样可以先选课再扫）。
   - **选中方案（全店一码）**：门店只在前台/教室张贴一张固定二维码，**载荷只含门店标识、不含课程 ID**；教练扫码后的"课程归属"由服务端判定：按"扫码教练 × 服务器时间"，在该教练**当日课程**中筛出"当前时间落在签到时间窗（开课前 30 分钟至开课后 15 分钟）内"的课程——命中恰好 1 节 → 直接完成该节签到；命中 ≥2 节（连上相邻两节课、时间窗重叠）→ 小程序展示教练端"我的课程"列表（只列命中的课程），教练点选一节后完成签到；命中 0 节 → 拒绝并给出具体原因（未到签到时间／签到时间已过／你今日无课／你与该门店无教练关系）。教练端"我的课程"列表因此写入 P0 范围（§3.1），但它只承担"确认签到归属"这一件事，不做名单、不做调课。
   - 代价：① 二维码被拍照外传时，任何非本店人员都能扫到同一个码，靠"必须是该课教练 + 必须在签到时间窗内 + 归属只由服务端判定"三道校验挡住绝大部分误签；② 连上两节课的教练要多一次点选操作（AC6.8）——缓解措施：命中 ≥2 节时页面明确提示"本次命中 2 节课，请选择要签到的课"，签到成功后显示"已为『课程名』签到"、其余节次保持"未签到"（教练可据此自查是否漏选），并由门店在试点期向教练说明该步骤（R8）；若上线后该点选步骤成为漏签主因，再评估在列表中把"即将开始的一节"排在最前（不默认选中，避免误签）；③ MVP 不能从技术上杜绝代签，只能靠"签到时间窗 + 定位距离软校验留痕（>500 米或未授权定位即标记疑似代签）+ 门店可事后核对"管理，不引入动态码/人脸等更强校验（工程量与现场稳定性不划算）。若上线后疑似代签记录频繁出现，再评估动态码或人脸方案（P1 之后）。
5. **门店运营只消费数据、不做管理界面**，因为门店已有排课与会员系统，MVP 重复做后台会大幅增加工期。代价：教练漏签、课程需临时取消只能线下找门店处理（见 §7 R5）。
6. **取消无惩罚、自动转正后不到场也不惩罚**（自动转正方案下，"超时未确认"这一情形已不存在），因为 MVP 先验证"能不能约上、名额是否被有效利用"，惩罚规则需与服务条款和门店政策对齐，过早引入会让会员不敢预约（尤其是被系统自动占位后不敢不管），反而降低使用率。
7. **时间冲突采用"一个时段只能占用一次（预约／候补二者互斥）"（B9），而不是"允许候补、到自动转正时再判断"**，因为后者会让会员同时排两节重叠课程，转正时再被跳过，会员既没拿到名额又不知道原因，规则无法向门店和会员解释。代价：会员不能"两头排队"提高命中率（可能被抱怨"我本来还想上 20:00 那节"），接受，并按 R11 监控冲突拦截次数——若拦截量很高，说明真实需求是"同时排两节、到时择一"，作为 P1 输入。

| 依赖 | 需要的内容 | 提供方 | 频率 | 缺失时的降级 |
| --- | --- | --- | --- | --- |
| 会员数据 | 手机号、会员有效状态、归属门店 | 门店现有会员系统 | 每日同步 + 预约时实时校验 | 校验不可用时：允许登录但预约前置校验失败则提示"请联系门店"，不放行无效会员 |

订阅消息的技术约束（已与工程师确认，写入需求约束）：一次性订阅消息"授权一次 = 可下发一条"；长期订阅不对健身房类目开放；同一模板不得与其他通知类型混用。因此候补自动转正使用独立模板 ID（语义为"结果通知"：名额已自动为你占用，不能到场请取消），会员在"加入候补"时被请求授权，二次转正需重新获得授权，无配额时记录 notify_failed=no_quota 并在页面提示"请重新开启提醒"。**注意**：授权与通知只影响"会员知不知道"，不影响转正结果本身（AC5.2、AC5.3）。

### 6.5 非功能需求

- **不超卖**：名额扣减必须在服务端以事务 + 唯一约束/乐观锁保证，"有效预约人数 ≤ 课程容量"是硬约束（AC2.2、B6）；"取消 + 触发队首自动转正"也必须在同一事务内完成（AC5.1、AC5.7、AC5.9）。候补自动转正成功的会员此时已计入"有效预约"，**不得再按"已转正"重复计数**（口径见 §9.4），否则正常的转正会被误判为超卖并触发回滚（§8）。
- **幂等**：预约、取消、加入/退出候补、自动转正、签到 5 组写操作都必须支持重复请求而不产生副作用（AC2.3、AC3.5、AC6.4）；自动转正由服务端按"课程 + 空位数 + 队首"确定性地执行一次，重试不得产生第二次转正。
- **时间以服务器为准**：所有截止时间判定不可信任客户端时间（AC3.2）。
- **并发能力**：需要在"开课前整点"这类抢课高峰稳定工作（假设：单门店峰值 200 次/分钟并发预约请求，具体压测目标由工程师在技术方案中给出），并发场景下不得出现超卖或重复记录。
- **可用性**：课表与预约主流程可用性目标 99.5%（按月），接口失败必须给可重试的明确提示。
- **可追溯**：签到、转正、通知下发、取消都必须留事件记录（含时间、原因、结果），用于门店核对和上线后分析指标（§1.2）。
- **数据与隐私**：只收集必要的手机号与定位信息，定位仅用于签到风控留痕，不用于其他用途；对会员展示隐私说明，遵守微信小程序隐私协议要求。

## 8. 上线与回滚

分阶段上线（本期只出文档，以下为后续执行计划）：

| 阶段 | 范围 | 时长 | 通过条件（进入下一阶段） |
| --- | --- | --- | --- |
| P0 内测 | 1 家试点门店，会员与教练各 ≤ 30 人，每日由店长盯名单 | 2 周 | 无超卖、无重复预约；候补转化率 ≥ 30%；教练签到率 ≥ 90%；门店侧反馈"名单可用" |
| P1 灰度 | 3~5 家门店，覆盖不同规模 | 2~4 周 | 候补转化率 ≥ 50%；取消留痕率 ≥ 80%；转正后取消率 ≤ 40%；无 P0 级投诉 |
| P2 全量 | 全部门店 | — | 硬底线指标（超卖 = 0、重复预约 = 0）持续达标 |

回滚条件（满足任一即回滚）：

1. 出现一次超卖（同一课程"有效预约人数" > 容量）且非数据导入错误；
2. 同一会员同一课程出现 > 1 条有效预约且无法解释；
3. 课表或预约主流程连续 30 分钟不可用且不能快速修复；
4. 候补自动转正在试点门店引发 ≥ 3 起无法解释的争议（如队列顺序无依据、名额被抢、自动转正后会员称完全不知情且站内无任何记录）。
5. 会员数据校验大面积失败（> 20% 试运行会员无法登录）。

回滚方式：先关闭小程序内的"预约/候补"入口（仅保留课表查看），通知门店恢复微信群/前台登记流程（试点前必须准备好这份线下回退流程说明）；数据层保持只读，保留已产生的名单与签到记录供对账，不做数据删除；问题定位并修复后，从试点门店重新灰度。回滚决策由产品经理与门店运营共同确认，工程师负责 30 分钟内完成开关切换（是否需要开关由工程师在技术方案中确认；若无远程开关能力，则回滚依赖发版，需在阶段 P0 前明确）。

### 9.4 术语表

| 术语 | 含义 |
| --- | --- |
| 空位 | 课程剩余名额 ≥1 的通俗说法，即有效预约人数 < 容量。MVP 中空位只有两个来源：①会员在开课前 ≥2 小时的自助取消且未被候补占用（AC3.1、AC5.8）；②排课数据变更，如门店调大容量（§6.4）。**来源②按发生时间分叉**：发生在距开课 ≥2 小时且队列非空时，按 AC5.1 立即触发队首自动转正、不留下空位（课程保持"已满"）；发生在距开课 <2 小时、或距开课 ≥2 小时但队列已空时，才留下空位由会员主动预约（AC5.5、AC5.15③）。**不存在开课前 2 小时后取消、或门店在系统内释放名额这两种来源**（AC3.3、AC3.3a） |
| 剩余名额 | 课程容量 − 有效预约人数。超卖判定、"已满"判定统一用这一个公式（自动转正不引入额外的占用项） |
| 有效预约 | 状态为"已预约"的预约记录（已取消、已结束不算）；**含候补自动转正成功的会员**（AC5.1 后其状态即"已预约"，因此计入本项） |
| 自动转正 | 候补队首在课程**本身已有空位**（来源见本表空位一行：①会员在开课前 ≥2 小时的自助取消且未被候补占用；②排课数据变更——**仅当该变更发生在距开课 ≥2 小时且队列非空时才产生"需要转正的空位"**）且距开课 ≥2 小时时，由系统**在同一事务内直接**把名额转为该会员的"已预约"，**无需会员做任何确认操作**（AC5.1）；**触发条件是"课程出现空位"，不限于会员取消**，因此容量调大同样会触发转正；转正完成后立即尽力下发通知（AC5.2） |
| 已转正（自动） | 候补记录的终态名：因自动转正而离开队列，其预约进入"有效预约"。**只作为候补记录的终态名，不作为容量计数口径**，以避免与"有效预约"重复计数（超卖判定 = 有效预约人数 ≤ 课程容量） |
| 超卖 | 同一课程"有效预约人数" > 课程容量；另：同一会员同一课程有效预约 > 1 条称为"重复预约" |
| 候补位次 | 会员在候补队列中的序号，按加入候补的服务器时间先到先得；会员在"已转正／主动退出／因冲突失效"时离开队列，位次随即前移（B10、AC5.13） |
| 顺延 | 自动转正前的冲突校验未通过（AC5.8）时，**已经存在的那个空位**在同一事务内按队列顺序交给下一位候补（自动转正，无通知确认环节）；若队列中已无人可接，该空位保持可预约状态（由其他会员主动预约，见 AC5.15） |
| 已结束 | 预约终态：开课时间到达即置，与教练是否签到、是否漏签无关（AC3.7、§6.2 C） |
| 签到时间窗 | 开课前 30 分钟至开课后 15 分钟，仅此区间内可自助签到；重叠时由教练在"我的课程"里点选归属（AC6.8） |
| 取消留痕率分子／分母 | 分子 = 小程序自助取消次数；分母 = 小程序自助取消次数 + 门店侧人工登记的取消请求次数（MVP 期无门店后台，靠前台按日人工登记，属估算口径，见 AC3.3a） |
