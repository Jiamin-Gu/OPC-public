| 教练与会员是两个角色（PRD §2.1、§3.3、AC6.3） | 界面把身份校验拆成**会员线**与**教练线**两条彼此独立的入口线：会员线失败只拦课程相关页面（课表/详情/预约/候补/我的预约/我的候补）；教练线只决定 P7 签到与 P8「我的课程」，**不要求教练是会员**（详见 §2.1.1，本轮修订） |

## 1. 用户与核心任务

假设（验证方式：可用性测试 + 数据观察）：会员在晚上 21:00 左右、通勤路上打开小程序，单手操作、30 秒内想完成一件事；教练在开课前 10 分钟、站在门店前台掏手机扫码，希望 3 秒内看到"签到成功"。因此所有主操作放在拇指可达区（页面下半部或底部吸底条），详情页不放入口极深的嵌套展开。

| 任务 | 对应的用户故事（PRD §5） | 成功标准（界面可验证） |
| --- | --- | --- |
| 查看课表 | AC1.1~AC1.6（S1） | 打开即见"今天"，每节课 1 屏内看到课程名、教练、时间、门店、剩余名额或「已满」；7 天可切且第 8 天不可选；失败可重试且不显示过期名额 |
| 预约团课 | AC2.1~AC2.6（S2） | 课表卡片 1 次点击 + 弹窗 1 次确认 = 2 次点击完成；结果在同屏立刻可见（按钮变「已预约」、名额 −1） |
| 取消预约 | AC3.1~AC3.7（S3） | 在「我的预约」1 屏内找到课程并完成取消；<2 小时时按钮置灰且写明原因与下一步；取消后卡片进入「已取消」筛选 |
| 满员后排队候补 | AC4.1~AC4.9（S4） | 已满课程卡片上直接出现「候补」；加入后同屏显示「候补中 · 第 N 位」与"不需要你操作"的规则说明 |
| 候补自动转正与通知（原「转正确认」） | AC5.1~AC5.15（S5） | 会员**零操作**：转正后「我的预约」直接出现「已预约 + 已自动转正」；无论是否收到订阅消息，打开小程序都能在首页横幅看到结果（AC5.3）；不能到场时有明确的取消入口与截止说明 |
| 教练签到 | AC6.1~AC6.8（S6） | 扫门店固定码后 ≤1 屏内看到「签到成功」或具体失败原因；命中 2 节时必须点选，且不默认选中 |
| 前置：会员身份与门店归属校验（决定课程相关页面是否可见） | AC1.5、PRD §3.3 | 非有效会员/未绑定门店时，课表、详情、预约、候补、我的预约、我的候补一律不出现，只显示 P9 引导页，且不请求任何课程数据 |
| 前置：教练身份校验（决定签到页与教练「我的课程」是否可用） | AC6.1、AC6.3、PRD §3.3 | 与会员校验**彼此独立**：教练档案已绑定即可扫码拿到 P7 的签到结果、并打开 P8；**不要求教练同时是会员**（详见 §2.1.1） |

## 2. 信息架构

### 2.1 导航结构（底部 Tab = 3 个）

#### 2.1.1 两条彼此独立的校验线（本轮修订）

| 校验线 | 校验内容 | 决定哪些页面/能力可见 | 是否要求「是会员」 |
| --- | --- | --- | --- |
| **会员线** | 有效会员 + 归属门店（PRD §3.3） | 课程相关页面：P1 课表、P2 详情、P3/P4 弹窗、P5 我的预约、P6 我的候补，以及 Tab1/Tab2 与 Tab3 里的课程相关入口 | — |
| **教练线** | ①教练档案已绑定 ②与该门店的教练关系（“该门店”＝当前上下文门店：扫码码里的门店，或 P9/P10 展示的归属门店）（PRD §3.3、AC6.3） | P7 教练签到、P8 教练「我的课程」（含 Tab3 的教练入口）、P9 的教练入口 | **不要求**：PRD §2.1 把「团课教练」与「会员」列为两个不同角色；AC6.3 的拒绝原因只有「你与该门店无教练关系」「尚未绑定教练档案」，没有「你不是会员」 |

- 会员线失败 → 只拦课程相关页面：不进入、也不请求课程数据（AC1.5）；**不影响教练线**——教练线通过（档案已绑定 且 与该门店有教练关系）的账号照样能扫门店码进 P7、并打开 P8。
- 教练线失败 → 只影响 P7/P8：按 AC6.3 给具体原因（尚未绑定教练档案 / 与该门店无教练关系），**不跳 P9 引导页、不影响会员侧任何功能**。
- 两条都失败 → 落地 P9 引导页，**不显示教练入口**。上一轮这里两条 bullet 对“两条都失败是否显示教练入口”给出了相反结论，本轮统一为一条判断：**教练入口的唯一条件是「教练线通过」**（教练档案已绑定 **且** 与该门店有教练关系）。“档案已绑定但与当前门店无教练关系”属于教练线失败，同样不显示入口，P9 只给「联系门店」/「重新检查」（见 §5.7）。
- 落地顺序：会员线通过 → Tab1 课表；会员线失败但教练线通过 → P9（带教练入口）或由扫码直接落 P7；两条都失败 → P9（无教练入口，只有「联系门店」/「重新检查」）。

#### 2.1.2 导航树

```
微信入口（搜索 / 最近使用 / 会话卡片 / 扫门店码）
        │
        ▼
   启动页（微信授权登录；会员线与教练线两条校验彼此独立，见 §2.1.1）
        ├── 会员线校验失败 → ① P9 引导页（非会员 / 未绑定门店）—— 无 Tab，只有"联系门店"+规则说明；若教练线同时通过（档案已绑定 且 与该门店有教练关系）则追加教练入口 → P7 / P8（§5.7）
        └── 会员线校验通过 → 主框架（底部 3 Tab，选中态主色，含安全区内边距）
                 ├── Tab1 课表（首页，默认今天，未来 7 天）   ← 需会员线
                 ├── Tab2 我的预约（二级分段：我的预约 / 我的候补）
                 └── Tab3 我的（身份与门店、通知授权、规则说明、隐私说明）← 需会员线
                          └── 「我是教练 · 我的课程」→ P8            ← 只校验教练线
扫码入口（门店固定二维码，载荷含门店标识）—— 不经过会员线校验
        └── 教练线校验 → P7 教练签到页（扫码落地页，不属于任何 Tab）
                 ├── 通过 → 签到成功 / 命中 ≥2 节点选 / 已签到（AC6.1、AC6.4、AC6.8）
                 └── 失败 → 原因页（5 种原因，AC6.3，含「尚未绑定教练档案」）
```

Tab 数 = 3，理由：会员的 3 件日常事（看课、看自己的约、看自己的设置）各占一个；候补与转正是"我的预约"的一个维度，做成 Tab2 内的分段而不是第 4 个 Tab（避免两个列表页承载同一组"我的课程"数据、也避免会员在两个 Tab 间找不到自己约的课）。
教练签到**不做 Tab**：教练的真实入口是"扫门店那张码"，做成 Tab 会让会员也长期看到一个与自己无关的 Tab；同时按 PRD §3.1，"我的课程"列表只承担"确认签到归属 + 自查签到记录"，放在 Tab3 的入口 + P7 的「查看我的课程」即可（详见 §5.6）；该入口只校验教练线，**不要求会员线**（§2.1.1）。

### 2.3 关键跳转与返回关系

- P1 卡片 → P2；P2 返回 → 回到来源页（记住 P1 的日期与滚动位置）。
- P2 预约/候补成功后：**留在 P2**（按钮就地变化），提供「查看我的预约」文字入口 → P5；不使用强制跳转（避免用户丢失浏览位置）。
- 首页横幅（转正结果）点击 → P5（并高亮该课程卡）；横幅里的「不能到场请点此取消」→ P5 对应卡片（若 <2 小时则卡片按钮置灰，见 §6.2 第 2 条）。
- P6 卡片「已转正（自动）」→ P5（该课程卡）。
- P7 与主框架是两条并行入口：P7 有「返回课表」次要按钮 → P1；不返回 P7 也不影响主流程（签到为独立动作）。
- P7/P8 与会员线解耦（§2.1.1）：会员线失败的账号（例如未办卡的兼职教练）扫门店码仍直接落 P7，此时 P7 底部的「返回课表」在该账号上替换为「返回」（回到微信会话，因为该账号没有课表权限）；教练线失败的账号扫码后停在 P7 原因页，不跳 P9。
- 任何写操作（预约/取消/候补/签到）完成后，「我的预约」「我的候补」两个列表角标与内容**下次进入时重新拉取**，不做乐观缓存。

## 3. 用户流程

约定：下文"服务器时间判定"指按钮可点性由接口字段决定（§0）。所有流程的错误提示都是**正面句 + 原因 + 下一步**（见 §6.8 文案规范）。

### 流程 1：查看课表 → 课程详情 → 预约（AC1.x、AC2.x）

主路径：
入口（Tab1 课表，默认今天）→ 点日期条切到要上的那天 → 点课程卡片（**1 次点击**）→ 课程详情页 → 点「预约」→ 预约确认弹窗（课程名 / 时间 / 教练 / 门店 / "距开课 ≥2 小时可自助取消，不足 2 小时请联系门店"）→ 点「确认预约」（**第 2 次点击**）→ 按钮进入 loading 并禁用（防重复点击）→ 成功：Toast「已预约成功」+ 同屏按钮变「已预约」+ 名额 −1 → 完成。

分支与异常路径：

| 场景 | 界面行为 | 依据 |
| --- | --- | --- |
| 会员线校验失败（未绑定/非有效会员） | 课程相关页面不进入：落 P9 引导页，不发课表请求；**教练线不受影响**（教练档案已绑定且与该门店有教练关系的账号仍可扫门店码签到，§2.1.1） | AC1.5 |
| 切到第 7 天之后 | 日期条到第 7 天即止，第 8 天不可选、不发请求 | AC1.3 |
| 当天无课（空状态） | 卡区显示空状态：「今天（8月14日）暂无课程」+「看看明天」按钮（切到下一天） | AC1.3 |
| 课表接口失败/超时（8 秒） | 整页错误态：「加载失败，没有显示旧名额」+「点击重试」；**不展示缓存名额** | AC1.4 |
| 已满（有效预约 = 容量） | 卡片显示灰底「已满」标签与「候补 N 人」；详情页主按钮为「候补」→ 走流程 3 | AC1.2、AC4.1 |
| 距开课 <30 分钟 | 主按钮置灰，文案「已过预约截止时间」；点击无响应（按钮 `disabled`），页面同时给出禁用原因文字 | AC2.4 |
| 课程已开课/已结束 | 主按钮置灰，文案「已开课」/「已结束」；预约与候补均不可点 | AC1.6 |
| 时间冲突 | 弹窗内联错误（不关闭弹窗）：「与《单车燃脂》8月14日 19:00—19:45 时间冲突」，主按钮保持禁用直到用户关闭弹窗 | AC2.5 |
| 并发抢最后一个名额失败 | Toast「名额已被抢完」+ Toast 上带「加入候补」按钮（或弹窗内出现同一入口）→ 走流程 3 | AC2.2 |
| 重复提交/重复点击 | Toast「你已预约该课程」，按钮直接回到「已预约」，不重复扣名额 | AC2.3 |
| 网络中断/5xx（结果未知） | Toast「预约结果未确认，请在『我的预约』中查看」+「去我的预约」；按钮恢复可点，会员重试幂等 | AC2.6 |

### 流程 2：取消预约（AC3.x）

主路径：
入口（Tab2 我的预约 → 待上分段，或 P2 的「取消预约」）→ 找到目标课程卡（按钮「取消预约」可点）→ 点击 → 取消确认弹窗（课程名 / 时间 / 固定两句：「取消后名额会立即释放给候补队列（如有）」+「取消后无法撤回」，与 §6.2 第 4 条一致）→ 点「确认取消」→ loading 并禁用 → 成功：按钮恢复，**名额显示与 Toast 文案按接口返回值分两种口径**（本地固定 +1 或固定提示「已转正」都会错，因为队列可能为空）：

| 服务端返回的空位归属 | 名额显示（课表/详情页） | 成功 Toast |
| --- | --- | --- |
| 候补队列为空 → 空位对普通预约开放 | 按接口返回的剩余名额渲染（如原「0/20」→「1/20」），该课回到可点的「预约」 | 「已取消，名额已释放」 |
| 候补队列非空 → 空位在同一事务内已自动转正给队首（AC3.1） | 保持接口返回的「0/20」与「已满」+「候补 N 人」，**不出现一个并不存在的空位** | 「已取消，名额已自动转正给候补会员」 |

两种情况卡片都移出「待上」、进入「已取消」分段。

分支与异常路径：

| 场景 | 界面行为 | 依据 |
| --- | --- | --- |
| 距开课 <2 小时 | 「取消预约」置灰不可点，**按钮下方常驻说明**「距离上课不足 2 小时，无法自助取消，请联系门店」；直接调接口被拒时返回同一文案 | AC3.3 |
| 距开课恰好 2 小时 | 由服务端 `canCancel` 决定为可点（按服务器时间），界面不做本地临界判断，避免出现"两秒后又不可点"的抖动 | AC3.2 |
| 开课时间已到（无论教练是否签到） | 卡片状态「已结束」，「取消预约」位置保留但置灰，文案「课程已开始」；教练漏签不改这个显示 | AC3.4、AC3.7 |
| 重复取消/网络重试 | Toast「该预约已取消」，名额不重复 +1 | AC3.5 |
| 取消后想再约 | 「已取消」分段的卡片提供次要按钮「再次预约」→ 跳课程详情页（按当时的 `canBook`、名额渲染按钮），页脚无任何惩罚提示 | AC3.6 |
| 取消后候补队列为空 | 空位回到可预约状态：名额按接口返回 +1（课表该卡回到「剩余 1/20」+ 可点「预约」），Toast「已取消，名额已释放」 | AC3.1 |
| 取消后课程仍有候补队列 | Toast 用「已取消，名额已自动转正给候补会员」，让取消者知道名额去向（不暴露他人身份）；名额显示**保持接口返回的 0**（空位已在同一事务内转正），不渲染并不存在的空位 | AC3.1、B5 |
| 取消失败（5xx/断网） | Toast「取消失败，请重试」；卡片保持「已预约」，可重试且幂等 | §6.5 非功能（幂等） |

### 流程 3：满员 → 加入候补 → 自动转正 → 通知（AC4.x、AC5.x）

主路径（A 加入）：
课表/详情页显示「已满」→ 点「候补」（**1 次点击**）→ 候补确认弹窗：规则说明三句话（① 按加入时间先到先得；② **有空位时系统自动为你占位，不需要你操作**；③ 不能到场请在开课前 2 小时前在小程序内取消）+（若未授权订阅消息）「开启转正提醒」按钮 → 若未授权也可点「确认候补」→ loading → 成功：Toast「已加入候补：第 3 位」+ 按钮变「候补中 · 第 3 位」+ 卡片显示「候补 3 人」。

主路径（B 自动转正，会员零操作）：
有人按流程 2 取消、或排课数据变更产生空位（PRD §9.4"空位"）且距开课 ≥2 小时 → 服务端在**同一事务内**把名额给队首 → 系统尽力下发订阅消息 → 会员打开小程序：首页顶部横幅「你已被自动转正：《瑜伽舒缓》8月14日 21:00，不能到场请在开课前 2 小时前取消」+「我的预约」角标 +1 → 进入「我的预约」看到该课程状态「已预约」、来源标签「已自动转正」→ 完成。**全程不需要任何确认操作**（PRD v1.3 已删除"转正确认"）。

分支与异常路径：

| 场景 | 界面行为 | 依据 |
| --- | --- | --- |
| 队列达上限（= 容量） | 「候补」置灰，文案「候补已满」；页面同时给出原因文字 | AC4.5 |
| 课程未满 | 不出现候补入口（由 `canWaitlist` 控制）；详情页只显示「预约」 | AC4.1 |
| 重复点击候补 | Toast「你已在候补队列中」 | AC4.3 |
| 已预约该课程再点候补 | Toast「你已预约该课程」 | AC4.4 |
| 加入候补时时间冲突 | 弹窗内联错误「与《课程名》时间冲突」；详情页「候补」置灰并显示同一原因 | AC4.9 |
| 未授权订阅消息 | 仍可成功加入；候补卡显示「未开启提醒：排到后会为你自动占位，请自行到小程序查看，不能到场请在开课前 2 小时前取消」+「开启提醒」 | AC4.8 |
| 转正时发现时间冲突（转正前校验） | 该会员被移出队列，终态「因时间冲突失效」；**不给他发通知**；卡片文案「因与《单车燃脂》时间冲突，已跳过」；空位在同一事务内立即顺延给下一位 | AC5.8 |
| 同一空位被抢约的并发 | 以服务端事务为准：转正在先 → 抢约者见 Toast「名额已被抢完」+ 可加入候补；预约在先 → 队首不被转正、继续排队。界面不出现"同一个名额同时属于两人"的画面 | AC5.7 |
| 转正处理失败/重试中 | 服务端 1 分钟内重试收敛；界面**不呈现任何中间态**（不显示"名额已释放但未归属"），只显示服务端的最终名额数字 | AC5.9、B6 |
| 距开课 <2 小时仍有队列 | 队员在「我的候补」看到终态「候补已截止（未排到）」，文案「该课程已停止候补，未排到你」，展示截止时的位次，**不再显示「取消候补」按钮、不显示任何倒计时** | AC5.5、AC5.12 |
| 距开课 <2 小时看课程页 | 课程仍有空位 → 主按钮「预约」（可点，<30 分钟时「已过预约截止时间」）；课程仍满员 → 「候补已截止」（不可点） | AC4.7、AC5.5、AC5.15 |
| 位次前移 | 队首转正/退出/失效离开队列的那一刻，第 2 位变为「候补第 1 位」，卡片提示「下一有空位将自动为你占位（无需操作）」 | AC5.13、B10 |
| 主动退出 | 点「取消候补」→ 二次确认（"退出后需重新排队，不保留原位次"）→ 成功后位次前移，无任何惩罚提示 | AC4.6 |
| 候补自动作废（并发兜底） | 卡片终态「已预约该课程，候补已作废」，无操作按钮 | AC4.4 |

### 流程 4：教练签到（AC6.x）

主路径：
入口（微信扫门店前台/教室张贴的固定二维码；码只含门店标识）→ **只做教练线校验（不要求会员身份，§2.1.1）** → 小程序直接打开 P7 教练签到页 → 页面依次显示「正在获取定位…」（可拒绝授权）→「正在匹配你的课程…」→ 服务端判定：

- 命中 1 节 → 直接签到成功：「签到成功 —《燃脂搏击》8月14日 20:00，签到时间 19:42，静安店」。
- 命中 ≥2 节（连上相邻两节课，时间窗重叠）→ 列表点选：「本次命中 2 节课，请选择要签到的课」+ 两节单选（**不默认选中**）→「确认签到」→ 成功页显示「已为《燃脂搏击》签到」，其余节次保持「未签到」。
- 命中 0 节 → 原因页（见下表）。

分支与异常路径：

| 场景 | 界面行为 | 依据 |
| --- | --- | --- |
| 早于开课前 30 分钟 | 「未到签到时间（开课前 30 分钟开始签到）」+「返回课表」 | AC6.2、AC6.3 |
| 晚于开课后 15 分钟 | 「签到时间已过，请联系门店运营处理」+ 说明本期无线上补签 | AC6.2 |
| 当日无课 | 「你今日无课」+ 展示「我的课程」列表（可自查排班） | AC6.3 |
| 与该门店无教练关系 | 「你与该门店无教练关系」+「去我的页确认绑定」 | AC6.3 |
| 未绑定教练档案 | 「尚未绑定教练档案，请联系门店运营」 | §6.4 降级 |
| 重复扫码 | 「已签到（签到时间 19:42）」，不生成第二条记录 | AC6.4 |
| 命中 2 节但直接退出未点选 | 不生成任何签到记录；再扫一次仍进入点选态 | AC6.8 |
| 定位被拒 / 距门店 >500 米 | **不阻断**：签到成功页加一行「本次签到未获取定位（或距门店较远），记录已被标注，门店可事后核对」 | AC6.5 |
| 弱网/请求失败 | 页面内错误块「网络异常，请重试」+「重新签到」按钮；连续失败 2 次后追加「持续失败请联系门店运营」 | AC6.6 |
| 教练查看签到结果 | 「我的课程」中每节课显示「未签到 / 已签到 19:42 / 已签到（疑似代签）」 | AC6.3、AC6.7 |

### 流程 5：被自动转正后不能到场（AC5.4、AC5.14）

主路径：
入口（首页转正横幅，或「我的预约」中带「已自动转正」标签的卡片）→ 距开课 ≥2 小时：点「取消预约」→ 确认弹窗（含"取消后名额会立刻自动转正给候补队列中的下一位"）→ 成功：名额与 Toast 按接口返回值取（同流程 2 的两种口径：队列非空 → 名额保持 0、Toast「已取消，名额已自动转正给候补会员」；队列已空 → 名额按接口返回 +1、Toast「已取消，名额已释放」）→ 卡片进入「已取消」。
异常与说明：
- 距开课 <2 小时：取消按钮置灰 +「距离上课不足 2 小时，无法自助取消，请联系门店」；名额不释放（门店只线下登记）。
- 既未取消也未到场：界面**不显示任何处罚、违约、扣次或信用提示**（PRD §4、AC5.14），只留记录供门店核对。
- 无"一键让位"入口（PRD §4 明确不做）：取消是唯一把名额还回去的路径，因此转正卡片的文案必须把这条路指出来。

## 4. 视觉规范

一句话风格定位：**场馆感的干净底 + 一个高饱和主色承担"行动"**。信息以文字和数字为主，动效与装饰性图形在 MVP 中一律不做（性能与识别效率优先）。

### 4.1 色彩

| 用途 | 色值 | 说明与对比度（按 WCAG 2.1 相对亮度公式计算） |
| --- | --- | --- |
| 主色 Primary（主按钮底、链接、选中态） | `#1D4ED8` | 白字置于其上 6.70:1；作为白底上的文字/链接 6.70:1，均达 AA |
| 主色按下态 | `#1A44BF` | 仅用于 `:active`，不承载正文 |
| 主色浅底（选中卡片、信息条、"候补中"标签底） | `#EFF4FF` | 其上 `#1D4ED8` 文字 6.1:1；其上 `#4B5563` 文字 6.86:1 |
| 正文主色 | `#111827` | 白底 17.7:1 |
| 次要文字 | `#4B5563` | 白底 7.56:1；灰底 `#F3F4F6` 上 6.81:1 |
| 页面底色 / 卡片底 / 分割线 | `#F7F8FA` / `#FFFFFF` / `#E5E7EB` | 分割线不承载文字，仅作视觉分隔 |
| 中性标签底（「已满」「已截止」「已结束」） | `#F3F4F6` + 文字 `#4B5563` | 6.81:1 |
| 成功（「已预约」达成感、「签到成功」、「已转正（自动）」） | `#15803D`，浅底 `#ECFDF3` | 白底 5.01:1；浅底上 4.75:1 |
| 警告（满员提醒、"疑似代签"、"因时间冲突失效"、临近截止说明） | `#B45309`，浅底 `#FEF6E7` | 白底 5.02:1；浅底上 4.67:1 |
| 错误（提交失败、冲突阻断、取消被拒） | `#B91C1C`，浅底 `#FEF2F2` | 白底 6.47:1；浅底上 5.92:1 |
| 禁用（按钮底/描边/文字） | 底 `#F3F4F6`，描边 `#D1D5DB`，文字 `#4B5563` | 禁用控件按 WCAG 豁免，但本项目仍把禁用文案提升到 6.81:1，**并要求禁用原因用正常次要文字（7.56:1）写在按钮外**，不允许只靠灰 |

**满员 / 候补 / 可约 三态的颜色区分规则（本项目重点）**：颜色只是第三重编码，同一状态必须同时有**文字**与**图标形状**，避免色觉障碍用户只靠色相分辨（详见 §7）。

| 状态 | 底色 | 文字 | 图标（线性，16×16） | 详情页 P2 的主按钮形态 | 课表卡片 P1 上的表现 |
| --- | --- | --- | --- | --- | --- |
| 有名额 | 无标签，直接显示「剩余 3/20」 | 主色 `#1D4ED8` | 无 | **实心**主色按钮「预约」 | 同左：实心主按钮「预约」 |
| 已满 | `#F3F4F6` | `#4B5563` | 🔒 锁形（描边） | **描边**按钮「候补」（主色边框+主色文字） | 同左：描边按钮「候补」 |
| 已满·候补也满 | `#F3F4F6` | `#B45309` | 🔒 + 斜线 | 置灰按钮「候补已满」 | 同左：置灰按钮「候补已满」 |
| 已满·候补已截止（<2 小时） | `#F3F4F6` | `#4B5563` | ⏱ + 🔒 | 置灰按钮「候补已截止」 | 同左：置灰按钮「候补已截止」（**前提是课程此刻仍旧满员、无空位**；课程一旦出现空位，按钮位让给可点的「预约」，AC5.12） |
| 我已候补中 | `#EFF4FF` | `#1D4ED8` | ⌛ 时针（描边） | 置灰按钮「候补中 · 第 3 位」（详情页底部已有主行动，不重复放写操作） | **可点**标签「候补中 · 第 3 位」→ P6（**不是**置灰按钮：列表页要能从这里看到位次与规则） |
| 我已候补·已截止，**课程仍旧满员** | `#F3F4F6` | `#4B5563` | ⏱ | 置灰标签「候补已截止（未排到）」 | 不可点标签「候补已截止（未排到）」（AC5.12） |
| 我已候补·已截止，**但课程已有空位**（<2 小时容量调大） | 按“有名额”行：无标签底，名额数字用主色 | 主色 `#1D4ED8` | 无 | **实心**主色按钮「预约」（空位优先于个人终态） | 可点实心「预约」＋课程名右侧**只读**小标签「候补已截止（未排到）」（`#F3F4F6`/`#4B5563`/⏱，12/500） |
| 我已预约 | `#ECFDF3` | `#15803D` | ✔ 勾（描边） | 次要按钮「取消预约」（`canCancel=false` 时置灰 + 原因文字）+ 禁用态「课程已开始」 | **不可点**标签「已预约」：列表页不做取消，避免误触；写操作只留在 P2 详情页与 P5 我的预约 |

实心 vs 描边是"可约/已满"在**不看颜色**时也能区分的关键（形态差异），这也是本设计刻意不把「候补」也做成实心主色的原因。

**三重编码之上还有一条优先级（本轮修订）**：只要课程此刻**已有空位**（剩余名额 ≥1），按钮一律是可点的**实心「预约」**，个人终态（如「候补已截止（未排到）」）只作为只读小标签出现在课程名旁；只有课程**仍满员**时，「候补已截止」才占按钮位（AC5.12、AC5.15③；唯一取值表见 §5.1、§5.2、§6.1）。

「候补中」在详情页是**置灰按钮**、在课表卡片上是**可点标签**：详情页底部已有唯一主行动（预约/候补），而列表页需要给会员一个查看位次与退出候补的入口（§5.1 卡片按钮状态表）；两处都呈现同一句文案，只有可点性不同。

### 4.2 字体层级

字体族：跟随微信小程序默认（iOS 系统字体 / Android 系统字体），不引入自定义字体（首屏性能与体积）。数字使用等宽数字（`font-variant-numeric: tabular-nums`），让「剩余 3/20」「第 3 位」在刷新时不跳宽。

| 层级 | 字号 / 行高 / 字重 | 用途 |
| --- | --- | --- |
| 页面标题 H1 | 20 / 28 / 600 | 页面顶端标题、签到结果主文案 |
| 卡片标题 H2 | 17 / 24 / 600 | 课程名、门店名 |
| 关键数字 | 17 / 24 / 600（等宽数字） | 剩余名额、候补位次、签到时间 |
| 正文 Body | 15 / 22 / 400 | 时间、教练、说明正文 |
| 次要 Assist | 13 / 20 / 400 | 门店地址、规则一行说明、禁用原因 |
| 标签 Label | 12 / 16 / 500 | 状态标签、日期条星期、角标 |
| 按钮 | 16 / 22 / 600（主）/ 15 / 22 / 500（次要、文字） | 全部按钮 |

不使用小于 12px 的字；不使用纯图片承载文字（含二维码页的所有说明）。

### 4.3 间距、圆角、阴影、断点

- 间距体系：基础单位 **4px**；常用值 **8 / 12 / 16 / 24 / 32**（对应 16 / 24 / 32 / 48 / 64 rpx）。页面左右内边距 16px；卡片内边距 16px；卡片之间 12px；卡片内元素间距 8px；区块之间 24px。
- 圆角：卡片 12px；按钮 8px（主按钮通栏时仍 8px，不用胶囊）；标签/角标 6px（小尺寸标签用 4px）；弹窗 16px；头像/图标容器 8px。
- 阴影：卡片 `0 1px 2px rgba(17,24,39,0.06)`；吸底操作条 `0 -1px 0 #E5E7EB`（用分割线而非阴影，滚动区更干净）；弹窗 `0 4px 16px rgba(17,24,39,0.12)`。不使用大面积彩色阴影/渐变。
- 栅格与断点（设计基准 375×667 逻辑像素，1px 设计 = 2rpx）：
  - `320–374`：单列，页面内边距 12px，卡片内边距 12px，主按钮通栏，字号不缩（文本允许换行）。
  - `375–413`：默认，内边距 16px，课程卡片为「左信息 + 右按钮」两栏。
  - `414–599`：单列，内容容器最大宽度 480px 居中，卡片仍两栏，可多显示一行（教练 + 类型）。
  - `≥600`（平板 / 折叠屏展开 / 微信 PC 端）：容器最大宽度 960px 居中，**课表页与我的预约页变双列卡片（列间距 16px）**；详情页与弹窗最大宽度 640px 居中；底部 Tab 保留（不改成侧边导航，避免与微信外壳冲突）。字体与触控尺寸不随断点缩小。

### 4.5 状态视觉区分总则（写在实现前）

1. 每个状态 = **文字标签 + 图标形状 + 颜色**三重编码，缺一不可（本项目的满员/候补/已取消/已结束/签到成功都按此执行）。
2. 「可操作」与「不可操作」的区别不能只靠颜色：可操作按钮是实心/描边+主色，不可操作按钮必带**原因文字**在按钮之外。
3. 同一状态在全站用同一个词、同一个图标、同一个颜色（例如"已满"在课表、详情页、我的预约里文案完全一致）。
4. **空位优先于个人终态**：课程此刻已有空位时，课程页与课表卡片一律给可点的实心「预约」，把「候补已截止（未排到）」降级为课程名旁的只读小标签；只有课程仍满员时，才用按钮位表达个人终态（AC5.12、AC5.15③；唯一取值口径见 §5.1 优先级规则，落地位置 §5.2、§5.9、§6.1）。

### 6.2 取消规则交互（与服务端一致）

1. 可取消条件：距开课 **≥2 小时**（含恰好 2 小时；`canCancel=true`）。判定全部由服务端下发，客户端不本地算。
2. 不可取消（距开课 <2 小时）：取消按钮置灰，**按钮外**常驻说明「距离上课不足 2 小时，无法自助取消，请联系门店」；不提供任何替代写入口（PRD AC3.3a：门店只线下登记，名额不释放）。
3. 已开课（含教练已签到或漏签）：预约状态显示「已结束」，取消位保留置灰，文案「课程已开始」（AC3.4、AC3.7）。
4. 取消确认弹窗固定两句话：「取消后名额会立即释放给候补队列（如有）」+「取消后无法撤回」。**取消成功后的名额显示与 Toast 文案一律按接口返回值，不本地 +1**（AC3.1）：① 队列为空 → 该课回到「剩余 1/20」+ 可点「预约」，Toast「已取消，名额已释放」；② 队列非空 → 空位在同一事务内已自动转正给队首，课表维持「已满」+「候补 N 人」，Toast「已取消，名额已自动转正给候补会员」。这样既不与 AC3.1 的「同一事务内转正」矛盾，也避免取消者看到一个并不存在的空位去点「预约」被拒（PRD R13 描述的「名额错配」表象）。
5. 重复取消：Toast「该预约已取消」，名额不重复释放（AC3.5）。
6. 取消无惩罚：界面任何位置不出现"违约 / 扣次 / 信用 / 影响后续预约"字样（PRD §4、AC3.6）。
7. 取消后想再约：走正常流程 1；「已取消」卡片提供「再次预约」次要按钮，但它只是跳转入口，能否预约仍由当前 `canBook` 决定（AC3.6）。

### 6.3 候补与自动转正交互规则（本项目的核心，逐条与 PRD 对齐）

1. 候补入口出现的唯一条件：课程已满（有效预约 = 容量）且队列未达上限（= 容量）且距开课 ≥2 小时。界面不自行判断，只渲染 `canWaitlist` 与 `disabledReason`（AC4.1、AC4.5、AC4.7）。
2. 加入候补的规则说明（弹窗 + 我的候补卡内重复一次，三句话，缺一不可）：
   ① 顺序按加入时间先到先得；
   ② **有空位时系统自动为你占位，不需要你操作**；
   ③ 不能到场请在开课前 2 小时前在小程序内取消。
3. **不存在"转正确认"交互**：界面没有确认按钮、没有倒计时、没有"你需要在 X 分钟内确认"的文案，也没有"超时"提示（PRD v1.3）。
4. 通知（AC5.2、AC5.3）：小程序订阅消息尽力下发；**无论通知是否送达**，会员下次打开小程序都能在课表页看到横幅、在「我的预约」看到角标与该课程。横幅文案固定结构：`你已被自动转正：《课程名》<开课时间>` + `不能到场请在开课前 2 小时前取消`。
5. 转正结果呈现：该课程在「我的预约」中=「已预约」+ 来源标签「已自动转正」；在「我的候补」中= 终态「已转正（自动）」+「已计入我的预约」（AC5.1、AC5.2）。
6. 位次与提示：位次即"我在队列中的当前位置"；第 1 位卡片提示「下一有空位将自动为你占位（无需操作）」；位次前移不做动效与 Toast（AC5.13、B10）。
7. 未授权订阅消息：仍可加入候补、仍会被自动转正；卡片显示「未开启提醒：排到后会为你自动占位，请自行到小程序查看，不能到场请在开课前 2 小时前取消」+「开启提醒」按钮（AC4.8）。
8. 截止（AC4.7、AC5.5）：距开课 <2 小时起 —— 课程页不再出现可点的候补入口（仍有空位则显示可点的「预约」，无空位则显示不可点的「候补已截止」）；队列全体进入终态「候补已截止（未排到）」并回到「已结束」分段，不再显示任何操作按钮。**该终态不影响他约这一节课**：队列全体进终态后课程若出现空位（唯一来源是 <2 小时的容量调大），他在课表/详情页看到的仍是可点的「预约」（AC5.12、AC5.15③），P6 只作只读展示。
9. 时间冲突（AC4.9、AC5.8）：加入候补时冲突 → 拒绝并显示冲突课程名与时间；转正前发现冲突 → 该会员被移出队列（终态「因时间冲突失效」）、**不发通知**、空位在同一事务内顺延给下一位。
10. 并发（AC5.7）：以服务端事务顺序为准，界面只显示服务端的最终结果（成功 / 「名额已被抢完」+ 候补入口），**不出现"名额空着但已锁定"的中间态 UI**（B6）。
11. 退出候补（AC4.6）：仅在「候补中」状态显示「取消候补」，二次确认文案含"退出后需重新排队、不保留原位次"。
12. 让位入口（PRD §4）：**不提供**"一键让位/放弃名额"按钮；被转正后要还回名额，只能用「取消预约」（≥2 小时）。

### 6.7 时间冲突提示（AC2.5、AC4.9、AC5.8）

统一句式：「与《课程名》《开始—结束时间》时间冲突」。出现位置：
- 预约/候补弹窗内联错误（弹窗不关闭，确认按钮禁用）；
- 详情页主按钮置灰时，按钮下方常驻同一句（原因文字用正常次要色 7.56:1，不用灰字）；
- 候补终态卡片：「因与《课程名》时间冲突，已跳过」（AC5.8）。

### 6.8 文案规范

1. 用会员语言，不用系统术语：写「已自动为你占位」，不写「自动转正成功」；写「停止候补」，不写「队列失效」；不出现"待确认/超时/顺延"。
2. 每条错误 = 原因 + 下一步：「距离上课不足 2 小时，无法自助取消，请联系门店」而不是「操作失败」。
3. 危险操作二次确认里必须写清后果（不可撤回 / 需重新排队）。
4. 不承诺不确定的事：不说「你一定会被转正」，只说「有空位时系统自动为你占位」。
5. 时间一律写绝对时间（8月14日 20:00）+ 相对说明（距开课约 5 小时），**不写秒级倒计时**（本项目已无倒计时场景）。

### 7.1 对比度（≥4.5:1 正文，≥3:1 大字/图形）

说明：以上按 WCAG 2.1 相对亮度公式计算；实现时若调整色值，需重算并把结果写回本表。

### 7.2 触控与尺寸

- 所有可点元素触控区 **≥44×44px**：主按钮高 48px；次要按钮高 44px；日期条单元 44×48px；Tab 项 50px 高；卡片「×」关闭按钮 44×44px；列表项 ≥56px。
- 相邻可点元素的间距 ≥8px（避免长指甲/手套模式误触，健身房场景常见湿手操作）。
- 列表滚动区不放在吸底条下方：吸底操作条高度 72px + 安全区，滚动内容预留同等底部内边距。
- 单屏最多 1 个实心主按钮，减少"误点成取消"的风险。

### 7.3 键盘与焦点（微信 PC 端 / 外接键盘）

- 焦点顺序按视觉顺序：页头 → 日期条 → 卡片列表 → 吸底主按钮；Tab 键可遍历所有可操作元素，**不做仅 hover 才出现的按钮**。
- 焦点态可见：2px `#1D4ED8` 外描边（在浅底上用 `#1D4ED8`，在 `#1D4ED8` 实心按钮上用 2px 白色内描边），不依赖颜色变化之外的任何提示。
- 弹窗打开时焦点锁定在弹窗内、Esc 关闭（等价于点「取消」）；关闭后焦点回到触发按钮。
- 无键盘专用快捷路径不影响主流程（键盘用户可用 Tab + Enter 完成预约/取消/签到点选）。

### 7.4 不只用颜色传达信息（色觉障碍）

- 每处状态都是「文字 + 图形 + 颜色」：已满（🔒 + "已满" + 灰）、候补中（⌛ + "候补中 · 第 N 位" + 主色）、已预约/已转正（✔ + 文字 + 绿）、失败/冲突（⚠ + 文字 + 橙/红）。
- 满员与可约的区分不靠红/绿，而靠**按钮形态**（描边 vs 实心）与**标签存在与否**：可约课程没有状态标签、只有数字「剩余 3/20」；满员必带灰底标签。
- 禁用状态不用灰度区分"可点/不可点"：禁用按钮一定有置灰底 + 描边，并且在按钮**外**有原因文字。
- 校验与提示不用红框独有：错误全部带图标与文字，并可用键盘焦点到达（读屏可读）。
- 图标与图片有文字替代：装饰图标标注 `aria-hidden`；状态图标带 `aria-label`（如「已满」「候补中第 2 位」）；二维码页面提供文字说明「扫码后按页面提示完成签到」，不依赖扫码图片传达信息。

### 7.5 字体可读性与认知负担

- 最小字号 12px，正文 15px；不因断点缩小字号；数字用等宽数字避免跳动。
- 支持系统字号放大（iOS 动态字体/微信字体大小设置）：卡片文字允许换行到 2 行，主按钮文案不截断（必要时按钮高度自适应到 56px），关键数字不换行。
- 一处只讲一件事：规则说明在弹窗内≤3 句、在详情页 1 条提示条 + 完整规则页链接。
- 术语一致：全站只用「已满 / 候补 / 候补中 · 第 N 位 / 已预约 / 已取消 / 已结束 / 已转正（自动） / 已签到」这几个词。唯一例外并写明关系：**「已转正（自动）」是状态名**（P6 候补记录终态）、**「已自动转正」是来源标签**（P5 预约卡片上叠加在「已预约」之上的来源标注，说明这个名额从哪来），二者不得互换使用；状态一律说「已预约」＋来源标签，P6 说「已转正（自动）」。

### 7.6 性能与慢网络（设计侧约束）

- 首屏只渲染当前日期的列表（7 天数据按需请求）；卡片无大图（MVP 不使用课程封面图，减少流量与等待）。
- 骨架屏替代转圈；动效仅保留 1.5s 呼吸与 ≤200ms 的按钮态过渡；不播放自动轮播、不做视差。
- 弱网下写操作超时按 §6.4 给可重试文案；不展示过期名额（AC1.4），宁缺勿错——这是本项目的硬要求，优先于"看起来有内容"。
